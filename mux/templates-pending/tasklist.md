# RFD-<ID> SMART 任务清单（tasklist 模板）

> **模板来源**：方案 §2.7「系分拆分」行字段规范。产出 `docs/analysis/RFD-<id>-tasklist.md`，是 RACI 派发与追踪的唯一依据；缺此文件不得派发（harness 硬失败，不降级）。
> **SMART**（首现释义）：每条任务须具体（Specific）、可测（Measurable）、可达（Achievable）、与本需求相关（Relevant）、有时限（Time-bound）。落到本模板的判据=下表七列齐备且每列可机械核对。
> **RACI**（首现释义）：Responsible 执行人、Approver 批准人、Consulted 咨询方、Informed 知会方，四元组逐任务填写，不允许空列。
> **填表人三问（每节写完自检）**：①本节首句是判断句吗？②每个判据可机械化核对吗？③黑话首现给一句话人话释义了吗？

## 1. 拆分口径

先按模块职责初分，再按架构统筹合并同类项；一个任务只归一个应用模块，跨模块任务拆开。

## 3. 机械核对判据（缺一打回）

| # | 判据 | 核对方式 |
|---|---|---|
| 1 | 七列齐备，无空单元格 | 逐行计数列数=7 |
| 2 | 任务 ID 唯一且连续可查 | 正则 `T-[0-9]+` 去重计数=行数 |
| 3 | 依赖列只引用本表已存在 ID | 逐行解析依赖值 ∈ 本表 ID 集 |
| 4 | 预估人日为数值 | 正则 `^[0-9]+(\.[0-9]+)?$` |
| 5 | 责任人在编制表内 | 对照 docs/admin/org.md 账号列 |

## 4. 编号纪律

任务编号为本清单终局编号，后续设计/排期/测试/报告一律引用本表编号；改版重编号时在本节留旧新映射，引用历史编号不映射=评审 FAIL。
