# Ycode 评审/验证轮范式模板（自研；cc code-review"高信号纪律+独立验证轮"概念参考，专有许可红线：不抄原文）

> 概念来源声明：claude-code 评审/验证轮编排模板的**概念**——高信号评审纪律
> （只评真问题不评风格）+独立验证轮（验证者≠实现者，另起一轮只读核验）。以下为
> Ycode 自研文本。

## 评审轮纪律（高信号）
1. 只报三类：**正确性缺陷 / 安全风险 / 契约违背**。风格、命名、格式不报（lint 管）。
2. 每条发现必须带：文件:行 + 复现或推理依据 + 修复建议。无锚点的发现不提。
3. 结论四态：PASS / PASS-with-nits（仅风格）/ REQUEST-CHANGES（有正确性问题）/ BLOCKED（无法评审）。

## 独立验证轮（验证者≠实现者）
1. 另起只读轮：不看实现者自述，先跑门禁命令再读 diff。
2. 验证三问：门禁真的绿吗？（跑一遍）｜声称的覆盖面真的测了吗？（读测试）｜回归面有没有漏？（相邻路径）。
3. 产出：验证报告（命令输出锚点+逐条声称对账）；发现不符即 REQUEST-CHANGES。
