# SwarmStudio:当 AI Agent 多到需要"驾驶舱",而不是又一个聊天框

> **核心洞察**:我们正处在 AI 协作方式被重新定义的拐点——当你在 5 个终端里同时跑着 Claude Code、在 3 个浏览器标签里开着不同模型、在 2 个项目里和人类伙伴协同推进,混乱就开始了。**工具的形态,决定了协作的效率。**

---

## 一、它解决了什么核心问题

### 1.1 三类工作割裂的混乱局面

今天的 AI 协作面临一个结构性困境:

- **人类协作伙伴**:Matrix 群聊、Slack 频道、微信讨论组……散落在多个 IM
- **本地 Agent 集群**:Claude Code 终端、模型 API 调用、自动化脚本……各自独立运行
- **人机 1:1 协作**:Agent 生成内容、人类审批、反馈迭代……在聊天框里来回滚屏

**三类工作互不相通**。人类伙伴的消息和 Agent 的运行事件在完全不同的界面里,无法统筹。切换成本极高:看一眼 Agent 运行状态要切终端,回一条协作伙伴消息要切 IM,审批一个 Agent 生成结果要切回聊天框。

### 1.2 线性聊天流无法呈现多 Agent 协作

当系统扩到多 agent 协作、调 MCP/Skills/ACP/Claude Code、联动远端 Git/ELK/DB、跨机分布式协同时,**线性聊天消息流彻底失控**:

- **并行**:三个 agent 同时跑,聊天流交错混乱,看不出谁先谁后
- **派生**:主 agent 拉起 subagent,聊天流只显示"启动子任务",看不到嵌套层级
- **收敛**:多个 agent 结果汇总到主流程,聊天流只显示最终输出,中间过程丢失

调试、复现、编排全部失控。线性流无法回答"哪个 agent 在什么时候做了什么、和谁协作、结果如何"。

### 1.3 AI 运行过程缺乏可观测性与可追溯性

AI 决策越来越复杂,但运行过程呈现极简:

- Agent 推理链条只显示最终输出,中间思考过程黑盒化
- 工具调用无 duration 记录,无法判断哪一步慢
- subagent 嵌套层级扁平化,看不出任务分解拓扑
- distributed peer 协作无 trace propagation,无法定位跨机故障点

**审计 AI 决策时,你只能看到"做了什么",看不到"为什么这么做"**。这对需要合规审计的场景(金融/医疗/法律)是致命缺陷。

## 二、它的关键价值:一个驾驶舱统御三类工作

### 2.1 三段联动布局:全貌 → 聚焦 → 处理

SwarmStudio 的核心创新是 **Cockpit(驾驶舱)**——三列联动式布局:

```
┌─────────────────────────────────────────────────────────┐
│ 顶栏：品牌 │ 日程 │ 时钟 │ 搜索 │ 在线状态 │ 通知 │ 用户 │
├───────────┬─────────────────────────────────────────────┤
│ 注意力条  │ [n] 需要你  │ [待办项…] │ 历史                 │
├───────────┼───────────────┬─────────────────────────────┤
│  左栏     │   协作图      │                             │
│  Kanban   │   (图谱画布)  │      右栏·工作区（重心）     │
│  统筹     ├───────────────┤   ┌─────────┬───────────┐   │
│           │   时序事件流  │   │ A2UI表单 │ 文件资源  │   │
│  ·筛选    │   (纵向时间线)│   │         │ 管理器    │   │
│  ·三类    │               │   └─────────┴───────────┘   │
│  ·按优先级│               │      底部：Claude Code/稍后/提交│
└───────────┴───────────────┴─────────────────────────────┘
```

**核心价值**:

- **左栏 Kanban 统筹**:按优先级聚合三类工作(协作/管理/易用),一眼看清全局
- **中栏协作图+时序流**:图谱画布呈现并行/派生/收敛,纵向时间线显示事件流
- **右栏工作区(重心)**:三种模式切换(⚡工作项 / 💬协作 / ⌘编程),同一任务多视角处理

**三段联动**:点击左栏任务 → 中栏面包屑更新 + 时序流切换 + 右栏文件树根目录同步 + Claude Code 根目录同步。**注意力条只在需要你时轻轻提醒,重心始终在右栏工作区。**

### 2.2 Evidence Graph:把线性聊天流重构成证据图

SwarmStudio 最硬核的能力是 **RunTraceView**——把已有的 Socket.IO 事件流重构成 **Evidence Graph(证据图)**:

| 证据层级 | 来源 | 可见性 | UI 渲染 |
|---------|------|--------|---------|
| **L1**(立即可用) | 前端事件流 | 实线边 + 实边框节点 | 可靠可见 |
| **L2**(运行时补齐) | 运行时 hook 后准确补齐 | 虚线边 + `推断` 标签 | 需 hook 支持 |
| **L3**(分布式补齐) | Trace propagation | 点线边 + `future` 标签 | 分布式场景 |

**核心创新**:

- **不可伪造原则**:L2/L3 节点若第 1 层拿不到真实数据,必须用 `future` 样式或 `推断` 标签呈现,绝不画成 L1 实线节点误导用户
- **skill 下钻**:skill 节点可展开内部"思维链 + 工具"交错编排,思维链以动态激活流转呈现
- **三层联动**:时间轴 + 检查器 + 时间游标,支持 live / replay 两种回放模式
- **零运行时改动**:第 1 层纯前端消费已有事件流,无需改 hermes-agent

**关键价值**:

- 多 agent 协作的并行/派生/收敛一目了然
- 审计 AI 决策时每一步推理都可追溯、可回放、可导出
- 调试时能精确定位哪个 agent 哪一步出错、耗时多久

### 2.3 模式切换:同一任务,三视角推进

右栏工作区提供三种模式,**同一件事切到不同视角推进**:

- **⚡ 工作项模式**:A2UI 表单 + 文件资源管理器,处理审批/决策/补充
- **💬 协作模式**:嵌入式 Matrix 聊天,人类伙伴和 Agent 消息同一界面
- **⌘ 编程模式**:Claude Code 终端,以当前任务 Workspace 为根目录的 sandbox 编程

**核心价值**:

- 写代码时是 IDE 感,切到协作视角就是对话流,切到工作项视角就是看板卡
- 不用在文件管理器和终端之间反复横跳
- 人类伙伴的消息和 Agent 的运行事件被同等对待

### 2.4 Pure Ink 视觉哲学:颜色是信号,不是装饰

SwarmStudio 严格遵循 **Pure Ink 黑白灰主题**:

- 仅 status 用 error/warning/success 三色
- 类别/阶段/优先级用灰度+文字+字重区分
- **避免颜色过载**——每一抹颜色都必须有信息含义

**核心价值**:

- 在一个信息密度极高的驾驶舱里,颜色回归语义本位
- 视觉严格克制,专业感强,避免彩色过载导致的认知疲劳

## 三、技术创新点:工程成熟度的体现

### 3.1 Overlay 注入架构:上游可独立升级的革命性设计

SwarmStudio 不是 fork 后大改的"分叉泥潭",而是**工程上极其克制的 overlay 二次开发层**:

**核心原则**:

> 三个上游仓始终保持上游原状,`.git` 永不污染,可独立 `git pull` 升级;所有二次开发代码集中在 overlay 仓。

**混合注入策略(A 类 + B 类)**:

| 类别 | 改动性质 | 接入机制 | 可逆性 |
|------|---------|---------|--------|
| **A 类**(91 个) | 纯新增文件(组件/store/服务) | 构建期 alias 重定向 + entry shim + 运行时 registry | 零侵入上游源码 |
| **B 类**(39 个) | 修改上游骨架(schema/config/路由) | `git apply` 构建期注入 | `git apply --reverse` 完全还原 |

**关键创新**:

- **构建期 alias 重定向入口**:上游入口文件 100% 不改,overlay 提供 shim 在 re-export 上游后调用 bootstrap
- **运行时注册中枢**:提供类型安全的 registerRoute/registerNavEntry/registerComponent 接口
- **功能开关**:所有自定义功能用 `VITE_*` 环境变量控制,默认全开可一键关闭

**核心价值**:

- 上游升级流程明确、可重复、冲突可定位
- 73 个 active patch 100% inject 通过率
- 一次性全量迁移现有成果,功能与当前对等

### 3.2 Evidence Tier 分层:可观测性渐进落地的工程诚实

RunTraceView 的 **Evidence Tier 分层**是工程诚实度的体现:

- **第 1 层**(纯前端、零运行时改动):立即可用,不触碰 hermes-agent
- **第 2 层**(运行时 hook):补齐 LLM span、memory recall、claude code 工具、active_skill 准确归因
- **第 3 层**(分布式 trace propagation):补齐 peer 节点、跨机拓扑

**关键创新**:

- 不在第 1 层伪造 L2/L3 数据,显式标注占位
- 渐进落地,每层独立可验证
- 对齐 **OpenTelemetry GenAI 语义约定**的 JSONL 导出 + 证据档案导出

### 3.3 A2UI 模板化:灵活性与稳定性的折中

Agent 生成的处理表单遵循"生成 → 编辑 → 锁定 → 复用"流水线:

- **生成**:Agent 按任务上下文自由生成 UI 形态(审核单/对比卡/表单…)
- **编辑调整**:用户字段级编辑,可从 8 类受控字段类型添加
- **锁定为模板**:满意后一键锁定,存入模板库
- **复用**:同类任务参考模板生成,可接受或调整

**关键创新**:

- 灵活性来自生成+编辑+复用可调
- 稳定性来自字段类型受控+锁定模板+同类默认参考

### 3.4 完整的 Matrix 即时通讯客户端(49 个组件)

不只是"集成了聊天",SwarmStudio 内置了 **49 个组件**构成的完整 Matrix 客户端:

- 房间列表 / 消息流 / 输入 / 上下文菜单 / 消息操作栏
- 文件面板 / 成员列表 / 成员信息 / 邵请 / 转发 / 导出 / 加入 / 离开 / 创建房间
- 群聊未读追踪、自动 join、日期分隔符
- 基于 `matrix-js-sdk`,经 Matrix homeserver 认证

**关键创新**:

- 人类伙伴的消息和 Agent 的运行事件在同一个界面里被同等对待
- tenant 三段式编码(matrix:roomId:名称 / session:id@profile:名称 / group:roomId:名称)

## 四、应用场景:谁应该用 SwarmStudio

### 4.1 AI 协同密集型团队

典型场景:

- Agent 多到需要看板统筹,而不是终端切换
- 多个 Claude Code 实例并行跑,需要全局概览
- Agent 集群和人类伙伴频繁互动,需要统一协作入口

**关键价值**:三类工作统一统筹,注意力条克制提醒,右栏工作区多模式切换。

### 4.2 需要审计 AI 决策的场景

典型场景:

- 金融风控模型审批,需追溯 Agent 推理链条
- 医疗诊断辅助,需可观测性证据链
- 法律合规审查,需导出证据档案(Evidence Dossier)

**关键价值**:Evidence Graph 呈现运行全过程,每一步 agent 推理都可追溯、可回放、可导出;L1/L2/L3 分层保证审计可信度。

### 4.3 Matrix 生态用户

典型场景:

- 已使用 Matrix 作为团队 IM
- 需要把 Agent 运行事件纳入协作流
- 多租户隔离(Matrix roomId + profile + tenant 编码)

**关键价值**:49 个组件构成的完整 Matrix 客户端,人类协作伙伴和 Agent 在同一个 IM 里。

### 4.4 AI 协同的组织发展需求

典型场景:

- 从单机 AI 工具升级到多 Agent 协作
- 建立人机混合团队的协作规范
- 需要可观测性支撑运维与治理

**关键价值**:驾驶舱式统筹,协作图呈现空间-组织联动,时序流体现时间维度,RunTraceView 提供运维可观测性。

## 六、写在最后

我们正处在 AI 协作方式被重新定义的拐点。**工具的形态,决定了协作的效率。**

SwarmStudio 的答案很朴素:

- 不要更多聊天框,要一个驾驶舱
- 不要更多终端,要一张证据图
- 不要更多切换,要一个多视角工作区

**技术实现的克制与诚实,正是它的成熟度体现**:

- Overlay 注入架构保证上游可独立升级,避免分叉泥潭
- Evidence Tier 分层承认第 1 层能力边界,不伪造数据
- Pure Ink 视觉哲学收敛颜色维度,回归语义本位
- A 类/B 类分类诚实面对"无法纯新增"的现实,转为 patch

**100% AI 编写,Apache 2.0 开源,从今天起,你的 AI 协作有了一个统一的家。**

## 快速开始

SwarmStudio 桌面端当前版本 **0.6.20**,已提供 macOS 与 Windows 两个版本构建物:

```bash
cd overlay

# macOS 版(arm64 DMG + zip)
npm run build:dmg:mac

# Windows 版(x64 exe + zip + msi)
npm run build:dmg:win
```

若只想运行上游原版:

```bash
pip install hermes-agent[all]
npm install -g hermes-web-ui
hermes-web-ui start
hermes --tui
```

> 注:上述是上游官方用法。SwarmStudio 二次开发版需经 `npm run inject` 注入后从源码构建,详见仓库 README。
