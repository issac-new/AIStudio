# RedEvoAgent：基于技能进化的自动红队智能体，攻得更准、调得更少
# URL: https://mp.weixin.qq.com/s/lm4J3hEqDFgAdMwFy026tQ

id="js_content" style="visibility: hidden; opacity: 0; ">

当你的安全团队正在评估接入
 Claude Code 或 Code
x 的内部智能体。它不只回答问题，还能改文件、传数据、调外部 API。你想知道，一个恶意提示词绕过后，会不会触发破坏性工具调用或持久化状态变更。于是你跑了几种越狱工具，结果很不稳定：
同一个攻击手法在 MiniMax 模型上有效，换到 DeepSeek 就失效；在 Claude Code 执行环境里能过，切到 Codex 又被打回
。

这正是当前自动红队最大的尴尬：
攻击经验很难跨目标复用
，而现有智能体化方法靠检索历史攻击轨迹，又容易引入误导、吃掉上下文、输出一堆难以审计的低层动作。

一篇 2026 年 8 月发布在 arXiv 的研究提出 RedEvoAgent，试图把自动红队从
“检索轨迹”推进到“进化技能”
。核心结论很直接：它把跨案例攻击轨迹蒸馏成一份人类可读的 Markdown 攻击技能文档，通过工具有效性画像和验证棘轮筛选更新。在 ASB 和 AgentHarm 两个基准、多个目标模型和 Claude Code/Codex 执行环境中，这份技能让
攻击效果普遍超过最强单一越狱工具
，同时平均工具调用次数下降。更关键的是，这份技能
可以跨攻击模型和目标执行环境迁移，不用重新进化
。

为什么这项研究值得关注：从文本越狱到状态变更

LLM 智能体正在进入产品级执行环境。Claude Code、Codex 这类工具允许模型修改本地文件、传输数据和调用外部 API。这意味着越狱的后果不再是生成一段不安全文本，而可能变成一次真实的命令执行、一次数据外传或一次系统状态篡改。

但
自动红队手段
没有跟上这种变化。

大多数现有越狱方法依赖固定攻击机制。比如 GCG 在预设搜索空间里优化对抗提示词，FlipAttack 用字符翻转伪装，AutoDAN 做进化搜索。它们各自只能覆盖攻击空间的一小部分，面对不同目标模型和执行环境时表现极不稳定。论文在实验中反复看到这一点：
在某些组合下，GCG、AmpleGCG 和 AutoDAN 的攻击成功率甚至低于不越狱的原始提示词
。原因在于，这些迁移过来的对抗后缀或模板前缀，在产品级智能体执行环境中显得更异常，反而提高了拒绝率。

近期的智能体化自动红队尝试引入攻击工具组合。典型如
 RedCodeAgent
，它把攻击方法建模为可顺序调用的工具，并通过语义相似性检索成功轨迹来指导后续决策。思路有价值，但存在三个明显问题。

第一，检索偏差会放大错误经验
。语义相似不代表工具贡献明确，一条成功轨迹里可能混着大量与最终成功无关的工具调用。如果攻击智能体把这些伴随出现的工具误判为有效工具，就会形成自强化偏差。

第二，全轨迹上下文开销大
。每条历史轨迹都包含工具调用、候选提示词、目标响应等低层记录，塞进攻击智能体的上下文窗口里，既增加推理成本，又干扰决策。

第三，可解释性差
。一堆低层动作记录很难让安全团队看清攻击策略到底进化成了什么，也不便于审计。

RedEvoAgent 的研究目标正是解决这些问题：把攻击经验压缩成一份高层策略文档，把技能更新纳入独立验证，避免被误导轨迹带偏。

研究设计拆解：攻击技能怎么“学”出来

RedEvoAgent 的核心思路可以类比成一个安全团队的作战手册迭代机制。
攻击智能体不是每次去翻原始行动记录，而是维护一份不断更新的“攻击技能手册”
。手册里写着哪些工具更有效、遇到失败时应该怎么切换或组合。

整个框架由四个部分组成：攻击工具箱、攻击技能文档、经验收集和验证棘轮。

攻击工具箱

集成七种越狱工具：GCG、AutoDAN、AmpleGCG、Template、FlipAttack、RolePlay，以及论文提出的 Prompt Substitution。最后一种工具用辅助 LLM 重写失败提示词，保持原始意图不变。攻击智能体的每一步要么调用某个工具优化当前越狱提示词，要么执行 QueryTarget，把提示词提交给目标智能体并接收响应。

攻击技能

是一份插入攻击智能体系统提示词的 Markdown 文档。它不堆砌历史动作，而是总结工具效能排序和攻击编排启发式。相比轨迹检索，这种技能级抽象上下文开销更小，也更接近人类安全分析师的阅读习惯。

经验收集是技能学习的原料
。这里有两个关键机制。

一是

工具效能画像。

在技能进化前，RedEvoAgent 先在训练集上逐一测量每个工具对目标的孤立攻击效能。不同目标模型对同一工具的抗性差异很大，所以工具优先级必须针对具体目标环境重新测量，不能照搬通用经验。

二是

决定工具归因。

原始攻击轨迹存在一个危险的自我强化偏差：攻击智能体本来就有工具偏好，某些工具会频繁出现在成功轨迹里，但真正让攻击成功的往往是之后另一个工具。如果错误地把“常出现”当成“有贡献”，技能文档就会强化这个偏差，最终导致策略塌缩。

针对这一问题，论文提出了 Deciding-Tool Attribution。它不是搞新的攻击能力，而是给每条成功轨迹打标：把最后导致 QueryTarget 成功的那个工具标记为“决定工具”。这个机制在轨迹里工具共现较低时作用温和，但在严重选择偏差下能显著降低策略塌缩风险。

真正决定技能更新是否保留的，是

验证棘轮。

每次生成候选技能后，RedEvoAgent 会把它和当前已接受技能在独立验证集上比较。只有严格超过当前技能的验证分数，候选技能才会被接受。如果被拒绝，旧技能和旧轨迹保留，
失败候选记录在拒绝上下文中，指导下一次生成避开同样错误
。

这个机制类似于企业里的灰度发布
：不管你从训练数据里总结出什么新策略，先放到独立验证集上证明自己有效，否则不上线。论文的消融实验显示，验证棘轮并不是可有可无的装饰，它直接关系到攻击技能的稳定性和泛化能力。

核心发现：攻得更准、调得更少、迁移更强

发现一：技能型红队普遍超过最强单一工具和现有自动红队方法

在 ASB 和 AgentHarm 两个基准上，
RedEvoAgent 在所有被评估的目标模型与执行环境组合中，都达到或超过最强单一越狱工具的攻击效果
。

以 ASB 基准、MiniMax-M2.5 目标模型、Claude Code 执行环境为例，RedEvoAgent 的 ASR 为 93.2%，高于最强单一工具 FlipAttack 的 91.8%，也显著高于不越狱基线 72.5%。在 AgentHarm 基准、DeepSeek-V4-Flash 目标模型下，RedEvoAgent 的 HarmScore 为 74.3，而 FlipAttack 只有 67.9。换到 Codex 执行环境，ASB 场景下 RedEvoAgent 在 MiniMax-M2.5 上达到 92.8%，同样超过 FlipAttack 的 81.1%。

更值得关注的是与现有自动红队方法的对比
。在同一 AgentHarm / DeepSeek / Claude Code 场景下，RedCodeAgent 的 HarmScore 只有 37.5，甚至不如直接使用 FlipAttack。这表明基于向量相似性检索的历史轨迹，在这个场景里没有正向帮助，反而可能拖累了攻击。RedEvoAgent 通过技能级抽象避免了这个问题，达到 74.3。

发现二：技能文档带来更高攻击效果，同时工具调用更少

论文做了一个关键
消融实验
：不提供技能文档、提供人工编写的通用技能、以及提供 RedEvoAgent 进化出的攻击技能。

结果非常清晰。在 ASB / MiniMax / Claude Code 场景下，无技能基线 ASR 为 77.5%，人工技能为 78.3%，而进化技能达到 93.2%。同时，平均工具调用次数从无技能的 3.0 次降到 1.8 次。在 AgentHarm / DeepSeek / Claude Code 场景下，无技能 HarmScore 为 34.3，人工技能为 40.5，进化技能达到 74.3，平均工具调用次数从 3.0 次降至 2.2 次。

这个结果对安全团队有直接意义：
更强的攻击效果不一定要靠更多尝试。一份针对性强的技能文档能让攻击智能体一次就选对路，减少无效工具调用，也降低评估过程中的算力消耗
。

发现三：经验组件缺一不可，验证棘轮有边界

消融实验逐个移除经验组件，结果说明每个模块都在起作用。移除工具效能画像，ASR 从 93.2% 骤降到 76.9%，影响最大。没有这个先验，技能进化等于在盲选工具。移除轨迹收集，ASR 降到 85.0%。移除决定工具归因，ASR 降到 87.5%，同时工具调用次数增加。

决定工具归因虽然单看下降幅度不是最大，但它的价值体现在阻止策略塌缩。一旦技能被错误归因污染，后续每一次工具选择都会放大偏差，最终攻击会退化成只会反复调用少数工具。

验证棘轮的轮数也不是越多越好
。在 AgentHarm / MiniMax 场景中，R4 轮更新让验证 HarmScore 从 18.5 提升到 28.1，但测试 HarmScore 反而从 28.8 下降到 20.8。论文检查接受技能后发现，R4 的技能从覆盖多种工具，转向反复采样 FlipAttack 和 RolePlay。这个集中策略在验证集上得分更高，但对测试集的行为泛化更差。

这说明技能进化需要警惕验证集过拟合。一个更分散、更多样化的验证集是可能的缓解方向，但论文没有给出最终解决方案。

发现四：技能文档可以跨攻击模型和执行环境迁移

零样本迁移实验显示，用 MiniMax-M2.5、GPT-4o mini 攻击模型和 Claude Code 执行环境进化出的攻击技能，在切换到 Qwen3-8B、Qwen3-4B 攻击模型后，仍然比无技能基线表现更好。

当目标执行环境从 Claude Code 切换到 Codex，迁移技能达到 90.5 ASR，而无技能基线只有 80.8。
直接针对 Codex 进化出的技能为 92.8 ASR。也就是说，迁移技能保留了大部分效果，不需要重新跑完整进化流程。

这对企业评估不同执行环境有实际价值：一次高质量攻击技能产出后，可以作为后续多个执行环境评估的起点，降低重复工作。

意义与影响：企业怎么用这项研究

RedEvoAgent 首先是一个攻击框架，但它揭示的评估逻辑，同样适用于防御侧和内部安全测试。

第一，停止依赖单一越狱工具做安全评估。

 论文多次验证，不同目标智能体对不同工具的抗性差异极大。GCG 在某个环境里可能比不攻击还低，语义伪装类工具反而更强。如果你的红队只跑一两种固定攻击，很可能高估了智能体的安全性。建议至少覆盖梯度类、模板类、语义伪装类和角色扮演类工具，形成混合工具箱。

第二，用独立验证集约束策略演进。

 如果你正在自建自动红队或攻击脚本迭代流程，不要直接把每次训练结果纳入生产评估。可以借鉴验证棘轮的做法：设定一个独立验证集，只有当新策略严格超过当前基线时才替换。对防御侧而言，这个逻辑同样适用于防御策略迭代，避免只看训练数据上的表现。

第三，要求攻击经验可审计。

 轨迹检索带来的最大问题是不可解释。技能文档的高层描述更容易让安全负责人判断攻击策略是否合理、是否已经塌缩成单一套路。可以要求红队工具输出类似技能摘要，而不是只给一堆原始工具调用记录。

第四，关注技能迁移的生命周期。

 如果你的企业会持续接入新的目标模型或执行环境，可以先用一个代表性环境进化出初始攻击技能，再迁移到其他环境做快速评估。论文中迁移技能保留了大部分效果，但仍低于直接进化结果。因此对于高风险场景，迁移只能作为初筛，最终评估仍需针对具体环境重新进化或微调。

一个可落地的评估检查清单可以包括：目标智能体是否具备文件修改、API 调用、数据传输能力；工具箱是否覆盖梯度、模板、语义重写等至少四类攻击；是否设立独立验证集避免技能过拟合；红队报告是否输出可读策略文档；攻击预算中工具调用次数是否被纳入成本评估。

结尾：自动红队从“翻记录”走向“学手册”

RedEvoAgent 的核心价值，不在于发明了新的越狱手法，而在于改变了自动红队组织经验的方式。
它把分散的跨案例攻击轨迹压缩成一份可读技能文档，用决定工具归因降低错误归因风险，用验证棘轮保证每次更新都经得起独立检验
。

这个思路的影响会超出攻击侧。对安全团队来说，它同时提供了一个更高效的评估框架和一个更可持续的经验沉淀机制。未来智能体红队很可能会从
“每次重新检索相似案例”转向“持续进化并验证一份战略手册”
。而验证集的多样性与独立性，会成为决定这份手册上限的关键瓶颈。

留给从业者的问题也很直接：当你开始用技能文档而不是轨迹检索来组织攻击经验时，你的验证集是否足够多样，能挡住一次“局部高分、全局失效”的糟糕更新？
