## 一、标准定位（§1 范围 / §2 规范性引用文件）

- **目标**: 规定个人金融信息在**收集、传输、存储、使用、删除、销毁**生命周期各环节的安全防护要求，从安全技术和安全管理两方面提出规范性要求（§1）
- **适用**: 金融业机构 = 国家金融管理部门监督管理的**持牌金融机构 + 涉及个人金融信息处理的相关机构**（§3.1）；并为安全评估机构提供检查评估参考
- **核心引用**: GB/T 22239-2019（等保基本要求）、GB/T 35273-2017（个人信息安全规范）、JR/T 0068-2020（网银）、JR/T 0092-2019（移动金融客户端）、**JR/T 0149-2016（支付标记化）**、JR/T 0167-2018（云计算）
- **关键术语**（§3）: 支付敏感信息（§3.3，磁道/芯片等效信息、CVN/CVN2、卡片有效期、银行卡密码、网络支付交易密码等支付鉴权信息）、支付账号（§3.11，银行账户+支付机构支付账户+银行卡卡号）、支付标记（§3.12）、匿名化（§3.23，处理后果**不属于**个人金融信息）、去标识化（§3.24，仍属个人信息）、明示同意（§3.22）

---

## 二、个人金融信息定义（§3.2）

> 金融业机构通过提供金融产品和服务或者其他渠道获取、加工和保存的个人信息。
> 包括**账户信息、鉴别信息、金融交易信息、个人身份信息、财产信息、借贷信息**及其他反映特定个人某些情况的信息。

注：匿名化处理后的信息不属于个人金融信息（§3.23 注1）。

## 三、个人金融信息内容：七大类枚举（§4.1，全文核实）

| # | 类别 | 定义 | 包括但不限于 |
|---|------|------|------------|
| a | **账户信息** | 账户及账户相关信息 | 支付账号、银行卡磁道数据（或芯片等效信息）、银行卡有效期、证券账户、保险账户、账户开立时间、开户机构、账户余额、基于上述信息产生的支付标记信息 |
| b | **鉴别信息** | 用于验证主体是否具有访问或使用权限的信息 | 银行卡密码、预付卡支付密码；登录密码、账户查询密码、交易密码；卡片验证码（CVN 和 CVN2）、动态口令、短信验证码、密码提示问题答案 |
| c | **金融交易信息** | 主体在交易过程中产生的各类信息 | 交易金额、支付记录、透支记录、交易日志、交易凭证；证券委托/成交/持仓信息；保单信息、理赔信息 |
| d | **个人身份信息** | 个人基本信息 + 个人生物识别信息 | 基本信息：法定名称、性别、国籍、民族、职业、婚姻状况、家庭状况、收入情况、身份证/护照等证件、手机号、固话、电子邮箱、工作及家庭地址、照片/音视频；生物识别：指纹、人脸、虹膜、耳纹、掌纹、静脉、声纹、眼纹、步态、笔迹等样本数据/特征值/模板 |
| e | **财产信息** | 提供金融产品服务中收集或生成的财产信息 | 个人收入状况、不动产状况、车辆状况、纳税额、公积金存缴金额 |
| f | **借贷信息** | 借贷业务产生的信息 | 授信、信用卡和贷款的发放及还款、担保情况 |
| g | **其他信息** | 衍生信息及其他个人信息 | 消费意愿、支付习惯等衍生信息；提供产品服务中获取保存的其他个人信息 |

## 四、敏感度分级 C3/C2/C1（§4.2，核心）

| 类别 | 定性 | 危害程度 | 具体枚举（标准原文口径） |
|------|------|---------|------------------------|
| **C3（高敏感）** | 用户鉴别信息 | 未经授权查看/变更后对主体信息安全与财产安全造成**严重危害** | ① 银行卡磁道数据（或芯片等效信息）、卡片验证码（CVN/CVN2）、**卡片有效期**、银行卡密码、网络支付交易密码；② 账户（支付/证券/保险）登录密码、交易密码、查询密码；③ 用于用户鉴别的**个人生物识别信息** |
| **C2（中敏感）** | 可识别特定主体身份与金融状况的信息 + 金融产品与服务的关键信息 | 造成**一定危害** | ① **支付账号及其等效信息**（支付账号、证件类识别标识与证件信息〔身份证、护照等〕、手机号码）；② 账户登录用户名；③ **用户鉴别辅助信息**（动态口令、短信验证码、密码提示问题答案、动态声纹密码）——**若与账号结合使用可直接完成用户鉴别，则属 C3**；④ 直接反映金融状况的信息（个人财产信息〔含网络支付账号余额〕、借贷信息）；⑤ 金融产品与服务的关键信息（交易指令、交易流水、证券委托、保险理赔）；⑥ KYC 及存证保全需要的照片、音视频等影像信息；⑦ 其他能识别特定主体的信息（家庭地址等） |
| **C1（低敏感）** | 机构内部的信息资产 | 可能造成**一定影响** | ① 账户开立时间、开户机构；② 基于账户信息产生的支付标记信息；③ C2/C3 未包含的其他个人金融信息 |

**四条通用判定规则（§4.2 末段）**：
1. 主体因业务需要（如贷款）**主动提供的家庭成员信息**（身份证号、手机号、财产信息等）→ 依 C3/C2/C1 分类保护
2. **低敏感信息组合升级**：两种及以上低敏感类别信息经组合、关联、分析可能产生高敏感信息（如组合构成交易授权完整要素）
3. **场景依赖**：同一信息在不同服务场景中可能属不同类别，依场景和作用识别类别
4. 支付账号属 **C2**；磁道数据/CVN2/有效期/密码等支付敏感信息属 **C3**（§3.3 + §4.2a）

## 五、安全技术要求（§6.1 生命周期六环节）

### 5.1 收集（§6.1.1）
- 不应委托或授权**无金融业相关资质**的机构收集 C3、C2 类别信息
- 收集来源可追溯；隐私政策弹窗/明显位置 URL 引导查阅，获**明示同意**后收集
- C3 经受理终端/客户端/浏览器收集时必须加密防护
- 密码输入须展示屏蔽；网络支付业务系统应采用**安全控件**（输入防护+即时加密）保护支付敏感信息，并防止合作机构获取留存
- 停止提供产品服务时应及时停止收集

### 5.2 传输（§6.1.2）
- 传输前通信双方身份鉴别认证；公共网络传输 C2/C3 必须加密通道或数据加密
- 支付敏感信息的传输控制措施应符合行业技术标准与主管部门规定
- 低敏感信息因参与身份鉴别敏感度上升时（组合构成交易授权完整要素），提升传输保障
- 接收方完整性校验；传输链路冗余保障可用性

### 5.3 存储（§6.1.3）
- **不应留存非本机构**的磁道/芯片等效信息、卡片有效期、CVN/CVN2、银行卡密码、网络支付密码等 C3 信息；确需留存须取得主体及账户管理机构授权
- **C3 必须加密存储**；终端（受理/个人/客户端 App）不应存储支付敏感信息及生物识别样本/模板，仅可保存完成当前交易必需要素且交易后及时清除
- 去标识化/匿名化数据与可恢复识别信息**逻辑隔离**存储
- 停止运营时妥善处置或移交指定机构

### 5.4 使用（§6.1.4，七个子环节）
- **展示（§6.1.4.1）**: 屏幕/App/受理设备/自助终端/纸质凭条均应信息屏蔽（截词），方式见附录 A；未登录态不展示 C3；已登录态**除银行卡有效期外 C3 不应明文展示**；卡号/手机号/证件号等应屏蔽展示，完整展示需用户身份验证；后台系统支付账号/法定名称/预留手机号/证件号宜屏蔽，**不应具备开放式查询能力，严格限制批量查询**，明文查看须细粒度授权+行为审计；截词屏蔽不应用散列（hash）代替被截词部分（防散列碰撞推导）
- **共享和转让（§6.1.4.2）**: 事前安全影响评估 + 接收方安全保障能力评估 + 数据保护责任承诺；**支付账号共享转让时应使用支付标记化**（JR/T 0149-2016）脱敏，无法标记化时加密；**C3 及 C2 中的用户鉴别辅助信息不应共享、转让**；导出按"业务需要+最小权限"细粒度控制+两种以上鉴别技术+全过程审计
- **公开披露（§6.1.4.3）**: 原则上不得公开披露；确需的先评估、告知、征得同意；**不应公开披露个人生物识别信息**；C3 及 C2 用户鉴别辅助信息不应公开披露
- **委托处理（§6.1.4.4）**: **C3 及 C2 用户鉴别辅助信息不应委托第三方处理**（转接清算、登记结算按国家规定执行）；委托信息去标识化（不应仅使用加密技术）；未经书面授权受托方不得再次委托；委托解除时按约定销毁
- **加工处理（§6.1.4.5）**: 清洗转换全程保护，C2/C3 更严格；评估汇聚后重识别风险；防调试信息/日志泄露；防滥用监控预警
- **汇聚融合（§6.1.4.6）**: 不应超出收集声明范围，超范围须再次明示同意；融合后重新评估定级
- **开发测试（§6.1.4.7）**: 开发测试与生产环境有效隔离；**不应使用真实个人金融信息**，用虚构或去标识化（不应仅加密）数据；账号/卡号/协议号/支付指令等测试确需信息除外

### 5.5 删除（§6.1.5）
- 技术手段使信息不可被检索、访问；主体请求删除时依法依约响应

### 5.6 销毁（§6.1.6）
- 建立销毁策略制度；介质销毁全程监督（登记/审批/交接/执行）；保留销毁记录（内容、方式与时间、销毁人签字、监督人签字）
- 不再使用的介质：消磁/焚烧/粉碎等**不可恢复方式**；继续使用的介质：不应只删索引/文件系统，应**多次覆写**安全擦除
- 云环境数据清除依 JR/T 0167-2018 §9.6
- ⚠️ 标准原文未规定统一销毁记录保存年限，"至少 3 年"系旧版文档讹误，已删除

### 5.7 安全运行（§6.2）
- 网络安全：符合 GB/T 22239-2019、JR/T 0071；个人金融信息数据库应处于机构**可控网络内**并有效访问控制
- Web 应用：防页面篡改/源码暴露/穷举登录/重放/SQL 注入/XSS/钓鱼/木马/任意文件上传下载；组件上线前安全评估；实时监测
- 客户端 App 与 SDK：符合 JR/T 0092-2019、JR/T 0068-2020，上线前安全评估
- 密码技术产品：符合国家密码管理部门与行业主管部门要求

| 维度 | 条款 | 要求 |

| 监控审计 | §7.4.1 | 识别记录管理员/业务用户访问；网络流量安全监控；**日志和匹配规则数据至少保存 6 个月**，定期全组件审计 |

| 事件处置 | §7.5 | 应急预案+培训演练；遗失/损毁/泄露/篡改后及时处置并**邮件/信函/电话/推送告知受影响主体**（难逐一告知时发布警示）；系统漏洞或人为原因泄露应立即止损并**向行业主管部门报告**；记录、鉴定原因、评估影响、补救、按规定报告 |
| 投诉申诉 | §7.2.1j/§7.5f | 建立投诉申诉处理程序与跟踪流程，规定时限内响应 |

## 七、附录 A 信息屏蔽/脱敏规则（资料性附录，全文核实）

**原则**: 对外输出的任何个人金融信息原则上应事先做屏蔽（截词）等脱敏处理（已获明示同意或法律法规要求除外）；脱敏后保留原始格式和属性，保证开发测试可用。

**两类方法**:
- **模糊化**: 名称 ID 化+哈希、金额笔数去绝对值化（区间分段/取整）、星号模糊化；缺省隐藏规则 = 显示前 1/3 和后 1/3（向下取整），中间用 * 代替（保长易辨别）
- **不可逆**: 匿名/差分隐私等技术使信息无法识别且不可复原；不应通过拼接关联还原完整敏感记录；不应由局部占比推全量

**表 A.1 特定类型隐藏规则**:

| 敏感信息类型 | 信息范围 | 展示规范 |
|------------|---------|---------|
| 银行卡信息 | 银行卡卡号 | 显示**前 6 位** + *（实际位数）+ **后 4 位**，如 622575******1496 |
| 个人身份信息 | 身份证号码、军官证号、护照号码 | 缺省隐藏规则，如隐藏出生日期；身份证号码**屏蔽后 6 位** |
| | 客户法定名称（姓名） | 隐藏部分字符 |
| | 手机号码 | 除区号外**至少隐藏中间四位**；大陆：前 3 位+****+后 4 位（137****9050）；港澳：前 2+****+后 2（90****85）；台湾：前 2+****+后 3（90****856）；其他海外：缺省规则 |
| | 固定电话号码 | 推荐显示区号和后 2 位 |
| | 电子邮箱 | @ 前显示前 3 位+3 个 *，@ 后完整（con***@111.com）；不足 3 位全显示、@ 前***（tt***@111.com） |

> 注：截词的目的在于**永久删除**某条信息的某个数据段，仅存储部分数据（如仅保留银行卡卡号前 6 后 4）。

## 八、与既有知识库衔接

| 维度 | 既有知识 | JR/T 0171 补充 |

## 十一、版本与时效（2026-09-06 核验更新）

- JR/T 0171—2020 现行有效（2020-02-13 发布即实施）
- **上位法演进**: 《数据安全法》（2021-09-01）、《个人信息保护法》（2021-11-01）、《网络数据安全管理条例》（国务院令第 790 号，2025-01-01 施行）相继施行后，本标准作为技术规范继续有效，个体权利响应口径以法律为准
- **部门规章双轨（重要）**:
  - 金规〔2024〕24 号《银行保险机构数据安全管理办法》（金融监管总局，2024-12-27 发布施行）——银保机构数据安全监管规章，含数据分类分级（业务分级思路与 JR/T 0197 衔接）
  - **央行令〔2025〕第 3 号《中国人民银行业务领域数据安全管理办法》**（2025-04-02 审议通过、2025-05-01 发布、**2025-06-30 施行**，7 章 56 条）——覆盖支付清算、征信、反洗钱等央行履职领域；要求数据处理者开展数据分类分级保护、明确重要数据目录动态管理；**对高敏感数据提出不得在终端设备和移动介质存储、不得导出处理、未脱敏不得对外展示等硬约束**。支付机构适用本办法，其数据分类分级实操应与 JR/T 0171 C1-C3、JR/T 0197 五级对齐
- 2026-06 六部门《金融信息服务数据分类分级指南》（4 级：核心/重要/敏感一般/常规一般）适用于金融信息服务提供者，与 C1/C2/C3 需映射
- 引用本标准条款时，注意与上述规章就同一事项规定不一致时的适用顺序：法律 > 行政法规 > 部门规章 > 推荐性行业标准
