# 数据分类分级与脱敏检查清单 (security-checklist)

> 数据安全域 SOP #3 的执行载体。**新 CDC 管道开工前必填**,个人信息字段无脱敏方案 = 拒绝开工。

## 一、字段分级标准(四级)

| 级别 | 定义 | 示例 | 处理要求 |
|------|------|------|---------|
| L1 公开 | 可对外发布 | 产品目录、公开价格 | 无限制 |
| L2 内部 | 仅内部使用 | 订单状态码、页面埋点聚合 | 不出域(不出内网/不进第三方) |
| L3 敏感 | 泄露损害业务 | 交易金额明细、供应商合同额 | 入湖必脱敏或聚合,权限最小化 |
| L4 个人信息 | 可识别自然人 | 手机号/身份证/姓名/地址/设备号 | **强制脱敏 + 单独授权 + 访问审计**;身份信息参照 GB/T 35273 |

> 判定依据: GB/T 43698-2024(重要数据识别)、JR/T 0197-2020(金融分级)、GB/T 35273(个人信息规范)。

## 二、新管道检查清单 (CDC 管道开工前逐项打勾)

```markdown
## 分类分级检查单 <管道名>
- [ ] 源表全字段逐一定级(L1-L4),清单附后
- [ ] L4 字段清单已确认,且每个字段有脱敏方案(见三)
- [ ] L3 字段确认是否需要(最小必要原则),不需要的从 SELECT 中排除
- [ ] 目标表(Paimon/Fluss)的 ACL 计划已定(谁可读)
- [ ] 源端 binlog 账号权限 = 仅 SELECT 所需库表(不带 ALL)
- [ ] 管道日志不打印 L3/L4 字段明文
- [ ] 结论: 通过 / 有条件通过(条件) / 拒绝
```

## 三、脱敏方案速查 (Flink 管道内置实现)

| 字段类型 | 方案 | Flink SQL 实现 |
|---------|------|---------------|
| 手机号 | 保留前 3 后 4 | `CONCAT(LEFT(phone,3),'****',RIGHT(phone,4))` |
| 身份证 | 保留前 6 后 4 或哈希 | `SHA(xxx)` / 截断 |
| 姓名 | 哈希化(保持可关联) | `SHA2(name, 256)` |
| 银行卡 | 保留后 4 | `CONCAT('****',RIGHT(card,4))` |
| 金额(L3) | 视需求: 区间化/聚合 | `FLOOR(amount/100)*100` |
| 通用 | 加密存储(可逆场景) | KMS/信封加密,密钥不出 KMS |

> 原则: 入湖即脱敏(transform 在 flink 管道内完成);**湖中不存 L4 明文**。确需明文的场景(如对账)走源库直查 + 审计,不入湖。

## 四、权限与审计基线 (infra 执行)

- 目标表权限: 默认拒绝,按角色开白(开发只读生产脱敏表)
- Paimon/Iceberg 权限集成: Ranger 插件社区有进展但未成熟,现阶段以「存储路径隔离 + 账号隔离」替代;select 后续跟踪
- 审计: mysql 开启审计插件(如需);所有直连产线数据的查询走有留痕的通道
- 出境红线: 任何数据不出本机集群;确需出境走出境评估路径(安全评估/标准合同/认证三选一),此为 HumanGate 必须 kanban_block 请示

## 五、参考法规速查

| 法规/标准 | 关键点 |
|-----------|--------|
| 数据安全法(2021) | 数据分类分级是法定义务;重要数据目录管理 |
| 个人信息保护法(2021) | 处理需告知同意;敏感个人信息单独同意;最高罚 5000 万或上年度营业额 5% |
| 网络安全法(2017) | 等级保护义务 |
| GB/T 43698-2024 | 重要数据识别规则 |
| GB/T 35273-2020 | 个人信息安全规范(收集/存储/使用) |
| JR/T 0197-2020 | 金融数据分级 5 级(C1-C5) |
| GDPR(欧盟,如涉) | 数据主体权利/DPO/跨境传输 |
