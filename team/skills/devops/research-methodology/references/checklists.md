## 1.2 集群级已有红线（AGENTS.md 1.2 研究/调研类 DoD）

- 来源可追溯：每个关键数字/结论都有 file:line 或 URL 锚点
- 无编造：不输出"看起来合理"但无来源的数据
- 三角验证：关键结论至少 2 个独立来源确认
- 时效标注：注明数据获取时间 + 数据本身的时间窗口
- 证据强度分级（第四节）：Missing/Present/Wired/Exercised/Outcome-supported 五级，按证据定分不按"有没有"二元判断
- `worker-completion-independence-verification`：不信 worker 自报，逐项机械验证

## 1.3 现状缺口（as-is 的问题陈述，不是提案）

1. **方法论纪律散落在工程纪律里**：deep-research-workflow 教"怎么抓、怎么恢复、怎么拆报告"，但不教"怎么判断证据质量"——没有因果鉴别、来源独立性、抽样框、信度效度等概念。
2. **三角验证是裸红线，无操作定义**："2 个独立来源"的"独立"没有判定标准（同源转载是否算？）；没有理论根据支撑为什么是 2 个。
3. **报告诚实纪律不完整**：有"无编造"，但没有"负面结果必须报告""事后发现不得粉饰为预先计划""局限必须披露"等配套条款。
4. **无开题环节**：调研任务直接开跑，没有"概念化→操作化→抽样策略"的前置设计步骤，导致模糊问题直接变成检索词。
5. **无伦理/合规章节**：抓取合规、涉人数据、利益冲突披露、递归风险等没有任何 skill 覆盖。

## 2.1 落地架构决策

**决策：新建 `research-methodology` 底座 skill + patch `deep-research-workflow`。**

理由（orchestrator 已授权 worker-coder 决策）：
1. **体量大**：4 篇笔记共产出 100+ 方法论点（part1 42 条 M 系、part2 12 块 M4-x/M5-x/M6-x/M7-x、part3/part4 各含整节迁移小节），压缩后核心清单仍有约 40 条——全部塞进 deep-research-workflow 会使其从"工作流 skill"变成不可加载的巨墙。
2. **多 skill 引用**：该方法论同时被 `deep-research-workflow`（web 调研）、`open-source-architecture-research`（源码调研）、`open-source-skill-fusion`（融合调研）、`grounded-citations`（引用纪律）四个以上 skill 需要——按 `fusion-skill-placement` 与 skill 库治理惯例，共享底座独立成 skill、各工作流 skill 以 related_skills + 摘要小节引用，避免同一规则多处复制（单一事实源原则，见 as-is-design-doc pitfalls"单点事实源冲突"）。
3. **deep-research-workflow 仍被 patch**：注入压缩版检查清单（骨架十条 + 指向底座 skill），满足"方法论进工作流"的验收要求。

## 2.4 证据判断：信度、效度与因果（对应书中 ch5、ch8、ch12、ch15）

| E1 | 信度自检：同一调研重跑一次结论一致吗？来源分两组独立得出结论一致吗？（信度=随机误差，可靠加样本摊薄） | p162-165 | part2 M5-2 |

| E4 | 因果三问门禁：凡"X 导致 Y"断言，机械过三问——有相关证据吗？时间顺序对吗？有无第三变量？缺一则降级为"X 与 Y 相关" | p114-116 | part2 M4-2 |
