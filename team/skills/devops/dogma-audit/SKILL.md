# Dogma Audit（教条主义/本本主义排查）

> 定位：对已入库的融合类资产（共享契约/skill/设计文档/SOUL 段落）做存量排查，抓四类症状。与 `fusion-output-quality-gates`（写入门，含门 0）互补：门 0 管新产出，本 skill 管存量与全面体检。

## 四类症状与判据

| 症状 | 判据 | 处置 |
|---|---|---|
| 理论术语裸奔 | 正文用理论术语但不给工程判据/操作定义 | 补判据或删术语 |
| 生搬硬套映射 | 「理论概念→内部机制」映射行右侧只是左侧换名（同义反复=0信息量） | 删行；右侧必须带独立判据（阈值/触发/命令/排除项） |
| 规模错配 | 十人小队披五百人流程；流程条目说不出「谁消费、拦住过什么」 | 纯仪式条目整删 |
| 无消费方产物 | 机制只有文档写了，无脚本消费、无 grep 可见使用记录 | 降级标注或归档，不占主文档正文 |

## 机械排查步骤

1. **圈对象**：共享契约（_shared/*.md）、融合 skill、设计文档理论章节（如 §5.13 类）、SOUL 内嵌框架段。
2. **实判消费方**：对每个「机制/契约」grep 全仓库找脚本/import/工具引用——只有文档自引用 = 无消费方。判据：机制在跑（有脚本/grep 证据）≠ 只有文档写了。
3. **映射表逐行审**：右侧删掉理论词后剩什么？剩不下 = 贴标签行。统计同义反复行比例，>30% 的整表重写。
4. **SOUL 段落判定**：worker 执行时这段是真决策界面（有触发词/判据/动作）还是装饰（纯概念陈述）？装饰段降为一行引用。
5. **产出结构化 findings**：逐条 {对象, 症状, 证据 file:line, 严重度, 纠正方向}，先给用户裁决清单再动文件——不预设立场。

## 与费曼纪律的关系

同一根因的两个表现：写的时候违反费曼（术语不定义、理论先行）= 门 0 拦；写完入库后存量体检 = 本 skill。排查发现的问题回写修复时，按 `design-doc-feynman-craft` 的融合表达纪律（④ 实践为体、理论为名）执行。

## Pitfalls

- **审查自己写的产物**：自查通过率天然虚高——存量排查派独立子代理（delegate_task 只读侦察），产出结构化 JSON 再人工裁决
- **把「有引用」当「有消费」**：文档 A 引用文档 B 不算消费方；脚本 import/工具调用才算
- **一刀切删除**：理论框架有锚定/沟通价值，处置分三档——删（纯映射产物）/降级（移台账+一行指路）/改写（补工程判据），别全删
