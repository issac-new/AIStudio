# 调研报告转述修正（research-report-correction）

> 定位：`research-ledger-reconciliation`（default profile，recheck 管线权威源）管「发现与验收」；
> 本 skill 只管判定后的**落改程序**。recheck 每轮产 CORRECT/FLAG 清单，修正是独立可复用的一类动作。

## 何时用

- recheck 跑完，CORRECT/FLAG 清单待落改
- 引文编号/标题/作者被质疑错配
- 转述被指与原文不符（杜撰标签、语义反转）
- 单源数字与另一源打架且无法裁决

## 错型四分类（先分诊再动手）

| 错型 | 判据 | 处置 |
|---|---|---|
| 引文错配 | 编号实际指向另一篇论文（web 回源验证） | 拆条各归各号，附错配注记 |
| 杜撰标签 | 被引原文 0 命中该词 | 回改原文实际用语，注记禁再转引 |
| 语义反转 | 转述把主体/颜色/方向对调 | 按原文语序回改，注记对调原因 |
| 单源冲突 | 官方与第三方口径打架且无法裁决 | 不选边：两口径并列+「未定谳」标注 |

## 落改程序

1. **引文错配先回源**：web_search 可疑编号看实际指向。标题、作者、编号可能拆自两篇不同论文（标题是 A 的、编号是 B 的）——拆成多条各归各号。禁猜合并方向。
2. **杜撰标签按原文层判定**：该词出现在转述层（报告自己的概括）还是被引原文层？grep 被引原文 0 命中 = 转述杜撰，回改为原文用语；外部原文自带该词（人家真用此术语）不改。判定看层，不看词本身。
3. **语义反转从译文内部不可察觉**：颜色/主客体对调类错误必须比对原文才现形；发现一处即按原文语序回改。
4. **修正注记统一格式**：（日期 修正：错因 + 真身）。留在原位不删——注记是下次对账的证据面，历史可审计。
5. **机械验收四步**：①旧值 grep = 0（注记内历史引述除外，逐条判残留性质）；②新值 grep 在位；③全库连带扫同错引是否残留他文件；④涉设计文档正本引用面时核正本/副本 md5 一致。
6. **台账入账**：锚点追加法写 gap-closure-ledger，逐项记病灶/改法/边界（改什么、不改什么、为何不改）。

## Pitfalls

- **修正注记里的历史引述 ≠ 活引用**：验收 grep 旧值会命中注记内引述（如「原引 X 系错配」），有意保留，逐条判定性质再定性，勿机械清零。
- **同一术语逐文件判层，不一刀切**：A 文件是转述杜撰（改）、B 文件是外部原文自带用词（不改）可在同一次修正里并存。
- **行号漂移先重定位**：修旧报告 file:line 引用前先 grep 内容重定位，旧行号大概率已漂。
