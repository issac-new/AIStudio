# cc-switch native Responses schema compatibility (Moonshot/Kimi)

Fix `HTTP 400: tools.function.parameters is not a valid moonshot flavored
json schema — <At path '$defs.__schema20': when using $ref, type should be
defined in the referenced schema instead of the parent schema>` when Codex
runs through the local cc-switch proxy (127.0.0.1:15721) to Moonshot/Kimi
(api.kimi.com/coding, model k3).

For the 503/circuit-breaker class of failures see
`cc-switch-provider-troubleshooting` instead.

## Root cause model

```
Codex Desktop (wire_api=responses)
  → cc-switch native Responses PASSTHROUGH (no schema rewrite)
    → Moonshot strict validator rejects zod-style schema → 400
```

Codex Desktop plugins (browser-use, codex-app-tools, …) emit tool schemas
with `$defs.__schemaN` alias nodes carrying a sibling `type` next to `$ref`.
Moonshot's strict validator forbids `$ref` + sibling keywords. The plain
`/v1/chat/completions` path is unaffected.

Key files (source repo `/Volumes/nvme2230/lab/cc-switch`):

- `src-tauri/src/proxy/forwarder.rs` — native passthrough gate (only fires
  for xAI upstreams by default)
- `src-tauri/src/proxy/providers/transform_codex_chat.rs` — the
  Responses→Chat bridge; contains the fix
  `sanitize_parameters_ref_siblings` (+244 lines, inlines `$ref` with
  siblings from `$defs`, strips sibling `type` for unresolvable/cyclic refs)

## Decision tree

1. Binary contains the fix?

```bash
python3 - <<'EOF'
import re
b = open('/Applications/CC Switch.app/Contents/MacOS/cc-switch','rb').read()
print('vite assets (UI present):', len(set(re.findall(rb'index-[A-Za-z0-9_-]{8}\.js', b))))
EOF
```

- Fixed binary (local build) → wire_api=responses works; done.
- Official binary → apply workaround (below) or build the fixed binary.

2. Workaround: `wire_api="chat"` — **all three places**, or it gets undone:

   - provider `settings_config` in `~/.cc-switch/cc-switch.db` (per provider)
   - `~/.codex/config.toml` (generated by cc-switch proxy-takeover mode)
   - **every codex-queue provider** (local: MK/MBGM/HK) — sibling providers
     re-enter via failover

   Even then, Codex Desktop (ChatGPT.app) runs a background config rewriter
   that rewrites config.toml wholesale (model/effort/plugin sections drift);
   a one-shot sed is undone within the hour. Treat it as stopgap only.

3. Durable fix: build & swap the binary (next section).

## Rebuilding cc-switch with the fix

```bash
cd /Volumes/nvme2230/lab/cc-switch
pnpm install --frozen-lockfile
pnpm run build:renderer        # produces dist/ — REQUIRED
pnpm tauri build --bundles app # codegen embeds dist into the binary
```

Pitfalls (all hit 2026-09-02):

- **Bare `cargo build --release` produces a NO-UI binary**: tauri codegen
  (which embeds dist/) only runs under the tauri CLI. Proxy works, app
  window is blank. Verify embed before swapping (script below).
- `--bundles none` is invalid; legal values: ios/app/dmg.
- Missing `TAURI_SIGNING_PRIVATE_KEY` → exit=1 at the END, but the binary
  is already produced before signing. Check `target/release/cc-switch`
  mtime and embedded assets instead of retrying blindly.
- Old official binary is a 59MB fat (x86_64+arm64) build; a local arm64
  build is ~31MB. Similar per-slice size does NOT imply assets embedded —
  check vite asset names, not file size.

Verify embed, then swap:

```bash
NEW=target/release/cc-switch
python3 -c "import re;d=open('$NEW','rb').read();print(len(set(re.findall(rb'index-[A-Za-z0-9_-]{8}\\.js',d))))"
# >=1 → assets embedded

cp "/Applications/CC Switch.app/Contents/MacOS/cc-switch" \
   "/Applications/CC Switch.app/Contents/MacOS/cc-switch.bak-$(date +%Y%m%d)"
pkill -f 'CC Switch.app'; sleep 3
cp "$NEW" "/Applications/CC Switch.app/Contents/MacOS/cc-switch"
open -a "CC Switch"
shasum -a 256 "$NEW" "/Applications/CC Switch.app/Contents/MacOS/cc-switch"  # must match
```

## Verify the fix end-to-end

Reproduce the exact failing shape (a `$ref` whose parent carries `type`,
via `$defs.__schema20`); fixed binary → HTTP 200:

```bash
curl -s -X POST http://127.0.0.1:15721/v1/responses \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer PROXY_MANAGED' \
  -d '{"model":"k3","input":[{"type":"message","role":"user","content":[{"type":"input_text","text":"ping"}]}],"max_output_tokens":16,"tools":[{"type":"function","name":"demo","description":"d","parameters":{"type":"object","properties":{"cfg":{"$ref":"#/$defs/__schema20","type":"object"}},"$defs":{"__schema20":{"$ref":"#/$defs/Filter","type":"object"},"Filter":{"type":"object","properties":{"a":{"type":"string"}}}}}]}}'

sqlite3 ~/.cc-switch/cc-switch.db \
  "SELECT datetime(created_at,'unixepoch','localtime'), status_code
   FROM proxy_request_logs WHERE app_type='codex' ORDER BY created_at DESC LIMIT 3"
```

Rust-side regression tests:
`cargo test --lib transform_codex_chat` (93 passed incl. 4 new
$ref-sibling tests: inlines / idempotent / unresolvable-drops-type /
cyclic-terminates).
