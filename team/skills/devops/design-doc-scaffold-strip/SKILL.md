# 设计文档脚手架剔除（Scaffold Strip）

> 权威源声明：泄漏分类学与单条探针的权威在 default profile 的 `cot-leakage-audit`（八类分类 + HEAD 读者测试）；as-is 纪律与回填义务的权威在 default profile 的 `as-is-design-doc`。本件只补两者都未覆盖的**批量剔除 strip pass 操作协议**——用户说「去除设计文档中的脚手架内容」这类一次性批量清理怎么扫、怎么判、怎么改、怎么验收。

## When to Use

- 用户要求「去除脚手架内容」「转纯 as-is」「把会话痕迹从设计文档里清掉」
- 混合了执行过程/融合卡叙事的文档做终态化收口
- 单条修复不适用、需要全文五类扫描的批量剔除

## 五类脚手架与探针

```bash
D=<目标文档>
# A 执行卡号
rg -nE 't_[a-f0-9]{8}' $D
# B 过程叙事（执行过程/故障恢复/限流重试）
rg -nE '执行卡 t_|attempt [0-9]|恢复包重派|重派完成|限流熔断|403 崩溃|秒死|补 [0-9]+ 次|实锤 [0-9]' $D
# C 变更叙事（前身状态对比）
rg -nE '曾因|曾触发|原为|此前曾|曾 [0-9]+ 次' $D
# D 会话语用（决策来源的对话框架）
rg -nE '用户指令|用户裁决|用户质疑|追加口径|经用户' $D
# E 重复节（同一节被写入两份）——先机械比对再删
python3 -c "对比两节文本 identical 后删其一"
```

## 判性：命中 ≠ 必删

探针是行级匹配，命中点要先过两个测试再动手：

1. **机制名词豁免**：命中词只是术语成分——标准域名词（如 GB/Z 185.1 的「用户域」撞「用户」探针）、判例术语（「实锤事故」「反面判例」= 已证实案例的结构化存档）、流程出口分类词（四分法的「转执行卡」）。**句子测试**：剥离命中词后句子仍承载机制语义（规则/阈值/出口条件）→ 保留；句子只剩「谁在何时做了什么」→ 删。
2. **保留清单**（脚手架剔除时的禁删区）：裁决代号（D?-? 类——被其他文档引用的跨文档契约，代号永远保留，只删围绕它的对话叙事）、机制参数（阈值/巡检间隔/门名）、证据锚点（file:line / pN / sha256）、成色分级、数据快照数字。

## 改写模板（保留决策语义，去会话框架）

| 泄漏版句式 | 清洁版句式 |
|--------|--------|
| 经用户裁决（D1-A/D2-A/D3-A，按推荐执行，后续「继续完成所有」补齐剩余两项）： | 按裁决 D1-A/D2-A/D3-A 执行，剩余两项随后续指令补齐： |
| 经用户质疑后全量逐项复检：80 项逐项检索 | 全量逐项复检（80 项逐项检索） |
| 复盘重审（用户质疑「…」，按 30 项对账）后补落 8 项 | 复盘重审（按 30 项对账）后补落 8 项 |
| X 原为 A 单向入湖 | X 已从 A 演进为 B——仅当前身状态本身承载机制语义时保留 from-state，否则直陈现状 |
| 卡 t_xxxx 落地 | 删卡号，机制事实（测试通过数/验收命令/门名）保留 |

## 终验三件套（收工判据，三件全绿）

1. **探针归零**：五类计数全 0；残留命中逐处取 ±60–80 字符上下文窗再判性——豁免或保留清单项标注后可留
2. **结构完整性**：代码围栏计数为偶、无畸形表行（`^||`）、小节编号连续（`grep '^### 4\.'` 类计数抽查）
3. **实质保全抽查**：从被删区域取 5-8 个机制关键词（脚本名/参数/阈值/门名）逐个 grep 计数，全部在位——这是剔除操作上的回填义务机械化

## Pitfalls

- **动手前备份改前快照**（每文件一份到 /tmp 级临时目录）——批量剔除的回滚路径只有备份，误删机制内容无 backup 即不可逆
- **禁对 500+ 字符长行凭 grep 行号盲 patch**：命中点常在长行中部，行内偏移不定，盲 patch 会伤同行机制内容——先取上下文窗精确定位子串再 patch
- **E 类重复节先 identical 比对再删一份**：两节若非逐字节相同，先 diff 出差异再决定合并方向，禁直接删其一
- **词形相近 ≠ 该删**：「实锤事故」是机制术语（事故存档制度），「实锤 4 次」是过程叙事——探针计数归零不是目的，语义纯化才是；豁免残留要能逐条说出豁免理由
- **删除裁决叙事前先查代号是否被别处引用**：D?-? 类代号常被台账/其他文档引用，正文删光代号会制造悬空引用——删叙事、留代号
