# 融合落地对账纪律（裁决粒度 = 落地粒度）

> 外部方法论/制度框架裁决「要不要搬」之后的落地对账与复盘审计阶段。完整融合流程（抓取→通读→扫描→裁决矩阵→落地）在 `article-methodology-fusion`（default profile，本侧只读）；本 skill 只管裁决之后的对账与复盘，跨 profile 写不进时经验沉淀回此处。

## 原子粒度对账（防域级遮蔽）

- **机制级四判定只回答「框架要不要搬」，落地对账必须拆到源文档的原子检查项**逐项 grep 本机——域级「等效印证」会把域内没覆盖的子项一起宣布等效，这是融合漏项的头号根因。
- 对账产出四态状态表：**等效**（本机已有+锚点）/ **已落**（本轮落地）/ **补落**（复盘发现的漏项）/ **有意不落**（附触发条件）。覆盖率按原子项计数汇报，禁用「某域已覆盖」域级口径。
- 用户质疑「还有没落地的」时，正解 = 降粒度重审出状态表并补落真缺口，不是重辩原结论。

## 判定禁连带

- **判「等效」时显式确认不携带相邻子项**：登记表等效 ≠ 同域发现侧义务已覆盖——机制是相邻但独立的检查项。
- **判「不吸收」先问 drop 的是机制本体还是依附语境**：语境 drop（如本体/平台依赖）时，能脱离语境独立成立的轻量检查项必须单独重判，否则被误杀。

## 落地插入机制（patch 锚点）

- **🔴 锚点是插入点，不是替换靶**：往编号步骤/条款结构插新节，old_string 取「插入点之后那节的标题」，new_string = 新节 + 该标题；把既有编号项的正文当替换靶会覆写原步骤、打断骨架，事后要反向修复。
- 既有编号不动（防悬空 § 引用），新内容接最大号或跳号插入；插入后 grep 标题序/步骤序核对骨架完整。
- 改技能/规范文档必须升版本号 + changelog 行（版本纪律）；修正报告/台账里既往误判时，**原判定行加降级注记而非删除**——保留审计链，防后人顺引用扑空。

## 复盘交付物

复盘审计落盘一份 RETAKE 报告：原子项状态表 + 根因（粒度错位/连带判定）+ 复盘纪律沉淀 + 有意不落清单（带触发条件防重复评估）。落点统计与台账条目同步（设计文档落地表 +1 行、gap 台账增量记录）。
