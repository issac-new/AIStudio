# Fusion Doctrine Audit（融合教义资产的教条审计）

> 定位：**入库后周期审计**——写前门禁见 `fusion-output-quality-gates`（default 库，只读）；本 skill 是对已入库教义资产的机械审计 + 处置分流。
> 用户裁词：审计目标是「教条主义/本本主义/生搬硬套」，但处置纪律是「恰当应用、不盲目剪裁」——两个方向都要防。

## 四探针（机械审计，不靠印象）

1. **消费方 grep**：理论术语/对象名（如学术设备名、透镜概念词）在 bin/ scripts/ cron/ skills 全仓 grep——零命中 = 无运行时消费方。
2. **留痕探针**：全看板 task_comments `LIKE '<机制强制词汇>'`——凡正文写「强制/必须/每次必过」的规则，必须有可 grep 留痕通道；零留痕 = 该强制是无锚承诺，降措辞或接 hook。
3. **夹具识别**：DB 表中**同一秒批量插入**的行是测试夹具不是运行数据——对照测试脚本的 INSERT 源（`pid = f"..."` 模式）确认后再判「机制无真实实例」。
4. **声称对账**：文档/版本记录自称的部署面（如「下沉到所有 worker」）vs grep 实测命中数——不符 = 假声称，只修声称向实况对齐，不动机制。

## 处置三分法（审计易犯的反向错误：盲目剪裁）

审计发现分三类，处置完全不同：

| 类别 | 判定 | 处置 |
|---|---|---|
| **假声称** | 文档说 A 实况是 B | 只修声称，机制不动 |
| **先于使用而存在** | 资产已就位、判据真实、等使用时机 | 保留 + 诚实状态标注（如 Wired 待实判）+ 归档触发条件（如 30 天零调用零产物影响→归档）。「无留痕」**不是**删除判据——判断力塑造型知识（决策问句/透镜/偏差清单）的证据活在产物质量里，不在检查表里；强制 comment 念咒是 Goodhart 诱饵 |
| **无消费方纯仪式** | 契约层的学术设备/纯映射段，grep 零消费 | 零丢失移 research 档案，正文留一行指路 + 复查条件；出现真实消费方时回迁 |

**分层准入**：契约层只放活机制；方法层允许先于使用存在但须诚实标注；调研档案是前置理论的合法居所（零丢失，非删除）。

## 知识→应用通道三分法（替代「必过即仪式」）

| 通道 | 形态 | 验证方式 | 准入 |
|---|---|---|---|
| A 结构化 | 铸进格式与门：派工卡必含边界决策、验收 frozen 二分、发布必附回滚 | 产物天然携带证据 | 不允许跳过的规则 |
| B 决策界面 | SOUL/skill 按需加载启发式 | 抽查产物质量（审分解卡时看边界分析在不在），不查 comment 仪式 | 判断力塑造型内容 |
| C 仪式化 | 强制 comment 打勾+执行率统计 | 机械统计执行率 | 仅限有实测失败基线且复发频繁（判例：侦察摘要基线 13%）；无基线不新建 |

审计前先盘点：框架的结构化落点是否已存在（派工卡含边界决策 = A 通道已承载系统问）——已存在则该问句不缺通道，缺的是审计时的产品抽查，不是新仪式。

## 流程

1. **只读侦察**：派独立子代理（leaf）跑四探针，输出严格 JSON findings（对象/症状/证据 file:line/严重度/纠正方向），落盘 research/。审计员与被审资产零利益关联。
2. **事实性漂移立即修**：文档状态与磁盘事实互相打脸的条目（如「⏳ 待派工」实已 done）不经裁决直接修——这是纠错不是变更。
3. **处置清单交用户裁决**：按三分法归组（常 5-6 组），每组给「删除/降级/接 hook/保留」选项与建议——不单边执行。
4. **用户批「恰当应用不盲目剪裁」后**：按通道三分法重排处置，保留项落通道标注，仪式项验基线。

## Pitfalls

- **两个方向的教条都要防**：一是「理论术语裸奔」（定义先行、映射表同义反复）；二是「机械判据一刀切」（无留痕即删）——后者会剪掉判断力塑造型资产，用「Exercised 或死」的伪纪律包装。
- **被审对象是测试夹具 ≠ 机制造假**：先查 INSERT 源再定性，测试脚本的遗留数据与文档假现状是两回事。
- **审计自己也可能越权**：处置清单是裁决材料不是执行令；「同意继续」只覆盖已列选项，新发现的相邻问题（如 worktree 堆积）须单独列出待裁决。
