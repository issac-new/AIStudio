## delegate_task goal 模板

```
蓝军对抗审查 <项目> 融合产物。你是独立审查者，立场：假设融合有缺陷，直到证据证明没有。

审查维度：
1. 【忠实性】读 <源码路径> 抽查 N 个关键机制（列出），对照 <协议文档路径> 逐项验证
   是否忠实转译，有无编造/弱化/添加源项目没有的内容
2. 【一致性】产物文件之间引用是否一致（路径、节号、版本号），section 编号连续无重复
3. 【可执行性】脚本是否真能跑（--help + 最小 case + 边界 case），SKILL.md 里的
   用法命令是否 copy-paste 可执行
4. 【越界】是否改了不该改的（mtime/git 扫描改动文件，对照申报清单找计划外修改）

输出格式（前三行控制头，用你正在审查的协议审查你自己）：
状态/完整性/契约审计 三行 + 发现清单（每条 file:line + severity）+ 总评。
```

## 实测结果（LHH 融合，6 产物文件，509s）

4 WARNING / 0 BLOCKER，全部真实：

| # | 类别 | 缺陷 | 修复 |
|---|------|------|------|
| W1 | 忠实性 | 概念腐化一字之差：`常验证假设`≠源码`待验证假设`（语义反向） | 改 1 字 |
| W2 | 忠实性 | 缺控制头处置失实转述：写 `invalid`，源码实际注入 `blocked/suspect/unknown` | 对照 auditor_agent.py:441 改写 |
| W3 | 可执行性 | 退出码碰撞：崩溃也是 exit 1，会被误读为"检出篡改" | try/except → exit 2，四路径回归 |
| W4 | 越界 | 同日 mtime 出现未申报文件 | 归因：调研阶段产物 + 自己补 pitfall 所改，非越界 |

## 关键纪律

- **同音/近形字是转译最大陷阱**（常/待验证）：协议文档落盘后必须对照源码逐词校对关键术语，不能只校对结构。
- **门效果等价 ≠ 忠实**：`invalid` 和 `unknown` 都阻断 complete，但 reviewer 照抄会把语义写错——忠实性审"值"不审"效果"。
- **退出码三态设计**：0=clean，1=检出（detection），2=运行错误（crash）。检出信号与崩溃信号共用一个码 = 脚本化调用方必然误判。
- **蓝军用被审协议的格式自审**：形成一致性闭环，也顺带验证协议本身可执行。
- **结果读取**：subagent-summary-*.txt 是完整版；live task-N.log 的长行有 `…(+N chars)` 显示截断，tail 看到的截断行不是最终结论。
- **回归测试改什么验什么**：修 W3 后重跑 clean/tamper/crash/corrupt 四路径，不是只跑出错那条。
