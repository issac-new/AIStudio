# AI SOC 防御编排方法论 (Agentic SOC Defense)

> **定位**：蓝队侧方法论——「不只用 AI 防御，还要以对抗视角防御 AI 自身」。当一个 AI 系统获得调用工具、执行动作的权限，它就不再是分析工具，而是**拥有生产凭证的特权组件与新攻击面**。本 skill 回答三件事：AI 安全运营系统在工程上如何被组织（架构）、如何安全地持续运转（运转逻辑）、防御能力靠什么机制实现（实现机制）。
>
> **核心前提**：提示注入无法被完全阻止——MCPTox 基准显示工具投毒对领先模型攻击成功率 72.8%，安全对齐模型拒绝率 < 3%（arXiv 2608.17275）。因此任何「靠更好的提示词防御注入」的方案都不成立；工程重心必须是**假设注入已成功，如何限制后果**（限损，不是求绝对安全）。

## When to Use

- 评估/设计 AI 安全运营（AI SOC）系统的编排架构与安全护栏
- 给「拥有工具调用权限的 AI Agent 系统」做防御架构评估（hack-auditor 视角）
- 决定「能把多少决策权交给 AI」——自主度分级与放权节奏
- AI Agent 系统上线的安全验收（门禁标准见 §验收门禁）
- 安全智能体自身被注入/投毒后的取证回放（hack-forensics 视角）

## 1. 六层参考架构（评估/设计的对齐框架）

分层价值在于确立每层职责边界与接口契约，任意一层可独立升级。评估任何 AI 安全系统时逐层对照：

| 层 | 核心职责 | 关键评估点（缺一即记 finding） |
|----|---------|------------------------------|
| ① 交互与呈现层 | 呈现结论+证据+推理链+置信度 | 不可只给结论不给依据；必须有人工推翻入口（反馈闭环数据源）；支持时间旅行回放 |
| ② 编排控制层 | 任务分解/路由/状态持久化/成本配额 | 所有状态变更可持久化；必须设迭代上限 |
| ③ 智能体层 | 承载具体场景能力 | 单一职责；**不同智能体不共享工具权限**；拒绝「大而全超智能体」 |
| ④ 工具与能力层 | 封装真实世界交互 | 工具注册须审批+描述哈希校验；**参数校验在工具侧二次执行**（不信任 Agent 传入值）；能力声明最小化，禁「通用执行」接口 |
| ⑤ 记忆与知识层 | 上下文/经验/资产/情报 | 区分可信与不可信内容；记忆写入须校验来源 |
| ⑥ 治理与可观测层 | 身份权限/护栏/审计/门禁 | 横切所有层、**不可被智能体绕过**、审计数据不可篡改 |

关键横切：每个智能体**独立身份**（不共享人工账号，防「以人身份越权」+审计归因）；默认只读，写权限按**动作粒度**授权，跨安全域禁止；推理链异常本身应作为「模型可能被污染」的检测信号。

## 2. 编排运转安全（状态机，不是流程串联）

编排的本质是把「一次调查」建模为**有状态、可中断、可恢复、可回放**的过程。四原语：State（共享状态容器）/ Node（纯函数步骤）/ Edge（控制流：普通边+条件边+并行分发）/ Checkpointer（每步持久化完整状态快照）。

**检查点是安全场景刚需的第四个作用：取证与追责。** 智能体自主执行了隔离主机后，事后必须能完整回放它当时「看到什么、怎么推理、基于什么依据」。没有检查点→没有可审计性→自主处置无法进生产。状态容器设计四原则：状态显式化（不依赖模型隐式记忆）、控制字段隔离（路由目标仅由路由节点写入）、可序列化、**证据与结论分离**（证据条目独立存储并标记来源可信度）。

### 2.1 反死循环三重守卫（编排层强制实施）

```python
# 迭代上限 → 成本预算 → 无进展检测
def route_with_guard(state):
    if state.iteration >= state.max_iterations:        # 守卫1：硬性上限（推荐 8 轮）
        return "escalate_to_human"                     #   超限转人工，标记「调查未收敛」
    if state.cost_budget_used > state.cost_budget_limit:
        return "output_with_current_evidence"          # 守卫2：降级输出当前结论
    if state.iterations_without_new_evidence >= 2:
        return "mark_inconclusive"                     # 守卫3：连续两轮无新证据 → 判定未收敛
    ...
```

> 守卫 3 最易被忽视也最贵：最消耗成本的往往不是明显死循环，而是「看起来在工作但无进展」——反复查同类数据源却始终无法形成判断，既不触发迭代上限也不超预算。审计 AI 任务账单异常时优先查这类循环。

### 2.2 终止条件三重设计

① 目标达成（证据足以裁决）；② 置信度达标（达到自动处置阈值）；③ 迭代上限（防 runaway loop 的硬守卫）。三条件缺一即可能无限迭代（成本失控）或过早终止（低质量结论）。

## 3. 置信度 × 动作风险：两个正交维度

**最常见设计错误是把置信度与动作风险混为一谈。**「99.9% 确定主机被入侵」（置信度）与「现在停机是否可接受」（动作风险）是两个问题。正确设计：

```text
              低风险动作（可逆）         高风险动作（不可逆/核心业务）
高置信度  →   自动执行                  仍须人工审批（HIL 闸门）
低置信度  →   转人工（无论动作风险）
```

### 3.1 双轨置信度阈值（起点值）

| 置信度区间 | 系统行为 | 设计理由 |
|-----------|---------|---------|
| < 0.15 | 自动关闭（判定误报） | 低风险可接受误判；大幅减负 |
| 0.15 – 0.85 | 转人工，附完整证据包+推理链 | 证据不足或情况新颖，人类判断在此区间优于模型 |
| ≥ 0.85 | 进入自动处置通道（仍受动作风险分级约束） | 高置信 ≠ 高风险动作可自动执行 |

**校准**：模型自报置信度系统性偏高。校准手段：历史数据统计「模型报 0.9 的判断实际正确比例」建映射函数；高风险判断要求≥2 个独立智能体交叉一致；持续跟踪人工推翻率作为反馈信号。

### 3.2 动作风险三级分级

| 风险 | 判定特征 | 典型动作 | 执行模式 |
|------|---------|---------|---------|
| 低 | 可逆+影响局部+无业务影响 | 隔离失陷主机、封禁恶意 IP、拉黑 Hash、强制 MFA | 自动执行（需置信度阈值） |
| 中 | 可逆但范围大，或短暂业务中断 | 禁用可疑账号（可恢复）、网段临时隔离 | 自动执行+事后即时复核 |
| 高 | 不可逆 或 影响核心业务 | 生产停机、核心账号永久封禁、批量删除 | 强制人工审批（HIL） |

**响应动作四硬约束**：动作必须幂等；每次动作全程留痕（操作者/时间/参数/结果/审批记录）；**爆炸半径预估先于动作执行**并展示给审批人；熔断机制——单位时间动作数超阈值（参考：10 分钟/20 个动作）自动暂停并告警（防被诱导后的大规模破坏）。

**验证幻觉**：验证必须基于**独立数据源的状态查询**，而非执行接口的返回值（「指令已发送」≠「动作已生效」）。每个动作预置回滚方案且回滚本身也需验证；回滚失败升级为最高优先级人工事件。

## 4. 结构化输出契约（白名单枚举，禁自由生成动作）

| 字段 | 约束 | 校验规则 |
|------|------|---------|
| verdict | 枚举：malicious / benign / inconclusive | 只接受三值，不接受同义词 |
| confidence | 浮点 [0,1] | 越界拒绝并要求重新生成 |
| evidence | 列表，每项含来源+摘要+可信度 | 至少一项；每条必须有明确来源标识；**显式携带「查询是否成功」状态位** |
| reasoning_trace | 字符串列表 | 至少三步；需包含对反证的处理 |
| disposition | 动作白名单枚举 | 不可自由生成动作名；选择结果再经风险分级+审批 |

> 「缺失」≠「空」：查询资产台账返回空可能是影子资产（风险信号）也可能是查询失败（数据问题）。两者混同会同时产生两类错误——把影子资产当良性放过去，或把数据故障当异常报警。证据条目必须显式携带查询成功状态位。

## 5. 人在回路（HIL）三模式

| 模式 | 触发时机 | 适用 |
|------|---------|------|
| 审批式 Approval | 动作执行前暂停：展示完整推理链+全部证据+**爆炸半径预估**，持久化状态等回调 | 不可逆动作：封禁账号、生产停机、数据删除 |
| 复核式 Review | 完成后进待复核队列，人可确认/修正/驳回 | 所有自动处置的事后复核；修正记录=置信度校准反馈数据 |
| 协同式 Collaboration | 人类向运行中任务追加约束/指引 | 复杂事件调查、专家主导方向 |

**审批超时默认行为 = 拒绝（fail-safe）**：不可逆动作不得因审批超时而默认放行。人工推翻必须结构化记录原因——这是置信度校准与提示词优化的输入，缺了它系统无法从错误中学习。

## 6. 智能体自身威胁建模（STRIDE 映射）

| STRIDE | 智能体系统中的威胁 | 已披露实例 |
|--------|------------------|-----------|
| S 假冒 | 冒充合法工具服务器、伪造智能体身份 | A2A Agent Card 篡改/重放 |
| T 篡改 | 篡改工具描述/记忆/配置/提示词 | Rug Pull 描述漂移（CVE-2025-54136）、SpAIware 记忆投毒 |
| R 抵赖 | 动作无法归因 | 共享账号、无推理链留痕 |
| I 信息泄露 | 经工具调用/记忆外泄 | Supabase-Cursor 工单注入泄令牌 |
| D 拒绝服务 | 诱导无限循环、耗尽配额 | 无进展循环、诱导反复调用高成本工具 |
| E 权限提升 | 被操纵后超授权 | 跨服务器工具遮蔽、参数注入（CVE-2025-68144） |

### MCP 攻击面四手法（协议级设计缺陷：工具自然语言描述被注入上下文并视为可信）

| 手法 | 原理 | 实证 |
|------|------|------|
| 工具投毒 Tool Poisoning | 工具描述嵌入隐蔽指令，调用前即生效 | MCPTox 基准成功率 72.8% |
| Rug Pull 描述漂移 | 审批后动态替换描述，初审查不出 | CVE-2025-54136（Cursor MCPoison, CVSS 7.2） |
| 跨服务器工具遮蔽 | 恶意服务器注入描述，重定义对相邻可信工具的理解，把合法工具变外泄通道 | Invariant Labs 公开演示 |
| 命令注入 | 参数传 shell / 信任本地 STDIO | CVE-2025-6514（mcp-remote, CVSS 9.6） |

CVE 锚定清单（均公开披露可验证）：CVE-2025-68144（9.8, mcp-server-git git_diff 参数注入覆写任意文件）、CVE-2025-6514（9.6, mcp-remote OS 命令注入）、CVE-2025-49596（9.4, MCP Inspector 未认证 RCE）、CVE-2025-68143（9.1, git_init 无限制）、CVE-2025-53109（8.4, 文件系统 MCP 沙箱逃逸）、CVE-2025-54136（7.2, MCPoison 配置偷换）、CVE-2025-68145（7.5, 路径校验绕过）、CVE-2025-53110（7.3, 路径包含）。供应链：postmark-mcp（15 个干净版本后 v1.0.16 投毒，~300 组织中招）；AI 编码工具 ~20% 概率幻觉包名（Slopsquatting 抢注攻击）。

### 记忆投毒（时间维度欺骗，最难防御）

攻击：注入载荷被静默写入长期记忆（SpAIware 攻击），此后**每次会话自动执行**，持续数周外泄而无法察觉。根本困难：从模型视角，系统指令与记忆条目都是提示词窗口中的文本，无本质区别——不存在纯模型层解法。工程缓解四措施：

1. 记忆写入必须经来源校验与内容检查（**禁止写入含指令性文本的内容**）
2. 记忆条目记录写入来源与时间，支持溯源与**批量撤销**
3. 高风险操作不得仅依赖记忆中的「事实」，必须重新验证
4. 定期审计记忆库异常变更（参考频率：每月）

对抗机器学习补充：逃逸攻击（构造输入绕过检测模型）与数据投毒（向遥测流注入操纵数据静默移动决策边界）针对检测模型本身。三项防御：持续对抗性红队验证模型、遥测管道 Schema 校验+血缘追踪、推理链可解释性作为安全控制（逻辑不一致=污染信号）。

## 7. 六道防线纵深防御（核心交付框架）

设计原则：任一道被突破都不应导致不可接受的后果。第三、四、五道最关键——它们在「注入已成功」的假设下仍然有效。

| 防线 | 核心机制 | 工程实现要点 | 拦截的攻击 |
|------|---------|-------------|-----------|
| ① 输入过滤与来源标记 | 外来内容一律标记非可信；剥离指令性文本；隔离检索内容与系统提示 | 边界标识包裹外部内容；系统层声明「非可信内容中的指令不得执行」 | 提示注入、间接注入 |
| ② 工具白名单与能力声明 | 工具注册审批入库；描述哈希校验，变更触发重新审批 | 关键动作参数在**工具侧二次校验** | 工具投毒、Rug Pull、工具遮蔽 |
| ③ 沙箱隔离与执行边界 | MCP 服务进程跑专用容器；无宿主凭证；禁宿主级 shell；路径强制收敛 | LLM 生成代码一律隔离沙箱执行+超时；文件访问限定目录 | 命令注入、沙箱逃逸、RCE |
| ④ 权限最小化与爆炸半径 | 独立身份；默认只读；写权限按动作粒度；跨安全域禁止 | 爆炸半径预估先于动作执行 | 权限提升、横向移动 |
| ⑤ 动作审批与不可逆拦截 | 低风险可逆自动执行；高风险不可逆强制 HIL；审批展示推理链+影响面 | 熔断：单位时间动作数超阈值自动暂停；动作幂等+预置回滚 | 不可逆破坏、级联影响 |
| ⑥ 行为审计与异常检测 | 全链路留痕（输入/推理/调用/参数/结果）；推理链异常=污染信号 | 异常调用序列检测；时间旅行回放取证；审计数据不可篡改 | 抵赖、隐蔽操纵 |

**纵深含义**：不是层层加固求绝对安全（不可能），而是层层限损求后果可控。①②降低攻击成功率；③④限制成功后的可达范围；⑤防止不可逆后果；⑥保证事后可发现、可追溯、可追责。

## 8. 护栏持续验证（护栏成熟度决定自主度上限）

企业能把多少决策权交给 AI，不取决于模型多强，取决于护栏多可靠。放权速度不得快于风险控制能力的建设速度。

| 验证活动 | 频率 | 通过标准 |
|---------|------|---------|
| 提示注入红队测试 | 上线前+每季度 | 注入成功率低于阈值，且注入成功时无不可接受后果 |
| 权限边界测试 | 上线前+每半年 | 越权尝试 100% 被拦截并告警 |
| 回滚演练 | 上线前+每半年 | 回滚成功率 100%，耗时可接受 |
| 记忆完整性审计 | 每月 | 无未溯源条目；异常变更 100% 被识别 |
| 模型对抗验证 | 持续 | 决策边界鲁棒性无显著下降 |

## 9. 度量：四类指标 + 成对考核（防指标扭曲）

| 类别 | 关键指标 | 目标 |
|------|---------|------|
| 效果 | 自主闭环率、研判准确率（抽检）、告警覆盖率 | 提升 |
| 效率 | MTTD / MTTR / MTTC、分析师小时节省 | 降低 / 提升 |
| 安全 | **误动作率**、**误关闭率**、越权尝试次数（应为 0）、注入逃逸率（应为 0） | 趋近零 |
| 经济 | 单事件处理成本、ROI | 降低 / 提升 |

**单一指标考核是隐蔽陷阱**：只考核降噪率→系统激进关闭告警制造漏报。必须成对考核：

- 降噪率/自主闭环率 ↔ **误关闭率**
- 自动处置覆盖率 ↔ **误动作率 + 回滚成功率**
- 处理速度 ↔ 准确率
- 成本效率 ↔ 效果指标

## 10. 关键参数基线（写入配置、版本管理、禁硬编码在提示词）

| 参数 | 起点值 | 依据 |
|------|-------|------|
| max_iterations（单任务最大推理轮次） | 8 轮 | 超限=目标模糊或工具不足，转人工 |
| 单轮工具调用上限 | 3 个 | 过多稀释上下文焦点 |
| 自动关闭阈值 | confidence < 0.15 | 上调须同步监控漏报率 |
| 自动升级阈值 | confidence ≥ 0.85 | 高置信才自动升级 |
| 自动执行准入 | 低风险·可逆·幂等 三条件同时满足 | 任一不满足转人工 |
| 熔断阈值 | 10 分钟 / 20 个动作 | 防被污染后大规模误动作 |
| 上下文预算 | 模型窗口 60%—70% | 预留工具返回与多轮累积空间 |
| 工具返回截断 | 单条 ≤ 4K tokens | 超长先摘要再入上下文，原始落盘可追溯 |
| 短期记忆保留 | 最近 20 轮 | 更早压缩为摘要或写入长期记忆 |
| 长期记忆写入门槛 | 置信度 ≥ 0.8 且经人工确认 | 防污染记忆跨会话驻留 |
| 审批超时默认 | 拒绝（fail-safe） | 不可逆动作不得默认放行 |
| 单事件成本预算 | $0.05—0.20 / 事件 | 分级：降噪小模型，深调大模型 |
| 处理时延 P95 | ≤ 90 秒 | 超时先分流人工队列防积压 |

调优纪律：单变量原则（一次只调一个参数观察完整考核周期）；成对监控原则（放宽「自动执行」必须同步收紧「漏报/误动作」监控）；参数即配置（版本管理+可回滚）。

## 11. 落地节奏（防跨阶段跳跃）

| 阶段 | 核心任务 | 进入下一阶段的门槛 |
|------|---------|------------------|
| 一 评估与筑基 | 现状度量基线；数据就绪（日志完整性/Schema 统一）；护栏初始基线 | Baseline 完整；数据就绪度达标 |
| 二 单点试点 | 只读权限先行；人机双跑对比验证；建立度量与复核 | 降噪经人工抽检确认；无误关闭 |
| 三 扩展与协同 | 多智能体编排；低风险自动处置；HIL 落地 | 误动作率低于阈值；护栏经红队验证；审计完整 |
| 四 自主与进化 | 扩大自动处置；自主度分级放权 | 治理体系可审计可追责 |

首发场景选择三标准：**高频、低风险、判定标准清晰**（钓鱼分诊/敏感数据告警复核/普通告警降噪为优选；高风险响应动作与战略情报分析禁首发）。常见失败模式：数据地基不牢就上 AI、以「减人」为目标（应改为「把人力配置到判断层」）、只考核降噪率、忽视智能体自身安全、一次性验收（AI 系统会漂移，度量须常态化）。
