# IoT/智能设备「配对服务 → 本机桥 → 特权守护进程」三段 pre-auth 链（同族迁移）

- 标签: IoT配对三段链
- 概括: LAN 配对服务免交互拿凭证 → 桥接层继承权限 → root 守护进程收尾，同类嵌入式设备可整链迁移
- 类型: isomorphism（同族迁移）
- 日期: 2026-11-02
- 来源抽象: lg-webos-attack-surface（t_85020cc8 / gap-20261014-003）

## 适用形状（新目标命中任一即带本打法进场）

- **多阶段渗透链**：暴露面是「配对/注册服务 + 本机 IPC 桥 + 特权守护进程」三层的
  嵌入式设备（智能电视/音箱/门锁/打印机/车机）
- **同代工方案换品牌**：同一中间件 SDK（webOS Luna、AllJoyn、Matter bridge、
  ADB over TCP）做的不同厂商设备——桥与守护层大概率同形
- **结构相同的嵌入式 Web 服务换细节**：3000/3001 这类「本为局域网、公网常误暴露」
  的明文配对端口（Shodan 可见即命中）

## 迁移时要换的参数（目标特定值）

| 参数 | LG webOS 原值 | 迁移时换成 |
|---|---|---|
| 配对端口/协议 | 3000 HTTP / 3001 WSS | 目标设备的配对服务指纹（nmap -sV 先认端口） |
| 测试凭证面 | 内置 `com.webos.app.sync-demo` 签名清单 | 目标固件里的测试/工程模式清单（解包固件找） |
| IPC 桥 | PalmServiceBridge / luna:// | 目标的本机 RPC（DBUS/自定义 socket/Matter） |
| 收尾守护进程 | pmlogd 等 root 服务 | 设备侧 root 运行且接受桥调用的服务 |

## 迁移时保真的骨架（直接照抄的步骤序列）

1. **指纹层**：`nmap -sV -p- <target>` 找配对服务端口 + 版本；Shodan 复核该端口
   的公网暴露量（暴露量本身即风险证据）
2. **免交互凭证层**：找「注册/配对」handler 的逻辑缺陷——重点查三种模式：
   ①内置测试清单可重放 ②`skipPrompt` 类布尔参数服务端不验 ③低权限 key 可
   换发高权限 key（CWE-639 不当授权）。兜底：抓官方 App 配对流量对比字段
3. **桥继承层**：拿凭证后枚举 RPC 面（webOS 是 `luna://` 列表），找「web/远程
   页面可触达且不校验来源」的桥方法——导航/URL 参数类原语优先
4. **收尾层**：桥可达的守护进程里找 root 运行 + 参数直传命令/路径的，链成即 root
5. **证据要求**：每段留 PoC 截获（请求/响应原文 + 时间戳），链级结论给三段
   串联的最小复现脚本；对齐 poc-evidence-snapshot（sha256 内容寻址）

## 坑点

- 三段链**中间段最易断**：凭证拿到了但桥方法枚举不全时，先查官方 App 的 JS
  bundle（调用清单在里面），别盲扫
- 配对服务重启即吊销会话的设备，步骤 2-4 要在同一会话窗口内完成
- 公网暴露 ≠ 可利用：部分厂商云端代理剥离了配对方法，先 `curl` 探方法白名单

## 可复用模式

「**先偷身份，再找继承，最后找特权**」——凡是有配对概念的一体化设备，攻击面
优先按这三层排，比按 CVE 翻效率高（Bitdefender 四个 CVE 全落在第 1/3 层就是佐证）。
