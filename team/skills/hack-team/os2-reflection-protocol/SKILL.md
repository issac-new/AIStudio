## 触发条件

- 想法耗尽 / 思路耗尽 / 自认为的可能性耗尽 / 台账方向表耗尽
- 数字规则命中（见「判 C 规范」）：投入≥8 批次或≥2 小时且产出=空
- 收到反思唤醒消息或反思提醒纸条

**禁止等待"我觉得卡住了"再反思**——慢性零产出场景下每个变体都是"新的"，"卡住了"的自评永远不成立；反思由数字规则触发，不由感觉触发。

**前置清账**：若有用户问了但尚未回答的问题 → 先完整回答；若有已返回但未写入台账的实验结果 → 先写入台账（这算产出；若因此产出非空 → 该方向判 A，本次盘点结束，沿结果继续）。

## 0. 碰壁四分类（判定的组织核心）

| 碰壁情形 | 本质 | 正确处法 | 继续加变体 |
|---|---|---|---|
| A. 方向对，对的变体还没试到 | 采样不足 | 继续执行，换变体 | 有用 |
| B. 方向对，变体已试过、探针观测坏了 | 观测手段错误（假阴性） | 换观测手段重测 | 永远没用 |
| C. 方向错 | 前提/资产不属于本题 | 停止投入，换方向 | 纯浪费 |
| D. 想不出下一个变体 | 知识缺口/生成源枯竭 | 外部输入（检索/求助） | 浪费（先补知识） |

两种判别检验：
- **判 C ＝ 方向级证伪**：测试方向所依赖的前提或资产归属（例如"这条线索属于本题吗"），分钟级，测方向本身而不是加执行变体。
- **判 B ＝ 死路重审**：核对"已死"结论的探针三要素是否完整（见下）。三要素不全的死结论是假阴性嫌疑，复活重测一次。

## 探针三要素（权威定义）

一条证伪探针必须写全三要素，缺一不可：

1. **携带物**——请求带了什么身份/数据（凭据、session、payload 内容）
2. **宿主形态**——用什么地址形式访问（域名/IP/IPv6 环回/内网地址/localhost 变体）
3. **提交路径**——直接提交还是经外部包装（直连、经代理、经重定向链、经第三方服务）

**三要素不全的探针结果不可作为"方向死"的依据。**

## 1. 方向盘点

**盘点第 0 步（先于任何判定）**：用当前卡点的**技法词**（非题目词）直查一次记忆库（hindsight_recall）——同类场景已有现成解法/结论时直接采用或对照，命中方向免试错；无果再进入 A/B/C/D 判定。

更新台账「方向表」每行（没有该表就按 `os2-analysis-ledger` 模板建）：

| 字段 | 规范 |
|---|---|
| 方向 | 一句话描述在追什么 |
| 依赖前提 | 该方向成立所依赖的未验证假设（如"这条凭据属于本题"） |
| 最廉价证伪探针 | 能否定上述前提的最便宜实验，写全三要素 |
| 状态 | 活跃 / 待证伪 / 死 / 降权 |
| 投入 | 批次 × 时长（累计） |
| 产出 | 新增或推翻的「结论台账」条目编号；无则写"空" |

## 2. 判 C：方向级证伪规范

- 活跃方向 投入≥8 批次或≥2 小时且产出=空 → **必须先跑它的最廉价证伪探针**，禁止直接追加执行变体。
- 探针必须写全三要素（携带物/宿主形态/提交路径）；三要素不全的探针结果不可作为"方向死"的依据。
- 先写预期结果再跑；跑完对照判读：证伪命中 → 方向标死、换表中下一个未试方向；方向表空或全死 → 派独立评审（fresh-eyes，见 `os2-analysis-ledger` 触发条件）重灌方向池。

## 3. 归属与持有者清点

- 每条投入中的资产/线索（凭据/密钥/内部数据/发现的服务）回答一次："**属于本题吗**"——归属未验证的挂一条验证实验或降权（二选一，禁止挂起不管）。
- 每个行为体（外部用户 / 自动化客户端、渲染 bot / 服务进程 / 内置账号）× 持有物（会话/凭据/网络位置/权限）× 宿主形态列一遍矩阵；"**谁以自己的身份试过 X**"没有答案的格子挂一条实验。

## 4. 判 B：死路复核

- 挑投入最大的"死"方向，核对其证伪探针的三要素是否完整。
- 不完整（如提交路径经过外部包装、携带物丢失、宿主形态只测过一种）→ 假阴性嫌疑 → **换观测手段重测一次**（补全缺失的要素再观测），而不是原样重跑。

## 5. 换词检索矩阵（判 D 工具：知识缺口时用）

判 D 且 §1 第 0 步轻查无果时展开——列三栏，每栏独立写 3–5 个词，然后跨栏组合成检索词跑 3–5 次检索；渠道含外部（web_search）与本地（技法词直查 hindsight_recall、session_search 查同类历史与未闭环项），各至少一轮：

| 对象（涉及什么） | 时机（什么时候） | 机制（靠什么原理） |
|---|---|---|
| 例：postMessage / e.source / contentWindow | 例：pagehide / 卸载瞬间 / 导航后 | 例："delivered after navigation" / "message across document swap" |

**禁止用被卡住的当前问题原词去检索**——用旧问题的语言搜不到新答案。

## 6. 无知证书（判 D 工具：连续检索无果时用）

把"现在缺什么才能解释现象"写成可检索的条目（而不是继续在旧问题里猜答案）；按固定格式写入台账，区分"知识缺口"与"未想到"：

```text
缺失的概念交集：（要解释当前现象，需要哪几个概念的组合）
需要哪些概念：（逐个列出，2-4 个）
建议检索词：（组合成 3-5 个，交回第 5 节的检索矩阵）
```

连续检索仍无果 = 知识缺口的强信号 → 尽早转求助（kanban_block kind="needs_input"），停止变体穷举。

## 7. 独立反思评审（派 fresh-eyes）

- 派发契约：目标 + 原始材料绝对路径 + 分析台账全文；台账中的死路结论按**待复核**对待（不作为背景事实）。
- 消费义务：返回的**每条候选检验项**要么执行、要么记降权+理由，禁止只写进台账不办。
- Hermes 侧实现：delegate_task 派无历史上下文的子代理执行三节强制审计（前提清单/归属与持有者矩阵/死路重审），或 kanban_create 兄弟卡给未参与主分析的 profile。fresh-eyes 三节审计全文见上游快照 `.opencode/agents/fresh-eyes.md`。

## 与 L0-L4 压力升级的关系：并排不合并

- **pua-pressure-engine L0-L4**（`~/.hermes/skills/devops-worker/pua-pressure-engine/SKILL.md` §压力升级）：按**连续失败次数**升级应对强度——L0 信任 → L1 换本质不同方案 → L2 灵魂拷问（搜完整报错+读源码+列 3 假设）→ L3 七项检查 → L4 拼命模式。管的是「单点操作怎么应对失败」。
- **本协议 A/B/C/D**：按**投入×产出数字规则**（≥8 批次/≥2h 产出空）判**方向**生死——方向级证伪、死路复核、知识缺口转求助。管的是「整个方向该不该继续」。
- 两者正交互补：L0-L4 只升强度不判生死，反思协议判生死不升强度。执行时**并排引用、不合并触发**：命令级连败走 L0-L4，方向级零产出走本协议。
