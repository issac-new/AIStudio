# 受控语言纪律——面向人的输出怎么写

**定位**：全流程（生成流程、开发工作流、回归轮、审查）中，AI 说给人听的每一句话服从本档。目标一句话：**读者第一遍读懂，不用回猜**。

来源：ASD-STE100（简化技术英语，航空维修文档受控语言标准）规范思想 + 公文笔法 skill 调研档案（本机，含改写保真基线测试）。

## 为什么需要本档

不受控的回复有三类高发问题，全流程推演与回归轮中实测出现过：

1. **黑话**：自造缩略语和内部代号不加定义直接用。读者不知道"物化""记档""薄轮"指什么，只能逐个猜，猜错一个就跟丢整段。
2. **跳跃**：结论后置、节与节之间无承接、时间顺序与逻辑顺序混排。读者要自己补路径，补不上就断线。
3. **机器腔**：句长均匀、段末升华、排比成串、箭头链（A→B→C）当叙述。读起来像机器生成，信息密度反而低。

三类问题的共同代价：读者耗费精力猜意思，而不是判断内容。

## 规则分两档

ASD-STE100 的基本二分：**结构规则可机械核对，词汇规则仅方向**。机器查结构（句长、顺序、情态分级），人查词汇（黑话、空词）。本档照此分层。

### 结构规则（六条，机器可核对大部分）

| # | 规则 | 判定方式 |
|---|------|---------|
| S1 | 结论先行 | 首段首句给结论或答案，先说结果再展开 |
| S2 | 一词一义 | 同一概念全篇只用一个名字。"检查/校验/核对/确认"轮换是高发问题，选定一个用到底 |
| S3 | 术语首现定义 | 缩略语和内部代号第一次出现时给全称或一句话定义，之后才能裸用 |
| S4 | 短句单义 | 单句超过 40 字重写；一句话只装一件事；指令类文本一句一动作 |
| S5 | 顺序不跳 | 事实按真实时间排列；节与节之间给一句承接（为什么从这里走到那里）；相邻事件只写先后，不夹因果 |
| S6 | 情态不升降级 | 必须/应当/可以/可能四级不得互换。"可能"是置信度内容，不是风格——不删也不升格 |

### 词汇规则——黑话替代表（方向性，机器只提示不裁决）

| 高发词 | 替代写法 |
|--------|---------|
| 赋能 / 抓手 / 闭环 / 对齐 / 沉淀 / 拉齐 / 颗粒度 / 链路 / 心智 | 写具体事实：谁对谁做了什么，配数字或路径 |
| 极大地 / 显著 / 深度 / 全面 | 删，或换成具体数字 |
| 值得注意的是 / 综上所述 / 不难看出 | 删，下一句直接说事 |
| 箭头链 A→B→C 当叙述 | 改成完整句子，说清每步谁做了什么 |
| 段末升华（这意味着 / 这正是） | 删，段落在信息结束处结束 |

## 双轨制：人面与机面

| 面 | 载体 | 适用规则 |
|----|------|---------|
| 人面 | 会话回复、进度汇报、回归轮报告、审查意见、发布说明 | 本档全部规则 |
| 机面 | trace.jsonl、decisions.jsonl、gate-runs.jsonl、conf 键值、脚本 stdout 的登记行 | 紧凑登记式，不受本档约束 |

CHANGELOG 条目的文件清单行属机面；条目的叙述段属人面——结论先行、术语首现定义同样适用。

## 回归轮报告专项

全流程自动回归的报告是用户直接读的人面文字：

1. 首屏给结论：回归通过与否、关键数字（几栈、几条门禁、几条用例）、遗留风险。
2. 每栈一段：跑了什么命令、原文关键输出、结论。命令与输出如实引用，不转述成形容词。
3. 过程细节（每步的中间产物）归 trace.jsonl 与 CHANGELOG，报告里不重复。

## 改写时的保真底线

在已有文字上润色或压缩时，六件不可丢：事实与数值（含单位）、条件及其作用范围、否定与禁止、顺序、比较关系、引用原文。"可能出现超时"不得写成"偶发超时"——可能性不能升格为观测频率。改完逐项语义对照，不是词匹配。

## 写完自检（30 秒）

1. 遮住作者名，这段话像人对同事说的吗？逐段朗读一遍，不像就重写。
2. 每个术语第一次出现时有定义吗？
3. 逐段问：删掉这段，结论受损吗？不受损就删。
4. 情态逐句对照：有没有把"可能"写成"确定"、把"必须"降成"建议"？
5. 有没有连续三句等长？有没有箭头链？
