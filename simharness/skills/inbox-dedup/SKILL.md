# Inbox Dedup 与双兜底（收单分诊纪律）

## 触发

收到 @自己 的派单/任务消息（包含任务 ID、需求文档或 git 仓库地址）时执行。

## 分诊登记

1. 解析消息中的任务要素：任务 ID、标题、发起方（消息 sender）、团队负责人、
   交付物要求、期限、**推演轮次标识（RUN_ID，派单消息必带）**。
2. 查本机 kanban：`hermes kanban list`。
3. **去重判定（键=任务 ID + RUN_ID，双键）**：仅当同任务 ID **且同 RUN_ID** 的卡片
   已存在才算重复派单：
   - 同键且内容一致 → 不新建，回复「任务 <ID>@<RUN_ID> 已在 kanban（卡片 <cardId>），
     本次为重复派单，已合并」；
   - 同键且要素有更新（期限/要求变更）→ 更新原卡片并回复说明更新了哪些字段；
   - **同任务 ID 但 RUN_ID 不同（复跑/新一轮）→ 不是重复派单**：历史轮产物不抵扣
     本轮交付，必须按新派发执行（或核验本轮产物后）并回执本轮结论行。
4. 不存在则登记到分诊台：`hermes kanban create "<标题>" --body "<任务要素>" --triage`
   （title 为位置参数，无 --title/--status 旗标；body 记任务 ID、RUN_ID、发起方、
   来源房间 event 摘要）。

**禁止静默**：无论判定为新派发还是重复派单，都必须在派单房间回执至少一行
（新派发=按交付要求回执结论行；重复派单=上述合并回执）。对派单消息零回复=违规
——发起方与门禁都在等结论行，静默会被判未完成并打回。

## 人工确认语义

- 卡片处于 triage 即「待人工确认」。人类在驾驶舱/看板确认后才推进（status 前移）。
- 若消息来自团队负责人的转派，而本机已有同 ID 卡片（员工已直接领用），按去重
  合并处理，不重复登记。

## 完成双兜底

任务完成（交付物落 git 仓库）后必须发两条回执：
1. 给任务发起方（或转派人）；
2. 给本团队负责人（manifest 中 teams[].leader）。
两者为同一人时只发一条。发送方式：在当前任务房间直接回复即可；对方不在该
房间时用 `hermes send --to 'matrix:@<账号>:matrix.test' "<回执文本>"` 私信送达。
回执格式：

```
【完成回执】<任务ID> 已完成
交付物: <git 仓库路径/commit>
负责人: <本机 owner>
请 @<发起方-agent> 与 @<lead-agent> 更新各自 kanban 关联任务状态。
```
