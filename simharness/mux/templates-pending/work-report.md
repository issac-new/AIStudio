# 工作管理台账（work-report 模板）

> **模板来源**：方案 §2.7「工作台账（22）」行字段规范 + harness `work_report_gen`（mx-scenario-lib.sh）输出契约。台账由导演侧全量扫描 14 账号板机械生成，落 evidence/work-report.md 并归档 origin/main 仓根。
> **数据纪律**：计数全部出自看板库实查，不手编。扫描基准时刻写入文首，跨表口径一致。

---

> **主导者字段（V8.29 方案 §2.6.5）**：本交付物落仓时须在文档首部标注主导者（AI 产出·角色 agent ／ 人类角色模拟·驱动代演），逐件写实；代偿净额对账与清偿门按此取数，缺标即审计 FAIL（§5.9 净额对账线）。

## 1. 按人 × 状态分布（跨全部账号板）

| 账号 | todo | running | review | done | 其他 | WIP（running） | 卡壳 72h |
|---|---|---|---|---|---|---|---|

卡壳=非 done 且超 72h 未动的卡，逐张清点。72h 以文首基准时刻减 259200 秒实算。 -->

## 2. WIP 清点

<超限账号逐行列：谁、running 几张、分别是什么卡、处置建议（挂起/移交/增援三选一，写明理由）。全员 ≤2 时写「全员 WIP ≤2，无超限」。>

## 3. 72h 未动任务清点与处置

<逐张列：卡号、标题、停滞时长、处置（继续/挂起/移交下轮，三选一 + 一句理由）。无则写「无」。>

## 4. 机械核对判据（缺一打回）

| # | 判据 | 核对方式 |
|---|---|---|
| 1 | 状态分布计数与看板库实查一致 | 逐账号抽核 |
| 2 | WIP 超限行必有处置建议 | 逐行核对 |
| 3 | 卡壳清单必有处置，无则整节写「无」 | 存在性核对 |
| 4 | 基准时刻在文首，全表共用 | 正则命中时间戳 |
