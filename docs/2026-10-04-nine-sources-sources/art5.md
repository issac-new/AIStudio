# LLM自进化的系统性困境：字节跳动最新论文解读（附下载）

今天大多数自进化Agent看似在没有人类干预的情况下改代码、做实验、调策略，但前提是有人已经把目标、评测和反馈集都定好了。模型只需要回答这道题怎么做，不需要问为什么要做这道题。换句话说，它们都在一个默认的温室里运行，外部站着一个判卷人，手里拿着标准答案，模型每走一步，它只负责告诉你这步对不对。这个判卷人不一定是某个人。它可以是一个固定的 benchmark、一个写死的 reward 函数、一段人类提前准备好的单元测试。只要模型还在这些人类搭好的轨道上优化，它就不是真正的自己进化。
从 OpenAI o1 到 DeepSeek R1，再到各类 Agentic 产品，自进化已经成了 AI 的关键词。但大家要的是一个能自己设定方向、自己验证进步、自己修复执行的系统。字节跳动Seed团队近日集中发布**Aspire、S³Gym、HarnessDev**三篇系列论文，共同组成一套完整大模型自进化评估体系。三篇论文拆解了**目标可操作化、交互经验的测试‑评判‑学习闭环、Agent运行框架构建进化**，分别揭示当前大模型自进化的真实能力边界与典型失败模式。（项目主页：https://self-developing-agents.github.io/）
三大基准分工定位
1. **目标层**：把模糊业务诉求翻译为可执行目标、约束与成功标准；
2. **反馈层**：在没有现成评判器时，构建测试、评判体系，识别改进与失败；
3. **系统层**：搭建、迭代工具、上下文、故障恢复等整套执行运行系统（Harness）。
Aspire：从模糊目标出发的自进化基准
传统LLM自进化基准（PostTrainBench等）是**显式任务范式**：人类预先定义任务格式、评测指标、数据集，Agent只需要搜索“怎么优化目标”，不需要思考“该优化什么目标”。
核心设定
Aspire只向Agent提供**自然语言描述的宽泛模糊能力目标**，下游专家编写的评测集完全对Agent保密（密封隐藏评测集，共520条样本，覆盖六大能力：科研推理、人文社科、医疗推理、数学推理、逻辑与指令遵循、学术写作）。
Agent需要自主完成全套工作：解读模糊目标、定位能力缺口、挑选训练数据、选择更新方法、搭建训练与验证信号、决定何时评估，支持两种进化对象：

- **权重进化**：更新模型参数；

- **Harness进化**：固定权重，修改Agent运行框架。
控制器侧保存隐藏评测集，Agent只能拿到聚合分数，看不到样例、标准答案，杜绝泄露。同时控制器做安全回滚：只有确认新版本比基线更好才保留，否则回退原始模型，避免越训越差。

三大研究问题与关键实验结论
1. **RQ1：把明确任务替换为模糊目标会发生什么？**
模糊目标会把大量计算消耗转移到**目标解读与可操作化**，决策思考时间显著变长，实际训练GPU时间变少，总体最终效果显著低于有明确任务的对照组。部分任务上反而有提升，但不存在统一规律。
2. **RQ2：模型权重自更新，能不能从模糊目标获得稳定保留的能力增益？**
实验分为仅最终评测（final‑only）和自适应反馈（adaptive‑feedback）两套协议。

- Agent可以完整跑完“选数据‑启动训练‑产出检查点”整套技术流程，但是**真正高于基线的能力提升非常稀少，并且很难稳定保留**。

- 现象：很多时候局部自我验证分数上涨，但迁移到隐藏的专家评测集就失效；持续训练搜索甚至会抹掉之前微弱提升；训练时误用不匹配数据集会出现灾难性退化，例如全部输出变成单数字标签。

- Final‑only协议：12组模型‑目标配对，**仅1组平均得分高于基线。**自适应反馈也只观测到极少量有效提升。
3. **RQ3：固定模型权重，进化Agent Harness**
Agent可以产出可运行、行为改变的新版Harness，但是**所有进化得到的Harness性能全部低于人工精心开发的Qwen‑Agent参考版本**。
典型失败案例：Agent在自己的小验证集上拿到满分，靠固定模板套答案，但在隐藏评测上泛化崩塌。修复一类bug又引入新的空输出故障。
Aspire得出的最重要结论是**能跑完训练循环 ≠ 真正获得对齐目标的能力提升**，很多看似成功的迭代只是在过拟合自己构建的代理验证集，无法泛化到真实隐藏任务。
S³Gym：自我测试、自我评判、自我提升，把交互经验转化提升
S³Gym聚焦**反馈层问题**：当Agent和环境交互，没有外部给出可靠奖励信号，能不能自己做测试、自己评判轨迹，把交互经验转化为未来更好的行为。
论文把经验驱动自进化拆解成三大耦合能力：

- **Self‑Testing自我测试**：主动探索，生成有诊断价值的交互轨迹；

- **Self‑Judging自我评判**：评估轨迹好坏，识别成功、失败；

- **Self‑Improvement自我提升**：利用评判后的经验改变后续行为。

提供7套可程序化验证文本游戏环境（国际象棋、扫雷、Nullify、俄罗斯方块、贪吃蛇、植物大战僵尸、信任博弈），每个游戏有两套配置：宽松的**探索配置**用于Agent自我探索，严格的**留出评测配置**用来衡量真实泛化。
三条经验内化路径做对照：

- **History ICL原始上下文**：直接把完整交互轨迹放进后续上下文；

- **Summary Memory摘要记忆**：模型把轨迹提炼成规则、失败教训，用简短摘要代替完整历史；

- **Parameter Training参数训练**：把自我评判筛选的轨迹拿来微调模型权重。
核心发现
1. **没有万能最优经验内化路径，效果高度依赖任务本身结构。History ICL原始上下文**会保留全部细节，适合强依赖精确状态信息任务，缺点是消耗大量token，冗余信息多。**Summary Memory摘要记忆**适合可以压缩成简单策略规则的任务。但是压缩过程会丢失关键状态细节，会把错误的自我判断固化成规则，造成性能下降。
2. **Self‑Judging自我评判本身并不可靠。**模型的自我打分和环境真实奖励只有部分对齐。尤其当结果取决于隐藏博弈状态、多步复杂推理，自我评判偏差非常大。**仅仅拥有高准确度的局部自我评判，并不等价于后续就一定能带来性能提升。**识别好坏只是第一步，更难的是把经验转化为可执行策略。
3. **参数训练（微调）风险很高。**微调可以带来巨大收益，但也会出现严重负迁移：把有效旧能力覆盖抹除。部分任务完全得不到收益，同一个模型在不同游戏上表现分化巨大。
S³Gym得出的最重要结论是**交互产生大量轨迹≠自动学会变强**，自我测试‑自我评判‑自我提升整条链路每个环节都存在显著瓶颈，任何一环失效，整条自进化链路就断裂。
HarnessDev：大模型能否创造、迭代Agent Harness
什么是Agent Harness
Harness是模型权重之外整套Agent运行基础设施：执行循环、工具调用策略、上下文管理、持久状态记忆、生命周期故障恢复、验证逻辑。**同样模型权重，换一套Harness，任务性能可以发生巨大差异**，但绝大多数Agent基准固定Harness，只评估模型输出，不去评估“模型能不能自己开发这套运行系统”。

HarnessDev分为两大阶段：**Creation（从零构建）、Evolution（迭代改进已有Harness）**。
**Creation创建阶段**：输入一个功能极度弱化但是可运行的H_seed弱种子框架。种子没有Agent循环、没有工具策略、没有记忆、没有校验逻辑，仅仅提供基础文件读写、进程调用等底层原语。模型要基于少量开发样例，从零开发完整可用Agent框架。评估分为两种模式：

- Self‑Eval：开发Harness的模型同时也是运行该Harness的runtime模型；

- Unified‑Eval：全部生成出来的Harness统一使用同一个固定runtime模型执行，隔离Harness本身质量和运行模型能力，评估Harness的可移植性。
**Evolution进化阶段**：拿自己第一阶段产出的Harness，基于下游执行反馈不断迭代修改代码。会在**反馈开发集**看到分数，同时存在完全隔离的**held‑out留出测试集**，全程不给模型看，用来衡量真实泛化，规避在开发集上过拟合。
数据集覆盖**代码、写作、数据分析、搜索研究四大领域，合计2207个任务实例**，同时记录两大核心指标：任务能力得分 + **Executor执行token开销**，发现性能高不代表token消耗低，部分Harness效果一般但token开销巨大。
关键实验发现
**Creation从零构建结果：**

- 在写作、机器学习实验任务，模型生成Harness可以达到甚至超过人类工程参考系统；

- **代码、搜索研究领域差距巨大**；

- 可移植性痛点：很多Harness只适配开发它的那一个模型。换到另一个runtime模型性能大幅下滑，存在大量硬编码步数、模型专属提示逻辑。

- 代码修改行数与最终性能**没有正相关**，精简的针对性修改有时远好于大量堆砌代码。很多代码片段是死代码，实际运行永远不会触发。
**Evolution迭代进化结果：**

- 在开发反馈集上经常看到性能上涨，但是**增益很难迁移到held‑out留出测试集**；

- 版本迭代不是单调变好：新版本经常发生回归，开发者模型经常选中反馈集最优版本，但这个版本往往在留出集表现很差；

- 同一个Harness，更换runtime执行模型，性能变化巨大，很多在原模型上的改进会直接消失，说明进化出来的逻辑高度耦合特定模型行为，通用性不足。
HarnessDev得出的最重要结论是**Harness是智能的另一个载体，和模型权重同等重要，但是当前大模型可以修改Agent脚手架，却很难产出稳定、可移植、泛化的持续迭代增益**。
三篇论文统一揭示的共同瓶颈
把Aspire、S³Gym、HarnessDev结合，可以总结当前大模型自进化的系统性短板：
1. **Agent验证信号过拟合陷阱**
Agent在自己构建的小验证集、任务上拿到漂亮指标，但是迁移到独立、隐藏专家评测就失效。无论是权重更新（Aspire），Harness迭代（HarnessDev），摘要记忆（S³Gym）都高频出现该现象。闭环跑通不等于真实能力提升。
2. **增益不稳定，非单调迭代**
不管是改权重还是改Harness，迭代不一定越做越好，后续更新经常会摧毁之前微弱进步，需要回滚、版本管理机制。
3. **泛化与可移植性差**
进化得到的权重、Harness、记忆策略高度耦合当前模型、当前开发分布。换到新任务、新模型，收益很容易消失。
4. **自我评判是薄弱环节**
模型很难可靠判断“什么才是真正的进步”。模糊目标下，缺少外部真值，Agent很容易误把表面形式变化当成能力提升。
5. **目标可操作化是前置硬门槛（Aspire核心）**
现实世界自进化起点往往只是一句宽泛自然语言需求。如何把模糊需求拆解为训练、验证目标，恰恰是现在模型最薄弱环节，过去大量自进化工作直接跳过该步骤，由人类预先做好目标翻译。
总结
三篇论文并未否定LLM的能力，也无意否定自我进化这一研究方向的价值。它们所做的是以实验证据划定了当前技术能力的边界，当下模型可以完成目标拆解、自我评判、修改 Agent 运行框架等各类形式上的自进化流程，但流程跑通并不等同于真实能力获得提升。这意味着评估自进化能力，不能只看过程是否完成，必须依靠密封的留出评测，区分开发环境表现与真实泛化效果。纯粹依靠模型自主完成从模糊目标到稳定可迁移的能力增长，目前依旧是极具挑战的开放研究方向。**AI确实很强大，但它还不知道“自己不知道什么”。而识别自身认知的边界，或许才是通往更高阶智能的第一块基石。**
