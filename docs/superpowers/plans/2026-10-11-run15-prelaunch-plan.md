# run15 开跑前冲刺实施方案

**文档定位**：run15 前置工作的唯一执行清单（2026-10-11 立案，来源=run14 复盘观察项+挂账缺件+质量审计待选件三层整合）。执行主体=复盘会话；期限=run15 开跑前全部完成。每件带改动面、验收线、代价；完成后在本文档勾销并记提交锚。

## 一、结论与范围澄清

十个工作件分四批（P1 缺件 → P2 实测验证 → P3 接线 → P4 产品开发），按依赖序执行，预计两个工作日当量。范围有一处必须先纠正的事实：**上轮汇报把"产品八件清单"报成六件未做，是错的**——该八件（git 进度源/建卡校验/字段流转/Turn ended 入审计/告警差分/报告指标行/文案钩子/停滞任务自动提醒默认开）已于 2026-10-11 上午随 overlay `6a0608c6` 全数落 main。真正待做的第三层只剩质量审计三方案中的 B（安全合规三件）与 C（契约执行器接线）两件，本方案将其纳入 P3/P4。

**Non-goals（本轮明确不做）**：宿主级真沙箱与 per-agent 资源限额（原判另立轮）；多机进度总线后两步（端点聚合/跨机巡检，不在本次三层范围）；驱动自愈/帧采集强制内置/产物等待提醒/审批臂四件维持不进产品的既有裁定。

## 三、依赖与顺序

P1/P2 无相互依赖可并行；P3-6 依赖 P2-4（六域读数口径统一）；P3-7 依赖 QUALITY 段已在（V8.8 接线完成）；P4-9/10 独立可并行。每批完成即提交（overlay/simharness 分支→合 main→推 origin），不积攒大提交。

## 四、风险与降级

- P4 两件是产品/语义级改动，若实施中发现超期：9 可降级为"入口按钮+采集实拍"最小面；10 可降级为"影子模式接线"（跑而不断，run15 实测后再转强制）——两降级都不阻塞 run15 开跑。
- 补档件（1/2）必须带 provenance 头注，否则构成"事后冒充当轮"违例（截图红线④同族纪律）。
- 全程遵守：upstream 只读（产品改动走 overlay patch）、驱动主脚本改动后 bash -n+门禁测试全绿才提交。

## 五、run15 开跑门槛（本方案完成后的终检）
