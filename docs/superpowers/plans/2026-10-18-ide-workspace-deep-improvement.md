# IDE 工作区深入重构、优化、整合、整改方案（2026-10-18）

**主旨**：把本轮回归暴露的 13 项缺陷归并为四类结构性债，用分阶段重构替代继续打补丁。先修正确性与安全边界，再优化加载与轮询，最后整合状态与质量门禁。

**受众与用途**：写给 IDE 工作区维护者与产品负责人。读完后应能判断先做哪一档、每档的代价与验收线。

## 一、现状判断

本轮回归证明功能面是完整的，但四个结构问题会持续制造同类缺陷。

1. **启动与选择状态分散**。`IdeShell` 的路由 watcher、`IdeChatPane` 的 `onMounted`、`IdeTaskSidebar` 的点选各自决定「当前是哪个会话」。本轮两个 P1（引导页遮挡、冷启动深链被顶掉）都源于此。锚点：`custom/client/ide/views/IdeChatPane.vue:145`、`custom/client/ide/views/IdeShell.vue:60`。
2. **工作区根有多个事实源**。文件页签用「会话 workspace → ide.workspace」，Git 页签用 `ide.workspace`，队列/回滚/侧问/自检又各读各的。同一个界面里不同面板可能指向不同仓库。锚点：`IdeFilesPane.vue:20`、`IdeGitPane.vue`、`IdeQueuePanel.vue:61`、`IdeTurnRail.vue:101`。
3. **17 个页签静态打包、各自拉取、各自处理错误**。`IdeSidePane` 顶部静态导入全部页签。存储、工作流、轨迹、上下文档案各自管理请求与空态。401/404/503 有的直出裸错误，有的静默。锚点：`IdeSidePane.vue:13`、`WorkflowObservationPanel.vue`、`IdeTrajectoryPane.vue`。
4. **安全加固与文件访问路径没有统一收口**。下载改 header 鉴权、补 root 是本轮补丁。Markdown 媒体仍走 query token。文件 API 沙箱拒绝 `~/.hermes-web-ui` 根。草稿会话仍轮询 404。这三件事是同一层能力的不同出口。

判断：继续按单点修，下一轮还会出现「某个面板指错仓库」「某个错误直出」「某个深链被顶掉」。需要先把选择、根、资源访问三件事收成单一事实源。

## 二、目标架构

```
路由/深链 ──► useIdeBoot（启动意图 → 会话/任务落位）
                  │
                  ├─► useIdeWorkspace（唯一根：任务 > 会话 > IDE 偏好，含校验）
                  ├─► useIdeTask（任务读模型：overview 板提示 + getTask 详情 + 缓存）
                  └─► useIdeResource（请求去重/TTL/超时/错误分级）
                            │
侧栏页签注册表 ──► 懒加载 + 生命周期（active 才挂载/轮询）
                            │
                      IdeSelfCheck 注册表（同一批探针供 UI / CLI / E2E 复用）
```

四个组合式函数是重构骨架。页签、聊天、状态栏只消费它们，不再各自判断。

## 三、分档方案与代价

### 方案 A：先整改、再优化、后整合（推荐）

顺序：P0 正确性与安全 → P1 性能与生命周期 → P2 状态与 i18n 整合 → P3 质量门禁。每阶段独立可交付、可回滚。

- 代价：约 4-6 个 AI 工作会话，折合人工 8-12 天。
- 收益：同类缺陷不再复发。性能与可观测性同步提升。
- 风险：周期最长。P0 期间需要冻结 IDE 的大改。

### 方案 B：先稳后优（P0 + P3 先行）

先做正确性/安全整改与质量门禁，性能与整合延后。

- 代价：约 3-4 个会话，折合人工 5-7 天。
- 收益：最快把「不可用/不安全」清零，回归可自动化。
- 风险：静态打包、根多源、轮询重复仍在，后续改动仍可能踩同类坑。

### 方案 C：只做 P0 整改

只修正确性与安全，不动架构。

- 代价：约 1-2 个会话，折合人工 2-3 天。
- 收益：本轮 13 项缺陷与媒体 401 清零。
- 风险：结构性债保留，下一轮回归很可能再次发现同类问题。

## 四、P0：正确性与安全整改

### P0-1 启动编排器

新增 `custom/client/ide/composables/useIdeBoot.ts`，把「路由意图 → 载入会话 → 选择目标 → 必要时建草稿」收成一个状态机。`IdeShell` 只调用它，`IdeChatPane` 不再在 `onMounted` 里重复 `loadSessions` 与 `ensureSession`。

验收：

- 裸落地、`?session=`、`?task=`、幽灵任务、归档任务五种入口都有自动化断言。
- 任何入口只触发一次 `loadSessions`。后续初始化不得覆盖已选中的会话。

### P0-2 工作区根单一事实源

新增 `useIdeWorkspace.ts`，统一优先级：任务 `workspace_path` → 活动会话 `workspace` → `ide.workspace` 偏好。提供 `root`、`source`、`valid`、`refresh()` 与变更事件。所有消费方（文件、Git、终端 cwd、Wiki、Worktree、队列、回滚、侧问、自检）只读它。

验收：

- 同一界面内文件、Git、终端、简报 Git 块指向同一个根。
- 根不在允许沙箱时显示可解释状态，不再打 400。
- `~/.hermes-web-ui/coding-agent/...` 这类产品自管目录要么显式放行，要么禁止新建的会话落到那里。

### P0-3 任务读模型

新增 `useIdeTask.ts`：先用看板 overview 拿板提示，再用 `getTask` 拿详情。缓存结果并带 stale 守卫。任务简报、任务上下文条、看板页签统一消费，不再各自 `listTasks`。

验收：

- 归档/已完成任务深链能出简报。
- 跨板任务能切到正确板。幽灵任务快速收起。
- `listTasks` 的状态过滤不再影响深链解析。

### P0-4 请求与错误分级

新增 `utils/ideErrors.ts` 与 `useIdeResource.ts`：统一 401/403/404/503/超时的文案与级别。404 静默冷却，503 显示「依赖未启动」，500 显示真实错误。工作流页签、轨迹、上下文档案、草稿轮询先接入。

验收：

- IDE 界面不再出现 `http_401:`、`ECONNREFUSED` 这类裸错误。
- 草稿会话的 `workspace-run-changes` 404 不再周期性刷控制台。

### P0-5 下载与媒体鉴权

下载按钮已改为 header 鉴权并补 root。剩余媒体需要二选一：

- A 案：客户端鉴权 blob（fetch + object URL）用于图片/音频。视频走 B 案。
- B 案：服务端签发短 TTL 下载令牌，仅对媒体/下载端点放行 query token。

建议混合：图片/音频用 A 案，视频用 B 案，兼顾 Range 请求与安全。

验收：

- Markdown 图片、音频、视频在会话内可预览。URL 不含 API key。
- 下载、预览、附件三条路径共用同一套 root/profile 解析。

### P0-6 E2E 冒烟基线

把本轮手工走查固化为 `scripts/regression/ide-smoke.mjs`，复用现有 `scripts/regression/` 设施与 Playwright。覆盖裸落地、深链、五类入口、17 页签、下载、存储、命令面板、中英切换、Esc 关闭。加 npm script。

验收：一条命令在开发链跑完，失败输出截图与控制台错误。

## 五、P1：性能与生命周期优化

### P1-1 页签懒加载

`IdeSidePane` 的 17 个静态导入改为注册表 + `defineAsyncComponent`。files/review/terminal 可保留 eager，其余按需。加加载态与错误边界。

验收：IDE 首屏 JS 体积下降并记录基线。17 页签逐个可打开、可关闭、不重复挂载。

### P1-2 页签生命周期与轮询治理

定义「页签激活才挂载、隐藏即暂停」的生命周期。统一计时器服务，接入 Page Visibility。侧会话 30s 轮询、恢复建议、运行计时、终端重连都受控。

验收：隐藏页签零轮询。切回时按需刷新。无重复计时器。

### P1-3 存储快照服务化

4 秒预算只是止损。改为应用启动后空闲时后台扫描一次并落盘缓存，面板读缓存。清理后失效。大树用 worker 或子进程，避免与聊天请求争事件循环。

验收：热打开 <200ms。首次扫描有上限与进度。清理后数据正确失效。

### P1-4 大会话性能

导入的 CLI 会话有 430 条消息，当前分页加载。验证 `MessageList` 的滚动与交互预算。若滚动帧率低于 50fps，再虚拟化或按轮折叠。给大会话定性能基线。

验收：430 条会话滚动、搜索、回放不卡顿。内存有上限。

### P1-5 状态栏与窄屏

状态栏改为优先级溢出（低优先指标收进「⋯」），不再靠挤压。1280 宽与英文态复测。侧栏分组过滤按会话记忆，存储/配置页签更容易找到。

验收：1280 宽无裁切、无 7px 热区。英文态无截断。

## 六、P2：整合与体验

### P2-1 IDE store 拆分

把 `ide` store 拆为 `ideSession`（选择/引导）、`ideLayout`（栏控/页签）、`ideWorkspace`（根/校验）、`ideBriefing`（任务读模型）。迁移现有消费者，删掉组件内重复状态。

验收：同一状态只有一个写入点。store 测试覆盖迁移后的关键路径。

### P2-2 i18n 单一事实源

把 `STATUS_TEXT`、`CTXARCHIVE_TAB_TITLE`、`GROUPS`、`IDE 工作区` 这类本地字典收进 `custom/client/ide/i18n.ts`，zh/en 成对。新增 IDE 模板 CJK 字面量扫描门禁（白名单只留运行期数据与新自检文案）。

验收：中英切换无裸键、无残留中文。门禁会拦下新增的硬编码。

### P2-3 自检产品化

自检探针改为注册表（id、severity、owner、fix hint、对应页签），支持 `--json` CLI、历史报告对比、失败项一键打开对应页签。CI/合入清单接 CLI 模式。

验收：自检既是手点入口也是机器门禁。报告可比较。

### P2-4 体验一致性

统一「新会话 / 未命名任务」文案。看板/轨迹/Wiki 空态给下一步动作而不是裸 404。命令面板补「打开页签」「最近文件」「自检」。键盘快捷键集中成一张表。

验收：走查不再出现「点了没反应」「空白不知道下一步」。

## 七、P3：质量门禁与流程

1. **Tab mount matrix**：17 个页签在 mock 环境下逐个挂载，断言根节点、无 pageerror、无裸 i18n 键。
2. **契约测试**：下载鉴权/root、归档任务、存储 partial、深链五入口、文件根校验。
3. **补丁守卫**：655/656/657 各自有存在性、series 注册与关键行断言。
4. **打包预算**：记录 IDE 页签 chunk 体积，超阈值失败。
5. **合并脚本**：自动识别 `main-live` worktree 与 IN-FLIGHT，避免在共享树切分支。spec 只认 `docs/superpowers/specs/*.md` 的规则写进开发说明。
6. **回归清单**：每次 IDE 改动的验收固定为「smoke + 自检 + tab matrix + 类型/构建」。

## 八、不做什么

- 不重写上游 FileTree/下载组件，继续用最小补丁。新增能力优先 wrapper。
- 不改登录默认落点。当前 `/app` 旅程页是产品决策，工程侧只提供可配置入口。
- 不在本方案内做桌面端装机、Electron 主进程、原生模块验证。
- 不顺手重构 cockpit/matrix/kanban 非 IDE 域。共享契约除外。

## 九、排期建议

| 阶段 | 内容 | AI 会话 | 人工折算 | 依赖 |
|---|---|---|---|---|
| P0 | 启动/根/任务/错误/媒体/冒烟 | 2 | 4-6 天 | 无 |
| P1 | 懒加载/轮询/存储/大会话/状态栏 | 1-2 | 2-3 天 | P0 的根与资源层 |
| P2 | store 拆分/i18n/自检/体验 | 1-2 | 2-3 天 | P0、P1 稳定后 |
| P3 | 门禁/脚本/清单 | 1 | 1-2 天 | 可并行，随阶段落地 |

推荐先批准 P0 与 P3 的冒烟基线。P1/P2 在 P0 验收后按实际回归结果再排。

## 十、验收总账

- 本轮 13 项缺陷 + 媒体 401 全部有自动化或实机证据。
- 全量测试不低于 4900 例且零失败。server tsc、vue-tsc、build:full 全绿。
- 自检 15 项在当前环境 0 失败。告警项有明确环境解释。
- 同一界面所有面板指向同一工作区根。无裸错误、无未解释 404。
- 新增硬编码 i18n、超预算 chunk、缺失补丁守卫均会在门禁阶段失败。
