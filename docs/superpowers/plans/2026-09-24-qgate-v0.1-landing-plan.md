## 二、剩余工作实施方案（核心复核区）

### W1 · L0 域门族（唯一整域缺口，v0.1 §6.1）

L0 = "Agent 是否做了完整且正确范围内的事情"。五项按可机检程度分两批：

**第一批（确定性，files+impact executor 可落）：**

| 门 | 实现方案 | 证据级 |
|---|---|---|
| `L0.scope-check` | 声明范围 vs 实际 diff：项目在 `.qgate/scope.yaml` 声明本任务预期改动路径（glob），门用 impact 引擎反向比对 git 变更集，超出声明范围 → FAIL 并点名超范围文件 | exercised |
| `L0.assumption-register` | `.qgate/registers/assumptions.md` 存在 + 格式检查（每条含 assumption/evidence/impact 三字段标题行） | present（诚实降档：在档 ≠ 被验证） |
| `L0.decision-register` | 同上，`decisions.md`（ADR 摘要格式） | present |
| `L0.acceptance-coverage` | 验收标准逐条映射：`.qgate/acceptance.yaml`（criteria 列表 + 每条关联 gateId/命令），门检查每条 criteria 有至少一个映射目标 | present |

**第二批（语义判断，llm executor 承接）：**

| 门 | 实现方案 |
|---|---|
| `L0.requirement-trace`（§6.1 Requirement Traceability） | llm executor 读 PRD/验收声明 + 变更集，输出 PRD→Code→Test 的追溯覆盖判断；按 OD-005 纪律**永不单独 PASS**（判 pass 强转 conditional，需确定性门旁证） |

**裁决点 ⚖️ 2**：第二批是否本轮做？我的建议：**做第一批（确定性、轻量、立即有价值），第二批后置**——LLM 审 PRD 的信噪比待真实项目验证，且 llm 门已就位随时可加。

### W2 · 命令面补齐（§35）

补 `/qgate-evidence`、`/qgate-risk` 两个命令文档（CLI 子命令已存在，仅缺插件 .md）。保留 plan/init（内嵌场景比 evidence/risk 更常用）。**建议：五个全有，共 7 个命令文档。**

### W3 · CI adapter（§2.1）

一个 `.github/workflows/qgate.yml`（15 行）：push 时 `cd custom/qgate && npx tsc && cd ../../ && node custom/qgate/dist/cli.js run --all`。GitLab/Jenkins 后置（等真实使用方）。

### W4 · Claude Code 双宿主实测

在 claude-code 里注册同一 plugin 目录，跑一轮 headless（等价 P0 spike 的 claude 版），证据落 evidence/。**风险预判**：claude 对 hooks.json 的 matcher/async/timeoutMs 字段兼容性良好（rtk-bridge 先例），但 `decision:block` 的 Stop 语义与 3 次上限需实测确认。

### W5 · evidenceCommit 归档 + 输出脱敏（§50/§51）

- evidenceCommit: true 时，`qgate run` 结束把本次 evidence JSON 复制到 `docs/delivery-evidence/<runId>/`（可提交区），对齐交付标准"证据落卡"；
- 脱敏：evidence 落盘前对 stdout/stderr 做 env 值与 `(api[_-]?key|token|secret)` 模式打码（约 30 行，落 store.ts 写入路径）。

### W6 · browser executor（§29，⚖️ 建议裁）

真浏览器门（L3.4 Visual/E2E）需要 playwright 依赖 + 浏览器二进制——与"轻内嵌、零复杂初始化"冲突。**建议：裁掉专属 executor，走 architecture.fitness 同款模板门**（`e2e.visual-regression` 门，项目覆盖为自己的 playwright 命令）。你若要框架内置，我再评估。

### W7 · 补三个 Profile（⚖️ 建议裁或后置）

frontend/backend-api/library 三档（§26）价值 = 域组合预设，用户可用项目级 profile 自定义等价实现。**建议：裁**，需要时 5 分钟可加。

### 明确不做（维持既有裁定）

- **MCP 服务**（D4 已移除，v0.1 §37/§64 Phase 8 作废——⚖️ 确认项 1：这是你上一条指令的直接落实，请最终确认）
- Mutation testing（§7 L1.4：重投入低频用，真实项目提出再加）
- NFR 性能门（§10 L4.2：需真实性能基线项目）
- 独立仓/独立服务形态（D1/D4/D5）
