# 驾驶舱重构设计（2026-10-22 全量走查驱动）

> 依据：Playwright 全量走查（65+ 页面/页签）＋端点对账审计（361 前端调用 × 538
> 服务端路由）＋动线与假功能源码审查＋交互实测（看板 CRUD/建板/审批/介入卡）。
> 修复实录与决策记录见《2026-10-22-cockpit-audit-fixes.md》（批 1-2，D1-D7）。

## 一、四条重构原则

1. **信息价值门槛**：每屏首屏必须回答「人类员工此刻要做什么决定」。内部代号
  （PR-7、dispatch-preset、g5_human 等）只允许进 title/详情层，主文案一律人话；
   无决策价值的面（纯状态展示）并入相邻页或降为详情。
2. **动线闭环三件套**：每个写操作=确认（不可逆必须）→ 反馈（成败都要就地可见）
   → 去向（成功后落到能看到结果的位置）。批 2 已把四处静默失败补齐；建板成功
   未跳转（走查实测）待补。
3. **死端点结构性防护**：@koa/router 嵌套挂载三律——子路由不带绝对前缀、父路由
   按路径挂载、**每簇必须带生产拓扑运行时测试**（nested-mount guard 模式，已立
   secaudit/human-gate+pipeline 三簇先例）。新增「启动时路由自检」候选项见 §三。
4. **单一事实源导流不复制**：驾驶舱对源系统的裁决只做导流（介入卡派发表先例），
   不在本地落第二份决策真相。

## 二、挂账缺陷清单（按优先级）

### P0（产品接线决策后即修）
- **human-gate 前端零调用**：服务端三端点已复活（批 2），但收件箱/发布门 UI 无
  调用——HumanGate 前置批准（run22 复盘②）端到端仍断。接线位=审批收件箱队列
  （GatekeeperSection 或独立卡），交互=批准/驳回+留痕。
- **kanban nudge 路由从未挂载**：`registerKanbanRoutes`（server/kanban/index.ts:8）
  全仓零调用——催办 owner 动态路由（run21/22 复盘①）带病上线。处置二选一：
  挂载进 bootstrap 并补消费方（谁催办谁调）／确认消费方不存在则删代码。

### P1（信息降噪，走查实测实例）
- 遗留项清算页：`PR-7 85 项未清（预设派发）` → `预设派发未清算 85 项`；台账
  `dispatch-preset/auto-approve/card-walk-done` 类型码 → 中文名；PR-N 编号进 title。
- 建板成功后停在原页（hash 未变、无跳转无提示）——补 replaceRouteBoard 生效或
  成功 toast+列表刷新（走查实测：API 建成、UI 无感）。
- 组织表「板（team）」列裸 slug 串（`bella-req-intake(requirements-analyst)
  bella-req-analysis(researcher)`）→ 主列显中文名/板名，括号详情进 title。

### P2（打磨，择机）
- 死视图清理（设计正本 §8.4 已列 3000 行）；OrgEditor 保存前 diff 预览；
  Eval 导出反馈移到行内；DirectorPanel 场景兜底标注「默认场景（列表不可用）」；
  检索→人员结果 `?user=` 预选定位。

## 三、守门机制（随批 1/2 已立）

- nested-mount-guard 模式：secaudit / human-gate+pipeline 三簇生产拓扑运行时
  探活＋源码锚定（双前缀回归必红）。
- 介入卡接线守门：空函数绑定必红＋14 键派发表全覆盖。
- 建议下轮：启动自检脚本（遍历 router 栈打印合成路径 vs 期望路径清单，异常即
  启动告警），把「上线即死」类缺陷消灭在部署时。

## 决策记录

| # | 决策 | 理由 | 否决的备选 | 可逆 |
|---|---|---|---|---|
| R1 | 重构以「信息价值门槛」为第一原则 | 用户 2026-10-22 裁定：页面要有供人类决策的必要信息、去技术噪声 | 以视觉统一为先（否决：噪声不除统一无意义） | 是 |
| R2 | P0 两项先决策后修 | 挂载/接线是产品决策（消费方与交互未定），盲修=再造死端点 | 顺手全修（否决：重蹈 nudge 覆辙） | 是 |
