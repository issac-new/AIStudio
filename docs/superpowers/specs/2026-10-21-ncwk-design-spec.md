## 0、怎么读

### 0.1 一页纸结论

系统是一套三层结构：产品面只读运行面数据，运行面消费能力层产物，能力层不反向依赖。三层之间只有五条契约，任何跨域功能必须落在其中一条上。

三条断言贯穿全部设计：

1. **证据先于声明**：完成=提交号+卡号；门禁、评审、发布都要有可反查锚。
2. **未配置不等于已治理**：inactive／partial／unavailable 如实标注。
3. **只迁不删、只补不覆盖**：能力在归属面有正身才退役；台账只增不改。

五个数字：编制 15／账号 30／profile 42；产品面 146 条用户决策；能力层 50 条决策文本、56 门禁；推演 21 轮／V8.46；全量测试 5,868。

## 1、架构总览

### 1.1 三层与四组件

四基础组件：SwarmStudio（产品面）、hermes agent（自改进运行时）、Matrix（协作基座，消息即凭证）、swarm-yuan（能力层，生成器造项目技能）。

```
产品面（人看与操作，Vue+Electron 注入 hermes-studio）
   │ 只读：看板 / 审批 / 团队 / 运行态 / 证据
   ▼
运行面（hermes agent 进程 + Matrix + kanban）
   │ 消费：项目技能（约束、配方、门禁）
   ▼
能力层（swarm-yuan 生成的目标技能）
```

| 维度 | 产品面 | 运行面 | 能力层 |
|---|---|---|---|
| 代码位置 | `overlay/custom/{client,server}`＋补丁 | `upstream/hermes-agent`＋Matrix | `~/lab/Swarm-yuan` 与安装态 |
| 状态存储 | 读模型＋少量本地配置 | kanban SQLite、Matrix 房间、证据 JSONL | 目标项目 `.swarm-yuan/`、技能目录、门禁账 |
| 变化速度 | 周 | 日 | 月 |

### 1.2 六层产品面架构

表现层（三模式壳）、页面层（六阶段 33 页签＋四岛）、读模型层（端点/适配器）、机制层（证据/门禁/审批/观测）、服务层（studio server 域）、注入层（382 补丁＋custom）。读模型不复制运行面数据；页面不建第二份任务表。

### 1.3 运行面架构

单网关多路复用 42 profile；账号与身份在 Matrix；任务真值在 kanban；证据在文件；协调靠房间消息；跨机靠 git 制品。per-agent node_modules 隔离依赖；gateway 按 profile 独立锁目录。

### 1.4 能力层架构

生成器（references 51＋assets 183＋scripts）—生成→ 目标技能（六段目录，92 随发文件）。生成器侧厚、目标技能薄；分发面与生成器侧分离。

## 2、边界判据与纪律

### 2.1 三条边界判据

1. **写入口唯一**：任务真值只在 kanban；技能只在能力层生成；UI 不建第二份任务表或技能库。
2. **读模型不复制**：产品面通过端点读运行面，不在客户端存影子数据。
3. **不反向依赖**：能力层不知道产品面；运行面不引用 UI 组件；产品面可换皮不动运行面。

### 2.2 五条贯穿纪律

证据先于声明；未配置不装已治理；单一事实源；执行面 fail-closed／读模型 fail-soft；只增不改。

### 2.3 七条设计原则

| # | 原则 | 来源 |
|---|---|---|
| D1 | 模式隔离，能力共享 | 推演污染日常实报 |
| D2 | 证据先于声明 | run15/20 报告失真 |
| D3 | 单一事实源 | 双源漂移事故 |
| D4 | 未配置不装已治理 | 安全检查「仪表盘绿但无边界」 |
| D5 | 执行失败即关闭 | 安全整改裁定 |
| D6 | 只增不改 | 供给链与决策史 |
| D7 | 真实素材优先 | 报告反凑数、假按钮 |

### 2.4 十二类问题形态与根治

| 形态 | 根因 | 根治机制 |
|---|---|---|
| 嘴炮不交卷 | 完成与交卷解绑 | 结论行三要素＋四步前置＋zero-delivery |
| 静默失败 | 六型 Bash 陷阱 | 静态门禁＋崩溃锚 |
| 容量饥饿 | 闸与扇出失配、年龄键不稳 | 并发 30＋稳定 event_id |
| 会话饥饿 | 上下文压力 | 饥饿检测＋换会话令 |
| 闸死锁/拆闸 | 派修链断裂 | 禁拆闸＋处置通道 |
| 代偿循环 | 产品能力缺口 | 台账＋净额＋清偿门＋激励反转 |
| 报告失真 | 生成器不校账 | 审计熔断＋真值脚本 |
| 判词盲区 | 存在性判据 | 结论行行首匹配 |
| 派发令过长 | 粒度太大 | 30 分钟粒度＋极简单步令 |
| 合并丢失/死锚 | 溯源判据错 | 分支保留 tag＋锚活性 |
| 驱动误改 | bash 惰性读取 | 冻结＋原子替换 |
| 帧壳页/刷单 | SPA 冷启动、无幂等 | md5 锚定＋幂等键 |

### 2.5 八项被推翻的设计

A 类导出可抽出→全归 patch；重写 KanbanView→独立路由；三栏→六区→单页→壳+四场景；LoopEngine.tick→图引擎；三 State Store→事件日志唯一源；codex→zcode→Ycode；共享 agent 命名→每账号实例化；--force 归因→rendezvous 争用。

### 2.6 复盘八条硬结论

完成≠交卷；证据链须与结论链同强度；产品承载率是验收指标；存在性判据≠归属判据；合 main≠生效；容量须随流水线演进；监督器存活独立监控；补拍≠当轮证据。

### 2.7 被证伪的假设（十条）

日志零增长=死亡；报告声称=台账；配置存在=工具集有效；20 项有完全符合；采集已挂驱动；合 main=生效；看板是 canvas；matrix 统一本地编排；十余套空态可接受；密封分数可指导更新。

### 2.8 十二类工程陷阱

全角吞字、空数组/pipefail、`local` 顶层、zsh 不分词、heredoc 中文乱码、cwd 静默重置、手改 hunk、vite 中文注释、第三方 dist 缺类型、rtk 列表丢归属、mtime 心跳假活、pid 文件失真。判据见附录 D。

### 2.9 二十条工作规则

见附录 D 第五节；其中七条为红线：已验证才声明、测试未绿禁提交、根治到产生层、未经指令不 push、未经指令不起轮、禁拆闸、worktree 只走 git 清理。

## 3、产品面设计

### 3.1 IA 结构

三模式壳（IaShell／IDE 壳／推演壳）；左栏常用 5＋六阶段＋四岛＋设置；阶段页 33 单层签；顶栏只切路由；跨模式跳转显式标注。阶段定义单一源 `stage-meta.ts`；路径→阶段单函数投影。

### 3.2 日常数据面

看板跨板聚合 `fetchKanbanOverview`，`task_links` 按 id 分桶挂 parents/children；审批单一契约 `pending-summary`；团队读 Matrix 注册房＋org 注册表；阶段进度只读看板，不读推演 run-state（domain-split 守门）。

### 3.3 推演设计

图运行时三态 `legacy/shadow/on`；事件日志 SQLite 单一事实源；26 步七幕（序幕 1-4／需求上锁 5-8／需求分析 9-14／设计排期 15-17／并行生产 18-19／发布验收 20-21／治理复盘 22-26）；六闸判据见表。

| 闸 | 判据要点 |
|---|---|
| G1 | AC≥3 可机械判定＋范围外清单＋影响面＋涉敏评估 |
| G2 | 设计五要素＋爆炸半径＋验证前移＋备选≥2＋历史偏差回应 |
| G3 | 无设计不编码＋需求-代码-测试对应＋testlog＋runtime-proof |
| G4 | 测试者≠写码者＋缺陷闭环＋只认本轮＋commit 同祖＋G4-E |
| G5 | 证据挂卡＋同 commit 可复现＋回滚阈值＋灰度＋HumanGate＋台账 |
| G6 | 三段式＋行动项＋问题单 100% DISP＋经验入库＋retro_done@步24 |

G5 三腿并行取证（集成真值/缺陷闭环/安全条件），只取证不判，终判单源。发布门与 UAT 独立 append-only，不改 run-state 闸键。导演 run 与 26 步 run 分流。

### 3.4 IDE 设计

双模式是呈现层模式，任务内核按 `codingAgentId` 分流，不另造运行时。模型与思考档单一源为 ZCode 配置。CUA 默认 fail-closed，凭据成对注入，broker 自有。用量账本只读 `~/.zcode/cli/db/db.sqlite` 三张表，零新增埋点；成本客户端估算，订阅型不显示金额。

### 3.5 机制终态

证据（双凭证/四锚/append-only）；门禁（qgate 六态，INCONCLUSIVE 不冒 PASS，证据三级，Profile 四档）；审批（14 介入点，凭证 scope/expiresAt，只认人类绑 head）；权限（super_admin/PL50/PL0）；观测（31 检测器、NUDGE 三级、告警落面板）。

已落地的机制扩展：组织五流诊断、决策图谱四类落账＋先例检索＋确定性规则闸＋PROV-O、KG 演化（攒批/三档去重/单批>20% 熔断/版本回滚）、六类成本账＋L1-L5、无损换窗三件、工具瀑布（pre/post hooks、按需暴露、held-out 限次 3）；三号调研吸收六件（2026-10-21，详见 docs/2026-10-21-wx-3accounts-research.md）：本体 Action 契约层（ActionType 四级读写/审批缺省 mandatory/权限标签写面必填）、工具契约 inputSchema/outputSchema/authRule、callgate 调用闸域（熔断三态×资源隔离＋滑窗限流＋五档降级阶梯＋重试×熔断互斥；执法接线挂账）、裁判×人工 Cohen's κ 校准＋盲测截尾均值、指标退化禁发闸（候选 vs 最近稳定版，无基线如实 no_baseline）、统一任务生命周期账本（五源映射七态，未登记不猜）。插件 24 缝为设计资产，未实施。

## 4、运行面设计

### 4.1 团队与身份

15 人编制→30 Matrix 账号→42 profile（14 调度＋28 执行）→28 板。角色模板 `role-boundary-registry.json`；org 注册表承载账号级能力；任务责任以卡 assignee 为准。

### 4.2 能力装配四层

| 层 | 机制 | 单一源 |
|---|---|---|
| 委托 | 四维能力＋否定式合成只收窄 | org 注册表＋角色模板 |
| 身份裁决 | toolAllowlist ∧ 委托白名单；未登记不改变行为 | identities.json |
| 能力目录 | 每机上报 profile×角色×技能数 | capability-reports/`<machine>`.json |
| 技能供给 | manifest 补缺失；只增不改/干跑/回滚 | 中央 skill-provisioning.json |

策略引擎附加层：identity/sandbox/budget → policy → ladder/mode；strict 无命中拒；加载失败 deny；带 policyRuleId。

### 4.3 多机舰队

Matrix 传协调、git 传制品、本机管执行；中央 bare 仓；每日 06:40 上报；48h 新鲜度；三实例共享 1.4G 运行时；进度联邦 60 秒心跳。

### 4.4 编排与派发

图→卡→spawn；DISPATCH_SAFETY 三条款沉常量；里程碑契约；NUDGE 1→2→3→换档案；持续流水线四持续；并发 30；宽度=工位数，testpass 分片幂等聚合。派发三件套（工人档案名＋ready 正文＋@）与 prework 门禁（G2 键前不 spawn）。

### 4.5 安全设计

先预警后阻断；20 项检查 4/15/1；硬边界（身份∧委托、opt-in 沙箱、审批凭证、执行面 fail-closed）；十项挂起双条件＋4 周；执法门 TS 钩子与 Python teams 的结构性缺口；run-trace 签名修复；27 profile 无效工具集名待改；告警不发群。部署三件套：产物命中＋实例在跑＋字面触发。

### 4.6 数据面与台账

kanban SQLite（task_links DAG、CAS 认领）；approvals＋pending-summary；Matrix 注册房；graph runs/specs＋journal＋evidence；skillgov provision；harness/tool-policies/secaudit。代偿台账 TSV＋清偿门（开跑前 resolve/waive，净额闸查 actor 非 proxy）。

### 4.7 聊天架构

Matrix 只做传输与身份；本地 GroupChatServer 保留编排器（流式/审批/队列）；ChatBridge 双挂。Phase 1 UI 统一已落，Phase 2 未实施。

## 6、跨域接口
