## 0、怎么读这份文档

### 0.1 一页纸结论

这套系统不是三个产品，而是一套三层结构：人用什么、AI 怎么干、项目知识怎么长，各自有唯一载体，靠同一套证据纪律串起来。

| 层 | 载体 | 一句话职责 | 主要产物 |
|---|---|---|---|

三条断言贯穿三层，任一层都可以拿它验收：

1. **证据先于声明**：完成=提交号+卡号双凭证；门禁、评审、发布都要可反查的锚。
2. **未配置不等于已治理**：inactive／partial／unavailable 如实标注，不拿“存在”冒充“生效”。
3. **只迁不删、只补不覆盖**：能力在归属面有正身才退役；技能供给、任务台账、决策记录只增不改。

五个数字先给结论：编制 15 人展开为 30 个 Matrix 账号、42 个 profile；产品面累计 146 条用户决策；能力层 50 条编号决策文本、56 个门禁；全流程推演已跑 21 轮、方案到 V8.46；全量测试 5,574 通过。

## 1、系统定位

### 1.1 三句话

**产品面的目标是把“现状”变成一眼可读的画面。** 人不再在聊天框、终端、看板之间来回找，而是在一个驾驶舱里看到谁在干什么、卡在哪一步、证据在哪。

**运行面的目标是把“AI 干活”变成可编制、可授权、可追责的组织行为。** agent 不是聊天对象，是有岗位、有权限边界、有在途任务、有审计记录的团队成员。

**能力层的目标是把“项目知识”变成机器可执行的约束。** 组件在哪、依赖怎么连、这类任务该怎么拼，不靠人记，也不靠 AI 猜，写成清单、配方和门禁。

### 1.2 三层结构

```
产品面（人看与操作）
   │ 只读运行面数据：看板 / 审批 / 团队 / 运行态 / 证据
   ▼
运行面（AI 执行）
   │ 消费能力层产物：项目技能（约束、配方、门禁）
   ▼
能力层（知识生成）
```

| 维度 | 产品面 | 运行面 | 能力层 |
|---|---|---|---|
| 代码位置 | `overlay/custom/{client,server}`＋补丁 | `upstream/hermes-agent` 运行时＋Matrix | `~/lab/Swarm-yuan` 与安装态 `~/.zcode/skills/swarm-yuan` |
| 状态存储 | 读模型＋少量本地配置 | kanban SQLite、Matrix 房间、证据 JSONL | 目标项目内 `.swarm-yuan/`、技能目录、门禁账 |
| 变化速度 | 周级 | 日级 | 月级 |
| 权威判据 | 用户决策与走查 | 卡状态与证据 | facts.conf 与决策史 |

### 1.3 三条边界判据

1. **写入口唯一**：任务真值只在 kanban；技能只在能力层生成；UI 不建第二份任务表或技能库。
2. **读模型不复制**：产品面通过端点读运行面，不在客户端存影子数据。
3. **不反向依赖**：能力层不知道产品面；运行面不引用 UI 组件；产品面可换皮不动运行面。

违反任一条，就会长出历史事故的形态：双入口、双事实源、幽灵状态。§9 的缺口大多可归到这三类。

### 1.4 五条贯穿纪律

1. **证据先于声明**：双凭证、四类锚点（事件 `$`／提交／卡 `t_`／房间 `!`）、append-only 台账。
2. **未配置不等于已治理**：策略未配置是 inactive、检测器缺数据显示 unavailable、静态能力标 partial。
3. **单一事实源**：manifest、阶段路径、工具契约、价目表、FIBO 正本，每个横切维度只一处定义。
4. **执行面 fail-closed，读模型 fail-soft**：边界拒绝优先；坏数据跳过并记名。
5. **只增不改**：供给只补缺失、用户改过不覆盖；台账 append-only；决策保留被推翻的旧条。

## 2、设计原则与历史教训

这章是全系统的“为什么”。每条结论都对应一次真实事故或一次用户裁决。

### 2.1 七条设计原则

| # | 原则 | 含义 | 来源 |
|---|---|---|---|
| D1 | 模式隔离，能力共享 | 日常/推演/IDE 共享组件，不共享导航与写入口 | 推演污染日常的实报 |
| D2 | 证据先于声明 | 完成、门禁、发布都要有可反查的锚 | run15/20 嘴炮与报告失真 |
| D3 | 单一事实源 | 契约、格式、口径、价目只在一处定义 | 多次双源漂移 |
| D4 | 未配置不装已治理 | inactive/partial/unavailable 如实标注 | 安全检查「仪表盘绿但无边界」 |
| D5 | 执行失败即关闭 | 权限与沙箱边界拒绝优先 | 安全整改裁定 |
| D6 | 只增不改 | 台账 append-only，用户改动不覆盖 | 供给链与决策史 |
| D7 | 真实素材优先 | 不造数据、不造截图、不造演示按钮 | 报告反凑数、假按钮整治 |

### 2.2 十二类反复出现的问题形态与根治

| 形态 | 表现 | 根因 | 根治机制 |
|---|---|---|---|
| 嘴炮不交卷 | 干完活不交证据 | 完成与交卷解绑 | 结论行三要素＋四步前置＋zero-delivery 检测器 |
| 静默失败 | Bash 无声死亡 | 六型陷阱（全角/空数组/pipefail/算术/local/curl） | fail-visible 静态门禁＋崩溃可 grep 锚 |
| 容量饥饿 | 并发拒绝丢派发 | 串行闸与扇出失配、年龄键不稳定 | 并发定标 30＋稳定 event_id |
| 会话饥饿 | 连续极小输出空转 | 上下文压力 | 饥饿检测器＋换会话令 |
| 闸死锁/拆闸 | FAIL 后绕闸放行 | 派修链路断裂 | 禁拆闸（用户裁定）＋处置通道 |
| 代偿循环 | 程序代演人类动作常态化 | 产品能力缺口 | 代偿台账＋净额＋清偿门＋激励反转 |
| 报告失真 | 计数/叙事与台账不符 | 生成器不校账 | 审计熔断＋真值脚本单一判据源 |
| 判词盲区 | 只查文件存在不查结论 | 存在性判据 | 结论行行首匹配＋内容判据 |
| 派发令过长 | 理解成本大于完成成本 | 任务粒度过大 | 30 分钟粒度＋极简单步令＋派发词窄化 |
| 合并丢失/死锚 | 集成分支赛后删 | 溯源判据错 | 分支保留 tag＋锚点远端活性检查 |
| 驱动误改 | 运行中编辑主脚本 | bash 惰性读取 | 驱动冻结＋owner 注册表＋原子替换 |
| 帧壳页/刷单 | 壳页同像素、重放刷单 | SPA 冷启动、记单无幂等 | md5 结构性锚定＋幂等键 |

### 2.3 被推翻或被替代的设计（8 项）

| 旧方案 | 新方案 | 推翻原因 |
|---|---|---|
| A 类导出可抽出 custom/ | 55 个修改文件全归 B 类 patch | 上游文件直接 import 新增导出 |
| patch 028 重写 KanbanView | 独立 SwarmKanbanView 路由 | 侵入式重写污染上游 |
| cockpit 三栏→六区域 IA | 单页驾驶舱→壳+四场景→两页并存 | 用户裁决“菜单太多” |
| LoopEngine.tick 五阶段 | GraphService 图引擎（双跑后退役） | 图为唯一主干 |
| 三 State Store 一等存储 | 事件日志唯一事实源，Store 降为投影 | 审计与回放需求 |
| codex 集成底座 | zcode 源码底座→Ycode | 用户两次裁定 |

### 2.4 人机边界三条主线

1. **从导演兜底到代偿记账**：早期脚本兜底一切；中期立监控代行边界（四类可代行、两禁区）；V8.29 正式命名代偿，立台账、净额、清偿门与激励反转——停滞但如实登记的轮也是有效轮。
2. **介入清单三分类**：启动/结束面全姿态保留；审批模拟面按判据批退；待收紧面（预写派发词/代走板/代建卡/排期）standard 记台账、strict 禁用。
3. **FAIL 唯一出口**：闸 FAIL 只能真派修订＋复审；监督编排层子智能体全部只读。

### 2.5 调研吸收的六条判定原则

标尺现行、需求侧校验、不做摆设件、核实优先于重造、许可与架构红线、验证纪律。六条逐条展开：

1. **标尺先行**：落点限于既有功能区，禁新增一级页。
2. **需求侧校验**：吸收点须追溯到真实痛点，优先补会让演示出丑的面。
3. **不做摆设件**：运行通道缺失时记档待环境，不做空 UI。
4. **核实优先于重造**：落库≠进产品，接线与数据源闭合才算落地。
5. **许可与架构红线**：专有许可只搬概念；不迁移架构只借语义。
6. **验证纪律**：产物 grep＋端点 200＋真浏览器走查；不确定记“未核”。

### 2.6 运行与方案复盘的八条硬结论

1. **“完成”与“交卷”必须分别检查**：run8/13/15/20 四轮同型——报告声称记单而台账无单、补拍冒充实时、往轮产物冒充本轮。
2. **证据链必须与结论链同强度**：run14 的“结论可信、证据不可信”证明只焊结论链不焊证据链，四查全过仍可能采集退化。
3. **产品承载率是验收指标**：V8 审计发现五产品面中三个被 harness 绕开；房间不进客户端列表、运行注册表空态=两套编排并行。
4. **存在性判据不等于归属判据**：run20 用“文件存在即可反查”取代“产物属本轮”，混入 4 件往轮产物与 13 件死锚。
5. **合 main 不等于生效**：NUDGE 链合入但未部署进运行树、检测器数据源从未写入；部署须三件套验收（部署产物命中／实例在跑／字面触发）。
6. **容量体系必须随流水线演进**：run11 并发闸默认 1 对 13 路扇出，丢 400+ 派发；并发定标 30 后才收敛。
7. **监督器存活要独立监控**：run20 监督器静默死亡 5 小时，日志新鲜度不等于进程存活。
8. **补拍不是当轮证据**：采集链必须挂进驱动；零帧拒出报告；补拍只能透明标注。

### 2.7 被证伪的十个假设

日志零增长=agent 死亡；报告声称记单=台账有单；配置存在=工具集有效；20 项安全检查有完全符合项；采集链已挂驱动；合 main=生效；看板是 canvas 渲染；matrix 能统一本地群聊编排；十余套平行空态可接受；密封集分数可反向指导更新。

### 2.8 十二类工程陷阱（最低配自卫清单）

1. Bash 全角吞字：全角前加花括号，中文标签处理用 `LC_ALL=C`。
2. 空数组与 pipefail 静默：赋值失败不报，管道退出码被吞。
3. `local` 出现在顶层：代码块搬移后 rc=127。
4. zsh 不对变量分词：`for f in $FILES` 把整串当单文件名。
5. heredoc 写中文乱码：走 Edit/Write，不进 Bash heredoc。
6. Bash cwd 静默重置：绝对 `cd`＋`[cwd:]` 标记＋服务 `lsof` 核树。
7. 手改 patch hunk 丢行：机械再生＋纯净基线重放＋字节对账。
8. vite 中文注释＋regex literal 崩：改 `new RegExp`，不在 worktree build。
9. 第三方 dist 缺类型：本地 interface 复刻，不用 `@ts-ignore`。
10. rtk 过滤列表丢归属：find/ps 直查。
11. 日志 mtime 心跳假活：取最后真实 API 行判活。
12. pid 文件失真：`lsof -sTCP:LISTEN` 取真监听进程。

### 2.9 二十条工作规则

1. 已落地/已生效/已根治必须给部署产物、运行时进程或字面事件三档之一；commit 不算生效。
2. 测试未绿禁止 commit/push/deploy；测试与提交分轮。
3. 根治=修产生缺陷的层；未实战一轮只说待验证。
4. 未经明确指令不 push 远端。
5. 未经明确指令不起跑任何推演轮次。
6. 闸 FAIL 唯一出口=真修订+复审 PASS；禁止拆闸。
7. 共享主树是共享可变状态：提交前查分支、小步提交、主树非 main 用临时 worktree；worktree 只走 git 清理。
8. 群令 ≤4 步；assignee 用工人档案名+ready+@。
9. 任务拆到 30 分钟可独立完成+独立 commit；阈值按真实 session 采样。
10. 全员静默先查监督器+驱动双活；判活看工具计数/API 行/产物。
11. SIM 快照必须 `build:full`→provision→重启 studio。
12. 服务载体三处同钉：custom 符号链接、vite config、cwd 全指 serve-main。
13. 端口拓扑固定：8801 网关/8802 studio/8647 后端/8649 前端/8008 synapse/15721 cc-switch。
14. 凭据 0600 放仓外；CLI 实测隔离 HERMES_WEB_UI_HOME。
15. 一切输出说人话、结论先行；文档终稿态。
16. 收尾给编号决策清单（事项+建议+保守选项）。
17. 文档一事实一源；重规划先全量盘点再对账。
18. 运行中禁改主脚本；必须改则原子 rename。
19. patch 机械再生+纯净基线重放+逐字节对账。
20. 每轮实时采帧；零帧拒出报告；补拍须透明标注。

## 3、产品面终态：SwarmStudio

### 3.1 定位与三类问题

用模式隔离＋机制约束解决：人找不到东西、推演与日常互相污染、完成声明不可信。

| 断言 | 兑现方式 |
|---|---|
| 日常与推演共享能力，不共享导航与写入口 | 三模式、`/app/sim*` 独立域、`useDailyStageProgress` 只读、domain-split 守门 |
| 一切完成都要证据 | 双凭证、四类锚点、append-only 台账、hash 链 |
| 判断权不交给执行者 | 六闸、FAIL 唯一出口、人工介入留痕、执行层 fail-closed |

### 3.2 三模式信息架构
