# 26 步/七幕的用户可见术语分层（spec）

日期：2026-10-18
分支：`feat/steps-display-names`
来源：完成审计指出 26 步登记表与 `SimStepBadge` 仍把「系分/搭台/上锁/并行生产」等方案原文词直接显示在界面，与「UI 上的菜单及功能名称要符合行业标准术语体系」存在可见冲突。此前以「方案逐字副本」为由未改，但界面可见性没有处理。

## 变更

- `steps-registry.ts`：`ActMeta` 增加 `displayName`；`StepMeta` 增加可选 `displayName`。
  - 方案原文 `name` 逐字保留，用于追溯与测试对账。
  - 界面可见的标准名写入 `displayName`：序幕·准备 / 第一幕·需求冻结 / 第四幕·并行开发；需求冻结（G1）/ 环境冒烟测试 / 建立协作群 / 任务派发 / 系统分析（四路）/ 系统分析收尾 / 独立验证（G4）/ IDE 工作区全程使用 / HTML 运行报告。
- `resolveStepRows`：返回行的 `name` 改为 `displayName ?? name`，26 步表与锚点抽屉只显示标准名。
- `OverviewPanel.vue`：七幕旅程条、分段头、锚点抽屉改用 `displayName`；表头去掉内部文档引用「§3.3 映射前端副本」。
- `SimStepBadge.vue`：幕名改为标准名（序幕准备/第一幕需求冻结/第四幕并行开发等）。
- 测试：七幕测试同时断言方案原文与 displayName；新增「用户可见幕名/步名无内部黑话」守门；锚点抽屉与步境标断言改标准名。

## 决策记录

1. **源副本与显示名分层，而不是直接改 `name`**：26 步表要与方案正本逐字对账（测试已有抽查断言），直接改会失去追溯锚；`name` 保留原文，UI 只读 `displayName`，两边都能满足。
2. **displayName 覆盖范围只限有黑话/缩写的步**：其余步名已是标准词（账号分配、登录、应用初始化等），不为了统一而制造无意义差异。
3. **不改完成键、闸键与 26 步顺序**：本批只改显示文本，状态推导、净计、端点契约零变化。
4. **守门测试直接扫黑话词**：新增断言覆盖全部幕名与步名，后续新增步名若带内部词会当场失败。
