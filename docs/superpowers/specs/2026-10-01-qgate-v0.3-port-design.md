## 三句话主旨

上游 v1.24 证明 v0.1 的方向成立，且在防伪核验、新鲜度、意图域三处走出了本地没有的工程深度。本地内核（六态判定、executor 模型、Matrix 桥、治理消费）承载 ncwk 特有语义，不替换，走特性移植。本轮落地三批：内核加固（rawOutput 交叉核验、inputSnapshot 新鲜度、元门二轮通道）、L0 门族升级（traceability、task-intent、debt、登记簿 exercised 化）、文档与清理，后续批次按 §5 路线图逐轮裁决。

## 2. 概念映射表（移植基准）

## 3. 本轮详设：内核加固批

### 3.1 rawOutput 交叉核验（上游 ADR-0007 本地方言）

要证明的 Claim：测试类命令"退出码 0"必须对应真实执行且零失败，静默空跑不得计 PASS。

最小实现：新增 `src/core/raw-evidence.ts`，手写 TAP 与 JUnit XML 子集解析（口径对照上游 `plugin/lib/raw-evidence.mjs:30-213`：TAP 的 ok/not ok 点、SKIP/TODO 指令、plan 互核、Bail out 拒收；JUnit 的 testsuite 属性求和与逐 testcase 互核）。command executor 的 ExecutorSpec 增加可选 `rawOutput: {format: 'tap'|'junit', file, minTotal?}`。命令退出码 0 时内核独立重算：failed>0 或 total<minTotal → evidence result=error（判定层转 INCONCLUSIVE）；重算计数写入 evidence details。退出码非 0 且文件可读时，重算的 failed 计数入证据便于 explain。

接线：`engineering.basic-check` 的 test 步声明 rawOutput（overlay 仓 vitest 输出走 TAP  reporter 或 JUnit）。

验证：正例（真实 TAP 全过 → PASS 且计数入证据）；负例三件套（exit 0 但 TAP 含 not ok → INCONCLUSIVE；exit 0 但 total=0 且 minTotal=1 → INCONCLUSIVE；文件缺失 → INCONCLUSIVE）。

准出：既有 52 测试全绿 + 新增 ≥6 例。

### 3.2 inputSnapshot 新鲜度（上游 fresh­ness 本地方言）

要证明的 Claim：一条 PASS 证据的输入在引用时点未变。

最小实现：GateRun 增加 `inputSnapshot: Record<string,string>`（门声明的输入文件 sha256，上限 200 项）与 `inputsStable: boolean`。run.ts 执行前对 appliesWhen 声明的输入与 executor 声明的输入文件取快照；store.isFresh 增加快照比对路径：快照逐项一致即新鲜（与原 treeHash/commit/路径三锚为或关系，任一锚定有效即新鲜）。`status --fresh` 输出引用快照比对结果。

验证：运行后改动被快照文件 → status 判不新鲜；改动未快照文件 → 新鲜度不受影响；快照上限截断如实记档。

准出：既有 isFresh 测试全绿 + 新增 ≥4 例。

### 3.3 元门二轮通道

要证明的 Claim：traceability 这类门需要"其他门的判定"作为输入，且不得改变普通门的执行顺序与语义。

最小实现：GateSpec 增加可选 `meta: true`。run.ts 编排分两轮：普通门按既有顺序执行完毕、evidence 落盘后，meta 门以只读方式拿到本轮全部 verdict 与证据索引再执行。普通门路径零改动。

验证：meta 门能看到同轮其他门 verdict（守门）；无 meta 门时编排行为与现状逐字节一致（既有测试即回归）。

准出：既有 run/decision 测试全绿 + 新增 ≥3 例。

## 4. 本轮详设：L0 门族升级批

### 4.1 traceability 门（L0，meta）

要证明的 Claim：每条验收条件都有实现代码与通过的验证门，不允许"做了但没说清证明了什么"。

最小实现：新 executor `traceability`。输入 `.qgate/registers/requirements.json`（与上游同形）：`requirements[].acceptanceCriteria[]{id, codeFiles[], testGateIds[], type?}`。核验三件套：codeFiles 逐条存在（防路径逃逸，复用 safe-path）；testGateIds 指向的门在本轮或新鲜证据中为 PASS；需求级 prdRef 存在。登记文件缺失/畸形 → INCONCLUSIVE；任一 AC 未过 → FAIL 并指名。

gate-pack：`L0.requirement-trace`（meta: true，policy block/warn）。

验证：rtm-demo 夹具正反场景（全链 PASS；删一个 codeFile → FAIL 指名；链接门 FAIL → FAIL；登记缺失 → INCONCLUSIVE）+ 单测 ≥6 例。

### 4.2 task-intent 意图登记与漂移对账（L0）

要证明的 Claim：本任务宣称要做什么（意图）与实际改了什么（git 事实）一致，意图文件本身不被静默修改。

最小实现三件：

1. 登记与写入通道：`.qgate/registers/task-intent.json`，形状 `{taskId, statement, scope: string[], acceptance: string[], constraints?: string[], confirmedBy, confirmedAt, revisions?: []}`。CLI 新增 `qgate intent`（参数化写入）与 `qgate intent --revise --reason <文本>`（修订自动追加 revisions 链并重置 acknowledgedSha256）。写入只经 CLI，对应"问询不代写"纪律（上游 ADR-0014）。
2. scope executor 扩展：ExecutorSpec 增加 `taskIntent: {file, acknowledgedSha256, require?}`。判定为交集语义：变更须同时落在 allowedPaths 与 intent.scope；登记文件哈希与 acknowledgedSha256 不符 → FAIL（intent-file-modified）；require 且无登记 → FAIL（no-task-intent）；acceptance 条目过 Gherkin 骨架校验（when/then 最小子集，缺 then 即 FAIL）。
3. 与 change-scope 既有能力复合：allowedPaths/requiredPaths 判定不变，intent 为叠加层。

gate-pack：`L0.intent-drift`（policy block/warn，默认不进 vibe-fast，进 feature-close/high-assurance/release）。

验证：intent-demo 五场景（ok PASS；越界 FAIL；登记被改 FAIL；显式修订 PASS；bad-ac FAIL）+ 单测 ≥8 例。与 ncwk 派发体系的融合（派单自动写意图）记档为后续治理融合点，本轮不接。

### 4.3 debt 门（L5）

要证明的 Claim：技术债显式在档、有责主、有期限，高危与逾期债阻断收口。

最小实现：files executor 升级支持 `jsonSchema` 轻量模式核验，或新增 register executor（取后者，命名 `register`，复用于 4.4）。核验 `.qgate/registers/debt.json`：条目 ≤100，字段 id/description/owner/impact/repayment/severity/status/dueDate；open 且 severity∈{high,critical} → FAIL；open 且 dueDate 过期 → FAIL；空登记须显式 `none:true`（裸空数组 FAIL）。登记缺失 → INCONCLUSIVE。

gate-pack：`L5.technical-debt`（policy warn/warn，high-assurance/release 升 block/warn）。

验证：debt-demo 正反场景 + 单测 ≥5 例。

### 4.4 assumptions/decisions 登记核验升级（L0）

要证明的 Claim：假设全部确认、决策全部闭合或显式延期，登记不是摆设。

最小实现：register executor（4.3 同模块）承担两登记：assumptions.json 要求全部 `confirmed: true` 且 source/evidence 为结构化引用（`{file}` 或 `{gateId}` 形，存在性核验）；decisions.json 要求 resolved，或 `status: deferred` 且 revisitBy 未逾期（逾期 FAIL）。既有 md 格式登记保留为 present 级兼容路径：JSON 存在走 exercised 级核验，仅 md 存在维持现 L0.registers 的 mustContain 判定。

gate-pack：L0.registers 门升级（executor files → register，policy warn/warn 不变）。

验证：单测 ≥6 例（未确认假设 FAIL；引用悬空 FAIL；decision 逾期 FAIL；md 回退 present 级）。

## 6. Non-goals

- 不 vendor 上游、不替换本地内核、不动六态判定与 Matrix 桥换算表。
- 不改配置格式（`.qgate/` YAML 声明不变，不引入上游单文件清单与 schemaVersion 0.2）。
- 不移植配置生命周期（templates/init/update/inspect）、F2P/P2P、Stop 复用降级（列入 R5-R7）。
- task-intent 不接派发体系，只做登记与范围对账。
- 不追求 37 门全覆盖；上游 v1.8 已砍的 migration/operational-readiness 类不回移植。
