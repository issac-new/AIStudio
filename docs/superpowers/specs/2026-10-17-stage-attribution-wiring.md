# 驾驶舱阶段归属接线批（spec）

日期：2026-10-17
分支：feat/cockpit-quick-nav-context（第二批同支）
来源：用户「拍板继续做」——完成上一轮列的剩余项：页签级阶段归属接线，让直接链接、搜索、分享 URL 也指准所属阶段。

## 变更内容

1. **页签级归属表**：`ia2/stage-attribution.ts` 成为工具页→阶段归属的单一事实源（多归属如实列多阶段；空数组=全程工具）。本批核对实际路由名/路径并修正：看板 [3,4]、场景编排 [2,4]、证据库 [4,5]；补 IDE 工作区 [4]；补 `/app/collab`、`/app/ide` 与四个专题工作台路径。
2. **顶栏多归属**：`activeStagesForRoute(name, path, from)` 的判定顺序=来路 `from` 优先 → 归属表 → 表外回退路径粗粒度。表内空数组=全程工具，顶栏不高亮。`IaCentersNav` 改为集合高亮（监督面板同时亮③④；运行总览不亮），根节点输出 `data-active-stages` 供守门。
3. **面包屑阶段徽标**：面包屑在「旅程」之后插入非链接徽标——单归属显示「①搭建」、多归属显示「③④」、全程工具显示「全程」；悬停标题给出完整阶段名。末段才带 `aria-current`，徽标不再被误标为当前页。
4. **中心归属回链动态化**：仿真/治理中心页头的「← 阶段」按当前页签归属生成——交付健康显示「←⑤验收」、监督面板「←③④」、运行总览「全程工具」（不可点）；点击多归属回第一个阶段并清除 `from`。
5. **守门测试**：新增 `stage-attribution.test.ts`——阶段页每个工具卡目标与搭建五步落点必须在表中登记；路径最长前缀、单/多/全程形态、阶段页恒等归属。导航测试同步覆盖多归属、全程工具与 `from` 优先。
6. **面包屑旧映射修复**：模型服务商路由名实际为 `ia2.modelProviders`，字典键却写 `govModelProviders`，导致该页缺「治理中心/模型服务商」两段。已改正并补测试（旅程＞全程＞治理中心＞模型服务商）。

## 决策记录

1. **from 与归属表分工**：`from` 答「我从哪一站来」（临时上下文，可分享），归属表答「这工具本身归哪几站」（固有属性）。两者并存，from 优先；无 from 的直达链接回落归属表。
2. **多归属亮多个阶段而不是选一个**：监督面板确实服务③分析设计与④开发；选任一都会对另一段撒谎。多亮如实呈现，面包屑徽标给出同一信息。
3. **全程工具不高亮**：运行总览/仿真设置/系统设置/驾驶舱概览/专题工作台跨阶段使用，硬指一站会制造假位置信号；顶栏留空+面包屑「全程」是诚实呈现。
4. **不动物理路由**：本批仍不把中心路由并入阶段路由；URL 不变、深链不破，只把归属信息补全。物理合并属独立迁移（需重定向与契约测试），本轮不做。
5. **中心回链对多归属取第一个阶段**：按钮标题明确「点击回第一个阶段」，不做下拉选择，避免在页头增加新交互层。
6. **阶段徽标不是链接**：它回答归属，不承担跳转；跳转由顶栏与中心回链承担，避免同一行出现两个去向。
