## 0、怎么读本档

### 0.1 一页纸结论

本档回答三个正本放不下的问题。一，这套设计承受了什么压力才成形：版本演进与 21 轮推演。二，业界调研吸收进来多少、又否决了多少：两卷吸收台账。三，用户在四个月里裁定了什么、推翻了什么：108 条决策、30 条常设原则、27 次纠正。

三条复盘总判断（全部带锚，细节见对应节）：

| 判断 | 依据 | 所在节 |
|---|---|---|
| 设计形态是走查与事故驱动的收敛，不是一次设计出来的 | 三中心（10-15/16）→旅程页六阶段（10-17）→左栏五组（10-18）→三模式（10-20），每次收敛对应一次用户全量走查或实报 | §4.1、§7.2 |
| 治理边界的每一次收紧都源自一次真实事故或用户质疑 | 拆闸立法源自 run20 G2 悬置 12 小时（正本 :1833）；代偿清偿门源自用户三次同句质疑（档案 §一:21）；任务粒度拍板源自 run20 嘴炮三轮追问 | §4.4、§7.2 |
| 吸收的有效形态是机制级吸收而非功能照搬，且吸收判定本身有纪律 | 标尺先行、核实优先于重造、不做摆设件、许可红线等六条判定原则；约 34 篇外部文章+5 个深读仓库的吸收落地率见 §2.8 | §2.9 |

1. **锚点纪律**：每条关键陈述带 `文件名:行号` 或 `§节号` 锚点，规格与《完整设计》正本一致；无锚点的结论在本档不成立。spec 相对路径省略前缀 `overlay/docs/superpowers/specs/`，研究档省略 `overlay/docs/`。

### 1.2 overlay 注入架构

全部二次开发的地基：三个上游仓（hermes-studio/element-web/hermes-agent）保持 git 历史干净，本地成果集中 overlay 仓。改动分两类接入——A 类纯新增（custom/ + 构建期 alias 重定向 + 运行时注册），B 类上游骨架修改（patches/ 经 git apply 可逆注入），`inject --clean` 可完全还原上游（2026-06-21-overlay-architecture-design.md §3-4）。实施修正了原设想：55 个修改文件最终全部归 B 类 patch（39 个），因为约 80 个新增导出有上游文件直接 import，抽出反而要 patch 更多 import 点（同文 :298-313）。这条「A 类可抽出设想不成立」的实测结论，是后来所有升级轮（0.7.36/37/38）补丁适配方法的起点。

### 1.3 Matrix 账号与 fleet

账号层渐进迁移：users 表扩 matrix_user_id 等列，Matrix 管理员自动获 super_admin，登录走 matrix-login 换 Hermes JWT，删除硬编码 bypass token（2026-06-19-matrix-account-integration-design.md §2-4）。

fleet 解决单机模拟多用户：每用户独立 HOME 沙箱三层（electron userData/.hermes/.hermes-web-ui），应用共享本机一份安装与单份约 1.4G 共享运行时，端口按 user_index 编址即路由（matrix-fleet-deploy-design.md §1-4）。09-18 用户指令确立「应用共享省空间+版本与全机安装一致」的部署取向（同文 :33-37）。

### 1.4 Kanban、工作项与驾驶舱

6 月把 hermes-agent 看板高级能力移植为 Vue 组件后，06-22 将 Swarm 看板解耦为独立路由（patch 028 归档，原生看板回归上游纯净）。工作项页面确立双通道交互模型：字段编辑类走 localStorage 草稿批量提交，动作命令类即时执行不可暂存。依据是用户 06-24 裁定「所有原页面可编辑可配置项都要」+「除文件上传外保持草稿批量提交」（cockpit-workitem-kanban-migration-design.md:18-19）。驾驶舱三栏联动+Pure Ink 黑白灰视觉，「既不失焦又不空洞」的核心诉求原文在同文 :19。06-23 去 mock 后，底层数据 100% 来自 useKanbanStore 派生（cockpit-kanban-integration-design.md:39-59）。

### 1.5 Loop 工程与 loop graph

07-11 的 Loop Engineering 把「人逐条 prompt agent」升级为五阶段循环（发现→交接→验证→持久化→调度）。配套三路验证（Programmatic+Judge+Human，Judge 须不同模型族）、7 个命名 pattern、BudgetGuard 三模式（loop-engineering-design.md §2-6）。09-09 重构为 loop graph：可编排可有限终止的图成为唯一执行与组织主干，append-only 执行事件日志（node:sqlite）为唯一事实源，四层终止防御（条件边/回边 guard/图级 maxSteps/成本时长熔断），旧 LoopEngine.tick 退役为编译产物（aihub-redesign-design.md §2-3）。这一「事件日志为唯一事实源」的裁决后来直接被 V8 推演的图执行终极形态继承（§3.2）。

### 1.6 运行观测与交付协议

RunTraceView 确立「不可伪造原则」：拿不到的数据显式标注占位，绝不画成实线节点（run-trace-view-design.md:56-65）。分布式交付网络一句话总纲：Matrix 传协调，git 传制品，本机管执行。注册房管组织、案例房管个案，G1/G5 HumanGate 强制人类 sender（distributed-delivery-network-design.md §4-6）。架构三裁决落款：任务状态以案例房事件流为准（Studio 是投影）、集群按用户机器组织、附属 Agent 是账号内虚拟身份（swarm-cockpit-architecture-design.md §3）——「Studio 是投影、事件流是事实」这条原则贯穿到今天的图执行器设计。

### 1.7 网关复用与 zcode 底座

网关侧分清两类锁语义：本 profile runtime lock=幂等在跑；host 守卫拒绝=未被服务（术语照原文）。旧判读误当在跑，导致静默失败；patch 373 修正判读并落 host-ownership.ts 单一事实源（gateway-host-ownership.md §1-2）。产品边界裁定「Studio ensure 只查不抢、长期靠上游 multiplex」（gateway-multiplex-design.md §1-3）；推演实测进一步归因争用点为 host rendezvous 记录，正解是 --force+每 profile 独立锁目录（aipaydev-fullchain-sim-report.md §五-e）。

编码引擎底座经两次用户裁定定型。09-23 三案对比选 B 案：upstream/zcode 受管 fork+patch 层，复刻 overlay↔hermes-studio 协议，内核只读，二开落 service 层；此裁定推翻 09-16 的 codex 集成决策（zcode-foundation-design.md:10-12,65-73）。09-25 用户纠偏确立 Ycode 定位红线：产物是全新编码工具、融合各工具优势功能，不是编码工具聚合器（同文 :10-12）。

### 2.9 吸收判定原则（从两卷台账提炼）

3. **不做摆设件**：runtime 通道缺失时记档待环境而非做空 UI。

6. **验证纪律**：三层验法（产物 grep+HTTP 200+真浏览器走查）+守门测试+词条快照防漂移；不确定即如实记「未核」。

### 7.5 主题脉络（三条线）

**产品方向线**：6 至 9 月是功能叠加期，以单点裁定为主（kanban 解耦、Loop 单页、IDE 主页、Ycode 红线）。10-08 出现第一次视角抬升（「核心是平台能力」）。10-15 是分水岭：推演程序升格为产品能力一环。10-16 进入再论证期：推翻已定稿的总设计，冻结 14R+8N，立纲三句话。此后进入走查驱动的快收敛：旅程页、左栏五组、IDE 锚定、三模式，至 10-21 汇编收口。贯穿取向不变：诚实优先于好看、能力不删只迁、真实素材优先、不装已实现。

**治理介入线**：本质是用户与「推演程序该不该伸手」的持续博弈。10-12 立「长期不介入」。10-14 拆闸事件确立 FAIL 唯一出口。10-15 用户三次同句质疑，逼出四层病根链：程序越界、方案条款化、愿景未挑明、命题结构漏洞；最终以「确认自组织+双态声明+§2.9 收窄+代偿台账+清偿门」一揽子立法收口。同期激励反转与任务粒度拍板，把治理从救火代偿扭向根治产品。AI 被纠正的形态从「技术判断错」上移为「方法论错」，用户追问深度同步上移。

**工作方式线**：四个反复强化的主题。一是说人话：四次反馈后升为全局规则，形成汇报、巡检、决策清单的分层沟通体系。二是闭环实证：三档验收锚，配测试未绿禁提交与机械门禁。三是协作纪律：worktree 立法、禁自动 push、撞车分工，均由多会话并行事故倒逼。四是文档纪律：终稿化、一事实一源、多格式一致、对账总表。用户介入方式从早期单点裁定，演进为后期「原则立法+机械门禁」。

### 7.6 统计

108 条按月分布：6 月 4 条、9 月 14 条、10 月 90 条。10-15（治理收口日）15 条为全程最高峰；10-16/17/18 各 11-12 条。按类型：IA/界面约 30、产品方向约 26、推演纪律约 16、工作方式约 14、工程规则约 14、治理原则约 8。被推翻的既有决策/做法 27 处，其中方法论级推翻（拆闸/任务归因/程序越界/边裁边补/设计定稿/撞车抢树）6 处。84 份含「## 决策记录」节的 spec 清单（按日期）：06-22×1、10-16×10、10-17×23、10-18×31、10-19×19、10-20×1（另含 3 个补批节）。
