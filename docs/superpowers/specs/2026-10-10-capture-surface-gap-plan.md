# 拍摄位规划落地轮暴露的缺失功能与 UI 实施方案

2026-10-10 用户指令「每步截图按 Swarm Studio 的 UI 功能规划拍摄位，不乱拍凑数；缺失的功能及 UI 给出实施方案」的配套交付。规划轮对 26 步逐一指认拍摄页面（simharness/mux/capture-plan.env，语义正本=方案 §2.5），过程中以真实截图复核每个指认位，暴露四项产品缺口。本文即四项的实施方案；每项含现象（带可查证的事件或截图依据）、根因、方案、验收判据、工作量。

## G1：IDE 路由缺省落聊天壳页（错页风险的直接来源）

**现象**：run13 步 18 实拍帧（视觉验收 2026-10-10）——`/app/ide` 不带参数进入时，fanfan 会话落在「collab-live-test 群聊对话」子页（「开始群聊对话」占位），不是 IDE 画布；带 `?task=DEV-PAYCORE-S` 才进任务简报抽屉。错页帧已按 V8.4 归档隔离并登记问题单（issues.log：frame-capture-failed|step-devimpl_done）。

**根因**：IDE 工作台（IaShell 子路由全屏画布）的缺省子视图跟随会话上次停留页；无任务上下文时无「应落在哪」的规则，聊天子页成为缺省兜底。

**方案**：`/app/ide` 无 task 参数时缺省进入「任务列表面/画布首页」（展示可进入的任务简报列表），禁止以聊天子页作缺省落点；聊天子页仅经显式会话列表进入。改动面=IDE 路由缺省重定向+画布首页组件（列任务卡）。

**验收判据**：清会话状态后裸访问 `/app/ide`，首屏为任务列表或画布（非聊天壳）；r18-frames 以 fanfan 裸路由采样同判。

**工作量**：S（0.5 人日；路由缺省+复用现有任务卡列表组件）。

## G2：IDE 资源权限报错（普通账号 401 toast）

**现象**：同帧画面右上角出现「你没有权限访问该资源」toast——fanfan（普通编制账号）进入 IDE 时有资源 401。

**根因**（待排查定位）：IDE 视图加载的某个接口对普通账号未放行（疑仅 admin 或特定角色可读），前端把 401 以 toast 显式抛出。具体 endpoint 以 studio 日志+网络面板复测为准（本文不预设结论）。

**方案**：定位 401 endpoint 后二选一——属账号自身任务资源则修 ACL（会话账号可读自身任务）；属管理面资源则前端静默降级（该卡片显示「无权限/不适用」而非全局 toast）。

**验收判据**：fanfan 会话进入 `/app/ide?task=*` 全程零权限 toast；若确属无权限资源，界面以就地声明呈现。

**工作量**：M（1 人日；定位+ACL/降级二选一+回归）。

## G3：跨账号工作台账视图缺失（步 22 无对应产品界面）

**现象**：拍摄位规划为步 22（工作台账）指认「交付健康页签」后实测复核（2026-10-10 截图）——该页签主体是审批工单类型分布（12 类）+左侧「机器执法实况」条，**没有跨账号板状态分布视图**。产品内不存在承载「跨账号板 todo/doing/blocked 状态分布与 WIP」的界面；run12/run13 步 22 靠仓内 work-report.md 文档承载，产品面为零。已按「功能不存在」声明态呈现并登记问题单。

**根因**：工作台账（workmgr 步）从 V7 起就以文档交付为正本，产品侧从未建对应聚合视图；§2.5 步级承载清单也未给它指定界面（规划轮首次补指认即暴露缺口）。

**方案**：交付健康页签（/app/board?tab=accounts）新增「账号板状态分布」区块——数据源=各账号板看板 API 聚合（14 账号 × todo/doing/blocked/review 计数+WIP 超限标红），服务端单接口聚合（沿用看板快道同源数据），前端表格+分布条渲染；点击账号行跳该账号板。

**验收判据**：一屏可见全部账号板状态计数（与各板实况一致，抽样 3 账号对账）；步 22 拍摄位从 none 改回该页签实拍。

**工作量**：M（1-1.5 人日；聚合接口 0.5+前端区块 0.5+对账回归 0.5）。

## G4：运行横幅 lite 轮口径（0/26 误导性诚实）

**现象**：run13 步 18 帧横幅读数「推演运行 20261010-v8-run13 · 0/26 段 · 进度已 43 分钟未更新」——lite 轮夹具步不落完成键，横幅 total 恒 26 且长期显示 0 进度+「未更新」，数字诚实但语义误导（看似停滞，实际在跑）。

**根因**：run-progress.json（mx_write_progress）只报 done/total，无轮型 scope 信息；横幅按全量 26 步渲染。

**方案**：state.env 已有 lite_round/lite_fixtures_from 键——mx_write_progress 增加 scope 字段（lite 轮报执行段集（11 个完成键）），横幅渲染「lite 轮 x/9（夹具自 run12）」；更新时间戳语义不变。

**验收判据**：lite 轮进行中横幅显示 x/9 且随完成键递增；全量轮显示不变（x/26）。

**工作量**：S（0.5 人日；progress JSON 加字段+横幅渲染分支）。
