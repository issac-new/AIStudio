# 2026-11-12 run30 行动项落地批（A1/A2/A3/A4/A6 工装化）

> 决策事实源。来源=`2026-11-12-run29-full-retrospective.md` 第五节行动项；本批把其中五项从「建议」变成「代码＋守门测试」，A5（vendor 对拍）落为台账待裁决。

## 变更

1. **A1 director 折中处置**（`simharness/mux/mx-scenario-lib.sh`）：
   - 派发正文追加声明式降级指令：总监无容量时回一行 `DIRECTOR-DEGRADED reason=<原因>`，立即走降级不空等。
   - 等待改双信号：`mx_wait_sender` 模式扩为 `(@[a-z-]+-agent|DIRECTOR-DEGRADED)`；命中降级声明时记 `reason=declared`，不计超时补偿（声明≠失职）。
   - 新增 `_mx_director_metric`：`evidence/director-metrics.jsonl` 逐次留档（outcome/reason/elapsed_s）；success/ok、degraded/declared、degraded/timeout、degraded/send-failed 四态。
2. **A2 确定性失败二段式**（`simharness/mux/run-driver-supervisor.sh`）：
   - 新增纯函数 `mx_storm_decision(<same> <max> <stage>) → continue|rearm|exit`（可行为测）。
   - 第 1 段：自动重挂一次（60 秒退避＋计数重置），写 `evidence/alerts.jsonl`（level=warn）与 `driver-deterministic-stage1` 记单。
   - 第 2 段：照旧停止自愈，记 `driver-deterministic-fail`，alerts level=error。
   - 新增 `mx_issue_once`（监督器不 source scenario-lib，本地幂等实现）与 `mx_alert`。
3. **A3 审计收敛纪律**（`simharness/aipay-scenario.sh`）：
   - 审计失败分支先调 `_mx_audit_checklist`：把 `report-audit-findings.json` 全量 fails 按族聚合写入 `evidence/audit-fix-checklist.md`（分族计数＋逐条）。
   - 失败消息带上清单路径，值守按清单一次处置完再复扫。
   - 方案 §5.13 补第 7 条（含 run29 数据：24 轮／4.18h／族名写错 6 轮／推送被拒 10 轮）。
4. **A4 UAT 条件验收终态**（`simharness/aipay-scenario.sh`）：
   - 步守卫从「只认 `uat_done`」改为「`uat_done` 或 `uat_conditional` 均视为终态」——run29 的 66 行噪音真因：条件验收后驱动每次重入都重跑 UAT 步 25 次。
   - `uat-conditional`/`uat-push`/`uat-cond-proxy` 三类记单改 `issue_once`（幂等）。
5. **A6 状态键判读行首锚定**（`mx-scenario-lib.sh`＋`mx-burn-test.sh`）：
   - 新增 `mx_done_key_count`：`^[a-z0-9_]+_done=(1|10位时间戳)$` 且排除 `capture_ok_*` 副键。
   - 烧机收据改用同口径——旧口径把采集副键计入（run29 烧机 done 键 21 / 真实主步 13）。
6. **守门测试**：新增 `simharness/tests/run30-actions.test.sh`（A1/A2/A4/A6 共 15 断言），入 `run-gates.sh` 套件面。
7. **文档**：方案 §5.13 追加第 8/9 条（director 处置口径、二段式）；新增 run30 前置行动台账 `2026-11-12-run30-prelaunch-actions.md`（含 vendor 四条对拍与三项开跑门）。

## 决策记录

| # | 决策 | 备选与否决理由 |
|---|------|----------------|
| D1 | director 默认仍为 preset，不改成默认 director | run29 成功 5/51 且全在低负载，默认开等于默认背 46 次空等 |
| D2 | 声明式降级不计超时补偿 | 总监如实声明无容量是正确行为，记成代偿会污染净额口径；指标里 reason=declared 单独分列 |
| D3 | 二段式重挂只做一次，不做指数退避无限重试 | 「同指纹重复执行不产生新信息」结论仍成立；一次重挂吃的是处置落盘窗口，不是要无限重刷 |
| D4 | UAT 修终态守卫而不是合并问题单文案 | 66 行噪音根因是 25 次重执行；合并文案会把真缺陷留在原地 |
| D5 | 计数函数放 scenario-lib 单一实现，烧机脚本用同表达式 | 烧机不 source scenario-lib（执行面极简）；用同一正则表达式维持单一口径，测试同时断言两处 |
| D6 | A5 只落台账不执行 | vendor 四条均在真实负载下涌现，本轮无复现手段；台账给出对拍方法与处置方向，不盲改 |
