# Palantir 吸收批待裁决事项的裁决落地（2026-11-27）

> 状态：已实施；实测结果见「验证」。
> 来源：用户 2026-11-27 指令「按推荐建议裁决」——对 Palantir 吸收批（规格 2026-11-26-palantir-self-improvement-architecture）交付说明里列出的七项待裁决事项，按执行会话的推荐逐项裁定。

## 变更

### 裁决表

| # | 事项 | 裁决 | 理由 |
|---|---|---|---|
| 1 | 纯降成本、降延迟、换模型这类目标与 `gain_within_noise` 规则 | 不改晋级规则；成本与耗时的变化写进审阅结论 | 改规则等于新增一条接受路径，与 2026-11-01「机制扩展停止」裁定相抵；「质量不降」的判据与成本的噪声阈值也需要真实案例来定。先把读数摆到审阅人眼前，等出现真实的降成本提案再立项 |
| 2 | 审批独立性与提升后观察期 | 不设「批准人不得是提出人」的硬拒；观察期与自动回滚不在本批做 | 单人使用时提出人与批准人常是同一人，无登录时操作人回落为缺省身份，硬拒会让工具不可用；审阅结论里已有「批准人与提出人是同一人」的限制说明。观察期与自动回滚要把运行指标按档案回连冠军，是独立的一批 |
| 3 | 「缺口导入」恒返回空 | 不处置；更正此前的表述 | 核实后它没有界面入口，客户端零调用，只是一个服务端接口，读的是写死在本机沙箱目录下的内核文件。它属于 2026-10-31 R5 设计的「只建双向桥」的储备；按域退役判据，零消费方的规划储备不是死代码。等内核缺口登记在本机有了真实数据，再设计经起草器生成候选的修法 |
| 4 | 导图导出的浏览器回退 | 回退链补系统 Edge | 系统 Chrome 在当前会话宿主下起不来，默认的浏览器缓存又会被磁盘水位清扫抹掉；Edge 装在应用程序目录，同样被拒时仍能启动。补一级回退，导出功能与依赖它的测试在这台机器上恢复可用 |
| 5 | 任务卡单槽位在并发会话下的用法 | 定为仓规：推送前登记本批任务卡，推送后按字节归还；不改门机制 | 两个以上会话并发时单槽位必然相撞；「登记—推送—归还」已经走通。多槽位属于门的机制改动，当前不需要 |
| 6 | 上一批规格里「亮色可读」的验收当时未被执行 | 在原规格补一条勘误 | 验收记录是决策事实源的一部分，错了要在原处更正 |
| 7 | 树候选的可写范围 | 收紧：树候选不得写入只建议面的文件 | 只建议面（护栏、工具指导、子智能体）的产物都在 `profiles/` 下，而系统提示词面与技能面的树候选能写整个 `profiles/`，等于借树候选绕过「只出建议」。原设计（规格 2026-10-19-harness2-improvement-workbench 第 221 行）只说了放宽文件名格式，没有说要放开这些文件 |

### 交付

- `scripts/diagram-export-png.mjs`：浏览器回退链改为「自带浏览器 → 系统 Chrome → 系统 Edge」，三级都失败才报错并给出安装指引；回退函数导出并可被单测以假浏览器对象验证；脚本只在作为命令行入口时才执行主流程。
- `custom/server/harness/workbench/surface-registry.ts`：三个只建议面登记各自的领地（护栏：档案配置 `config.yaml` 与共享约束策略；工具指导：共享工具指导文件；子智能体：档案下的 `subagents` 目录）。`resolveManagedTarget` 在树候选路径上拒绝这些领地，单文件候选不受影响。
- `custom/server/harness/workbench/apply.ts`：回滚恢复快照里的文件时跳过这项检查——存量提案可能改过这些文件，回滚必须能把它们恢复。
- `custom/server/harness/workbench/loop-review.ts`：审阅结论列出成本与耗时的变化。下降的写进支撑读数；耗时上升写进限制，因为现行规则不拦耗时回退。
- `AGENTS.md`：工作规则新增第 14 条（任务卡单槽位与并发推送）。
- `docs/superpowers/specs/2026-11-26-trustworthy-rsi-fulltext.md`：验证一节补勘误。
- 任务卡：`.qgate/registers/task-intent.json` 登记本批任务卡 `palantir-rulings-followup-20261127`，`custom/qgate/gate-packs/l0/gates/scope-check.yaml` 与 `intent-drift.yaml` 里的哈希绑定同步；推送后把另一会话在先的登记与绑定按字节归还。
- 测试：`scripts/__tests__/diagram-export-browser-fallback.test.ts`（新）、`custom/server/harness/workbench/__tests__/tree-write-boundary.test.ts`（新）、`loop-review.test.ts` 补例。

### 验收判据

验收方式：下面各条逐条由测试锁定，命令与结果见「验证」一节。

- 自带浏览器可用时只用它；它失败时回退系统 Chrome；两者都失败时回退系统 Edge；三级都失败时抛错，错误里带安装指引，不直接退出进程，每级失败只记一行原因。
- 系统提示词面与技能面的树候选写档案配置、共享约束策略、共享工具指导文件、档案下的 `subagents` 目录时被拒，错误指明路径属于哪个只建议面。
- 人格文件、技能主文件与技能目录下的其他文件、档案内不属于只建议面的新文件照常可写；单文件候选的判定与改动前一致。
- 回滚恢复快照里的档案配置文件时不受这项检查限制。
- 审阅结论：成本或耗时相对基线下降时出现在支撑读数里；耗时上升时出现在限制里；没有读数时仍提示没有耗时读数。

## 决策记录

| # | 决策 | 理由 | 否决的备选 | 可逆 |
|---|---|---|---|---|
| E1 | 树候选的领地检查放在 `resolveManagedTarget` 里，而不是各调用点分别判断 | 写盘、删除、晋级前采集摘要都经过这一个函数，拦一处即全覆盖；回滚调用点用一个参数跳过 | 在建提案时拒绝（否决：建提案对根目录外的路径本就放行到写盘时才拦，改它会改变既有行为，需另议） | 是 |
| E2 | 回滚恢复不受领地检查限制 | 存量提案的快照里可能有这些文件；拦住回滚会让文件停在候选内容上 | 一律拦截（否决：回滚必须能把文件恢复原样） | 是 |
| E3 | 只登记三个只建议面的领地，不做通用推导 | 领地来自各面扫描函数里写死的路径；通用推导要改扫描函数的形状，收益小 | 由扫描函数自动推导（否决：超出本批） | 是 |
| E4 | 导出脚本三级失败时抛错而不是退出进程 | 单测要用假浏览器对象验证回退顺序，退出进程会让测试进程一起结束 | 保持退出进程（否决：无法验证） | 是 |
| E5 | 并发推送的做法写进 `AGENTS.md`，不改门机制 | 它是多个会话都要遵守的工作方式，属于工作规则；多槽位是门的机制改动 | 改成多槽位（否决：当前不需要） | 是 |

## 验证

实测结果（工作树 `feat/palantir-rulings`，基线 main b694f2e24）。当时机器 1 分钟平均负载在 220 到 330 之间（别的会话在跑重活），耗时读数受此影响。

- `scripts/__tests__/diagram-export-browser-fallback.test.ts`（4 例，新增）：自带浏览器可用时只用它；失败时回退系统 Chrome；两者都失败时回退系统 Edge；三级都失败时抛错并带安装指引、不退出进程、每级只记一行原因。
- `custom/server/harness/workbench/__tests__/tree-write-boundary.test.ts`（5 例，新增）：四个属于只建议面的路径被拒并指明属于哪个面；技能面同样被拒；不属于只建议面的五类路径照常可写；单文件候选的判定不变；回滚恢复不受此限。
- `custom/server/harness/workbench/__tests__/loop-review.test.ts`（+2 例）：成本与耗时都下降时写进支撑读数；耗时上升时写进限制。
