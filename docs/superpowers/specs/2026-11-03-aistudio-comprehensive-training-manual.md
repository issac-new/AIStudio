# AIStudio 全量功能盘点与培训手册完善

## 变更

以当前代码、配置、测试和设计正本为依据，全面盘点 AIStudio 的用户页面、服务端运行链、部署配置和设计文档，完善现有培训和使用手册。

本次交付分为七层：

1. 主手册保留 30 分钟首用路径，补齐任务交付、IDE、审批、治理、自主性、评测、发布、运维和安全边界。
2. `aistudio-feature-inventory.md` 提供完整页面、页签、写读边界、特性开关和未接线清单。
3. `aistudio-operations-reference.md` 提供管理员启动、配置、数据、健康检查和故障处置参考。
4. `aistudio-design-document-guide.md` 说明设计事实源、推荐阅读顺序、稳定机制和正本与实现的差异；`aistudio-design-document-index.md` 提供全部根目录 spec 与 archive spec 的可点击索引。
5. 交互培训页增加上述参考材料入口，本地启动器只放行明确登记的培训文档；同步文档导航、规格和守门测试。
6. 对照最新版全流程推演方案与最新完整 run 的真实报告，增加“方案判据、实际结果、事故根因、后续修复、未做项”案例，不把历史轮次或单次通过写成当前环境的永久保证。
7. 将主手册重构为面向产品需求分析、项目管理、研发、测试、运维监控、安全合规及审计内控六支团队的手册：各团队都有独立学习路径、交付物和完成判据；通用功能目录和组织管理留在参考附件。
8. 新增 `aistudio-swarm-yuan-developer-guide.md`，把 swarm-yuan 作为实际研发交付核心工具技能讲透：生成与 strict 激活、六段目录、九节点与研发四阶段、precheck、state-machine、L1-L4 spec-first、变异验证、worker/ACP/Ycode 链和 R134 离线边界。
9. 将交互培训页从四部分 12 幕改为六团队各两幕，保留 12 幕总数并扩展为六套独立拓扑。首页保留五层 15 步协作全景，研发第一幕以 swarm-yuan 为视觉中心；每幕提供角色流程、跟练动作和完成判据。

## 决策记录

1. 事实优先级采用“当前代码、配置、测试与真实运行证据 → 冻结需求和有效 spec → 整合设计正本 → 专题文档 → 历史档案”。静态盘点只证明实现存在，不把页面或源码存在写成全部环境已验证。
2. 手册采用分层结构。学员先读主手册，按任务查功能清单，管理员查运维参考，讲师和维护者查设计导读；完整 spec 索引不复制到主手册，最新完整 run 另设真实案例，避免多份事实漂移。
3. 每个功能域标明真实写、只读投影、模拟或离线计算、外部依赖和未接线边界。导航隐藏不等于服务端授权，配置存在不等于当前进程已生效。
4. 日常验收与 26 步推演分开叙述。日常操作按实际验收页面执行；SIM 课程按冻结方案的步 20 G5、步 21 UAT 顺序，不合并成唯一顺序。
5. HumanGate、组织双人会签、UAT、工具执法、OS 沙箱和改进实验分别说明。严格异人裁决、严格工具执法、OS 沙箱和实验写盘均需核对各自显式配置，不宣称全局默认开启。
6. 版本以当前载体为准：整体包 `1.0.10-overlay`。发布资产按 2026-11-03 长期规则只上传整体源码包与 yuan everything 离线包两件，四模块仍用于内容归属和版本对账，不等于每版都上传四份模块包。
7. 发现的设计正本旧注释、状态机缺项或计数差异只在导读中登记并给出现行裁决，不在本培训批中改写产品正本或历史 spec。
8. 交互培训仍使用模拟数据，不用静态培训页证明真实产品能力。新增文档入口继续保持本地只读、回环监听、路径白名单和无外部连接。
9. 推演培训同时引用方案与真实报告。方案回答“应当怎样验收”，最新完整 run 回答“本轮实际发生了什么”；报告中的时长、闸结果、提交和测试数字必须带回原报告或复盘锚点，后续清偿与未做项单独列出。
10. 主手册按六团队重写，不继续堆叠功能说明。产品需求分析负责范围、AC、影响面与 UAT；项目管理负责 RACI、派工、容量、质量门与复盘；研发负责 worktree、实现、提交与证据；测试负责独立验证、Eval 与缺陷闭环；运维监控负责部署、健康、恢复与发布观察；安全合规及审计内控负责安全姿态、独立审计、权限、证据链与合规边界。每节以输入、操作、交付物、通过判据和异常边界组织。同步纠正当前看板催办只返回路由而不投递消息、日常 UAT/G5 与 SIM 分写面、系统 verdict 不自动证明异人独立评审三处实现差异。
11. swarm-yuan 不只作为架构名词出现，研发主线必须同时讲清生成器与目标技能的区别、技能先行、分支测试与主干回归、门禁有效性、真实加载证据和“门禁全绿不等于业务正确”。生成器存在、目标技能 active、宿主发现与当次实际加载分别验收。
12. 交互呈现复用现有 SVG 渲染、播放和目录机制，不为换皮重写引擎。产品需求保留 15 步权威流；项目管理明确催办只返回路由；测试并列 G4 与 Eval；运维拆分探针和恢复；审计明确非主张人独立验证。六团队各两幕、每幕激活流与节点由守门测试机械校验。
13. 拓扑只是课程索引，教案才是内容主体。每幕必须有至少 2 项输入、4 步操作、一个不同实例、3 项交付物、2 项检查、2 项误区和本地深链；步骤与实例默认同屏可见，交付验收用展开区承载且展开即暂停，防止“只有壳”。

## 设计文档影响

DESIGN_SYNC: none。此次变更只增加培训材料、功能与设计索引、独立培训启动器的文档白名单和相应测试，不改变 AIStudio 产品架构、运行契约、稳定阈值或版本基线。

整合正本与当前实现之间需要后续对账的内容只在设计导读中登记，不在本批借培训文档之名修改正本。若后续修订正本状态机、版本旧注释或验收顺序，应另起对应设计变更并同步守门测试。
