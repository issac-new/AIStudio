## 变更

1. **D7 提案端全历史注入**（`loop.ts` `proposerEvolutionHistory()`＋`service.ts` suggestProposal）
   - 该面**全部**已采纳冠军（含轮次与 pass@1 增益）、被拒（含裁决 note）、回滚（含回滚理由）一次性进起草 prompt；垫脚石纪律显式入 prompt（「低分祖先可显式改造，注明来源 proposal id」），失败假设禁止换皮重提从「事后 Jaccard 警告」升格为事前注入（原 failedHypotheses 八条截断版仅在非剪枝态保留作冗余提醒）。
   - 空面给「首提案属结构性探索（带内增益可豁免）」权衡提示——与晋级门 exploratory_within_noise 豁免同构。
2. **D10 删除提案模板**（`loop.ts` `deletionProposalTemplate()`）
   - `pruneSignal` 命中（近 n_prune 个提案全部已记录探测增益≤0）时，起草器收到的从一句「优先做减法」升格为结构化模板：零增益证据清单（proposal id＋title＋最佳增益）＋删除计划格式（每项=段落锚点｜加入来源｜零增益证据｜删除理由）＋纪律（不新增机制段落／[待证] 标记防误删）。RRSI 剪枝=directive 定位保持：是否执行仍走人提案＋晋级门。
3. **D11 记忆压缩/遗忘策略**（`experience-freshness.ts` `memoryConsolidationPolicy()`）
   - 经验库（harness 记忆面）补策略层：**stale 采纳**（≥90 天无再验证，复用 HP-7 保鲜档）→ revalidate 建议（晋级引用即刷新 lastValidatedAt，既有通道）；**孤儿候选**（candidate 超 14 天未采纳）→ retire 建议（「可能有用」不是保留依据）。
   - `overview.memoryPolicy` 派生字段（纯函数不落盘）＋面板「记忆整理」折叠块（stale/orphan 双列，含天数与建议动作）；执行走既有 `setExperienceStatus` 按钮，人裁决。
   - 常量 `ORPHAN_CANDIDATE_DAYS=14`。

## 决策记录

| # | 决策 | 理由 | 否决的备选 | 可逆 |
|---|---|---|---|---|
| D1 | D7 注入全部历史而非近 N 条 | 面级历史总量有限（提案数十级）；截断会丢垫脚石，与 D3 档案语义冲突 | slice(-8)（否决：丢祖先） | 是 |
| D2 | D10 只在剪枝命中时给模板（directive） | RRSI 剪枝定位=建议非强制；未命中时给模板会诱导无依据删除 | 恒给模板（否决：违背 directive 定位） | 是 |
| D3 | D11 阈值复用保鲜档（90 天）＋孤儿线 14 天 | stale 与 HP-7 同源防双口径；14 天=两倍停滞窗（stallWindow=3 × 提案节奏）量级 | 孤儿线 7 天（否决：过激进，候选→采纳链路常跨多轮） | 是 |
| D4 | D11 纯派生＋人裁决执行 | 与「人提案、台正则、门拦险」边界一致；自动退役=记忆静默丢失 | 自动退役（否决：越过人裁决权） | 是 |
| D5 | prompt 注入不做长度护栏 | 全史行数=面提案数量级（≤百行），title/detail 各截 120-160 字已控 | 二级摘要（否决：丢理由细节，成本大于收益） | 是 |
