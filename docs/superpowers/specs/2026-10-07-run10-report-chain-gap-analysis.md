1. **报告验收链被绕行是本论最大问题**：方案 §5.7 收官判据②写明"审计 FAIL 即不得收官"，实测 mx-report-audit 对 run10 报告 15 项 FAIL（R18 全量呈现 13 项+载荷文件缺失+问题单缺 DISP），报告照样产出交付，且人读正本 final-report.html 压根没生成（双正本制缺一）。机制失效而非执行失误——审计从未被接进生成链当硬闸。
2. **"静态注册表真空=默认报喜"是失真放大器**：生成器对未注册轮次的默认分支一律沿静态文本渲喜报——闸门徽章"一次通过"（G2/G5 台账打回在案）、六域表"DISP 6/6"（run2 旧账冒充 run10）、附录手册"T-101~T-108"（run9 前旧编号）。同一病根三处发作，run6/run9 三轮审计都点过名却逐处复发。
3. **G5 门禁灯灰是"产品诚实、叙事撒谎"的标准样本**：交付案例面板 G5 灯灰（26-op1 帧实锤）是因为 harness 从未发射 gate G5 pass 事件（scenario.log 六条 delivery 行实查：G1/G2/G3/G4/G6 有成对 gate pass，G5 只有 stage done），面板如实呈现事件缺口；报告步 20 叙事却写"交付面板事件 stage P5 done+gate G5 pass"——叙事用想象补全了没发生的事。

## 三、B 区：生成器与审计器病根（17 缺陷 → 6 共性病根）

缺陷逐项定位与修复锚见 simharness 提交 fb07c6a / 41e1c53 / 94b775d 的 commit message 与 diff，此处只记共性病根（防复发靠机制不靠个案）：

1. **静态模板冒充实录**：按轮注册表（`_GATE_REJ_BY_RUN`/`_DOMAINS_BY_RUN`/steps_entry/注脚）真空时默认渲喜报或旧账。修复=默认分支一律 ⬜/拒绝渲染+本轮实算兜底（方案 §5.5 已补"静态注册表兜底条款"）。
2. **计数口径多源不互查**：问题单计数曾 5 套并存（叙事键白名单/唯一键 join/复盘文档原文/治理报告/审计），截图计数 2 套。修复=审计 A3 三源计数断言（复盘文档×issues.log×报告唯一键）。
3. **锚点解析链断裂无告警**：DISP join 断裂、键白名单漏键、布尔键映射时间列、run2 卡锚泄漏——全部静默降级为空串/0/旧值。修复=类型段 join+按轮实锚+布尔值渲"已落键"不冒充锚。
4. **布尔旗标与锚点混用**：state.env 的 `*_done=1` 与时间戳/事件锚同命名空间，靠值形状猜语义猜错即"✅ 1"/"—"。修复=值形状分类渲染（旗标/时间戳/锚）。
5. **生成时刻快照 vs 迟到证据无防陈化**：截图补拍、台账追加都晚于首次生成，重生成靠人肉。修复=图数对账（审计 A5）+补拍语义自动标注（图注含"补拍"即 hero/页脚带声明）。
6. **审计与生成器同源同病且不强制**：审计 R5 与生成器共用同一断裂 join；审计 FAIL 不阻断产出；"R29 三源一致性断言已落地"的方案声称无对应代码（承诺-实现断层）。修复=审计六项断言补强+R18 缺口记单降级通道（§5.6 ⑩ 同构）+方案 §5.7 补"驱动在 report_done 前硬跑审计熔断"。
