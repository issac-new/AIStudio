# 驾驶舱左侧导航与阶段页页签化设计（2026-10-18）

分支：`feat/ia-leftnav-stage-tabs`（overlay 仓）
来源：用户 2026-10-18 实报四条——六阶段与「IDE 工作区」切换按钮穿插；阶段页残留「XX 中心」且功能组织未更新；多个 UI 不闭环、只展示难处置、信息偏多；各阶段页功能需要页签化、一屏内完成，并与全流程推演分离。用户同日确认「按方案落地实施」。
验收：ia2/前端全量测试绿、开发态走查六阶段页与左侧栏、构建通过；不改路由路径，旧直达链接全部可达。

## 一、结论先行

现状不是功能缺失，而是三层组织叠在一起：六阶段顶栏、页头下方的常用入口条、与六阶段平行的「仿真中心/治理中心」。阶段页又把运行监控面板与跳转卡片堆在同一滚动页里，造成导航穿插、信息过载、动作断头。本轮把驾驶舱改为「左侧常驻导航 + 顶部上下文栏 + 页内单层页签 + 独立全流程推演区」，路由路径保持不动，先改壳层与页面组织，再补检索与分类。

## 二、现状证据

1. 六阶段在顶栏，④开发与 IDE 工作区共用一个分段控件：`custom/client/ia2/components/IaCentersNav.vue:44-78`；页头挂载点 `IaShellHeader.vue:195-196`。
2. 常用入口不在左侧栏，而是页头下方的独立条：`IaGlobalTop.vue:96-99`（`IaQuickNav`、`BackgroundWorkStrip`、交付读数条）。
3. 壳层没有左侧栏：`IaShell.vue:74-80` 只有顶区与 `router-view`；`ia2.scss:73-90` 的 main 为单列。
4. 「中心」是平行结构而非单点文案：`views/sim/sim-tabs.ts:14`（仿真中心）、`views/gov/gov-tabs.ts:13`（治理中心）、`IaBreadcrumb.vue:98-107`、`SimSettingsView.vue:62`、`SimOrchestrationView.vue:22`、`GovSettingsView.vue:38`、`SpotlightPanel.vue:49-52`、`i18n-tab-intros.ts:34`。
5. 阶段页为堆叠式：`views/stage/StageShell.vue:128-213` 依次渲染五步清单、密钥台账、质量门、组织知识、风险交接、审批、清算、运行态势、证据、交付、问题清单，最后是「进入 →」工具卡。
6. 日常与全流程推演混排：`StageShell.vue:142-199` 内嵌运行期面板；`SimCenterView.vue` 与 `GovCenterView.vue` 又各有一套页签。
7. 检索只覆盖会话/任务/命令：`SpotlightPanel.vue:58-81`；无运行、文档、证据与工作区过滤。工作台列表只有全部/会话/循环与三种排序：`FlowNavPanel.vue:100-160`。

## 三、目标信息架构

```text
注意力条（有需要人处理的事项时置顶）
┌──────────────┬────────────────────────────────────────────┐
│ 左侧导航      │ 顶部上下文栏：搜索 · 沟通协作|IDE · 运行 · 通知 · 账户 │
│ 常用          ├────────────────────────────────────────────┤
│ 流程（六阶段）│ 页面标题 + 一句话 + 主操作                  │
│ 整轮（全流程推演）│ 单层页签（≤7）                            │
│ 专题          │ 当前页签内容：一屏内，就地处置                │
│ 管理          │                                            │
└──────────────┴────────────────────────────────────────────┘
```

左侧栏分组与顺序：常用（流程总览、工作台、看板、审批收件箱、检索）；流程（①搭建、②需求、③分析设计、④开发、⑤验收、⑥治理）；整轮（全流程推演）；专题（流程架构、本体、评测、技能治理）；管理（系统设置）。

## 四、左侧栏规格

1. 五组子项共用 `IaSideNavItem` 一套行式：18px 前导槽（图标或 1-6 数字徽标）+ 标签 + 右侧槽（元信息/徽标/状态点）。行高 30px、左右内边距、圆角、悬停与选中态完全一致；流程组不再使用大圈序号与「未开始」长文字，状态收为 ✓/●/○。
2. 只有站在某个阶段页本身时，该阶段行才用底色高亮；其余页面只靠状态点表示当前阶段，避免「当前页面 + 当前阶段」两行同时高亮。
3. 「沟通协作 | IDE 工作区」切换独立为 `IaWorkspaceSwitch`，不再与六阶段共用分段控件；切换保留当前会话。
4. 左侧栏宽 216px，可折叠到 58px；用户未手动设置时，窄屏（≤1180px）自动收起；折叠状态持久化在 `settings-layers` 的 user 层。
5. 顶部只保留注意力条、页头（品牌/主题/语言/连接、视图切换、运行上下文、搜索、通知、账户）；常用入口条、后台工作条与交付读数条移出顶区。
6. 左侧栏只在 `IaShell`（/app 主壳）挂载；收编页（IaLegacyShell）保留其设置侧栏，避免双左栏。

## 六、全流程推演专区

页签：运行总览、监督面板、运行监控、证据库、运行编排、推演设置。阶段页只保留一行「本轮运行」摘要与跳转，不再内嵌运行监控面板。删除「签 N」徽标、「待实现」文案与端点清单占位；运行目录输入统一由运行选择器/`useRunContext` 承接。治理不再有「治理中心」壳，`/app/gov` 只作为⑥治理「质量门记录」深链。

## 八、闭环与信息减负

1. 每个页签必须有主操作；只读面板必须给出真实出口（打开任务、会话、文档、审批）。
2. 空态一句人话说明原因，加一个下一步按钮。
3. 列表行就地开抽屉，不整页跳转。
4. 阶段页只留一个滚动区：页头两行内、页签一行、内容区自适应。
5. 顶区删除后台工作条与交付读数条；首访导语降为一行副标题 + 问号提示。
6. 没有端点的写入动作不做假按钮，改为「去对应任务/文档处理」。

## 九、检索与分类聚类

检索页含类型页签（全部/会话/任务/运行/文档/人员）与过滤（工作区、团队、状态、负责人、时间）；顶栏搜索保留快搜，回车进完整检索。以 `workspace_path` 作为跨对象聚类键，工作台左栏增加「按最近活动/按工作区/按团队」分组并持久化；看板增加工作区过滤并复用命名视图。任务、会话、工作区、运行保持双向可跳。

## 决策记录

- D-1：六阶段从顶栏移到左侧栏，删除顶栏阶段条；「沟通协作 | IDE 工作区」拆成独立分段控件。理由=用户实报两类入口穿插，阶段是导航、视图是模式，语义不同层。
- D-2：五组左侧栏子项共用 `IaSideNavItem` 一套行式，流程组用 1-6 数字徽标、状态收为 ✓/●/○。理由=用户明确要求流程/专题子项与常用子项排列一致；三套样式会造成视觉层级漂移。
- D-3：阶段页改为单层页签，页签状态写 `?tab=`，不新增二级页签。理由=用户要求「尽量不要再次点击后跳转、不超出一屏」；query 承载保证刷新/分享/旧链接兼容。
- D-4：治理中心解体，七签按用途迁入①/②/③/⑤/⑥页签；`/app/gov/*` 作为深链保留。理由=「XX 中心」与六阶段平行是组织关系未更新的根因；直接删路径会破书签与既有测试。
- D-5：全流程推演独立成区，阶段页不再内嵌监控面板，只留一行本轮运行摘要。理由=用户要求正常功能与全流程推演分开；监控面在阶段页重复出现会挤占首屏并制造双入口。
- D-6：左侧栏只在 IaShell 挂载，收编页保留设置侧栏。理由=避免 2026-09-30 已根治的「点开侧栏又出现一个侧栏」双栏问题复发。
- D-7：只有阶段页本身高亮阶段行；其他页面用状态点表示当前阶段。理由=避免当前页面与当前阶段两行同时抢高亮，用户已明确要求统一行式而非双高亮。
- D-8：路由路径全部保留，先改壳层与页面组织，再改文案与检索。理由=零断链优先；在跑推演期间不做 inject，不刷新共享注入树。

## 验收标准

1. 左侧栏五组在位，六阶段只出现在左侧栏；阶段行与常用行同一行式。
2. 顶栏无六阶段；沟通协作/IDE 切换独立可见且双向可切，保留会话。
3. 六个阶段页均为单层页签，页签内就地操作；旧 `/app/gov/*` 与阶段路径可达。
4. 用户可见面无「仿真中心/治理中心/运行中心/签 N/待实装」残留。
5. 阶段页无运行监控内嵌；全流程推演区页签完整。
6. 检索覆盖会话/任务/运行/文档/人员，支持工作区过滤；工作台支持按工作区分组。
7. ia2 全量测试绿；开发态走查通过；构建通过（部署窗执行）。
