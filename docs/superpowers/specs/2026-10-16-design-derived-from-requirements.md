## 一、从场景推导信息架构

需求正本 §一 确立场景主轴：一轮 20 小时量级推演里主管的完整工作循环＝「开轮（手工过检）→ 周期观察（手工盯）→ 发现异常（手工翻日志定位）→ 介入决策（人工放行/打回/发指令）→ 收尾验收（人工对账报告）→ 复盘治理（人工处置问题单与代偿）」；SwarmStudio 界面的存在理由＝把这个循环里的手工动作逐件产品化（R1-R14 即由此提炼）。另有日常执行面：员工（人与 AI）每天在看板、沟通与 IDE 里干活。

把六段循环与日常执行面各自需要的能力列成一张推导表——每一行先写「该段要完成什么」，再推导「需要什么界面」，全程不引用旧设计：

| 循环段 | 要完成的事（需求锚） | 推导出的界面能力 |
|---|---|---|
| 开轮 | preflight 十六项检视、姿态声明、清偿门放行判定（R6/R11） | 开轮准备面：检视灯＋姿态选择＋清偿灯一屏 |
| 周期观察 | 健康一屏、停滞与静默判读、观察窗研判（R1/R2/R10） | 驾驶屏：服务/进程/派发/休眠＋闸态＋姿态＋净额一屏；深一层＝观察窗流与研判时间线 |
| 发现异常 | 判词与数字反查证据原文（R7/R12） | 证据反查：点任何数字/判词直达证据（事件/提交两类高频先行）＋帧图廊 |
| 介入决策 | 「等人决定的事」集中呈现、批准/打回留痕、收尾令模板（R5） | 把关待办：介入卡队列（14 介入点）＋动作留痕＋常用指令模板 |
| 收尾验收 | 交付健康、AC 逐条判词、报告对账（R4/R12） | 验收面：分支凭证表＋AC 判词链＋报告同构下钻 |
| 复盘治理 | 问题单处置、代偿清偿、度量基线、审计、密钥与容量风险（R3/R6/R13/R14） | 治理面：关卡与问题单、清偿门、度量体检（含阈值灯）、审计变更、组织资产（含密钥台账） |
| 日常执行 | 卡流转、沟通、IDE 生产（R8 导航锚下的既有面） | 执行界面：看板（我的卡）、沟通、IDE 入口 |

**推导结果**：界面按「日常执行 / 一轮推演 / 治理问责」三个关注面分一级导航（R8：导航按关注面归位，一级 ≤7 项、单层页签）。三关注面与旧「三中心」形似——原因是需求本就如此聚集（使用场景推导与旧盘点归位殊途同归），但签内内容以下文逐屏推导为准，与旧候选的差异处共五项，见 §四。

**镜头问题**（对照旧设计最大差异）：需求正本已论证「界面第一用户是主管」，AI 工作者不点界面（§一）。四角色镜头层无使用实证（Q1 裁定解体）；「治理驾驶位」不是独立首页，就是推演总览这一屏（R1 一屏开车）；产品/研发/测试/治理四视角的差异由「我的卡默认过滤＋待办分类」承接（R5/R8），不做角色专属路由。

## 二、页面与功能设计（逐屏推导）

通用件先行：**六个展示原子**（对照旧八原子，按锚筛选）——双凭证标（R4）、锚点反查抽屉（R7，全产品唯一反查交互，右滑 480px）、代偿紫标（N1）、判词结构位（R3：判据原文＋判词只认结构化字段）、介入卡（R5：人形图标＋批准/打回双钮＋留痕）、纪律提示位（N2：在制 ≤2 随卡列表、不许谎报随结论输入框）。另两件降级：步境标与 RACI 角标仅在报告同构面使用（R12 锚），不做全产品常驻。原子=共享组件包（VTU 单测各 ≥2 例含缺席态），一切屏引用。

### 推演关注面（/app/sim）

**S1 轮次总览＝驾驶屏** `/app/sim`（R1/R2/R3/R6/R12）
首屏自上而下：姿态横幅（三档色带＋清偿门灯，R6）→ 健康行（四服务/驱动/监督器/哨兵/派发器/休眠工作者，异常红显不靠翻日志，R1）→ 停滞行（静默提醒催单状态＋停滞判词最近三条，R2）→ 闸行（六闸全名＋状态＋判词来源，R3）→ 净额双行卡（含代偿/净额并列，N1）→ 下钻＝每步四段与报告同构（R12）。数字全部实测计算（N2）。
组件来源（对照采纳）：健康行与停滞行复用集群巡检官已有检测器数据面（spawn-health 先例），旧详设的端点契约经 R1/R2 锚检验成立，采纳。

**S2 监督与观察窗** `/app/sim/supervision`（R10/R2）
观察窗流（每窗一卡：窗号/时刻/轮数变化/结论摘要，展开＝该窗 journal 原行）＋研判/判词时间线（provenance 标）。只读零写。验收＝主管不翻 agent.log 即可回答「现在卡在哪、谁没动」（R10 判据原文）。

**S3 证据库** `/app/sim/evidence`（R7/R12）
两类高频锚检索先行（matrix 事件号 $ 与 git 提交号，R7）；卡号/房间号检索挂账不删（需求正本 §3.2 裁定）。帧图廊按步分组（零帧步如实「未采集」，N1）。台账/journal/审批事件三张只读子表。点任何结果→锚点抽屉。

**S4 交付与验收** `/app/sim/delivery`（R4/R12）
分支表（六 feat 行：双凭证标＋新鲜度三态）＋AC 判词链四列表（AC 编号/判据原文｜对应用例｜测试结果｜UAT 判词三态）＋交付物 13 件链（件名/字段核对状态/仓锚）。行点击→锚点抽屉。

**S5 场景编排与开轮准备** `/app/sim/orchestration`（R11 受 Q2 限定）
编排面（既有 OrchestrateView 整件迁入）＋preflight 十六项检视灯（可见性提前，Q2）＋姿态选择＋开轮/续跑发起（实际执行仍由 harness 侧承担，动作留痕可反查）。排期面只读消费 autosched 端点。

### 工作关注面（/app 即工作台）

**S6 看板·我的卡**（R8＋日常执行）：卡列表默认「我的卡」，双凭证标/纪律位随卡；分诊与流转语义不变。
**S7 把关待办 inbox**（R5/R6）：双队列＝人工介入卡（14 介入点，计数与端点一致）＋清偿门审批（resolve 挂 PR 锚/waive 强制理由）＋审批留痕可反查。收尾令模板＝介入卡延伸动作（结论行＋翻卡＋禁再跑三步指令一键发出，缺口③工具化）。
**S8 沟通面**（R7/R12）：系统消息（判词/派单/提醒催单）与人类消息分层渲染；消息可存证入证据库（存证消息在 S3 可反查回原消息）；直达链接可取证。
**S9 IDE 生产位**（R4）：任务简报＝派发词原文；分支新鲜度徽（与 S4 同源同值，双实现即缺陷）。

### 治理关注面（/app/gov）

**S10 关卡与问题单**（R3/R14）：六闸卡（判据原文＋判词 provenance＋闸修复单跟踪——FAIL 唯一出口＝登记修复单跟踪到复审通过，无任何绕过钮）＋问题单台账全量与 100% 处置进度。
**S11 清偿门**（R6）：代偿台账全量（九型）＋type→PR 映射＋resolve/waive 审批（与 S7 同源同值）＋开轮放行灯。
**S12 度量体检**（R13/N2）：五卡（首过率/并行度/六域体检/容量成本/会话健康）——成本卡**新增阈值灯**（超阈值主动亮红，数据同卡）；另配套服务端容量检测器（见 §三），阈值一致。
**S13 审计与变更**（R14）：四查状态灯行＋审计意见书＋基线变更带提交锚。
**S14 文档评审**（R4 派生）：13 交付物字段级核对（缺字段红显）。
**S15 组织与资产**（R13/Q3）：人员编制/RACI/账号/应用资产/技能/功能开关（对照采纳旧两区合并）＋**新增密钥最小台账**（清单＋最近轮换时间＋归属，不含密钥本体；数据＝仓库内登记文件，界面只读小节）。

### 设置（R9，维持已完成大半的合账框架）
三设置页：个人偏好（user 层）/系统设置（workspace 层，按治理域分组）/推演参数（姿态缺省/观察窗节奏/清偿门策略/审批升级超时）。R9 验收＝123 行对账已达成，后续只维护。

## 四、与旧候选的差异清单（推导独立得出的五项）

1. 镜头层解体（Q1）：旅程条/四维带/切换器/三首页不立项——无 R 锚；介入卡与驾驶屏有锚保留。
2. 展示原子 8→6＋2：步境标/RACI 角标降为报告同构面使用（R12），不做全产品常驻。
3. 证据检索收敛：四类锚→两类高频先行（R7），卡号/房间号挂账。
4. 新增三件旧候选没有的：容量阈值灯＋巡检官容量检测器（R13 双通道）、密钥最小台账（R13/Q3）、收尾令模板（R5 延伸）。
5. 旧「重审三详设」路径废止：本正本即设计正身，旧详设仅作组件级实现素材（对账总表 123 行的实存锚继续有效——那是供给面事实）。

## 六、Non-goals（继承需求正本与方案 §1.4）
