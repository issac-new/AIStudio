## 修改

### 1. 当前功能地图

本轮直接读取路由、页签、注册表和调用方。清单生成器从真实注册链派生 116 条路由记录：76 个页面、40 个重定向。六阶段共有 36 个页签，合计 152 个只读访问状态。路由源码是唯一事实源，清单和截图均为派生证据。

|---|---|---|

| 专题工作台 | 评测、流程架构、本体、技能治理，统一 `IaFeatureShell` | 保留特性开关与诚实降级，逐页验证 |

### 2. 已确认的源码问题

1. 审批去重吞卡：`custom/client/cockpit/api/approvals.ts:65-72` 对所有 kind 使用 `kind:taskId|title`。同会话的不同命令通常共用标题且没有 taskId，结果只保留一条，直接影响人该审批什么。
2. 注意力输入契约错位：`custom/client/cockpit/adapters/attention-adapter.ts:17-27` 要原始 KanbanTask，`custom/client/cockpit/store/cockpit.ts:145-161` 却传 CockpitTask。`created_at` 缺席使时间恒为 0，`P0` 等字符串相减得到 NaN，排序失效。
3. 关联轨迹串扰：`custom/client/cockpit/composables/useRunTrace.ts:369-448` 把关联 session 回放到主 state，`trace-middlewares.ts:60-71` 的运行节点归属仍依赖主 session 与单一 runId。实时关联事件也走同一上下文，不能只修历史回放。
4. 回放实现重复：`useRunTrace.ts:542-627` 与 `run-trace-adapter.ts:570-653` 各自生成同类事件。`run-trace-adapter.ts:137-318` 还保留着 middleware 链早已替代的私有处理器，增加误读与漂移成本。
5. 待办提醒显示错时：`custom/client/ia2/store/workspace.ts:329-332` 把 todo 的 `createdAt` 写入日程 `ts`，`CockpitScheduleModal.vue:194-199` 随后把它显示成闹钟时间。
6. 全路由工具不可直接复跑：`scripts/regression/walk-routes.mjs:4` 未导入 `bootApp`，`:69` 却调用未定义的 `openApp`，`:110-113` 固定访问 8689，`:8-55` 是陈旧静态清单。脚本语法检查通过不代表可运行。

### 3. 本轮改动

- 审批只对 review 做同对象去重，command 按审批 id 保留。
- 注意力适配器在同一输入边界支持原始 KanbanTask 与 CockpitTask，统一毫秒时间和数值优先级。
- 主 session 与关联 session 各自维护 TraceState，合并只投影 nodes/edges，实时与历史共用这套隔离规则。
- 历史消息到事件的转换只保留一份，进度与让出主线程策略留在调用侧。无生产调用的旧处理器一并删除。
- 日程使用真实 remindAt 显示与排序，无提醒项保留可解释的次序。
- 路由清单从实际注册链生成，走查默认端口改为 8649。重定向、动态参数、阶段页签、合法空态和预期错误均分类记录。

## 决策记录

| # | 决策 | 理由与边界 |
|---|---|---|
| R1 | 保留现有信息架构 | 当前已有单一事实源与深链兼容，本轮主要矛盾是数据正确性和验收能力，不是视觉换皮 |
| R2 | 审批去重仅覆盖 review | review 的历史双卡仍需新盖旧，命令审批的独立 id 代表独立风险，不能按标题合并 |
| R3 | 轨迹按 session 隔离 reducer 上下文 | 节点 ID、运行状态和工具父子关系都属于 session，共享 runId 会串扰。对外 TraceState schema 与节点 ID 不变 |
| R4 | 复用现有消息转换与合并函数 | 不再创建第三套轨迹模型，主回放的进度更新属于 composable，纯转换留在 adapter |
| R5 | 原始优先级语义不改 | 数值 3 及以上是 P0，2 是 P1，1 是 P2，0/缺省是 P3，只修 DTO 映射，不改业务优先级 |
| R6 | 路由清单由注册表生成 | 静态副本会再次过期。清单输出是派生证据，路由源码仍是唯一事实源 |
| R7 | 本轮只读走查，不批量运行写操作 | 路由覆盖不等于批准、删除、开轮等危险操作验收，这些另列权限与写流验证，不伪造完成度 |
| R8 | 使用独立 worktree，不替换在线服务 | 保护并行会话与 `serve-main`，隔离前端只用于本轮验收，成功合入前不改在线版本 |

## 验证

### 修复项（先失败后通过）

每项缺陷都先新增失败测试并确认失败原因，再实现。目标测试结果：

- 审批与注意力：`approvals-dedupe`、`approval-panel`、`attention-adapter`、`cockpit-store` 共 70 用例通过。旧实现实锤了三处失败——同标题双命令只剩一条、CockpitTask 的创建时间归零、同梯队排序颠倒。
- 轨迹：`use-run-trace`、`run-trace-adapter`、`trace-middlewares` 共 49 用例通过。新增三组回归分别锁定历史归属、实时交错与慢加载缓冲，旧实现全部失败于关联 run 未闭合。
- 日程：`workspace-store`、`cockpit-schedule-modal` 共 26 用例通过。旧实现把 14:00 的提醒显示成创建时刻 12:00，无提醒待办显示假闹钟。
- 驾驶舱全目录 `custom/client/cockpit` 369 用例通过。

### 全量只读走查

- 路由清单由真实注册链生成：116 条记录（76 页面、40 重定向）加 36 个阶段页签，共 152 个访问状态。
- 第三轮全量走查（隔离前端 8651 + 主仓后端 8647）：176 条记录、0 缺陷、152 张截图。台账与截图在 `/tmp/aistudio-cockpit-full-v3-20261026/`。
- 26 条警告单独分类：占位资源的预期 404、跨页延迟请求、Matrix 两页未认证、宠物页默认关闭。它们不是缺陷，也不代表对应业务数据已验证。
- 走查过程中修掉了三类工具误报，每类都有探针单测锁定：
  - 固定等待把加载页当内容页。
  - 重定向只看路由不看浏览器地址。
  - 跨页请求归错页面。

### 构建与类型

- `npm run build` 通过，`verify-dist` 出厂口令扫描零命中。
- 上游 `tsconfig.app.json` 的类型检查失败 52 处，全部位于 vendor 注入态。根因是该 tsconfig 不解析 `@/custom` 别名，属既有问题。
- 追加诊断 tsconfig 后，本轮改动文件里审批、注意力、日程、路由清单零类型错误。`useRunTrace` 报出的 1 处未使用变量与 1 处调用类型问题在父提交同样存在，属既有债务。

### 全量测试与测试基建修复

- 首次全量 `npm test` 失败 27 文件 56 用例，主仓复跑同样失败。定性为既有基线问题：这些守门测试读取的 `../upstream` 缓存已随 0.7.39 升级回到未注入态。
- 修复方式是创建共享解析器 `custom/test/upstream-root.ts`，解析序为显式 env、当前检出 vendor、旧缓存，与 `vitest.config.ts` 一致。27 个测试文件只换读取根，不改任何断言。迁移后 28 文件 216 用例全绿。
- 最终全量 `npm test`：888 文件，6348 过、3 败、13 跳过。败例为 diagram 导出×2 与 runtime-verify 探针×1，单独复跑全部通过，定性为并发负载下的环境抖动。
