> **这份文档让读者做的决定**：更新后的设计正本、六团队培训手册与运维参考，能否作为「人与 AI 集群怎样协作」的现行陈述使用；哪些内容明确不在本批写进本仓文档；实施中查出的八处不一致由谁处置。

## 变更

### 事实

**审计时确认的事实**

- 参照文档是「Hermes Agent 集群」的设计正本，讲三层结构的中间一层：驾驶舱（Studio）→ 集群（一个调度入口加专业 worker）→ 目标技能（swarm-yuan），执行记录回流驾驶舱。
- `docs/DESIGN.md` 自称唯一整合正本，把 hermes agent 列为五个组件之一；3.4 节讲了岗位范式与能力装配，但 1.1 节没有说这一层在三层数据流里的位置，全文也没有声明它与参照文档的分工。设计导读只把参照文档归为「组件内部事实源」，没有给阅读路径。
- 培训手册把「组织」讲成六支人类团队之间的交接；AI 集群一侧的内容缺席：编制与五岗接力、唯一调度入口、建卡写板名、技能白名单挂载、卡死处置、完成交接三样、两套评审的边界。手册里的「白名单」三处都是审批角色或模型池的白名单，与技能挂载无关。
- 运维参考与参照文档几乎不相交：看门狗的自动动作、配置由脚本生成不可手改、备份恢复、升级须走安全脚本、退役档案纪律，这些关键词在运维参考里命中数全是零，而定时任务登记与多数脚本都在本仓 `team/` 下。
- 文档入口不通：只有根 README 链接到参照文档；`docs/README.md`、使用指南、设计导读都没有链接。调度入口的七份操作类参考（`team/profiles/orchestrator/references/` 下 `matrix-conventions.md`、`notification-format.md`、`board-keywords.md`、`topic-tags.md`、`routing-examples.md`、`workspace-packaging.md`、`implementation-examples.md`）没有人读的入口。
- 过期数字：Windows 安装说明与离线安装说明仍写 30 或 36 个档位、aiteam 6 个；工具参考写 Python 3.12、31 个 npm 包（`team/package-all.json` 实数 37）。
- 审计中判为「冲突」的条目多数是两个不同的对象：返修轮次 5（`runtime/hermes_cli/kanban_db.py` 的 `DEFAULT_MAX_REWORK_ROUNDS`）与「agent 互审第 3 轮仍不通过升级」（`team/profiles/_shared/03-evolution-memory/review-gates.md` 第七章）；「评审凑不齐可降级」（集群评审委员会规则）与「没有子代理就停机」（`skills/swarm-yuan/references/independent-review-protocol.md`）。两边各自成立，手册没有讲清边界。

**实施中逐条核实后确认的事实（决定了几处写法）**

- 完成交接的键名两头不一致：集群规范 `team/profiles/_shared/02-org-orchestration/ontology.md` 第 3.2 节写的是 `artifacts_produced`；运行时模板读取的是 `metadata.artifacts`（`runtime/hermes_cli/kanban_db.py` 的 `_cleaned_artifact_paths`、`_persist_scratch_completion_artifacts` 与 `runtime/tools/kanban_tools.py` 的 `_merge_artifacts`），`artifacts_produced` 在 `runtime/` 的代码里没有读取点。规范自己的审计表也记着完成卡里很少填这个字段。
- `team/shared/profiles.yaml` 有 48 个档位条目，`team/profiles/` 只有 27 个现役目录；多出的 21 个是已退役档位（eda 系列 11 个、k12 系列 7 个、`hack-referee`、`hack-soc`、`lcm-dev-test`）。它是配置来源，不能当作现役名册。
- `team/profiles/orchestrator/cron/retired_jobs.json` 被 `team/.gitignore` 忽略，不在仓内。卡死巡检、meta-watchdog、夜间 Loop 存活看门狗、capability-gap 看门狗在仓内只有转发到宿主的包装脚本；`team/profiles/ops-devops/scripts/hermes-update-safe.sh` 在仓内只有 6 行，同样转发给宿主正本。并发熔断看门狗、cron 暂停巡检、会话接口漂移巡检的脚本正文在仓里。
- 四项「只在集群设计正本里讲」的机制里，三项的实现文件只在宿主安装树上：演练编排的协议与算分器（`team/profiles/_shared/01-scheduling-bus/` 下没有 `adversarial-drill-protocol.md`）、评测体系的两份技能（`team/skills/` 下没有 `agent-eval-system-design` 与 `skill-tuning-production`）、判分器防回流脚本（没有受控副本，本仓只有 `team/skills/devops/worker-completion-independence-verification/SKILL.md` 对它的描述）。生产知识库选型在本仓 `docs/knowledge-base/` 有选型记录与部署手册。
- 调度入口的规则文件 `team/profiles/orchestrator/orchestrator_rules.md` 的看板路由表仍列着 pay、aiteam、data 三个领域网关，而 `team/README.md` 记载它们已于 2026-11-18 并入顶层调度入口。
