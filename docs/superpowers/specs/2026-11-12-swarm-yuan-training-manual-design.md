# 2026-11-12 swarm-yuan 产品、技术与操作培训手册设计

## 变更

将现有 `docs/manuals/aistudio-swarm-yuan-developer-guide.md` 重构为一份完整中文培训手册，保留原路径与既有文档入口，不另建平行事实正文。

手册面向首次接触 swarm-yuan 的研发、测试、技术负责人和技能维护者。读者完成学习后，应能：

1. 说明生成器、目标技能与项目运行态的职责边界，以及产品适用与不适用场景。
2. 讲述认知、规范、装配、使用、验证、成长六层设计，指出对应实物文件与证据。
3. 完成安装、生成、AI 填充、strict 激活、日常研发、门禁判读、失败处置、反馈更新与离线安装操作。
4. 按步骤判断“看到什么算完成、失败怎么办、留下什么证据”，不把脚本退出码或模型自述当作全部交付证明。

产品总主线按用户 2026-11-12 补充定义，统一为“研发人员能力的 SOP 化”：

1. 用国内外行业标准的业务、质量、安全规范，以及技术栈与架构最佳实践，形成标准研发能力。
2. 用领域自身的特色经验和潜在知识，形成个性化研发能力。
3. 用本体方法解构并重组组织资产及其使用方法，使组件、关系、动作和配方可查询、可拼装、可检查。
4. 约束最小单元的质量标准与拼装标准，结合成熟工程方法论，编排标准研发流水线。
5. 用严苛、细致且独立的全面约束检查核验生产标准，区分机械门禁、真实验证与独立审查。

正文必须先讲这条能力形成链，再讲生成器、六层机制和操作命令；产品、技术设计、实训与考核都要能回指这五项，不得把它降成附录中的一句口号。

正文分为产品介绍、技术设计、操作使用、场景实训、考核与附录五部分。操作步骤统一包含“做什么、怎样解释、完成标志、失败处置、留存证据”五项。Mermaid 图紧跟对应原理、流程或案例，不设独立图解拼盘。技术术语首次出现时用中文解释，原始命令与文件锚点保留。

当前版本以 `RELEASE-MANIFEST.json` 和 `skills/swarm-yuan/CHANGELOG.md` 为准，采用 v2.100.3；安装与生成落点以当前 `install.sh`、`scripts/generator/subcommands.sh` 和有效 spec 为准。历史案例只证明其所属版本和场景，不冒充本轮实测。

1. 结构检查：手册包含产品介绍、技术设计、操作使用、贯穿案例、考核与附录；每个实操步骤具备五项教学字段。

3. 文档检查：运行 Markdown 本地链接与 `file:line` 锚点检查、`git diff --check`、文档索引检查及相关 Vitest 守门。
4. 技能检查：运行 `bash skills/swarm-yuan/scripts/self-check.sh --check-only`，确认本次手册引用的技能本体自检结果；失败如实披露，不改产品代码消红。
5. 独立审读：由未撰写正文的审查者检查技术准确性、章节连贯性、新手可执行性和证据边界，主会话复核发现并完成修正。
