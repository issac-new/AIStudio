## 0、怎么读

### 0.1 一页纸

AIStudio 是一套让「人指挥 AI 团队交付软件」的工作系统。它把三件事装进一个体系：人怎么看（一个驾驶舱，三种工作模式，看到谁在干什么、卡在哪、证据在哪）；AI 怎么干（一个有编制、有权限、有任务、有审计的 AI 团队）；项目知识怎么长（一个生成器，对任意代码仓库生成项目专属开发技能）。

三个断言贯穿全部设计：

1. **证据先于声明**：说「做完了」必须给提交号＋任务卡号；门禁、评审、发布都要有可反查锚。
2. **未配置不等于已治理**：inactive／partial／unavailable 如实标注，不装绿。
3. **只迁不删、只补不覆盖**：能力在归属面有正身才退役；台账只增不改。

五个数字先给结论：编制 15 人／30 账号／42 智能体；产品面累计 148 条用户决策；全流程推演 22 轮（run22 已收官、六闸全过）；全量测试 6,336（滚动口径，随总账随批更新）；能力层 56 门禁。

### 0.2 冲突裁决顺序

需求基线（14R＋8N，已冻结，§1.4）＞ 本文 ＞ 专题 spec ＞ 历史设计稿；代码、测试与机械守门是事实终裁。数字冲突以参考文献中的《数字总账》为准。

## 1、理念：定位与要解决的问题

### 1.1 一句话与三句话

**一句话**：把人、AI 团队、项目知识装进同一个驾驶舱，让 AI 团队按编制、按证据、按门禁交付软件。

**体系**：SwarmStudio 由五个组件构成分布式交付体系——SwarmStudio（产品面，驾驶舱）、Matrix（通信基座，消息即凭证）、hermes agent（运行面，服务端单网关多路复用）、Ycode（编码引擎，zcode 分叉内置 computer-use，IDE 工作区本机执行底座）、swarm-yuan（能力层，生成项目专属技能）。四条主线贯穿：分布式需求分析（需求冻结、G1 上锁）、研发协作（看板派活、催办、并行、RACI）、实施交付（IDE 编码、长程可信执行、多机舰队）、测试验证（G4 独立测试、评测岛、G5 发布准出）。组件分工详见 §3.2。

**三句话**：

1. 产品面让「现状」一眼可读：人不再在聊天框、终端、看板之间来回找。
2. 运行面让「AI 干活」可编制、可授权、可追责：agent 是有岗位、有权限边界、有在途任务、有审计记录的团队成员。
3. 能力层让「项目知识」变成写代码前必须通过的约束：组件、依赖、配方、门禁都由生成器产出，不靠人记、不靠 AI 猜。

### 1.2 解决的三类问题

| 问题 | 表现 | 产品的解法 |
|---|---|---|
| 人找不到东西 | 群聊、看板、终端、文档各说各话；同一任务五处呈现 | 三模式驾驶舱＋唯一看板＋审批收件箱＋全站检索 |
| 推演与日常互相污染 | 模拟环境的消息/任务/配置渗进真实工作 | 日常与推演共享能力、不共享导航与写入口；两套数据隔离 |
| 完成声明不可信 | 说做完了但找不到证据；报告漂亮但数字对不上 | 双凭证（提交号+卡号）、人工闸、证据库、机械审计 |

### 1.3 用户是谁

第一用户是**主管（总指挥）**，不是 AI 工作者。AI 工作者的「界面」是 Matrix 消息与看板 API；产品界面是给人监督与决策用的。典型使用者：主管（看全景/审批/拍板）、业务分析与产品（需求冻结/排期/验收标准）、架构与研发（看任务/看分支/进 IDE 编码）、测试/安全/运维/审计（独立测试/安全检查/发布与复盘/合规取证）。

### 1.4 需求基线（已冻结）

产品需求 14 条功能（14R）＋8 条非功能（8N）已冻结，是冲突裁决的最高优先。变更走冻结机制：新需求进 backlog 不改基线，冻结解冻须主管书面确认。14R 覆盖：三模式驾驶舱、六阶段工作台、唯一看板、审批收件箱、全流程推演（26 步六闸）、IDE 工作区、AI 团队编制与派活、技能供给、治理与审计、专题四岛（BPA/本体/评测/技能治理）、设置与权限、多机舰队、证据与台账、报告与复盘。8N 覆盖：性能（首载/页签）、可用性（说人话/无脚手架）、可审计（证据可反查）、安全（fail-closed/权限分层）、可回退、兼容（mac arm64/win x64）、可维护（单一事实源）、可演进（能力层只增不改）。基线全文见参考文献《SwarmStudio 完整设计（专题档案）》§2。

### 1.5 设计原则与验收

七条设计原则（D1-D7，§7.2 详）：模式隔离能力共享、证据先于声明、单一事实源、未配置不装已治理、执行失败即关闭、只增不改、真实素材优先。一条能力算「可用」，必须同时满足五条用户视角验收：看得见（归属页有入口）、点得通（真实数据真动作）、有证据（提交号+卡号可反查）、说得清（界面文案说人话）、可回退（改动可还原、不覆盖用户改动）。

## 2、产品：人用的界面

### 2.1 三种工作模式

| 模式 | 入口 | 用来做什么 |
|---|---|---|
| 日常工作台 | `/app` | 今天的活：看板、审批、沟通、阶段页、检索 |
| IDE 工作区 | `/app/ide` | 写代码与审查：任务、会话、文件、终端、变更、插件 |
| 全流程推演 | `/app/sim` | 演练一次完整交付：导演台、监督、运行监控、证据库 |

顶栏切换只换视图不换心智：跨模式跳转必须明确标注「在推演中查看／回日常处理」。阶段与侧栏有状态点交通灯（红=阻塞、黄=进行中、绿=完成）和待办徽标，一眼看出哪里需要人出手。

### 2.2 日常：六个阶段

| 阶段 | 人在这里做什么 |
|---|---|
| ①搭台 | 建组织、账号、团队、资产；配工作流、本体、技能、平台 |
| ②需求 | 收需求、冻结范围、分诊、排期 |
| ③设计 | 写系分与 spec、做方案评审、留评审记录 |
| ④开发 | 看看板、领任务、跟分支、查产物 |
| ⑤验收 | 跑测试、逐条 UAT、过发布门 |
| ⑥治理 | 评审治理、改进实验、度量检查、安全审计、问题单、文档 |

共 33 个单层页签。治理是「发生了什么、要处理什么」，设置是「改什么」，两面分工不重叠。

### 2.3 全流程推演

推演是把真实交付完整走一遍的场地，26 步、六道质量门：

| 门 | 人看到什么 |
|---|---|
| G1 需求冻结 | 验收标准、范围外清单、影响面、涉敏评估都齐了才开工 |
| G2 架构评审 | 设计五要素、爆炸半径、验证计划、备选方案都摆出来 |
| G3 编码门禁 | 有设计才编码；需求-代码-测试一一对应；测试记录随分支 |
| G4 独立测试 | 测试的人不是写码的人；缺陷报修验闭环；只认本轮证据 |
| G5 发布准出 | 七项证据、回滚方案、灰度节奏、人工闸 |
| G6 复盘 | 三段式复盘、行动项、问题单回写、经验入记忆库 |

推演产出：一份可审计报告＋证据库（截图、对话、操作、台账）。导演台可以建真实任务、3 秒刷新、批准或打回人工闸；启动与人工闸有真实通知。**run22 已收官**（10-21 10:01→10-22 05:32，约 19.5 小时）：六道门全部通过，发布门经真实打回后补齐，165 条问题单、58 条处置留痕。

### 2.4 IDE 工作区

一个任务导向的编码工作区，不是聊天页：双模式（编程/工作，按 codingAgentId 分流不另造运行时）、23 个页签（任务栏、会话、文件、终端、审查、插件、沟通=完整 Matrix 客户端等）、本机编码工具可直接拉起（zcode、DeepSeek Harness）、用量与上下文（token/成本/逐轮趋势/上下文构成/压缩事件）、电脑操作 CUA（默认关闭 fail-closed，凭据成对注入）。模型与思考档单一源为 ZCode 配置；用量账本只读本机会话库三张表，零新增埋点。

### 2.5 专题四岛

| 岛屿 | 用来做什么 |
|---|---|
| 流程架构 BPA | 流程定义、节点、执行视图；架构清单与 PCF 映射 |
| 本体 | 五要素建模、实例管理、词表；FIBO 金融本体 37 概念、12 官方域、4 个真实场景、逐条来源 |
| 评测 | 评测集、运行、红队、校准、处置链；失败样本回流；难度/角色分桶、同输入稳定性复测、行为信号（真实使用遥测当评测信号）、经营语言摘要（运行读数→决策者三句话） |
| 技能治理 | 技能目录、供给对账、舰队能力发现、使用读数 |

### 2.6 设置与权限

设置七域，覆盖账号、团队、模型、平台、通知、界面、集成。权限分层：超级管理员、领导层、普通成员；团队页有独立的负责人判定。组织的关键行（如 admin 权限）改动要双人会签才能生效；紧急通道必须带 [BREAK-GLASS] 标记并全程留痕。

## 3、设计：架构总览

### 3.1 三层结构

系统是一套三层结构：产品面只读运行面数据，运行面消费能力层产物，能力层不反向依赖。三层之间只有五条契约（§3.6），任何跨域功能必须落在其中一条上。

```
产品面（人看与操作，Vue+Electron 注入 hermes-studio）
   │ 只读：看板 / 审批 / 团队 / 运行态 / 证据
   ▼
运行面（hermes agent 进程 + Matrix + kanban）
   │ 消费：项目技能（约束、配方、门禁）
   ▼
能力层（swarm-yuan 生成的目标技能）
```

| 维度 | 产品面 | 运行面 | 能力层 |
|---|---|---|---|
| 代码位置 | `custom/{client,server}`＋`patches/`（注入 vendor 基线） | `vendor/hermes-agent`＋Matrix（运行时覆盖层 `runtime/`） | `skills/swarm-yuan/`（本体入仓）与安装态 |
| 状态存储 | 读模型＋少量本地配置 | kanban SQLite、Matrix 房间、证据 JSONL | 目标项目 `.swarm-yuan/`、技能目录、门禁账 |
| 变化速度 | 周 | 日 | 月 |

### 3.2 五组件

五基础组件：AIStudio（产品面，驾驶舱）、hermes agent（自改进运行时）、Matrix（协作基座，消息即凭证）、Ycode（编码引擎：zcode 分叉、内置 computer-use 插件，IDE 工作区的本机编码执行底座）、swarm-yuan（能力层，生成器造项目技能）。四个跨地域分布的组件经 Matrix 协议与 git 制品协同，覆盖分布式需求分析、研发协作、实施交付、测试验证四条主线（§1.1 体系）。

编码委托链（ACP，2026-10-26 现状）：执行者经 coding-delegate 技能以 `zcode-acp-server` stdio 桥调用编码引擎；驱动按四级序注入 `ZCODE_BIN`——显式环境变量 > 官方捆绑（在位时默认；coding-plan 端点对公开 main 基底 3.16.1 系客户端全量 500，修复仅在未发布的私有 3.16.3 线）> 分叉部署位 `~/.hermes/ycode/zcode.cjs`（`scripts/zcode-engine.mjs install-cli` 构建落位；upstream main 追平 3.16.2+ 后一行回切为默认）> 桥自兜底。委托日志记录 `engine_bin_source` 供审计；`--model`/`ZCODE_ACP_MODEL` 按任务指定会话模型。任务 workspace 即引擎会话项目根（dispatcher 注入 `HERMES_KANBAN_WORKSPACE`，驱动以 `--cwd` 传入 `session/new`）。技能装载根：引擎项目级直读 `.agents/skills` 与 `.zcode/skills`（官方与分叉均读，`skills list` 实测）；`.claude/skills` 仅分叉（补丁 009 兼容根）与 Claude Code 直读。项目技能（`<项目>-dev`）因此两条落法都成立——落 `.agents/skills` 项目级直读，或落 `.claude/skills` 再软链到用户级 `~/.zcode/skills`（core-chain 采用后者，官方引擎经用户级根可读）。

### 3.3 产品面六层

表现层（三模式壳）、页面层（六阶段 33 页签＋四岛）、读模型层（端点/适配器）、机制层（证据/门禁/审批/观测）、服务层（studio server 域）、注入层（对上游的定制改造层）。读模型不复制运行面数据；页面不建第二份任务表。

### 3.4 运行面架构

单网关多路复用 42 profile；账号与身份在 Matrix；任务真值在 kanban；证据在文件；协调靠房间消息；跨机靠 git 制品。per-agent node_modules 隔离依赖；gateway 按 profile 独立锁目录。

网关是消息与派发的唯一入口；其它用户的分布式 bot agent 互调也以本机网关为入口，走两条通道：peer api_server 协议（`hermes peer` 直连对端网关的 `/p/<profile>` 镜像面，凭据经 `HERMES_PEER_<NAME>_KEY`，跨源重定向剥凭证）与 Matrix 协议事件（投递单经 Matrix 落到成员本机 kanban）。产品面的统一身份聊天窗消费 peer 通道。产品面读运行面模型经 AgentBridge／hermes CLI 子进程／引擎 WS 桥多通道，只读不复制。

### 3.5 能力层架构

生成器（方法论库＋资产＋脚本）—生成→ 目标技能（六段目录，92 随发文件）。生成器侧厚、目标技能薄；分发面与生成器侧分离。

### 3.6 五条跨域契约

| # | 契约 | 上游→下游 | 违反后果 |
|---|---|---|---|
| 1 | 技能供给链 | 目标技能→profile/推演树 | 双库、覆盖用户改动 |
| 2 | 能力发现与委托 | 上报＋双清单→派发/执法 | 派给无权限、提权 |
| 3 | 任务与证据 | kanban＋证据→看板/审批/推演 | 幽灵任务、不可反查 |
| 4 | 治理与审批 | approvals/decisions/reviewgov/secaudit→⑥ | 无留痕、告警被淹 |
| 5 | 推演验证 | 图运行时＋26 步→导演/监督/证据 | 静默改道、闸键脱钩 |

### 3.7 边界判据与纪律

三条边界判据：写入口唯一（任务真值只在 kanban、技能只在能力层生成、UI 不建第二份任务表或技能库）；读模型不复制（产品面通过端点读运行面，不存影子数据）；不反向依赖（能力层不知道产品面，运行面不引用 UI 组件，产品面可换皮不动运行面）。五条贯穿纪律：证据先于声明；未配置不装已治理；单一事实源；执行面 fail-closed／读模型 fail-soft；只增不改。

## 4、实施（上）·运行面：AI 团队怎么被使用

### 4.1 团队与身份

| 项 | 数字 | 说明 |
|---|---|---|
| 编制 | 15 人 | 主管、业务分析、产品、架构、研发×4、测试×2、安全、运维、审计 |

| 看板 | 28 块 | 每人 2 块（主管不建板） |

每个智能体有岗位、能力边界与权限；任务责任以卡上的负责人为准，看板只是视图。

### 4.2 派活与执行

人把活派到某个人，卡进入他的看板，AI 助理认领并执行。并发上限 30；一轮里可按模块并行（系分 4 路、编码 6 路、测试+集成 3 路）。派活有里程碑（开发按节点报进度、测试首个用例就要提交、报告先出首片）；卡住会被催（先唤醒，再要验证账本，再按 1→2→3 重催，三次不交付建议换人）；完成后要交证据（提交号＋卡号）。

### 4.3 审批与人机边界

14 个人工介入点全部进审批收件箱，批准/打回留痕。推演里的模拟审批与真实审批是两条有意保留的通道，互为兜底。程序不能替人做决定：代做的人类动作要记代偿台账，净额单独呈现。

主动性按两轴裁决（2026-10-26 Qoder《Personal Agent 落地思考》吸收，proactivity 域）：横轴「谁定义问题」（L1 指令/L2 时间规则/L3 事件触发/L4 用户目标 Agent 算差距/L5 Agent 推断目标）×纵轴「做到哪一步」（告知/建议/起草待确认/可逆执行/不可逆对外执行）。L5 恒只告知（目标猜错全链跟错）；L4 无契约（目标未说清或无验收规则）上限起草，说清目标+验收规则才升仓放开且逐子任务受失败代价三要素（可撤回/影响谁/可验证）约束——授权跟着子任务走，不跟着目标走。长期目标配持续对齐台账：距上次人工确认超周期（默认 7 天）即压回起草，防「目标已错位还在用力推进」；hermes /goal 创建目标自动登记（补丁 696，completion contract=验收规则即升仓判据）。判定面 `/api/hermes/proactivity/{model,assess,alignment}`；执行面已接 enforce-gate 第四级策略源（HERMES_PROACTIVITY_ENFORCE=1 才执法、默认关；L4 无契约拦截可走审批桥——人核即「起草待确认」闭环，目标漂移拦截不可批单豁免）。

### 4.4 能力装配四层

|---|---|---|

### 4.5 治理与审计

## 5、实施（下）·能力层：项目知识怎么长

### 5.1 它给用户什么

## 6、使用：怎么跑起来、怎么走

### 6.1 五分钟跑起来

日常验证与使用走浏览器 web 版，不做安装包。四步：`npm run inject` 注入；进 `vendor/hermes-studio` 装 `npm install --no-audit --no-fund --ignore-scripts` 并 `mkdir -p dist`；回仓根起 `npm run serve`（后端 8647）；`npm run dev`（前端 8649）。浏览器开 `http://localhost:8649`；首次空库引导须后端显式 `HERMES_WEB_UI_DEV_BOOTSTRAP=1`（出厂默认口令已移除）。完整步骤、角色旅程与排障见《使用指南》（`docs/USAGE.md`）。

### 6.2 三种走法

日常工作台（`/app`）按六阶段侧栏走：看板派活、审批收件箱处理 14 个人工介入点、统一身份聊天窗与全部 AI 身份会话、全站检索五类对象。IDE 工作区（`/app/ide`）从任务栏领卡进编码，编程与工作双模式，用量与上下文零新增埋点。全流程推演（`/app/sim`）在导演台建真实任务、过六道门，最终报告为该轮 run 目录 `evidence/final-report.html` 独立 HTML 产物。

### 6.3 改动与重启

改 `custom/client/` 通常无需重启（vite 热更新）；改服务端或 B 类 patch 后先 `npm run clean && npm run inject` 再重启后端；改 vite 配置才重启前端。桌面端同版本号覆盖更新有缓存陷阱（`~/.hermes-web-ui/webui/<version>/` 副本），发版须递增版本号。
