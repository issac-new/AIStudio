## 0、怎么读

### 0.1 一页纸

SwarmStudio 是一套让「人指挥 AI 团队交付软件」的工作系统。它把三件事装进一个体系：人怎么看（一个驾驶舱，三种工作模式，看到谁在干什么、卡在哪、证据在哪）；AI 怎么干（一个有编制、有权限、有任务、有审计的 AI 团队）；项目知识怎么长（一个生成器，对任意代码仓库生成项目专属开发技能）。

三个断言贯穿全部设计：

1. **证据先于声明**：说「做完了」必须给提交号＋任务卡号；门禁、评审、发布都要有可反查锚。
2. **未配置不等于已治理**：inactive／partial／unavailable 如实标注，不装绿。
3. **只迁不删、只补不覆盖**：能力在归属面有正身才退役；台账只增不改。

五个数字先给结论：编制 15 人／30 账号／42 智能体；产品面累计 148 条用户决策；全流程推演 22 轮（run22 已收官、六闸全过）；全量测试 5,906；能力层 56 门禁。

### 0.2 冲突裁决顺序

需求基线（14R＋8N，已冻结，§1.4）＞ 本文 ＞ 专题 spec ＞ 历史设计稿；代码、测试与机械守门是事实终裁。数字冲突以参考文献中的《数字总账》为准。

### 0.3 三条阅读路径

- 想用/评估：§1 定位 → §3 产品面 → §7 状态 → §8 缺口。
- 改架构：§2 架构 → §4 运行面 → §5 能力层。
- 查来路：§6 治理与历史 → 参考文献中的档案与索引。

## 1、定位与理念

### 1.1 一句话与三句话

**一句话**：把人、AI 团队、项目知识装进同一个驾驶舱，让 AI 团队按编制、按证据、按门禁交付软件。

**三句话**：

1. 产品面让「现状」一眼可读：人不再在聊天框、终端、看板之间来回找。
2. 运行面让「AI 干活」可编制、可授权、可追责：agent 是有岗位、有权限边界、有在途任务、有审计记录的团队成员。
3. 能力层让「项目知识」变成写代码前必须通过的约束：组件、依赖、配方、门禁都由生成器产出，不靠人记、不靠 AI 猜。

### 1.2 解决的三类问题

| 问题 | 表现 | 产品的解法 |
|---|---|---|
| 人找不到东西 | 群聊、看板、终端、文档各说各话；同一任务五处呈现 | 三模式驾驶舱＋唯一看板＋审批收件箱＋全站检索 |
| 推演与日常互相污染 | 模拟环境的消息/任务/配置渗进真实工作 | 日常与推演共享能力、不共享导航与写入口；两套数据隔离 |
| 完成声明不可信 | 说做完了但找不到证据；报告漂亮但数字对不上 | 双凭证（提交号+卡号）、人工闸、证据库、机械审计 |

### 1.3 用户是谁

第一用户是**主管（总指挥）**，不是 AI 工作者。AI 工作者的「界面」是 Matrix 消息与看板 API；产品界面是给人监督与决策用的。典型使用者：主管（看全景/审批/拍板）、业务分析与产品（需求冻结/排期/验收标准）、架构与研发（看任务/看分支/进 IDE 编码）、测试/安全/运维/审计（独立测试/安全检查/发布与复盘/合规取证）。

### 1.4 需求基线（已冻结）

产品需求 14 条功能（14R）＋8 条非功能（8N）已冻结，是冲突裁决的最高优先。变更走冻结机制：新需求进 backlog 不改基线，冻结解冻须主管书面确认。14R 覆盖：三模式驾驶舱、六阶段工作台、唯一看板、审批收件箱、全流程推演（26 步六闸）、IDE 工作区、AI 团队编制与派活、技能供给、治理与审计、专题四岛（BPA/本体/评测/技能治理）、设置与权限、多机舰队、证据与台账、报告与复盘。8N 覆盖：性能（首载/页签）、可用性（说人话/无脚手架）、可审计（证据可反查）、安全（fail-closed/权限分层）、可回退、兼容（mac arm64/win x64）、可维护（单一事实源）、可演进（能力层只增不改）。基线全文见参考文献《SwarmStudio 完整设计（专题档案）》§2。

### 1.5 设计原则与验收

七条设计原则（D1-D7，§6.2 详）：模式隔离能力共享、证据先于声明、单一事实源、未配置不装已治理、执行失败即关闭、只增不改、真实素材优先。一条能力算「可用」，必须同时满足五条用户视角验收：看得见（归属页有入口）、点得通（真实数据真动作）、有证据（提交号+卡号可反查）、说得清（界面文案说人话）、可回退（改动可还原、不覆盖用户改动）。

## 2、架构总览

### 2.1 三层结构

系统是一套三层结构：产品面只读运行面数据，运行面消费能力层产物，能力层不反向依赖。三层之间只有五条契约（§2.6），任何跨域功能必须落在其中一条上。

```
产品面（人看与操作，Vue+Electron 注入 hermes-studio）
   │ 只读：看板 / 审批 / 团队 / 运行态 / 证据
   ▼
运行面（hermes agent 进程 + Matrix + kanban）
   │ 消费：项目技能（约束、配方、门禁）
   ▼
能力层（swarm-yuan 生成的目标技能）
```

| 维度 | 产品面 | 运行面 | 能力层 |
|---|---|---|---|
| 代码位置 | `overlay/custom/{client,server}`＋定制层 | `upstream/hermes-agent`＋Matrix | `~/lab/Swarm-yuan` 与安装态 |
| 状态存储 | 读模型＋少量本地配置 | kanban SQLite、Matrix 房间、证据 JSONL | 目标项目 `.swarm-yuan/`、技能目录、门禁账 |
| 变化速度 | 周 | 日 | 月 |

### 2.2 四组件

四基础组件：SwarmStudio（产品面）、hermes agent（自改进运行时）、Matrix（协作基座，消息即凭证）、swarm-yuan（能力层，生成器造项目技能）。

### 2.3 产品面六层

表现层（三模式壳）、页面层（六阶段 33 页签＋四岛）、读模型层（端点/适配器）、机制层（证据/门禁/审批/观测）、服务层（studio server 域）、注入层（对上游的定制改造层）。读模型不复制运行面数据；页面不建第二份任务表。

### 2.4 运行面架构

单网关多路复用 42 profile；账号与身份在 Matrix；任务真值在 kanban；证据在文件；协调靠房间消息；跨机靠 git 制品。per-agent node_modules 隔离依赖；gateway 按 profile 独立锁目录。

### 2.5 能力层架构

生成器（方法论库＋资产＋脚本）—生成→ 目标技能（六段目录，92 随发文件）。生成器侧厚、目标技能薄；分发面与生成器侧分离。

### 2.6 五条跨域契约

| # | 契约 | 上游→下游 | 违反后果 |
|---|---|---|---|
| 1 | 技能供给链 | 目标技能→profile/推演树 | 双库、覆盖用户改动 |
| 2 | 能力发现与委托 | 上报＋双清单→派发/执法 | 派给无权限、提权 |
| 3 | 任务与证据 | kanban＋证据→看板/审批/推演 | 幽灵任务、不可反查 |
| 4 | 治理与审批 | approvals/decisions/reviewgov/secaudit→⑥ | 无留痕、告警被淹 |
| 5 | 推演验证 | 图运行时＋26 步→导演/监督/证据 | 静默改道、闸键脱钩 |

### 2.7 边界判据与纪律

三条边界判据：写入口唯一（任务真值只在 kanban、技能只在能力层生成、UI 不建第二份任务表或技能库）；读模型不复制（产品面通过端点读运行面，不存影子数据）；不反向依赖（能力层不知道产品面，运行面不引用 UI 组件，产品面可换皮不动运行面）。五条贯穿纪律：证据先于声明；未配置不装已治理；单一事实源；执行面 fail-closed／读模型 fail-soft；只增不改。

## 3、产品面：人用的界面

### 3.1 三种工作模式

| 模式 | 入口 | 用来做什么 |
|---|---|---|
| 日常工作台 | `/app` | 今天的活：看板、审批、沟通、阶段页、检索 |
| IDE 工作区 | `/app/ide` | 写代码与审查：任务、会话、文件、终端、变更、插件 |
| 全流程推演 | `/app/sim` | 演练一次完整交付：导演台、监督、运行监控、证据库 |

顶栏切换只换视图不换心智：跨模式跳转必须明确标注「在推演中查看／回日常处理」。阶段与侧栏有状态点交通灯（红=阻塞、黄=进行中、绿=完成）和待办徽标，一眼看出哪里需要人出手。

### 3.2 日常：六个阶段

| 阶段 | 人在这里做什么 |
|---|---|
| ①搭台 | 建组织、账号、团队、资产；配工作流、本体、技能、平台 |
| ②需求 | 收需求、冻结范围、分诊、排期 |
| ③设计 | 写系分与 spec、做方案评审、留评审记录 |
| ④开发 | 看看板、领任务、跟分支、查产物 |
| ⑤验收 | 跑测试、逐条 UAT、过发布门 |
| ⑥治理 | 评审治理、改进实验、度量检查、安全审计、问题单、文档 |

共 33 个单层页签。治理是「发生了什么、要处理什么」，设置是「改什么」，两面分工不重叠。

### 3.3 全流程推演

推演是把真实交付完整走一遍的场地，26 步、六道质量门：

| 门 | 人看到什么 |
|---|---|
| G1 需求冻结 | 验收标准、范围外清单、影响面、涉敏评估都齐了才开工 |
| G2 架构评审 | 设计五要素、爆炸半径、验证计划、备选方案都摆出来 |
| G3 编码门禁 | 有设计才编码；需求-代码-测试一一对应；测试记录随分支 |
| G4 独立测试 | 测试的人不是写码的人；缺陷报修验闭环；只认本轮证据 |
| G5 发布准出 | 七项证据、回滚方案、灰度节奏、人工闸 |
| G6 复盘 | 三段式复盘、行动项、问题单回写、经验入记忆库 |

推演产出：一份可审计报告＋证据库（截图、对话、操作、台账）。导演台可以建真实任务、3 秒刷新、批准或打回人工闸；启动与人工闸有真实通知。**run22 已收官**（10-21 10:01→10-22 05:32，约 19.5 小时）：六道门全部通过，发布门经真实打回后补齐，165 条问题单、58 条处置留痕。

### 3.4 IDE 工作区

一个任务导向的编码工作区，不是聊天页：双模式（编程/工作，按 codingAgentId 分流不另造运行时）、23 个页签（任务栏、会话、文件、终端、审查、插件、沟通=完整 Matrix 客户端等）、本机编码工具可直接拉起（zcode、DeepSeek Harness）、用量与上下文（token/成本/逐轮趋势/上下文构成/压缩事件）、电脑操作 CUA（默认关闭 fail-closed，凭据成对注入）。模型与思考档单一源为 ZCode 配置；用量账本只读本机会话库三张表，零新增埋点。

### 3.5 专题四岛

| 岛屿 | 用来做什么 |
|---|---|
| 流程架构 BPA | 流程定义、节点、执行视图；架构清单与 PCF 映射 |
| 本体 | 五要素建模、实例管理、词表；FIBO 金融本体 37 概念、12 官方域、4 个真实场景、逐条来源 |
| 评测 | 评测集、运行、红队、校准、处置链；失败样本回流 |
| 技能治理 | 技能目录、供给对账、舰队能力发现、使用读数 |

### 3.6 设置与权限

设置七域，覆盖账号、团队、模型、平台、通知、界面、集成。权限分层：超级管理员、领导层、普通成员；团队页有独立的负责人判定。组织的关键行（如 admin 权限）改动要双人会签才能生效；紧急通道必须带 [BREAK-GLASS] 标记并全程留痕。

## 4、运行面：AI 团队怎么被使用

### 4.1 团队与身份

| 项 | 数字 | 说明 |
|---|---|---|
| 编制 | 15 人 | 主管、业务分析、产品、架构、研发×4、测试×2、安全、运维、审计 |
| 账号 | 30 个 | 每人一个人类账号＋一个 AI 助理账号 |
| 智能体 | 42 个 | 14 个调度器＋28 个执行 agent |
| 看板 | 28 块 | 每人 2 块（主管不建板） |

每个智能体有岗位、能力边界与权限；任务责任以卡上的负责人为准，看板只是视图。

### 4.2 派活与执行

人把活派到某个人，卡进入他的看板，AI 助理认领并执行。并发上限 30；一轮里可按模块并行（系分 4 路、编码 6 路、测试+集成 3 路）。派活有里程碑（开发按节点报进度、测试首个用例就要提交、报告先出首片）；卡住会被催（先唤醒，再要验证账本，再按 1→2→3 重催，三次不交付建议换人）；完成后要交证据（提交号＋卡号）。

### 4.3 审批与人机边界

14 个人工介入点全部进审批收件箱，批准/打回留痕。推演里的模拟审批与真实审批是两条有意保留的通道，互为兜底。程序不能替人做决定：代做的人类动作要记代偿台账，净额单独呈现。

### 4.4 能力装配四层

| 层 | 机制 | 单一源 |
|---|---|---|
| 委托 | 四维能力＋否定式合成只收窄 | org 注册表＋角色模板 |
| 身份裁决 | toolAllowlist ∧ 委托白名单；未登记不改变行为 | identities.json |
| 能力目录 | 每机上报 profile×角色×技能数 | capability-reports/`<machine>`.json |
| 技能供给 | manifest 补缺失；只增不改/干跑/回滚 | 中央 skill-provisioning.json |

策略引擎附加层：identity/sandbox/budget → policy → ladder/mode；strict 无命中拒；加载失败 deny；带 policyRuleId。

### 4.5 治理与审计

评审按风险分级，重要改动要人审、绑定具体提交。安全审计走六阶段（覆盖账本、对抗验证、三态结论、独立复核），审计面已扩到代码仓（密钥/依赖声明/危险 API）。工具调用可加策略：严格模式下未明确允许的一律拒绝；高风险命令可进 OS 级沙箱执行。巡检 31 个检测器，异常进治理面板不发群；含会话耗尽检测（长跑会话只应答不出活的识别与换会话建议）。线上失败可转回归样本（IDE 轨迹→评测岛复现，区分原证据复现与新证据修复）。完成态由框架判定：每条主张有独立三态审计（已复核/证据不足/有反证），且审计前后工作区清单一致才准入；不通过只降为未信任并累计伪造尝试。

### 4.6 多机舰队

Matrix 传协调、git 传制品、本机管执行；中央 bare 仓；每日 06:40 上报；48h 新鲜度；三实例共享 1.4G 运行时；进度联邦 60 秒心跳。

### 4.7 编排与数据面

图→卡→spawn；派发安全三条款沉常量；里程碑契约；NUDGE 1→2→3→换档案；持续流水线四持续；宽度=工位数，testpass 分片幂等聚合。kanban SQLite（task_links DAG、CAS 认领）；approvals＋pending-summary；Matrix 注册房；graph runs/specs＋journal＋evidence；skillgov provision；harness/tool-policies/secaudit。代偿台账 TSV＋清偿门（开跑前 resolve/waive，净额闸查 actor 非 proxy）。

### 4.8 长程可信执行面

接口 `/api/harness/trust/*`：主张三态审计（verified/unverified/refuted，审计者≠主张人，file+sha256 双向比对）；完成态双准入（审计全 verified 且工作区清单 clean，否则 untrusted 并累加 forgeAttempts）；CSWI 完整性栅栏（小文件 sha256、大文件大小+修改时间、自报 clean 被框架观察覆盖）；原子断点（案件摘要+工作区摘要，恢复核对 consistent/diverged）；角色工具面 0<10<17 单调链。事件账为前向哈希链；⑥治理页签「长程可信」；本地 CLI 供推演脚本调用。

## 5、能力层：项目知识怎么长

### 5.1 它给用户什么

对任意代码仓库跑一次，产出一个**项目专属开发技能**。此后 AI 在这个项目里写代码，会先查组件、依赖和规矩，再动手。它不是技能商店：不发别人写好的通用技能，而是按你的仓库现场生成。

### 5.2 八环链与产出

八环链：①认知→②规范→③框架与业务→④组件库与拼装→⑤习惯→⑥装配→⑦日常→⑧成长。产出三份实物：组件库清单（组件、接口、数据三类，每项带路径与约束）、关系边集（谁依赖谁、映射关系、语义关系）、配方（业务功能清单＋高频任务的拼装步骤）。

### 5.3 目标技能与九节点
