# 并行调度与编制饱和度——多轮未根治欠账的立项（run24 实据，用户质询「为什么不饱和多轮推演全都没根治」）

日期：2026-11-01 ｜ 类型：feat 立项（驱动调度模型+验收指标）｜ 状态：implemented（2026-11-02 落地：early-start 预备键＋依赖看护＋利用率报告行＋审计查 17；driver 与监督器内环双接线）

## 1. 历轮未根治的归因（如实）
1. 复盘定性错误：agent 静止被定性「异常」（修检测+催办族：15min 监督/空转催办/纪律 85-89/722），未把「不饱和」定性为常态设计缺口（无并行调度层）。
2. 代偿豁免欠账：值守人肉压饱和记 nudge 类被「监督器设计动作」豁免清偿——根治债从未进清偿门。
3. 利用率非验收指标：报告无编制利用率维度，不饱和不扣分。

## 2. run24 实据
G5 熔断等待 4.5h，15 编制平均活跃 3-4 人（利用率 ~25%）；尾段三件预备（UAT 材料矩阵/发布件骨架/复盘材料）可并行前置但无人派，值守人肉发 9+ 次 DM/预备令补位；mei 前端支未合致 fei 改判阻塞 100min（跨域依赖无调度看护）。

## 3. 设计（三件）
1. **early-start 预备步**（驱动）：方案 §2.4 步条中的材料准备面（UAT 证据矩阵、发布件骨架、复盘度量预收集）从正式步剥离为预备键（`prep_uat`/`prep_release`/`prep_retro`），驱动在**前一闸等待期自动派发**（G5 等待→派步 21/22/24 预备），正式步只做判定与定稿。判据=闸等待中+预备键未落。
2. **跨域依赖看护**（驱动）：lead 合并类依赖（fix 分支待合→解锁下游）进等待循环的检查面：等待 A 期间发现可合分支→自动 DM 催 lead（复用 DM 直达通道——批 2 的驱动 DM 后备件）。
3. **编制利用率入报告**（验收指标）：报告增「编制利用率」行（分母=编制×run 时长，分子=各 agent 回合时长），<50% 记问题单（saturation-low）进清偿门——让欠账显形。

## 4. 决策
- 调度器不做成通用 DAG 引擎：26 步依赖已静态已知，预备键+闸等待钩子够用（最小切口）。
- early-start 材料面不产正式判定（UAT 判词/发布批准仍在正式步）——预备与判定分离，不抢闸。
- 代码批与批 2（DM 后备/复测预启动/origin 立法）同窗落地（驱动面改动统一收官后换版）。

## 5. 验证（代码批时）
驱动侧：闸等待期预备键自动派发单测＋利用率行渲染；run25 首验=G5 等待期无「全编制闲置」形态、报告利用率>50%。
