# LLM 通道韧性——overlay 侧终态（推演 cc-switch 塌方收口）

- 日期：2026-09-23（aipaydev 推演收口轮，环境类缺口收口）
- 范围：**overlay/sim 自家域**。通道路由、冷却摘除、模型回退链都在 hermes-agent / cc-switch 上游，本文不做上游改造——overlay 侧以编排层可见性与 fail-fast 收口。
- 关联：推演报告 §四「环境类」、ISSUES-LOG cc-switch 双通道 403/401 事件

## 一、触发证据（为什么值得收口）

| 时刻 | 事件 | 影响 |
|---|---|---|
| 18:22 | chen 实例 cc-switch 主通道 403（额度窗打光） | 该 agent 停摆 |
| 20:58 | chen 再撞额度窗 403；备份 MGLM 令牌 401 | 双通道齐断，诊断只能翻 sqlite |
| 夜间 | cc-switch SRK 打光、MGLM 顶上恢复后 agent 未自动重叫 | 靠人工补发纠偏消息续上 |

根因（overlay 侧可承担的部分）：通道状态对编排层**不可见**——导演脚本不知道「现在双通道全断」，让 agent 回合静默卡死，事后才发现。

## 二、overlay/sim 侧终态（编排层可见性 + fail-fast）

不改通道本身（上游域），改**编排层对通道状态的感知**：

1. **通道状态采集**：`aipay-evidence.sh` 采集证据时把 cc-switch 代理日志/sqlite 的通道状态快照入台账（只读，不改通道行为）——事后能区分「模型问题」与「通道问题」。
2. **门禁前 fail-fast**：`aipay-scenario*.sh` 在关键门禁（如全实例就绪检查）前探测通道可用性，主备全断时**立即 fail-fast**（报「通道不可用」而非让推演卡死）。
3. **推演纪律**：推演前人工确认至少一条通道可用；双通道齐断时**暂停推演等恢复**，不靠 agent 硬扛（条款级，配合上述 fail-fast 强制执行）。

## 三、不做的事（边界声明）

- 不做通道路由/冷却/摘除/恢复重叫的实现——那是 hermes-agent / cc-switch 上游能力。推演环境可通过 cc-switch 既有配置（多 provider 配置）手工预置备份，但自动切换是上游的事。
- 不在 overlay 写模型调度代理。overlay 只在编排脚本层感知与裁决。

## 四、验收口径

- evidence 台账含通道状态快照（采集脚本落地后）。
- 人为掐断通道跑门禁前置检查：fail-fast 报「通道不可用」而非挂起。
- 本文即收口：推演侧「通道韧性」议题至此关闭，上游若落地自动切换再另行对接。
