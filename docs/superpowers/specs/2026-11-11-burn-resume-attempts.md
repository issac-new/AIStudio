# 2026-11-11 烧机续跑环：单发 rc 判定把「设计内 fail-续跑」误判机制死（burn2 实证）

> 来源：burn-20261111-021038（111 分钟 done 键 21）终判 fail，唯一 FAIL=G2 判词锚错配——而该路径是场景设计内的「fail 交监督器续跑重入复评（不计闸轮）」（aipay-scenario.sh:1202-1214，run27 两连熔断根治件注释明示）。烧机脚本单发执行驱动并以 rc=1 终判，把 agent 行为 hiccup（v0.23.1 arch 复评重派后 40 分钟未动）放大成机制失败。

## 变更

`simharness/mux/mx-burn-test.sh` 驱动调用改**重试环**：最多 3 次尝试；每试独立日志（`<RUN_ID>-driver-a<N>.log`）；任一试 rc=0 且目标键在位即停（后试跳过）；全部判读（rc/FAIL 行/目标键/收据）取**最后一试**日志，`--reasons` 前缀 `attempts=N;`；试间 sleep 30s。幂等依据=场景 state 键跳过（run28 监督器同款断点续跑语义；监督器对真跑同款续跑，烧机与真跑语义对齐）。

## 决策记录

| # | 决策 | 备选与否决理由 |
|---|------|----------------|
| D1 | 重试环在烧机脚本而非场景脚本 | 场景的 fail-续跑语义是产品正身（监督器消费）；烧机是单发试验场，对齐监督器语义是烧机的职责 |
| D2 | 收据取最后一试而非全部日志并集 | 收据绑 driver_log_sha256 单文件；最后一试 rc=0+零 FAIL 行=终态健康的充分判据；前试 FAIL 属已恢复过程，并集会把可恢复故障永久计罪 |
| D3 | 上限 3 试 | 与监督器重启风暴阈值（连续 3 次失败记单）同构；防无限重试掩盖真机制死 |
| D4 | 不放宽判词锚纪律 | 锚守卫是防伪判据（评审人读旧稿判错轮），只给更多时间与续跑机会，不降标准 |
