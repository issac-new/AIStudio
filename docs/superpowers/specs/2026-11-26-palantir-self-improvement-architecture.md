# Palantir 自我改进架构吸收：结构化归因、审阅结论、失败根因与逐案例对比（2026-11-26）

> 状态：已实施；实测结果见「验证」。
> 来源：公众号文章《Palantir实现自我改进的核心产品架构》（本体智能）；另逐句核对四篇 Palantir 官方文档——AIP Evolve 概览（`palantir.com/docs/foundry/aip-evolve/overview`）、2026 年 8 月发布公告（`/docs/foundry/announcements/2026-08`）、AIP Evals「分析运行结果」与概览（`/docs/foundry/aip-evals/analyze-run-results`、`/overview`）、AIP Logic 常见问题（`/docs/foundry/logic/faq`）。
> 采集精度：文章全文加官方原文。文章里的示例数字与官方概览页一致（10 个测试案例、最多 5 轮、GPT-4o 换成 GPT-5.4 Mini、两处提示词加约束、单次调用平均计算成本从 204.6 秒降到 72.4 秒）。官方公告的能力清单比文章多出四项（可接受的输出偏离度、Agent 活动图、置信评估、对象时间线），本规格按官方清单对账。

## 变更

### 调研结论（三个决定性发现）

1. **负面结果不问原因就归到改进方案头上，下一轮会走错方向。** 文章的原话：一笔订单延期可能与 Agent 建议无关，而是由突发停电或供应商违约导致；把所有负面结果直接归因于 Agent，后续优化就可能产生错误方向。仓内现状：回滚与驳回各只有一段自由文本原因；起草器把这两类提案一律列进「禁止换皮重提」的失败假设（`custom/server/harness/workbench/service.ts:478-481`、`:543`；`loop-advice-evolution.ts:31-85`）。一个因外部故障被回滚的假设，在起草器眼里与被评测证伪的假设没有区别。
2. **审阅人看不到「这次结论有多可信、受什么限制」。** 官方公告写明提案视图要包含验证结果、输出对比、支撑证据与置信评估。仓内现状：晋级报告已经算出三项披露——字典序分层、证据角色、选择偏差（`loop-report.ts:480-505`），但全仓没有消费方，面板的门禁类型只声明通过、阻断、告警三项（`custom/client/governance/api/workbench.ts:395`）。基线与候选是否在同一份试卷、同一组裁判下评测，晋级门不检查。逐题层面只保存回归集的失败题号（`types.ts:99-107`），没有「基线没过、候选过了」与反面的对照。
3. **评测域已有的失败根因分类没有进改进工作台。** 官方常见问题页：结果分析器把失败案例聚到根因类别、给出代表性样例、提出有针对性的提示词修改。仓内现状：`custom/server/eval/badcase-distill.ts:90-131` 有确定性的六类根因分类，工作台只数失败条数，起草器的提示词不读这些（`service.ts:530-555`）。

另有一项需要用户裁决、本批不改：官方示例的主用例是「质量不降、成本下降 65%」。仓内晋级规则只认「增益超过噪声带」，质量持平而成本下降的提案会被 `gain_within_noise` 拦下（`loop-report.ts:148-159`）；延迟与步数的读数算出来以后，晋级门和面板都不读。放宽这条规则等于新增判定规则，见「决策记录」D9。

### 交付

服务端（目录 `custom/server/harness/workbench/`）：

- `types.ts`：`DecisionCause`（提案自身／外部环境／判不清）；`ApprovalRecord.cause` 与 `RollbackRecord.cause`（可选）；`ProbeMetrics.failureClusters`；`Probe.caseFlips`；`Proposal.heldoutBaselinePassRate`；`PromotionGateReport.assessment` 与相关类型；`SuccessorStep.rollbackCause`。
- `service.ts`、`controller.ts`：驳回与回滚接口接受原因归属，非法取值返回 400；未传按空值保存。起草器把被否决的假设按归属分开列：提案自身的进禁止清单；外部环境的单列并写明假设未被证伪；判不清的单列并提示先确认原因。起草器另收到同面近期探测的失败根因分布（只有类别与数量）。起草提示词增加同面失败根因一段。
- `loop-advice-evolution.ts`：进化全史里被拒与回滚的条目带原因归属。
- `loop-joint-evidence.ts`：抽出两份评估条件指纹的逐字段比较，相邻后继与基线候选两处共用；后继轨迹的每个版本带回滚原因归属。
- `loop-review.ts`（新）：纯函数。审阅结论由固定规则推出四档——未知、不足、有限、充分；逐条列出支撑读数与限制。另算基线与候选的评估条件可比性（相同／有变更／未知）。
- `loop-report.ts`：晋级报告带审阅结论；只披露，不参与通过与否的判定。
- `evidence.ts`：`failureClustersOf`——取评测运行里首样本未通过的题，逐题调用评测域的 `classifyRootCause`，按根因计数并留至多三个题号作样例。
- `service-shared.ts`：记录探测与绑定基线时附带失败根因；记录探测时附带逐题对错翻转（与基线运行逐题比首样本）。绑定留出读数的接口可选提交基线答案，算出留出基线通过率存到提案上；增益保留率与背离诊断的读取点改为探针级优先、其次提案级。
- `loop-advice-tier.ts`：验证层级同时看探针级与提案级的留出读数（此前只看探针级，而生产只在提案级写，留出这一层级从未出现过）。
- `controller.ts`：创建提案时转发 `editClass`（此前面板上手工选的类别被丢弃）。

客户端：`custom/client/governance/api/workbench.ts` 的类型；`HarnessImprovePanel.vue` 增加审阅结论一块（置信档、评估条件可比性、限制、支撑读数、字典序分层、参与候选筛选的证据清单；选择偏差的结论在它构成限制或支撑读数时出现）；探测表每个候选下方一行逐题对比与失败根因；驳回与回滚表单带原因归属选择；后继轨迹表带回滚原因归属。i18n 中英成对。

走查面 `governance-rsi-walkthrough`（`scripts/regression/governance-rsi-walkthrough.mjs`）：补本批新界面的断言与演练 D（回滚带原因归属）。同时修复一处存量缺陷：亮色条件下的对比度检查自上一批起漏传台账参数，选择器零匹配却不报错；现已补上参数，并加一条自检——选择器一个元素都没匹配到即判未过。回归矩阵的说明补上运行方式：系统 Chrome 无法启动的宿主可改用 Edge。

机制预算：零增量（不加门、脚本、账本、npm 脚本），`config/mechanism-budget.json` 的 `changes[]` 增一条并附退役条件。

### 验收判据

验收方式：下面各条逐条由测试锁定，命令与结果见「验证」一节。

- 回滚与驳回带原因归属保存；非法取值返回 400；未传时字段为空，行为与改动前一致。
- 起草提示词里，提案自身的被否决假设在禁止清单内；外部环境的不在禁止清单内，另成一段并写明假设未被证伪；判不清的另成一段。没有归属的被否决提案仍在禁止清单内（存量数据行为不变）。
- 起草提示词含同面失败根因的类别与数量，不含题号；同面没有已采集的失败根因时不出这一段。
- 失败根因：首样本未通过的题逐题归类并计数；判定端离线导致无法归类的题计入「无法判定」；运行或试卷取不到时返回空值（未采集），没有失败题时返回空数组。
- 逐题对比：基线与候选都有首样本的题才比较；修好、弄坏、都过、都不过四类计数之和等于参与比较的题数；基线运行取不到时为空值。
- 审阅结论四档各有用例：选中候选没有已记录探测时是未知；评估条件有变更、质量判定未知、采样不足三者任一出现是不足；噪声未标定、未绑定留出、评估条件无法比较、批准人与提出人是同一人、多候选择优有偏差风险——这些限制任一出现是有限；没有任何限制是充分。
- 基线与候选的评估条件：试卷指纹或裁判指纹任一变更即记有变更并逐字段列出；任一侧缺指纹记未知，不按相同处理。
- 留出基线通过率可随留出绑定一起提交；提交后增益保留率与「代理涨、真实不涨」诊断有读数；只提交候选答案时行为与改动前一致。
- 验证层级：提案级有留出读数时判到留出这一层级；探针级与提案级都没有时不判。
- 创建提案时带上合法的 `editClass` 会保存；不带或取值非法时为空。
- 晋级报告的 `ok`、`blockers`、`warnings` 在加入审阅结论前后逐项相同（变异探针：把审阅结论接到判定上，对应用例判红）。
- 面板：审阅结论一块在旧数据（没有 `assessment` 字段）时不渲染；逐题对比行在没有读数时不渲染；驳回与回滚表单默认选中「提案自身」。
- 回滚带原因归属走真实接口：非法取值返回 400 且提案仍是已晋级；外部环境的原因返回 200 并保存，在后继轨迹里读出。
- 走查面的对比度检查在亮色条件下真正执行：选择器一个元素都没匹配到判未过；新增的审阅结论标签、限制行与标题，文字对底色的对比度不低于 4.5。

## 验证

实测结果（工作树 `feat/palantir-self-improve`；调研与首轮实测基于 main 16e9155b7，分支随后变基两次：先到 6f2c3b7ed，再到 93b243271，每次都重跑合并档回归）。

- `custom/server/harness/workbench/__tests__/loop-review.test.ts`（25 例，新增）：置信档四档各有用例——没有已记录探测是未知；质量判定未知、采样少于 3 次、评估条件不同各自判不足；噪声未标定、未绑定留出、评估条件无法比较、批准人与提出人相同、多候选择优有偏差风险、缺算力归因与反事实与执行证迹、缺耗时读数各自判有限；证据齐全且批准人与提出人不同判充分；没有增益时不要求算力归因与反事实；限制里不重复已经是阻断项的事实。评估条件可比性五例（相同、试卷指纹变更、裁判变更、试卷编号不同、缺指纹记未知）。审阅结论不参与通过与否的判定三例。原因归属的两处消费面两例。
