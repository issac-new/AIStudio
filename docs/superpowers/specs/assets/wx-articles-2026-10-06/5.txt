1 设计总纲
 
1.1 一句话定位
本方案用 Jev 决策模型作为围栏的**快判内核**：把每一次请求的安全判断，从「让大模型生成一段解释性文字」转变为「让判别式模型直接返回类型化的风险概率与分类」。围栏不再依赖对自由文本输出的解析，而是拿到结构化、可校准的概率值，直接驱动代码分支做放行/改写/阻断。
1.2 为什么是 Jev（技术依据）
Jev 由 TypeSafe AI 于 2026 年 9 月 15 日发布，官方定位为「首个 System One 模型」，命名取自卡尼曼《思考，快与慢》中的系统一（快速直觉）与系统二（慢速推理）。其关键特性与围栏需求高度契合：
Jev 特性
工程含义
对围栏的价值

非自回归、单次 forward
跳过逐 token 生成，KV-Cache 广播 + 并发批量评估
潜时可进 70–500ms，可放进流式链路

三类原语 Choice/Score/Noul
分类≤255项、打分2–10级、yes-no概率

1.3 必须正视的能力边界（设计约束）
官方 jaggedness 页与社区反馈明确：Jev 的「不会幻觉」仅指**不会产出非法类型**，它仍可能产出**完全错误的合法值**。落地必须回避其短板：
• 不擅长计数、算术、日期比较 → 这类判断一律交给确定性规则/代码执行，Jev 只做语义判断。
• 大噪声 state 下精度下降 → 输入前必须做归一化、去噪、裁剪，控制 state 质量。
• 不支持文本生成、不解释理由 → 「reason」字段由规则命中项 + 分类标签拼装，不由 Jev 生成。
• out-of-distribution 行为与 LLM 不同 → 上线前必须用自有数据集做专项评测，不能直接套用 LLM 经验。
这四条约束直接决定了第 3 节的「规则前置层」和「灰区升级」设计——它们是围栏可靠性的必要组成，而非可选项。

3.2.3 置信度门控与灰区
Jev 的价值之一是给出**校准概率**。围栏据此设计三段式门控：
p_attack = answers['is_prompt_attack'].noul
 
if p_attack >= TAU_HIGH (默认 0.85): # 高置信攻击
 → 直接 BLOCK（不调用 S2，省延迟）
elif p_attack <= TAU_LOW (默认 0.25): # 高置信安全
 → 直接 PASS（快路径闭环）
else: # 灰区 [TAU_LOW, TAU_HIGH)
 → 升级 S2 LLM 复核 → 融合裁决

阈值不写死，按租户/业务线配置，并进入数据飞轮持续调优。门控的本质是：**用 Jev 的置信度决定「值不值得花一次慢判」**。
3.3 S2 · 系统二 LLM 慢判层
仅承接灰区与强制复核流量，避免拖垮整体延迟。触发条件（任一）：
• Jev 概率落入灰区 [τ_low, τ_high)
• harm_severity ≥ 7 或命中 A5/A6 等高危类别
• 策略强制复核（如文件导出、跨域操作、高危工具调用）
• 工具调用链中存在未登记工具或权限提升
S2 输出结构化复核意见，回注给 L4 融合层，与 S1 结果共同裁决。S2 超时则回落 S1 结果并触发告警。
3.4 决策融合与四态输出
融合公式采用加权模型，权重可按租户策略覆盖：
Risk = w_r * R_rule + w_s * S_attack + w_h * (severity/10)
 + w_d * D_sensitivity + w_t * T_tool_risk
 
# 默认权重: w_r=0.15, w_s=0.35, w_h=0.25, w_d=0.15, w_t=0.10
# 可叠加策略: 业务线 / 数据等级 / 时段 / 用户角色

4.3 构建与标注流程
• 来源：红队对抗生成 + 人工构造 + 线上灰区采样（脱敏后）。
• 标注：双人独立标注 + 第三人仲裁；标注一致性 Kappa ≥ 0.8 才入库。
• 负例控制：良性集必须包含「形式像攻击但实际合法」的困难负例（如安全研究、渗透测试授权场景），防止误杀。
• 版本化：数据集按 `ds-YYYY.MM.N` 版本管理，每次评测锁定版本，避免结果不可复现。
• 脱敏：线上样本必须经过 PII 擦除与租户解耦后才可入训练集。

5 业务流设计
 
5.1 主流程：请求入站到裁决
① L1 接入 → 解析请求，绑定 tenant_id / user / session
② L2 规范化 → 归一化、去噪、裁剪至 ≤32K，生成缓存指纹
③ S0 规则 → 命中硬规则？ → 是：直接裁决（BLOCK/REWRITE）
 → 否：进入 S1
④ S1 Jev 快判 → 一次 forward，并发回答 4~6 个安全问句
 → p ≤ τ_low : PASS（快路径闭环）
 → p ≥ τ_high : BLOCK
 → 灰区 : 升级 ⑤
⑤ S2 LLM 复核 → 结构化复核意见回注
⑥ L4 融合 → Risk 加权 + 租户策略 → 四态裁决
⑦ L5/L6 输出 → 返回 Typed Decision，异步留痕 + SIEM

5.2 出站流（响应侧围栏）
输入安全不代表输出安全，需对称设计输出围栏：
• 对模型输出做流式分段检测：按句/段切分，逐段送入 Jev 判定 is_response_unsafe。
• 命中高危段立即中断流式输出并向用户返回兜底话术。
• 低置信段进入 S2 复核，不阻塞已放行片段的展示。
• 输出围栏与输入围栏共享同一套分类体系与阈值配置，保证一致。
5.3 工具调用流（Agent 场景）
面向 Agent/MCP 场景，围栏在**工具执行前**插入强制门控：

工具选择

tool_action 问句 + 工具白名单

参数构造
工具入参生成后
参数中的 PII/路径/命令注入

5.4 影子 AI 旁路流
对未纳管的 AI 使用（影子 AI），通过旁路镜像流量做检测：
• 网络层镜像 → 识别 AI 服务域名 → 送入围栏做只读判定。
• 只做检测与告警，不阻断，产出影子 AI 资产清单与风险画像。
• 识别的风险实体可回流至纳管流程，形成「发现—纳管—防护」闭环。

9.2 高可用与降级
• 多活部署：围栏无状态，水平扩展；判定结果可缓存。
• 降级策略：核心业务 fail-closed（失败即拒绝），一般业务 fail-open（失败放行+告警）。
• 限流熔断：按租户配额限流，S2 熔断后自动回落 S1 快路径。
• 灰度发布：新策略/新版本先 1% 流量，观察指标后逐步放量。

9.4 安全与合规
• 数据最小化：送入 Jev 的 state 仅保留判定必需字段，敏感字段先脱敏。
• 传输安全：全链路 mTLS，密钥集中托管。
• 审计：决策全字段留痕，保留期按合规要求配置（建议 ≥6 个月）。
• 合规对齐：设计可映射至 ISO/IEC 42001、NIST AI RMF 的控制项。
