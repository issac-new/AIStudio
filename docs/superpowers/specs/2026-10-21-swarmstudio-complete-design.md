## 0、怎么读这份文档

### 0.1 一页纸结论

SwarmStudio 用**模式隔离 + 机制约束**解决三类问题：人找不到东西、推演与日常互相污染、完成声明不可信。三条断言与兑现方式：

| 断言 | 兑现方式 | 复核入口 |
|---|---|---|
| 日常与推演共享能力，但不共享导航与写入口 | 三模式切换、`/app/sim*` 独立导航域、`useDailyStageProgress` 只读看板、`domain-split` 结构守门 | §3 / §5.5 |
| 一切「完成」都要有证据 | 双凭证（提交号＋卡号）、四类锚点、append-only 台账、hash 链证据 | §5.2 |
| 判断权不交给执行者 | 六道质量门、FAIL 唯一出口、人工介入留痕、执行层 fail-closed | §5.3 / §5.4 / §5.9 |

### 0.5 复盘结论（历史告诉我们的六件事）

1. **产品形态是走查驱动的收敛，不是一次设计出来的**：三中心（10-15/16）→ 旅程页＋六阶段（10-17）→ 左栏分组＋单层页签（10-18）→ 三模式＋日常/推演拆分（10-20）。每次收敛都对应一次用户全量走查，而非架构偏好。
2. **需求分析补课是分水岭**：10-16 之前「先盘点归位、后补定位」，导致角色镜头层等推测性设计；需求冻结后，镜头层解体、容量双件与密钥台账补入。**需求锚是防功能漂移的唯一工具**。
3. **日常/推演分离是当前最重要的架构边界**：共享组件与数据契约，不共享导航与写入口；`domain-split` 已机械化。此前 33 个阶段页签中推演选择器、台账写入、run-state 派生进度造成的互相侵入，是最贵的一类返工。
4. **推演产品化的瓶颈不在展示层，在执行器**：证据库、监督面板、导演台已可用；真正未闭环的是「一键开轮」（Phase C）、导演 run 与 26 步 run-state 的详情归口、G5 真实审批状态机。
5. **上游吸收的有效形态是机制级吸收**：证据契约、投影是索引、三层 Review Gate、审批 scope、hash 链、自治阶梯等机制被产品化；功能照搬大多被否决。最大技术债是**双实现**——发现即开单进遗留项清算。
6. **治理边界是事故逼出来的**：拆闸立法源自 run20 G2 悬置 12 小时，代偿清偿门源自用户三次同句质疑，任务粒度拍板源自嘴炮三轮追问（§13.4、§8.5）。读懂纪律 57/65-67 为何存在，才能读懂这套治理。

## 1、产品定位与理念

### 1.1 一句话与三句话

**产品定义**：SwarmStudio 是 AI 研发组织的「飞行模拟器 + 驾驶舱」。推演是模拟器——用典型场景把全部功能串起来，让 AI 员工组织完整走一遍研发全流程；驾驶舱是人机协同工作台——人在这里看状态、做决策、留痕迹。

**三条理念**（用户 2026-10-16 立纲）：

| 理念 | 含义 | 设计落点 | 验收终问 |
|---|---|---|---|
| **智慧型组织** | 组织会学习、自我改进：经验进 hindsight，复盘行动项改变下一轮准入，缺陷根治后代偿退役 | hindsight 记忆、复盘→行动项、遗留项清算、度量检查自我加严、经验候选台账 | 这个功能让组织下一轮比这一轮更聪明了吗？ |
| **AI 驱动 ALL** | 一切执行由 AI 完成：需求分析、编码、测试、审计、关卡判读、缺陷工单、监督研判 | multi-agent loop-graph、AI 治理角色、harness 约束 AI | 这件事还有任何一步必须人做吗？若有，为什么不是人的决策点而是执行点？ |
| **human in/on the loop** | **in**＝14 个人工介入点，缺人则停；**on**＝驾驶位/监督面板/旅程条/影子观察，人可随时介入但非流程必经 | 人工介入请求、审批收件箱、监督面板、旅程页 | 人的每次出现都是决策（in）或监督（on），而不是执行吗？ |

**三句合一**：AI 驱动 ALL 是执行原则，human in/on the loop 是人的定位原则，智慧型组织是目标态。任何功能若三问全答不上来，就是无根功能——不立项。

### 1.2 用户与真实工作循环

**第一用户是主管（用户本人，总指挥）**，不是 AI 工作者。AI 工作者的「界面」是 Matrix 消息与看板 API；界面是给人监督与决策用的。这个判断不是推演出来的，而是从 21 轮真实推演（run1-21，run22 于 2026-10-21 起跑在途）里手工动作反推出来的：

- 每 20 分钟手动观察一窗；
- 手动查运行状态、翻日志定位异常；
- 人工放行关卡（run20 G2 悬置 12 小时）；
- 人工处置代偿与密钥；
- 每轮开跑手动过 prelaunch 十六项（现为 30 项）；
- 系统盘 96% 靠肉眼发现后手工清理。

**主管的完整循环**：开轮（过检）→ 周期观察（盯轮）→ 发现异常（定位）→ 介入决策（放行/打回/发指令）→ 收尾验收（对账报告）→ 复盘治理（处置问题单与代偿）。SwarmStudio 的存在理由＝把这个循环里的手工动作逐件产品化，同时不破坏诚实呈现。

**其他干系人**：AI 工作者（15 编制 agent，数据生产方）、AI 治理角色（闸口裁判/工单员/接棒员/监督器/哨兵）、运维（用户兼任）、外部观演与评测（弱需求，不驱动设计）。

### 1.3 四柱技术总纲

SwarmStudio 的核心＝**以本体论组织和管理，以 harness 约束，以 multi-agent 通过 Matrix 分布式消息做 loop-graph 协作，以 hindsight 管理 agent 长期记忆**。

| 柱 | 含义 | 既存正身 | 对设计的约束 |
|---|---|---|---|
| **本体论**（组织与管理） | 一切实体与关系按本体建模：需求单/任务卡/质量门/代偿/证据/报告都是本体实例 | `/app/ontology` 五要素建模 + JSON-LD/SHACL、glossary 词表、看板数据自动摄取 | 各中心的数据面统一挂本体层；新实体入本体注册；报告＝本体投影 |
| **harness**（约束） | 闸/纪律/门禁/预算/清算门——质量与问责的规则面 | 六道质量门 + QGate 门禁 + 执行纪律 + prelaunch 30 项 + 遗留项清算 | 治理面的全部签＝约束的可视化与操作面；判据可反查 |
| **multi-agent loop-graph**（协作执行） | gateway 多路复用 hermes agent teams，ACP→zcode 编码引擎，swarm-yuan 生成研发技能；协作拓扑＝技能内循环×群体外循环 | gateway `:8801`、ACP 链、swarm-yuan 生成器、loop 域、Matrix + synapse `:8008` | 工作台沟通面＝loop-graph 的消息层呈现；监督面板观察 loop-graph 运行 |
| **hindsight**（长期记忆） | agent 长期记忆管理：跨会话经验积累与受控注入 | hindsight `:8888`、分组记忆库、经验受控注入 | 记忆注入走治理门；记忆条目＝本体实例；监督/报告可引用记忆轨迹 |

**四柱合一**：产品的一切功能都是四柱的投影——组织看本体、执行看 loop-graph、约束看 harness、记忆看 hindsight。任何新功能先问「落在哪根柱子上」，再定模式与入口。

### 1.4 三件产品 → 三种模式

产品功能分三件（2026-10-15 重规划）：

| 产品件 | 含义 | 当前承载 |
|---|---|---|
| **驾驶舱** | 人机协同工作台：看板/沟通/审批/运行中心/IDE/账户 | 日常工作台模式 + IDE 工作区 |
| **推演引擎** | 全流程推演的执行与观测：场景编排、运行模式、代偿台账、证据采集、报告链、监督面 | 全流程推演模式 |
| **研发治理** | 质量与问责：六道质量门、问题单、遗留项清算、审计、复盘 | 日常⑥治理阶段 + 治理工作台深链 |

**落地形态是三模式**，不是三个并列的「中心」：

```
[日常工作台]  [IDE 工作区]  [全流程推演]     ← 顶栏工作视图切换
```

- **日常工作台**：会话串起来的看板任务、工作区、审批、沟通，按六阶段分类管理。
- **IDE 工作区**：编码/工作双模式的开发工作位，zcode 会话内核。
- **全流程推演**：典型场景串联全部功能，导演模拟全体人类员工协作走完全流程。

两者**互相检验**：日常检验推演结论是否落到真实任务，推演检验日常流程是否有效。共享技术组件与数据契约，不共享导航与写入口。

> **可见性口径（2026-10-21 用户复查，正本=`2026-10-21-sim-visibility-and-ide-task-surface.md`）**：在推演实例内的日常工作台/看板，可看到该轮全部推演看板任务与 Matrix 房间；IDE 工作区可通过任务深链查看单个推演任务、任务简报及相关 Matrix 消息摘要。宿主日常实例与推演实例的 kanban 数据互相隔离；导演台只负责建卡与人工闸，不产生 Matrix 聊天。

> **历史说明**：2026-10-15/16 的「三中心」（工作台/推演中心/治理中心）+ 岛屿 + 角色镜头层，已在 10-17 旅程式重构与 10-18 阶段页重构中被**六阶段 + 左栏五组**取代；10-20 进一步拆成三模式。三中心作为历史形态保留在 §8 决策台账，不再作为现行 IA。

### 1.5 设计原则与准入

1. **单一事实源**：契约、阈值、格式、阶段定义、术语只定义一处；改一端必须同步消费者与守门测试。
2. **一处实现，处处消费**：每项能力只允许一个实现正身；驱动 bash、workflow、UI、报告都是消费方。发现双实现＝产品缺陷，进遗留项清算台账。
3. **诚实呈现**：缺数据如实显示缺席，不硬凑；机读原文降级到详情不删除；代偿/自动代处理全产品可见。
4. **执行层强制**：权限与沙箱不能只靠提示词；边界上的确定性检查优先；执行链 fail-closed，读模型 fail-soft。
5. **中文说人话**：用户界面不出现裸 JSON、枚举、绝对路径、内部黑话；技术证据可原样展示但要有解释。
6. **不删功能、零断链**：旧路由保留 redirect；死代码可删，能力不能丢。
7. **跑轮零打扰**：在跑轮次期间禁 inject，一切换装走部署窗。
8. **准入三问**：新增功能必须回答「锚到哪条 R」「落在哪根柱」「三句理念过不过」；三问全空不立项。

## 4、功能域设计

### 4.1 工作台（`/app/collab`、`/app/dash`）

**定位**：人的当日工作面。三栏壳：左栏会话/房间与智能体入口；中栏会话/Matrix/概览；右栏「待我处理 / 全部 / 已处理」三档任务决策栏。

- **待我出手**：人工介入请求队列，批准/打回双钮，动作全留痕。
- **我的会话**：单聊/群聊/房间三态入口；Matrix 房间画布内嵌，不跳出 `/app` 壳。
- **注意力条**：最高优先前 3 条 +「N 项待处理」抽屉，按阻塞/待审/待分类分组。
- **数据源**：`fetchKanbanOverview` 跨板聚合、`/api/approvals/*`、Matrix/GroupChat；**不读推演 run-state**（`useDailyStageProgress` 只读跨板任务）。

### 4.2 看板（`/app/board`）

三签：**看板**（我的卡/全局视角、泳道、任务抽屉）｜**任务协同**（loop-graph 实例化视图、依赖图）｜**协作与知识**（知识面 + 交接区）。

- 卡状态流转：分诊双通道、todo 推进语义；完成必须有双凭证。
- 在制上限 ≤2；超限列头琥珀警示。
- M3 实测数据：1082 任务、跨板 chips 正常。

### 4.3 审批收件箱（`/app/inbox`）

- 两队列：**待审批**｜**遗留项清算**（单层页签）。

### 4.4 沟通（Matrix）

四路由：`/app/s/chat`、`/app/s/chat/:sessionId`、`/app/s/group/:roomId`、`/app/s/room/:roomId`。

- 消息可「存证」：生成反查锚入证据库。

**六道质量门**：G1 需求冻结 / G2 架构评审 / G3 编码门禁 / G4 独立测试 / G5 发布准出 / G6 复盘。G6 键统一为 `retro_done@步24`（步 26 的 `report_done` 只表示本轮结束，不再承担闸语义）。

**导演台（产品内导演）**：

- 服务端三端点：`GET /api/graph/sim-director/scenarios`、`POST /plan`、`POST /start`。
- 需求 → `compileRequirementToGraph` → `validateGraphSpec` → 落库 spec → 按请求 JWT 构造独立 spec runtime 起跑。
- 默认场景 4 模块 = 29 节点（16 模块节点 + 13 全局节点，含 3 个人工闸）；限 500 步/成本 100/4h。
- 启动即建真实看板任务；3s 轮询；待决闸批准/打回。
- 边界：无 JWT=401、无 runtime 工厂=501、DryRun 仅测试预览；不接受任意图/命令；导演 run 不写 26 步 run-state/journal，旧三签自动改道导演台。
- Matrix 边界：导演台只创建真实看板任务与人工闸，不代发 Matrix 消息；全流程 Matrix 聊天由受控 harness 的模拟员工/网关产生。导演台 UI 明示该边界。

**受控 harness**：

- 默认关闭；后端须以 `SIM_HARNESS_LAUNCH=1` 启动且调用者为 super_admin。
- 只允许固定脚本 `simharness/aipay-scenario.sh`；runId 白名单；同一时刻仅一个本进程子进程；驱动锁拒绝双开；只终止自己拉起的 PID。
- 未启用时 UI 只显示说明，不放假启动按钮。

**演进判据**：一件能力在产品面有正身（端点/界面/测试）且一轮全量推演经产品面走通，对应 bash 原件退役（先影子对照一轮再删）。一键开轮＝Phase C 分水岭。

## 5、机制设计

### 5.1 单一事实源与合并铁律

**铁律：一处实现，处处消费。** 每项能力只允许一个实现正身（studio custom 组件、hermes-agent 模块或 simharness 脚本）；驱动 bash、workflow、UI、报告链一律是消费方，不得出现第二份同语义实现。发现双实现＝产品缺陷，进遗留项清算台账。

**已立单一事实源**（示例）：

| 事实 | 正身 | 消费方 |
|---|---|---|
| 阶段定义/完成键 | `ia2/stage-meta.ts` | 左栏、阶段页、旅程页 |
| 阶段页签 | `ia2/stage-tabs.ts` | StageShell、面包屑、守门测试 |
| 六门键 | `ia2/views/sim/steps-registry.ts` | 运行总览、报告、审计 |
| 术语 | `i18n-term-overrides.ts` / 词表 | 全站 |
| 工具契约 | `custom/server/toolcontract/` | 工具执行瀑布、审计 |
| 证据账 | `custom/server/evidence/` | 审批、报告、审计 |
| 图事件日志 | `loop/graph` 事件流（SQLite） | 导演台、运行监控 |
| 分支新鲜度 | 后端 `sim/branches` | 推演交付健康、IDE |

### 5.2 证据链

**四类锚点**：Matrix 事件号 `$`、Git 提交号、看板卡号 `t_`、房间号 `!`。任何结论/数字/判定可点击→右侧抽屉看证据原文（宽 480px，全产品唯一反查交互）。

**双凭证**：一切「完成」声明必须带 commit 号 + 卡号；缺一红显缺口。

**证据台账**：

- append-only JSONL：审批事件、发布门、UAT 判定、遗留项、治理快照。
- `custom/server/evidence/` 任务证据台账，hash 链（`sha256(prevHash + 规范化体)`）防篡改。
- 推演证据：帧图廊按步注册（步→URL→user），零帧步显示「未采集」不隐藏；消息可存证入证据库。
- 报告：交付物链 17 行（惯称 13 件）、证据九（治理结果）、审计前后各跑一次。

### 5.3 门禁与判定

- **六道质量门**：每门全名 + 判据原文 + 判定来源（agent 判/人类角色模拟/代偿代判）+ 首过/补过/打回次数。
- **FAIL 唯一出口**：登记修复单 → 派修 → 复审 → 放行；界面无「绕过门」按钮。G2 前置硬校验安全评审；G3 后 G4 前硬校验；UAT 非全过不落 `uat_done`，落 `uat_conditional` 且需显式批准事件。
- **评审治理**：风险分档、轮次上限、nit 上限、证据要求、head commit 绑定、熔断。
- **改进实验**：探测绑真实 Eval run；晋级阻塞 10 类；写入面仅 system_prompt/skills；人工批准 + 环境开关。
- **受控执行**：执行链 fail-closed；读模型 fail-soft；权限与沙箱做边界检查，不靠提示词。

### 5.4 审批与人工介入

- **14 个人工介入点**（G1 冻结判读、G5 HumanGate、UAT 判词、遗留项 waive、复盘拍板等）全部进审批收件箱。
- 每个动作记录：谁、何时、依据什么证据；批准/打回双钮；waive 强制理由。
- **in the loop**：缺人则停（流程必经）；**on the loop**：驾驶位/监督面板/旅程页可随时介入但非必经。
- 人工介入请求与「待我出手」同源计数；执行类项不得出现在「待我出手」。

### 5.5 日常/推演分离

**原则**：共享组件与数据契约，不共享导航与写入口。

| 面 | 日常 | 推演 |
|---|---|---|
| 导航 | 常用 5 + 六阶段 + 专题 | 导演台/监督/监控/证据/编排/设置 |
| 进度源 | `useDailyStageProgress` 只读跨板任务 | 图运行时 + run-state + journal |
| 运行上下文 | 不显示 run chip | 显示运行 chip |
| 写入口 | 看板卡/审批系统 | 推演台账/图运行时 |
| 跨区 | 只读「推演参照」链接 | 只读 graph specs/runs |
| 可见性 | 同一实例内：工作台/看板聚合全部账号板任务；IDE 看板/任务段同一数据源 | 宿主 `:8647` 与推演 `:8802` 按 `HERMES_HOME` 隔离；不跨实例聚合 |

> **可见性机制**：口径正本见 §1.4。同一实例内工作台/看板与 IDE 看板/任务段共用 `/api/hermes/kanban/overview`；宿主与 SIM 按 `HERMES_HOME` 隔离，不跨实例聚合。
>
> **未闭环**：宿主日常若以同一 `@admin` 登录，会看到 harness 观察员房间（同 `:8008`）；严格隔离需独立观察员账号/独立 homeserver 或 harness 房间标记，跨仓后续。

**机械守门**：`domain-split.test.ts` 禁 `views/stage → views/sim` 与 `api/sim-*` 导入；禁 `views/sim → workspace store`；白名单仅 crossref 链接模块。`useRunContext` 拆 sim/daily 记忆，`query.run` 只作显式跨域链接。

### 5.6 诚实呈现与失败语义

- **读模型 fail-soft**：源缺席返回 `null` / `available:false`，不猜数；审计失败可见但不阻断业务。
- **执行链 fail-closed**：环境变量缺席即关闭、无 JWT=401、无 runtime=501、非法迁移 409。
- **机读噪声降级**：原始 JSON/枚举/时间戳/路径只进详情/title；首屏用人话结构化字段（`ia2/format.ts` 统一映射）。
- **假功能零容忍**：不留无反应控件；占位必须有统一真实反馈；死链错链必修。
- **空态带出口**：原因 + 就地动作；不显示「未接入/未配置」列表项。

### 5.7 质量工程

- **测试**：`custom/**/*.test.ts` + `scripts/**/*.test.ts`；服务端纯 node、客户端按需 jsdom；测试与域同目录。
- **守门测试**：domain-split、cockpit-hygiene、daily-acceptance、layout-guards、z-layers、route-whitelist、sim-director-rest、share-link、permalink 等。
- **构建**：`npm run build` / `build:full`；`verify-dist`；出厂默认口令扫描零命中。
- **QGate**：L0-L5 gate packs、证据包、插件；质量门框架自带 vitest。
- **prelaunch 30 项**：可机械核对的开跑前检查，全绿才开跑。
- **走查**：Playwright 全量活页面截图 + 布局启发式；旗舰屏按风险最高选择；dev 热更新，不默认装机。

### 5.8 学习闭环

```
推演/日常执行 → 轨迹与台账 → 复盘行动项 → 经验候选 → 改进实验 → 下一轮准入阈值
        ↑                                                        ↓
        └──────────────── hindsight 长期记忆（受控注入）←──────────┘
```

- **hindsight**：跨会话经验积累；受控注入走治理门（默认关）。
- **经验库归流**：workbench experiences 为主库，expcandidates 为上游候选池；G6 复盘合并读取。
- **自动回流**：评测处置单关闭后自动回流回归库（内容指纹幂等），默认开、可关。
- **自我加严**：复盘行动项改变下一轮准入阈值时，阈值变更随度量卡展示。
- **代偿退役**：根治一项拆一项；遗留项清算清零才开新轮。

### 5.9 安全与受控执行

- 端点鉴权：JWT / super_admin / feature 开关三层。
- 受控 harness：固定脚本、runId 白名单、单进程锁、只杀自拉 PID、默认关闭。
- 路径围栏：路径包含判据锚定分隔符边界；防穿越。
- 密钥：只存 env 名；最小台账（清单+最近轮换+归属，不含密钥本体）。
- 供应链：上游运行时逐版本蒸馏，npm 裸名撞名陷阱已记账（详见 §7）。
- 审计不落敏感原值；不削弱既有安全边界。

### 6.1 总体分层

```

```

- 产品是 hermes-studio 的 **overlay fork**：上游只读，所有改动经 `patches/` 与 `custom/` 在构建时注入。

- 桌面端目前统一 Web 模式（不默认出桌面安装包）；desktop 源码保留因为 overlay 补丁落在其上。

### 6.2 Overlay 注入系统

**A 类 vs B 类**：

| 类型 | 性质 | 位置 | 机制 |
|---|---|---|---|
| **A 类** | 纯新增（组件/store/服务） | `custom/` | Vite alias 重定向 + 入口 shim + 运行时注册 |
| **B 类** | 骨架修改（schema/配置/路由） | `patches/` | 构建时 `git apply`（可逆） |

**注入流程**（`npm run inject`）：

1. 校验上游工作树干净；
2. 按 `patches/series` 顺序应用补丁（跳过 `#` 注释项）；
3. 软链 `node_modules → upstream/hermes-studio/node_modules`、`custom/server → upstream/.../server/src/custom`；
4. 生成 `vite.config.overlay.ts`（alias 重定向）；
5. 写 `.overlay-injected.json` 清单（用于 clean 反转）。

**当前口径**：382 条 studio 注入补丁 + 8 条 zcode 参考仓补丁（2026-10-21 基线升 3.16.1/3.16.2）；0.7.38 升级轮净树全序列重放 310 个 studio 补丁全过，官方 inject rc=0 / 382 applied，zcode 按既定容错策略处理。

**Vite alias 链**（顺序敏感）：

```
/src/main.ts  → registries/client/entry.mts
@/custom      → custom/client
@custom       → custom/client
@registries   → registries
@             → upstream/.../client/src
```

**入口 shim**：`registries/client/entry.mts` 复刻上游 `main.ts` 启动，在 `app.mount()` 前并行 `bootstrapClient(app)` 注册各域；路由在 mount 前 `addRoute`。i18n 词条不运行时合并，直接经补丁注入上游 locale 文件。

6. **验证纪律**：三层验法（产物 grep+HTTP 200+真浏览器走查）+守门测试+词条快照防漂移；不确定即如实记「未核」。

### 8.5 主题脉络（三条线）

**产品方向线**：6 至 9 月是功能叠加期，以单点裁定为主（kanban 解耦、Loop 单页、IDE 主页、Ycode 红线）。10-08 出现第一次视角抬升（「核心是平台能力」）。10-15 是分水岭：推演程序升格为产品能力一环。10-16 进入再论证期：推翻已定稿的总设计，冻结 14R+8N，立纲三句话。此后进入走查驱动的快收敛：旅程页、左栏五组、IDE 锚定、三模式，至 10-21 汇编收口。贯穿取向不变：诚实优先于好看、能力不删只迁、真实素材优先、不装已实现。

**治理介入线**：本质是用户与「推演程序该不该伸手」的持续博弈。10-12 立「长期不介入」。10-14 拆闸事件确立 FAIL 唯一出口。10-15 用户三次同句质疑，逼出四层病根链：程序越界、方案条款化、愿景未挑明、命题结构漏洞；最终以「确认自组织+双态声明+§2.9 收窄+代偿台账+清偿门」一揽子立法收口。同期激励反转与任务粒度拍板，把治理从救火代偿扭向根治产品。AI 被纠正的形态从「技术判断错」上移为「方法论错」，用户追问深度同步上移。

**工作方式线**：四个反复强化的主题。一是说人话：四次反馈后升为全局规则，形成汇报、巡检、决策清单的分层沟通体系。二是闭环实证：三档验收锚，配测试未绿禁提交与机械门禁。三是协作纪律：worktree 立法、禁自动 push、撞车分工，均由多会话并行事故倒逼。四是文档纪律：终稿化、一事实一源、多格式一致、对账总表。用户介入方式从早期单点裁定，演进为后期「原则立法+机械门禁」。

### 8.7 贯穿性裁决

1. **口径收紧**：全量快照 → 0→1 纯净建站 → 域裁撤 → 面裁撤 → 密钥脱敏 → 零降级全能力。裁决基准始终是「目标机离线自足运行」。
2. **渠道纪律**：依赖仅 pip/npm 源；外部渠道（electron 二进制/NSSM/uv）一律改道或裁撤。
3. **记档纪律**：每条指令留痕、每轮更新留注、每份组件留出典、配方入长期记忆——四处各司其职不重复。
4. **不删功能、零断链**：旧入口保留 redirect；死代码可删，能力不能丢。
5. **跨模式不互侵**：共享组件与数据契约，不共享导航与写入口；任何跨模式跳转显式标注。
6. **诚实优先于好看**：缺数据如实缺席；原始错误只进 title；假功能零容忍。
7. **执行层硬边界**：权限、沙箱、受控启动不能只靠提示词；fail-closed 优先。

### 11.2 overlay 注入架构

全部二次开发的地基：三个上游仓（hermes-studio/element-web/hermes-agent）保持 git 历史干净，本地成果集中 overlay 仓。改动分两类接入——A 类纯新增（custom/ + 构建期 alias 重定向 + 运行时注册），B 类上游骨架修改（patches/ 经 git apply 可逆注入），`inject --clean` 可完全还原上游（2026-06-21-overlay-architecture-design.md §3-4）。实施修正了原设想：55 个修改文件最终全部归 B 类 patch（39 个），因为约 80 个新增导出有上游文件直接 import，抽出反而要 patch 更多 import 点（同文 :298-313）。这条「A 类可抽出设想不成立」的实测结论，是后来所有升级轮（0.7.36/37/38）补丁适配方法的起点。

### 11.3 Matrix 账号与 fleet

账号层渐进迁移：users 表扩 matrix_user_id 等列，Matrix 管理员自动获 super_admin，登录走 matrix-login 换 Hermes JWT，删除硬编码 bypass token（2026-06-19-matrix-account-integration-design.md §2-4）。

fleet 解决单机模拟多用户：每用户独立 HOME 沙箱三层（electron userData/.hermes/.hermes-web-ui），应用共享本机一份安装与单份约 1.4G 共享运行时，端口按 user_index 编址即路由（matrix-fleet-deploy-design.md §1-4）。09-18 用户指令确立「应用共享省空间+版本与全机安装一致」的部署取向（同文 :33-37）。

### 11.4 Kanban、工作项与驾驶舱

6 月把 hermes-agent 看板高级能力移植为 Vue 组件后，06-22 将 Swarm 看板解耦为独立路由（patch 028 归档，原生看板回归上游纯净）。工作项页面确立双通道交互模型：字段编辑类走 localStorage 草稿批量提交，动作命令类即时执行不可暂存。依据是用户 06-24 裁定「所有原页面可编辑可配置项都要」+「除文件上传外保持草稿批量提交」（cockpit-workitem-kanban-migration-design.md:18-19）。驾驶舱三栏联动+Pure Ink 黑白灰视觉，「既不失焦又不空洞」的核心诉求原文在同文 :19。06-23 去 mock 后，底层数据 100% 来自 useKanbanStore 派生（cockpit-kanban-integration-design.md:39-59）。

### 11.5 Loop 工程与 loop graph

07-11 的 Loop Engineering 把「人逐条 prompt agent」升级为五阶段循环（发现→交接→验证→持久化→调度）。配套三路验证（Programmatic+Judge+Human，Judge 须不同模型族）、7 个命名 pattern、BudgetGuard 三模式（loop-engineering-design.md §2-6）。09-09 重构为 loop graph：可编排可有限终止的图成为唯一执行与组织主干，append-only 执行事件日志（node:sqlite）为唯一事实源，四层终止防御（条件边/回边 guard/图级 maxSteps/成本时长熔断），旧 LoopEngine.tick 退役为编译产物（aihub-redesign-design.md §2-3）。这一「事件日志为唯一事实源」的裁决后来直接被 V8 推演的图执行终极形态继承（§12.2）。

### 11.6 运行观测与交付协议

RunTraceView 确立「不可伪造原则」：拿不到的数据显式标注占位，绝不画成实线节点（run-trace-view-design.md:56-65）。分布式交付网络一句话总纲：Matrix 传协调，git 传制品，本机管执行。注册房管组织、案例房管个案，G1/G5 HumanGate 强制人类 sender（distributed-delivery-network-design.md §4-6）。架构三裁决落款：任务状态以案例房事件流为准（Studio 是投影）、集群按用户机器组织、附属 Agent 是账号内虚拟身份（swarm-cockpit-architecture-design.md §3）——「Studio 是投影、事件流是事实」这条原则贯穿到今天的图执行器设计。

### 11.7 网关复用与 zcode 底座

网关侧分清两类锁语义：本 profile runtime lock=幂等在跑；host 守卫拒绝=未被服务（术语照原文）。旧判读误当在跑，导致静默失败；patch 373 修正判读并落 host-ownership.ts 单一事实源（gateway-host-ownership.md §1-2）。产品边界裁定「Studio ensure 只查不抢、长期靠上游 multiplex」（gateway-multiplex-design.md §1-3）；推演实测进一步归因争用点为 host rendezvous 记录，正解是 --force+每 profile 独立锁目录（aipaydev-fullchain-sim-report.md §五-e）。

编码引擎底座经两次用户裁定定型。09-23 三案对比选 B 案：upstream/zcode 受管 fork+patch 层，复刻 overlay↔hermes-studio 协议，内核只读，二开落 service 层；此裁定推翻 09-16 的 codex 集成决策（zcode-foundation-design.md:10-12,65-73）。09-25 用户纠偏确立 Ycode 定位红线：产物是全新编码工具、融合各工具优势功能，不是编码工具聚合器（同文 :10-12）。

### 12.1 定位与五部分

冻结面：26 步主链、六道关卡、治理机制、交付物模板字段语义，变更须整轮推演验证（L90-95）。纪律条款编号是稳定标识，只增不改。历次版本明细一律入历史档案，不入正文。全文按本体论六要素（实体/属性/关系/规则/行为/事件，L19-30）组织成五部分：一方案目标定实体（考什么）、二方案设计定契约（靠什么）、三场景设计定实例（考哪张卷子）、四执行注意事项定操作面（怎么跑）、五验收标准定裁判面（怎么算考过）；冲突以第五部分为准（L38）。

### 12.2 目标层

- **三核原则**（L106-112）：贴近真实（跳步=污染实验效度）、最高质量（假绿=最贵返工）、最快速度（不得牺牲前两核）。
- **图执行终极形态**（L114-169）：当前推演是线性 bash 脚本，终极形态用产品自己的 loop graph 引擎跑推演——26 步转译 GraphSpec、事件驱动、关卡=join 屏障。一张图三用途：方案定义、运行日志、审计证据。上段生成面（需求→图编译器）是最大待建缺口。
- **全新环境独立回归**（L171-197）：每轮全新环境全流程独立回归，八维清理，污染防线四禁止；分组记忆跨轮回忆是设计功能但须声明来源轮次。
- **三条假设**（L199-208）：分布式多 agent 研发可按真实公司流程流式并行交付真实需求；治理靠机制不靠自觉；过程可完整重现给第三方。每条附证伪判据。V8.29 增补净额口径：满足面一律扣除代偿项，只呈含代偿行即虚报。
- **不做什么**（L270-276）：不接真实资金流、不实测性能容量、不多需求并行、不验跨机联邦、不验模型独立性。
- **双态声明**（§1.5，2026-10-15 用户裁定，L278-286）：产品形态两读——副驾（人类指挥）与自组织（体系自主）。当前实测态=副驾，如实声明不冒充；演进目标=自组织（人只保留审批类干预）。旋钮=推演姿态 posture（strict 零代偿/standard 保留但逐笔记账/demo 幕后编排全程标注），写入 state.env。收紧路径：产品缺陷按清偿门逐项根治，直至 strict 可作全量轮缺省。同日产品范围声明：推演程序是 SwarmStudio 产品能力的一环，simharness 升格为产品推演引擎仓。
