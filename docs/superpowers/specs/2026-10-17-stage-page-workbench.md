# 阶段页工作台化批（spec）

日期：2026-10-17
分支：feat/ia-stage-page-workbench
来源：用户实报驾驶舱四痛点（层次结构与组织关系不清晰、层级太深太乱、往返动线不合理、末端页不直观）裁定「全做」后的第二阶段。第一阶段「页签级阶段归属」已由并线批次合入 main（`87d5923e`）；本批治剩下的一根刺——阶段页此前只是跳板：每页只内嵌一块，其余全是「进入 →」卡片，日常操作要跳去中心再跳回。

## 变更内容

1. **run 口径统一**：StageShell 的轮次来源从「只读 query.run」改为 `useRunContext`（query 优先，无 query 回落最近一次成功读取的记忆值），读取成功后写回记忆。阶段页不再因为没带 `?run=` 就显示不出进度；与监督面板/交付健康/需求追溯/问题清单四面板同源。
2. **四块高频件内嵌**（全部复用中心既有自足组件，零新端点、零新路由）：
   - ②需求：运行态势条（CockpitPanel——运行模式档/遗留项清算灯/服务异常数，整条可点进运行总览）
   - ④开发：证据反查（EvidencePanel——贴事件号或提交号回原文）
   - ⑤验收：交付健康（DeliveryPanel——分支新鲜度+14 件交付物）
   - ⑥治理：问题清单对账（GovIssuesPanel——处置率+逐条状态）
3. **CockpitPanel run 口径随同统一**：从 query 单源改为 `useRunContext`（查询优先+记忆回落）——该条挂在仿真中心壳头与②需求阶段页两处，两处都不再要求手打目录名。顺带根治一处健壮性缺口：拓扑返回缺 services 字段时原本抛未处理拒绝，现按「服务未探测」呈现。
4. **测试**：`stage-shell.test.ts` 新增 6 例（四块内嵌在位+两条 run 优先级：记忆回落、query 优先），并补 localStorage 与 Mock 调用历史的跨用例隔离（jsdom 同文件内持久，不隔离会串味）。全量 4841 通过（较基线 +6），`npm run build` 绿。

## 决策记录

1. **阶段页从跳板改为工作台，但工具卡不删**：内嵌补的是各阶段高频件（本阶段日常要用的），工具卡留整页入口（全量面）。两者分工——内嵌答「本阶段日常操作」，卡片答「进去看全量」。
2. **①③不新增内嵌**：①搭建五步（建组织/建号/建团队/备环境/备智能体）与③的看板本就是整页操作，硬拆只会得到半个功能；①已内嵌密钥台账、③已内嵌组织视图，保持现状。
3. **run 记忆口径全站单一**：六个消费面（阶段页+四面板+轻量条）统一走 `useRunContext`，消除「这条要手打、那条能记住」的差异。记忆只由成功读取触发，失败与空值不写记忆。
4. **拓扑形状不符按未知呈现**：端点返回缺 services 时显示「服务未探测」而非崩溃——失败要如实，形状意外也要如实，两者都不该以未处理拒绝的形式冒到用户面前。
5. **零新端点零新路由**：本批只做组件复用与挂载，不碰路由树、页签文案与术语；采集位、直达链接与契约测试不受影响（四面对账见同日对账总表）。
