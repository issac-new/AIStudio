# zcode 3.15.3 源码可获得性与增量核对（2026-10-18）

## 结论

- **公开源码最新仍是 v3.15.1**。`git ls-remote --tags origin` 只有 v3.14.3、v3.15.1；GitHub API `/tags`、`/releases`、`/branches` 同样只有这两个 tag、一个 v3.14.3 release、main 与 feat/ui-plugin 两个分支。origin/main 的 `package.json:3` 是 `3.15.1`，没有 3.15.2/3.15.3 的 tag 或提交。
- 已安装的 ZCode.app 是 **3.15.3**（`Info.plist` CFBundleShortVersionString=3.15.3，CFBundleVersion=3.15.3.8237；`app.asar` 内 `@zcode/desktop` package.json version=3.15.3）。这是未公开源码的构建，无法从公开渠道取得对应源码树，因此**不能把 `upstream/zcode` 的 git HEAD 切到 3.15.3**。
- 本轮把 `upstream/zcode` 固定在公开最新 `origin/main`（v3.15.1），并用安装包产物做可复核增量核对（下节）。这就是"源码基线可达到的最新"；不把 3.15.1 改名冒充 3.15.3。

## 核对方法

1. 从 `/Applications/ZCode.app/Contents/Resources/app.asar` 解出渲染层产物（`out/renderer/assets/IntlProvider-*.js`）与 CLI bundle（`Resources/glm/zcode.cjs`）。
2. **i18n 键差集**：从 IntlProvider 提取全部点号命名键（6370 个），与源码 `packages/ui/src/i18n/locales/zh-CN.ts` 的键（6362 个）做差集。
3. **V4 协议方法差集**：从 app 的 renderer/host/main/preload 产物提取 `v4/...` 方法字符串（35 个），与源码 `packages/shared/src/zcode-protocol-v4/transport.ts` 的 `V4_METHODS`（36 个）做差集。

## 对 IDE 工作台的影响与吸收

- 8 个新键里 6 个属于验证码/套餐领取，IDE 工作台不呈现这些流程；不新增死词条。
- `settings.memory.viewer.disabled`：对应"记忆查看器被禁用"的诚实空态。本仓 `IdeMemoryPane` 已有 `memory-pane-isdir` 等错误态；若后端返回禁用，面板显示后端原文而不是伪造空目录，语义一致，无需新增 UI。
- `zcode.error.providerBusiness.3007`：IDE 的 `ideErrors` 分级可把 3007 归入"供应商业务错误（检查套餐/额度/验证码）"。本轮不改错误分类表的既有码段（3007 由引擎错误体透传），在本文记录，后续若引擎在 IDE 会话里回传 3007 再补映射。
- 无协议变化意味着本仓 002/398/399 等 zcode 补丁不需要因 3.15.3 重放；`zcode-patches/series` 保持现状。

## 未核项（如实标注）

- 3.15.2/3.15.3 的**行为级修复**（渲染/权限/工具执行的代码改动）无法从压缩产物逐行反推；本文只对 i18n 键与 V4 方法做可复核差集。
- 安装包的 `out/renderer` 是 minified 产物，不含 source map；不做逐文件源码还原。
- 若后续 ZCode 公开 3.15.3 tag，应重新做一次 `git diff v3.15.1..v3.15.3` 全量对照，替换本文的产物级结论。
