### 001 你的 Agent 评测，通过率 100% 却不可信？（2026-09-29）
方法论连载开篇，核心是五种「假通过」模式，全部来自作者真实踩坑：①恒真断言——评测判据检查的结构字段（format、content_len）其实是评测夹具自己塞进合成数据的，被测 Agent 换成永远返回空值的假对象照样全绿；修法是判据只准读被测对象真实产物，且每条新守卫上线前必须先做「突变验证」证明注入违规会变红（0 命中不能自证清白）。②零证据通过——框架默认「没有失败记录就算通过」，判据因维度不适用/数据缺失被静默跳过后仍计通过；规矩是零判据不许通过，要么有实测依据要么标「不可判定」退出统计。③裁判洗白——LLM 裁判把证据缺失「圆成」无需证据支持，系统采集缺陷被洗成加分项；规矩是 LLM 裁判只做补充判断、证据缺失直接标「未测量」不进裁判环节。④否定语义反转——两条链路各维护否定词表，一份漏收「不调用」，导致「未调用」被判「已调用」；且两链路行为等价性检查对「共同错误」免疫，结论是「行为等价不等于正确，单一来源才是」。⑤笼统豁免——用接入类型反推评测维度适用性，长时序任务型 Agent 被套通用模板，最强维度被判「不适用」；规矩是「不适用」必须由客观前置条件触发，配了工具没调用是失败不是不适用。总纲：评测系统不能默认自己诚实，每条通过都要能回答「它凭什么通过」。

### 002 AIGC 智能体怎么测？一套四层全链路评测体系（2026-10-01）
以人像视频替换 Agent 为例给出四层体系。第一层业务生成质量（核心价值层）：客观量化（ArcFace 人脸相似度、帧间方差、SSIM、音画同步）+ 主观盲测（5~10 名评审、1~5 分、去最高最低取均值、新旧版本背靠背盲选）+ 边界 Case/BadCase 库（暗光、侧脸、遮挡）；踩坑：客观指标全达标但用户反馈表情僵硬嘴型对不上，修复后主观盲测成为上线强制准入门槛。第二层 Agent 底层通用能力：安全（提示注入——用户把指令写进图片文件名绕过内容校验，教训是注入载荷不一定在内容里，全字段清洗）、性能与 GPU 成本（重试无上限导致同一视频烧 3 次 GPU）、系统鲁棒性、编排/工具调用轨迹（LLM 跳过人脸检测直接调换脸模型，修法是关键前置校验硬编码，不依赖 LLM 自主决策）。第三层移动端 App 交互：端云交叉场景（弱网、切后台、断点续传）是投诉最高发。第四层业务合规运维与对抗：业务指标（重生成率、NPS、留存）、法务合规（深伪水印、肖像授权）、版本回归与灰度（**每次模型更新全量回归+盲测对比，指标退化禁止上线，小流量灰度+一键回滚**）、线上监控、红队对抗（黑产刷 GPU）。主线一句话：BadCase 库贯穿始终，每个缺陷修复后入库，评测是持续对抗退化的基础设施，不是一次性验收。

### 003 把 AI Agent 比作一个人，终于把智能体架构讲明白了（2026-10-02）
科普篇，价值在「评测视角的架构观」：Agent 是 LLM（大脑皮层）+Planner（前额叶）+Memory（海马体）+Perception/Output+Tool（手）+Runtime（脊椎）+Safety（免疫）+RAG（胃）的复合身体。两条对评测有用的论断：①Agent 质量不是定值而是分布，必须固定用例集批量跑、统计成功率与失败模式，传统单条断言思维从根上不适用；②修复优先级排序：调提示词/数据 → 改工具/检索 → 改代码 → 换模型，80% 问题不用改代码，一上来嚷微调的多半没找准器官。附症状-病灶-处方对照表（引错知识是胃的锅不是脑子的锅）。

### 004 文档都上传了，AI 为什么还在胡说八道？（2026-10-03）
RAG 六环节故障手册，每环节带专业修法：①食材不新鲜（文档脏/多版本冲突）→ 元数据三件套（version/effective_date/source）入库、冲突检测转人工仲裁、旧版本打标 superseded 不物理删除（审计要查旧政策）；②切块切坏 → 语义切块、overlap 10-20%、父子块检索（small-to-big）治断章取义，抽查 20 个回答回查引用块；③Embedding 不匹配 → 换 Embedding 靠实测（50-100 条金标问题 + MRR/Recall@k）不靠榜单、查询改写、混合检索（向量+BM25，RRF 融合）；④召回策略错 → 50 条金标集先量 Recall@5（低于 85% 召回是瓶颈）、宁滥勿缺（漏检不可逆多检可重排兜）、元数据路由、每次只动一个旋钮；⑤没重排序 → 粗召回 20-50 条 + Cross-Encoder 精排 top 3-5、引用纪律写进提示词（没有就直说没有+强制 citation）；⑥知识冲突/过期 → 生效/失效日期元数据、增量同步（文档源是唯一事实，向量库只是缓存）、**金标问题集定时重跑（每周）做漂移监控**——验收测不出这类问题因为它只在上线后、知识库变更后发作。判例：加拿大航空客服机器人错误承诺判赔（Moffatt v. Air Canada）、纽约市企业服务机器人违法答小费。

### 005 特斯拉跑了 240 亿公里，为什么还不敢完全自动驾驶？（2026-10-05）
评测哲学篇。RAND 2016《Driving to Safety》的数学：事故这种小概率事件，想统计证明达到人类水平需 2.75 亿英里无故障里程，想精确到 20% 需 88 亿英里——「系统越安全越难用里程自证安全」，结论 cannot drive their way to safety。感知 Agent 测试五难关：长尾不可枚举（组合爆炸）、感知无标准答案（标注员都会吵）、失败样本昂贵不可复现、仿真与真实有 sim-to-real gap、OTA 版本漂移（每升级一次上版结论部分作废）。行业答案是分层证据链：场景库+仿真补广度 → 封闭场地校准仿真 → 影子模式真实世界低风险采样（生产环境替你写测试用例）→ ODD 运行设计域圈住长尾。三条对 Agent 评测的推论：①评测资产不是用例总数而是临界场景密度，100 万条平淡用例不如 1000 条真实翻车捞回的 corner case；②覆盖率要看「没测什么」，评测报告该有一栏「已知未覆盖」；③版本漂移是常态，评测必须是长在 CI 里的管道而不是停在 PPT 里的项目——行业只问「这一版 safety case 递交了吗」。

### 006 LLM 当裁判，到底靠不靠谱？（2026-10-06）
裁判可靠性综述。UC Berkeley 2026 最大规模「裁判体检」：21 个裁判模型、9 家厂商、3 基准、118 轮、54 万次判分——精确匹配一致率与 Cohen's κ 之间平均差 38.6 个百分点（33.8~41.3 无一幸免）：「85% 一致率」校正后 κ≈0.48 只是中等一致；同一裁判跨基准能力排名最多漂移 14 位次，裁判没有通用可靠度。四大偏置：位置偏置（换序判决翻转，GPT-4o 位置偏好重测一致性 >0.95——稳定的错是系统性的错，多次采样摊不平）、啰嗦偏置（长=好，RLHF 副产品）、自我偏爱（同家族打分虚高）、权威偏置（假引用就能翻转偏好）；隐藏款宽大偏置：抓错误输出的真阴性率普遍 <25%，分数系统性偏高。三个扎心发现：最稳定的裁判可能最不可信（高重测一致性+高偏置同现）；升级裁判≠变可靠（18 次对比仅 1 次稳健改善，vendor 静默升级=及格线悄悄移动）；任务越难裁判越拉胯（长文本 0.56、跨语言 κ≈0.3）。RAND 2026：没有任何裁判在所有检查项上可靠，基于 rubric 的简单自动打分器不输复杂裁判。五条守则：①换序双跑两次一致才采信；②裁判回避制（不同家族）+陪审团制（PoLL：三个不同家族小模型投票，效果超单个 GPT-4 裁判、成本低 7-8 倍）；③先校准再上岗——留 100-200 条人工标注黄金集，用 κ 不用精确匹配率做验收线，裁判换版本必须重校准；④能机械判的不劳裁判（脚本断言零成本零偏置，裁判只补开放维度）；⑤防刷分——裁判提示词当密钥管理+定期对抗测试（Goodhart 定律评测版）。自查表三条中招建议分数先打八折。

### 007 电商 Agent 评测技术拆解：淘宝落地实践（2026-10-14）
1688 首次线上真实日志抽样：任务「完全完成率」仅 42.4%，失败根因 71.6% 首先来自系统与基础设施（无响应 38%、额度异常 22.2%、交付关键内容缺失 22.2%）——换强模型解决不了大半问题。三侧七类考卷（消费者/商家/平台侧，对话类答错是体验问题、执行类答错是真金白银）。双轨评测：离线黄金集守已知 + 线上真实日志发现未知，跑在同一 SOP 下卡四个关口（数据接入与意图识别、可评测化改造、批量判分、归因回流）。淘宝 C 端日级流水线：核心指标执行成功率 = 路由准确率 × 回复正确率，跌了先拆因子分侧定位；判分用 CNT 六层漏斗（CTX 证据够不够是唯一允许 N/A 的层 → OOSR 越界拒答 → OOC 超范围编造 → TCC 工具参数 → CNT 内容，串行短路）+ RED 安全红线五条并联恒评不受短路影响。离线回归三层：提交阶段快速行为集（JSON Trace + pytest 行为断言，幂等键/重复支付等高风险行为）做 PR 门禁；夜间概率性回归（同一需求五种表达+库存变化/工具超时/回调乱序，记录**首次偏离位置**、工具调用次数、P95、单任务成本）；发布前少量真实端到端（受控账号小金额）。契约测试防模拟层与真实接口漂移（否则模拟层自己制造假信心）。零容忍清单：未经确认的支付、重复成功交易、状态未知自动重付，一票否决不参与加权平均。发布=闸门不是按钮（AI 店小蜜 300 人一年、数亿案例锤炼、灰度到错误率与资深人工客服齐平才放量）。BadCase 挖掘=原料采买：三路来源（日志抽样/用户反馈/人工巡检设专职评测产品岗），进库前抽「最小失败证据」五要素（用户原始意图｜发生变化的字段｜第一处错误工具调用｜实际副作用｜正确处置）+ 补相邻合法样本。四层归因（数据/Prompt/Rubric/Agent）：数据层错——tool_calls 混入生产系统提示词被 Judge 误读；Rubric 层错——忠实兜底被判幻觉记 0，Rubric 与技术认知不一致；分母错——上游意图模型误标 label 导致通过率假跌，剔除后五天跌幅全消失。反直觉原则：打标优化目标是让通过率更可信而不是更高。Meta-Evaluation：Judge 模型/Rubric/Prompt 变更后评测器本身回归——同一批人工标注样本在新旧 Judge 上跑，查误判率变化与失败归因一致性；Judge 与人工抽检一致性用纯随机 HASH 采样保证无偏；置信度反推样本量：±1 个百分点需约 4000 条人工标注、±0.5 需约 15000 条；通过率波动远超置信区间宽度时查 Rubric/模型实质变化而非抽样噪声。失败样本流回训练（SFT/GRPO）但「不能仅凭单一 Judge 评分决定上线」；无标准答案场景三层验证（规则断言层 + 校准过的 LLM Judge + 线上 A/B）。

### 008 OpenAI Evals 技术拆解：Agent 评测的入门教科书（2026-10-21）
三大设计原则：注册表驱动（Data JSONL / 任务配置 YAML / 评测逻辑 Python 三解耦，社区像提交代码一样提交基准）、严苛可复现（标准化输入输出结构 + Event Logging 记录从 Prompt 到 Token 到断言打分全过程，任意一次评测可审计）、Model-graded Evals（LLM-as-a-Judge 开山）。执行五阶段：资产加载 → Prompt 构造与采样 → Matching/Scoring → 事件日志持久化 → 聚合输出。工业级 Rubric 四要素：角色与权限定义、多维度评分细则（每个分数段配可观测硬性行为特征 Behavioral Anchors，忌笼统 1-5 分）、强制 CoT 优先（先 rationale 后结论显著提升稳定性）、格式硬约束（强制 JSON 输出+解析容错）。陷阱与对策：位置偏差用 Swap Test 交换 A/B 位置跑两次一致才计分；啰嗦偏好用 Rubric 负向约束（冗余扣分）；成本用小模型代理裁判迭代+大模型终验。Agent 轨迹评估：从终态评估升级为全轨迹评估，三维度=工具调用正确性（参数 Schema 校验+意图匹配）、步骤效率（冗余步骤比、Token/延迟开销）、环境状态断言（沙箱里跑单测套件用客观 Pass/Fail 验证副作用）；示例实现含死循环检测（连续相同工具签名）、关键工具遗漏检查。Evals 局限：重静态离线跑分轻生产态监控、缺生产 Trace 一键转回归用例的闭环、无协作看板、无沙箱管理。现代生态三大趋势：静态基准 → 数据飞轮（生产失败案例自动捕获打标成回归用例）；深度集成 OpenTelemetry 分布式追踪；安全红队自动化进 CI/CD。定论：大模型行为虽概率性，评测流程可以被代码化、声明化、自动化。

### 009（C_extra）字节扣子罗盘技术拆解：从离线打分到在线回归的评测闭环（2026-10-08，s_/x_ 两份副本内容相同）
核心判断：评测要做两次——上线前预设评测集离线评测回答「新版本能不能上」，上线后真实 Trace 自动采样在线评测回答「线上还健康吗」。三正交要素：评测集（考什么，CSV 限 5000 条/AI 种子合成扩样，带草稿-提交-版本记录的完整版本管理，实验绑定指定版本）、评估器（怎么判，四类：LLM 评估器 0-1 分带理由 / Code 评估器跑 Python-JS 做等值包含 JSON Schema 校验 / 30+ 预置模板 / 人工评估兜底可手动改分联动刷新）、实验（可比性，多实验对比做**行级劣化识别**：同一用例新版本比旧版差多少一行行看得见）。在线侧：Trace 持续上报（SDK/OTel 兼容），自动化评测任务按时间范围采样 1-5000 条按天/周重复；三个用途：线上质量监控（低分 Trace 直接进列表）、迭代效果比对（同指标按周期看曲线）、低分 Trace 回流成评测集。回流闭环=观测→评测→回流→回归，评测集跟着线上风险走。两条纪律：AI 合成扩样继承种子分布，盲区还是盲区，替代不了线上真实回流；回流要有准入去重，否则评测集被同类 badcase 灌水、难度均衡就破了。罗盘三缺口：发布环节无强制评测门禁（对照腾讯 Pre-Launch Checklist 强门禁是两条路线：信开发者自律 vs 信流程拦截）；人工标注一致性（Cohen's Kappa）无公开量化口径；LLM 评估器仅支持豆包。三步搬走：第一周立离线最小闭环（版本化评测集+Code 评估器+可重跑实验，先让「重跑便宜」成立）→ 接 Trace 上报（优先 OTel，评测和 APM 同一份链路数据）→ 定回流纪律（每周筛一次低分 Trace，按类型去重后回流，宁可慢不要灌水）。

### 010（C_extra）腾讯 Agent 评测体系技术拆解：从 Harness 工程化到质量飞轮（2026-10-09）

平台内嵌式评测（评测是千帆/AgentBuilder 工具链一等功能，非独立部门）。四层指标金字塔：模型层（知识问答/推理/理解/生成，千帆自动基线评估——**精调完成自动触发回归评估，一键报告，国内最早把回归评估做进精调闭环**；裁判员默认 ERNIE-4.0-8K，必须输出打分理由可审计；评估数据集 >3 条上限 10000 条，提交后禁止修改保证可复现；规则打分支持停用词表）、应用层（检索命中质量、回答质量、格式遵循）、Agent 层（端到端任务完成，FM Agent 领域评估器=correctness+effectiveness+LLM-supervised feedback 三路结合，MLE-Bench 登顶）、线上层（TURA 用 Session Success Rate + GSB 双指标在线 A/B）。评估器三角互证：规则打底（ROUGE/BLEU/accuracy，便宜可复现）、裁判补位（打分 prompt/步骤/满分制全开放）、人工兜底（可串流水线）；千帆杯两轮制：第一轮自动评估（内容分 0.6 权重，**裁判未明确返回参考答案更优时一律算选手得分——保守倾向系统性压低误杀率**；字数控制分 0.4 用规则分段线性），第二轮仅 TOP 12 人工复审三位专家独立投票。最被低估的一手：**评估器即回报函数**——评估织进精调流水线（分数决定能否进模型广场）、驱动进化搜索（FM Agent High 难度段领先 9 个百分点，因为高难度拼评估信号信噪比；进化系统的搜索上限=评估吞吐上限）、数据飞轮不封卷（评测数据同时是训练数据）；QC 思维 vs RL 思维分野（评测是成本项 vs 生产资料）。Goodhart 对冲三道：评测集与训练集分库隔离、隐藏测试集纪律（MLE-Bench 清洁赛道干净成绩重登榜首）、裁判打分理由强制可审计。分层归因产品化：命中测试四要素对比（检索策略 BM25/语义/混合 × Top-K（8 起步）× 匹配阈值（0.2 起步先统计分布）× 重排序）+「回答来源」一次点击直达切片（这句答案哪来的）；线上归因：监控检测准确率下降自动触发模板优化 A/B 选优（金融风控案例波动超 5% 触发）。评测集治理：数据集 SDK 化版本化（评估集与训练集同构管理）、安全评测集按风险分类/攻击类型/多模态三维度自动生成+舆情热点每日活水、防污染三路（分库隔离/隐藏集/预置平台基线集防口径漂移）；DeepResearch Bench 标杆=9.6 万真实查询筛 4.4 万任务统计 22 领域真实分布+博士级专家设计 100 任务+动态标准评估（RACE 与人类一致 71.33%）。AgentOps：评估流水线对接 Jenkins CI 提交自动触发回归、Prompt 版本管理回滚、资源/质量/成本三线监控异常自动预警回滚；数据飞轮三层调优（问答对调优冷启动 → 分析看板运营诊断 → 分发数据回流底座自调优）。安全红队算法化：攻击向量库 → 遗传算法+强化学习自动生成对抗输入 → 沙箱多版本并行攻防 → **裁判大模型微调自进化**；裁判大模型自动标注准确率 95%+超人工，隐蔽攻击拦截率 98.7%，漏洞发现周期 72h→8h；安全评测例行化嵌入全生命周期，上线前单次检查只是起点。七条借鉴之首：设计任何评估维度前先回答「这个评估结果驱动什么动作」——驱动不了精调回滚/检索调参/Prompt 重写的指标只是周报装饰。

### 2.1 四层体系全图

### 2.4 作者反复强调的铁律与危险信号汇总

铁律（多篇复现）：
1. 每条「通过」必须能回答「它凭什么通过」；零判据不许通过，宁可标不可判定（001/006/007）。
2. 突变验证/变异测试是判据的体检：注入违规必须变红，杀不死变异体的断言形同虚设（001/012）。
3. LLM 裁判：先校准（κ 不用精确匹配率）再上岗，换版本重校准；换序双跑；回避同家族；陪审团制；能机械判的不劳裁判（006/007/013）。
4. 安全红线一票否决、并联恒评、不参与加权平均（007/010）。
5. 期望行为而非期望答案（010）；「不适用」不许掩盖真实失败（001）。
6. 评测器自己也要被评测：Judge/Rubric/Prompt 变更即回归，人机一致率是裁判 KPI（007/012/013/015）。
7. 坏例必须回流成回归资产（最小失败证据五要素、去重准入），评测集跟着线上风险走（002/007/009/010/013）。
8. 版本漂移是常态：评测长在 CI 里、版本升级必跑黄金集、指标退化禁止上线+灰度+一键回滚（002/005/007/014/015）。
9. 评测资产的价值=临界场景密度，不是用例总数；报告要有「已知未覆盖」栏（005/015）。
10. 每个评估维度先答「驱动什么动作」，驱动不了的不建；假通过比假失败更危险，保守倾向压低误杀（014/007）。

危险信号清单（出现即高分存疑）：考卷恒真（喂什么都通过）；裁判与被评同家族；比较类评测单顺序跑一遍；验收只报精确匹配率没算 κ；vendor 静默升级裁判没重校准；开放题全交给裁判无机械判据兜底；重试无上限；关键前置校验由模型自己决定做不做；只有技术指标没有重生成率/留存等业务指标；灰度策略答不上来；注入载荷藏在文件名/元数据等旁路字段；审计日志可被被测对象改写；仿真结论无实车/真跑对账；回归失败项与修复项无对齐机制。

## 三、对 SwarmStudio 的可借鉴清单

> 对照基线：SwarmStudio 已有七维标注、不可变考卷快照（EvalSetRevision）、同卷复评、A/B 同卷版本门、LLM 裁判 S0 规则+S1 判分+冲突仲裁+参照泄漏 swap-test、多裁判多数决、处置单+坏例回流回归库、四层金字塔+驾驭工程四层、红队域（8 攻击类目）+secaudit 六阶段、发布门禁六检查、G1-G6 六闸。已知空白：judge×人工一致率（kappa）校准、主观盲测面板、独立 BadCase 库实体、线上坏例自动采集、指标退化自动禁上/灰度回滚、合规对抗层未单列。

### P1（直接补已知空白）

1. **裁判 kappa 校准闭环**（来自 006 LLM 裁判 + 007 淘系 Meta-Eval + 013 美团）：建 100-200 条人工标注黄金集，以 Cohen's κ（非精确匹配一致率）为裁判验收线（参考线 κ≥0.6，目标学美团人机一致率 95%+）；裁判模型每次换版本/换提示词强制重校准并出校准报告，校准不达标裁判降级为仅建议。落地：在 EvalSetRevision 上挂一个「校准集」修订类型，S1 判分跑完自动与黄金集人工标注算 κ，进 G1-G6 闸之一。
2. **独立 BadCase 库实体化**（来自 002 主线 + 007 五要素 + 009 回流准入）：坏例从「处置单附属回流」升级为独立实体，最小失败证据五要素 schema（用户原始意图｜变化字段｜第一处错误工具调用｜实际副作用｜正确处置），按类型去重准入（防同类灌水），每条可判可复跑、绑定来源版本；库本身带版本管理，回归集从库中按域组合生成。落地：新增 BadCase 实体 + 准入去重规则（LLM 语义等价判定合并同型）。
3. **线上坏例自动采集**（来自 009 字节 Trace 采样 + 013 美团 Data Loopback + 015 理想强制快照）：线上会话 Trace 定时自动采样（按比例/按天），低分会话自动进待回流队列；用户点踩/纠错/人工接管等关键事件触发快照优先入队（理想「关键事件强制回传」的桌面版）。落地：最小版先做「点踩+低分 Trace 每周筛一次、去重后一键转 BadCase/考卷条目」，对齐字节「宁可慢不要灌水」纪律。
4. **指标退化自动禁上/灰度回滚联动**（来自 002 第四层 + 015 理想熔断 + 012 RRI）：A/B 同卷版本门升级为发布闸门——同卷复评分数较上一稳定版下降超阈值（如 -2 分或红线项新增）自动阻断发布并生成处置单；灰度期指标（线上低分率、红线命中）越线自动触发回滚建议；熔断阈值随灰度阶段联动（越早灰度越敏感）。落地：把现有 A/B 同卷门接进发布门禁六检查，加「对比基准=最近稳定版」与红线项零新增两条件。
5. **主观盲测面板**（来自 002 盲测 + 013 美团双轨盲评 + 007 千帆杯式专家投票）：为开放维度（回答质量、满意度）建盲测面板：每 case 2-3 名评审独立打分、隐去版本身份、去最高最低取均值、新旧版本背靠背盲选；评审间分歧样本自动进专家仲裁与 Rubric 迭代素材。落地：在 S1 判分之外加「人工盲评」轨道，人工分与裁判分交叉验证，分歧率本身作为裁判质量指标回流第 1 条的校准闭环。
6. **合规对抗层单列**（来自 010 腾讯安全独立赛道 + 014 百度红队算法化 + 011 WorkBuddy 攻击面清单）：红队域 8 攻击类目从主评测维度中拆出为独立安全 benchmark，独立评分、独立报告、一票否决不参与七维加权；按攻击面（提示注入/越权工具调用/敏感数据外泄/供应链）建专属断言，注入防御率=被拦截注入数/投放注入总数等口径直接采用信通院三指标。落地：发布门禁六检查中安全项独立成门，主分与安全分双轨呈现。

### P2（机制增强，补现有体系薄弱处）

7. **换序双跑 + 裁判回避制 + 陪审团**（来自 006 五守则 + 008 Swap Test）：现有 swap-test（参照泄漏）扩展为通用换序双跑——凡比较类判分正反序各跑一次一致才采信；多裁判多数决加「裁判与被评模型不得同家族」回避规则，PoLL 式三家族小裁判对冲自我偏爱。
8. **四档判分流水线改造 S1**（来自 013 美团）：把 S1 的开放打分改造成「红线/完美/无效三个二分类裁定器并行 + 全不命中默认中间档 + 冲突才上专家仲裁」——二分类比 1-5 分单裁判准确率高、成本结构省，与现有 S0 规则+S1 判分+冲突仲裁三层天然对齐。
9. **判据突变验证门禁**（来自 001 突变验证 + 012 变异测试）：每条新判据/守卫上线前必须通过「注入已知违规会变红」的变异测试（把被测 Agent 换成永远空值/永远违规的假对象重跑），杀不死变异体的判据不许上岗；同时补「零判据用例标不可判定退出统计」规则，堵假通过。
10. **四层归因进处置单**（来自 007 淘系）：处置单增加归因层字段（数据/Prompt/Rubric/Agent 四选一），坏例先归因再修复，防止「通过率一降就调 Prompt，根因在数据或 Rubric 越调越差」；同步吸收淘系「分母污染」教训——指标骤跌先查上游标注/路由分母。
11. **期望行为替代期望答案**（来自 010 腾讯）：考卷条目增加「期望行为」字段（权限不足时正确行为是拒绝并解释），补「拒绝后是否换个说法重试」进指标（011）；覆盖模糊意图、缺参数、工具超时等异常场景用例。
12. **CNT 漏斗 + RED 并联结构**（来自 007）：七维判分组织为串行漏斗（证据够不够 → 越界拒答 → 编造 → 工具参数 → 内容，任一层 0 后续短路），安全红线并联恒评不受短路影响；CTX 层是唯一允许 N/A 的层。
13. **轨迹级第二道闸指标**（来自 010 腾讯 + 007 首次偏离位置 + 008 轨迹三维度）：考卷判分加 Tool Head Accuracy（工具选择正确率，抓「碰巧答对」）、轨迹编辑距离（绕路程度）、首次偏离位置（新版本从第几步走偏）、冗余步骤比——都是机械可算，直接复用现有 trace。
14. **元评测常规化**（来自 007 + 012 + 015）：Judge/Rubric/判分提示词任何变更自动触发同卷复评回归（对齐 EvalSetRevision 快照能力），对账新旧判分差异；参照 IPD drift 0.1 口径设漂移告警线，裁判准确率跌破阈值自动降级为「仅建议人工确认」。
15. **在线质检用规则不用大裁判**（来自 013 美团）：线上自动采集的判分用低延迟规则检查项（敏感词、格式、工具调用合法性等几十个具体项）而非 LLM 裁判——在线链路要的是精度和延迟，LLM 精检留给离线。
16. **测试资产治理（给用例库做减法）**（来自 012 IPD 03 号）：考卷条目记「战绩」（历史拦截数），两年零拦截进僵尸观察名单；判据做变异得分体检；同型用例语义合并——回归时长本身是被治理对象，瘦身腾出的窗口塞更多红队与边界用例。
17. **评测集周期刷新与「已知未覆盖」栏**（来自 005 + 013）：考卷集按真实使用分布定期重分层抽样刷新（评测集不新鲜跑分就是自欺）；评测报告强制增加「已知未覆盖」章节，明示本轮没测什么。

### P3（远期/组织级）

18. **事故/坏例用例化 SLA**（来自 015 理想）：线上每起重大坏例/客诉 48 小时内转化为考卷变体（改输入、改工具故障、改边界条件）进回归库，事故进料是优先级最高的进料。
19. **口径翻译层**（来自 015）：评测报告在内部指标外强制生成用户/业务方可读的能力边界声明（哪些场景可信赖、哪些需人工兜底），评测口径与用户口径不对齐是信任事故之源。
20. **跨会话记忆连续性指标**（来自 013 ATLAS 交互地平线）：单轮考卷测不出跨会话失忆，为长记忆场景设计多轮连续追问用例（上午问过的下午追问），当前评测工具普遍空档。
21. **裁判校准后蒸馏降本**（来自 013）：高置信样本校准过的 LLM 裁判蒸馏成轻量判分模型用于高频低风险判分，大裁判只兜关键判分与仲裁。
22. **「评估器即回报函数」原则入设计规约**（来自 014 百度）：每个新指标立项前必须回答「这个评估结果驱动什么动作」（禁上/回滚/调参/重写/回流），驱动不了动作的指标不建；评估吞吐决定迭代频率，评测链路性能本身立项治理。
23. **RRI 版本就绪指数**（来自 012）：多维证据（回归分、红队通过率、变异得分、与近 3 稳定版缺陷密度对比）聚合为红黄绿三态秒级裁决，黄灯带条件过（必须修 AI 指定中高风险）、红灯拦；权重双轨标定+误拦率自动回测。
24. **影子预言机/参照对账**（来自 012 + 015）：对关键业务不变量（金额、幂等、授权）先写数学表达再穷举反例；仿真/mock 判分结果与真实环境抽样双跑对账，对账差超阈值 mock 结论降权——与现有 swap-test 思想同源，扩展到环境层。
