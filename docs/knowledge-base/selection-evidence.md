# 选型证据摘要（黑盒 POC × 全市场 × 源码白盒）

完整版为内部五件套（POC 终报 / 全市场对比 / 源码对比 / 双仓源码深读报告），本文件是可公开的结论层。

## 市场分层与终选

- **基座引擎层**（pgvector/ParadeDB/SQLite-VSS）：不自建。
- **平台层终选 WeKnora**（Tencent 开源，Go 单仓 3500 文件/1877 测试，Apache-2.0）：检索数学完整（两路召回 pgvector HNSW + ParadeDB BM25，加权 RRF k=60，复合重排 0.6/0.3/0.1，MMR λ0.7，常数全可调）、单 PG 一库三用架构收敛（5 容器）、敏感配置 AES-256 落库、内置 MCP server（端点级 token + KB 范围 + 限流）。
- **RAGFlow v1.0.0 列观察名单**：Go 重构版检索层未完工（无 RRF、词法腿权重写死 0.001、ColBERT 未实现）、api_token 明文存储、ES 内存独占 2.6GB；但 DeepDoc native ONNX 解析与 canvas 模板驱动摄取是真实资产。复查触发条件：RRF/权重可配化、ColBERT 回归、token 哈希化。

## 检索质量根因（源码级）

RAGFlow 盲测 1/3 的病根不在解析在融合：`retrieval.go` 融合权重常量 "0.001,1" 使词法腿在召回窗近乎失效，混合检索名存实亡——属重构未完成度，非调优空间。

## 图版 PDF 的真相（双平台对照）

同批电路图 PDF：两平台产出同为 OCR 字面标注（器件名/节点名散碎文本），均无视觉语义层。跨语种查询命中差异来自融合权重与嵌入模型跨语能力，不来自解析深度——评测「解析浅」类结论须先对照内容形态再下判语。

## 两个被证伪的流行说法

1. 「WeKnora 三路召回（含 PMI 图谱）RRF 融合」→ 源码实证两路；PMI 图谱是独立管线、不进 RRF、默认关闭。
2. 「Go 重写后 RAGFlow 内存大幅下降」→ 实测峰值 5.2GB/闲置 3.9GB，ES 主导，下降的是镜像体积不是运行内存。
