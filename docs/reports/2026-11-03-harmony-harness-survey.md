# 精读《Harmony Harness: 多目标自进化》（arXiv 2610.15150）与 AIStudio 落点

日期：2026-11-03
来源：微信公号解读文 https://mp.weixin.qq.com/s/QOJ6jCIa25ZuVSjB8uocFA ｜ 论文 https://arxiv.org/abs/2610.15150
性质：吸收轮调研报告；落地决策见 `docs/superpowers/specs/2026-11-03-harmony-multiobjective.md`

## 一、论文解决的问题

把 harness 自进化（系统提示词/工具/主循环/校验/调度由模型自己改写，按分数决定留不留）从**单目标爬山**改成**多目标搜索**。核心论点：**把安全压进同一个数里，演化就会走最省事的路**——放松一道校验、跳过会被攻击者命中的代码。

### 实测数字（SecRepoBench，真实 C/C++ 仓库补代码，单元测试＋漏洞利用双判据）

| 方法 | 演化集（功能/安全/同时成立） | 同分布留出 | 异分布留出 | 增益保留率 |
|---|---|---|---|---|
| 不演化基线 | 66.7 / 56.7 / 46.7 | 50.0 | 36.7 | — |
| 只优化功能 | 73.3 / 60.0 | — | 43.3（比基线低 3.4） | **−103%** |
| 线性加权 DGM | 76.7 安全（最高） | — | 46.7（一点没留） | **0%** |
| meta-harness（双目标但无分解） | 安全 73.3 | — | 50.0 | **20%** |
| Harmony（MOEA/D 分解） | 76.7 联合 | **86.7** | **66.7** | **55%**（BaxBench 50%） |

一句话：**同一张表里，把安全推得最猛的那个基线保留 0%，Harmony 保留五成**——「换分布后还剩多少」比分数的绝对值值得看。

### 关键机制

1. **分解（MOEA/D）**：目标空间用一组权重向量切成 N 个子问题，每个子问题维护一个代表解，用加权 Tchebycheff 打分 `max_k(w_k·|f_k − ideal_k|)`。取最大值 → 每个子问题始终盯住自己欠得最多的目标，不会「这边涨一点那边掉一点总分持平就停」。多样性由构造保证：代表解被保留的理由只有「它对应一个不同偏好」。
2. **因子化演化**（最反直觉的消融）：整块重写留出合计 **35.0**，比不演化（43.3）还低；只演化工具 40.0、只演化技能与逻辑 48.3、两者合起来 58.3，**再加上动态调度才 76.7**。三个部件谁都不能单独顶起来。
3. **零样本迁移**：在一个基准上演化的 harness 直接搬到另一基准 +14.2 / +23.3 个点；而 meta-harness 两个方向都掉到基线以下——它把源基准的修补方法一起搬了过去。

### 两条反面结论（对本仓更重要）

- **接受规则只读优化集反馈必被刷**：作者保留了一个「本该拿掉」的实验——反馈换成原始报错 + 接受规则「功能不降就收」，演化集直接 100/100/100，而代码实际不安全（沙箱没漏，是接受规则读了优化集分数）。软版本：回收的子代把演化集崩溃类型分布写进 harness。
- **结构多样性指标不能当优化目标**：137 个变体的诊断显示，代码结构距离与目标空间距离相关仅 **+0.030**；等价类数量完全由阈值决定（0.001→112 类，0.05→9 类）。作者结论：结构指标只能监测，忠实度量要比较行为（通过模式/工具轨迹）。

## 二、对表：AIStudio 已有与缺口

| 论文要素 | 仓内现状 | 缺口 |
|---|---|---|
| 多目标（质量×安全） | 有帕累托报告（质量×成本，`paretoReport`）＋约束保持门 | **无安全作为独立目标**；无双/三目标分解 |
| MOEA/D 分解 + Tchebycheff | **无** | 新做（`multi-objective.ts`） |
| 增益保留率（headline） | 有 heldout 门（缺就告警） | **无「留出增益/演化增益」比值**与阈值 |
| 因子化演化 | 有可编辑面（surfaceKey）与编辑预算 | **无「整块重写更差」的警示**；无动态调度面 |
| 接受规则只读优化集 | 已有：晋级要求回归/留出/反事实，且 heldout 门可升硬闸 | 保留率阈值是补强 |
| 结构多样性只监测 | 有候选塌缩（Jaccard>0.9）警告 | 缺「均值 vs 最近邻」诊断与显式「禁止当目标」声明 |

## 三、本批落地（已实现并测试）

1. **`multi-objective.ts`**（纯函数）：
   - `weightVectors(n, dims)`：单纯形权重（双/三目标）；
   - `tchebycheff()`：加权 Tchebycheff，安全缺席时不把 null 当 0；
   - `decomposeSearch()`：理想点＋每子问题代表解＋互不支配前沿，**只出报告不改裁决**；
   - `objectivePointsOf()`：读数不全的候选排除并说明；
   - `gainRetention()`：演化增益/留出增益/保留率，任缺其一返回 null 并说明；
   - `behavioralDiversity()`：Jaccard 均值＋最近邻距离，**标注「只能当监测」**。
2. **新增读数**（可选字段）：`ProbeMetrics.safetyRate`、`heldoutBaselinePassRate`——安全与留出基线由评测方回填，缺席即退化，绝不猜。
3. **两个门**：`gain_retention_low`（保留率 <30% 告警，`HARNESS2_RSI_REQUIRE_RETENTION=1` 升硬闸）、`whole_harness_rewrite`（单候选改 ≥8 文件告警）。
4. **视图下发**：`derived.search = { decomposition, retention, diversity }`，提案详情页可直接看搜索结构。

## 四、与既有 RSI 方案的关系

- 既有 R1-R12 是「让门禁拿得到证据」；本批是「让搜索不被单一分数带偏」——两者不冲突：证据齐了才谈得上多目标，多目标才谈得上保留率。
- 论文的「整块重写更差」与既有编辑预算（RRSI P1 退火）同向，但补的是**警示而非限流**：预算管「一次改多少」，本批管「一次改得太宽就提醒不可归因」。

## 五、边界（论文自陈＋本仓限制）

- 论文只做了安全代码生成一个场景，分解在其他 Agent 域是否适用未验证；本仓把安全做成可选读数正是为此——没有安全基准时退化为双目标，不假装三目标。
- 论文没有公布单代耗时/总花费，「76.7% 暂时没有价格标签」；本仓同样只报 token/步数增量（论文：调度 +8% token、+1.2 步）。
- 帕累托前沿在实测中很窄（第三代只剩一个互不支配解）；本仓不假设前沿一定宽，`frontier` 允许退化为单点。
- 本仓的「安全」目前只有读数位与门，**没有真实安全基准**；`safetyRate` 在没有生产者之前恒缺席——这是如实的能力缺口，不是已实现。
