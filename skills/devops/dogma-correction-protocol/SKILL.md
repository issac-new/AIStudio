# Dogma Correction Protocol（教条融合的排查与纠正协议）

> 定位：**完成时防线**——把外部理论/开源项目融合进集群契约或 skill 前，以及教条排查后决定处置时，必过的质量门。融合者的浆糊和排查者的剪刀是同一种病，本协议两头都拦。

## When to Use

- 把外部理论（哲学框架/经典著作/方法论体系）融合进集群契约、charter 或 skill
- 把外部开源项目的流程/设备移植进 _shared/ 规则文件
- 教条主义排查后的处置抉择（删/降/修/留）
- 蓝军 delegate_task 审查前的自检

## 门 0：贴标签式融合（BLOCKER）

**症状**：理论定义先行，工程例子只当注脚——理论原文复述 + 一张「理论概念→内部机制」映射表。

**判据**：逐行审映射表——右侧必须携带左侧没有的独立工程判据（阈值/触发条件/命令/排除项）；右侧只是把左侧概念换个名字 = 同义反复 = 0 信息量，删。自测法：把右侧理论词全部删掉看剩什么工程动作，剩不下 = 贴标签，重写。

**纠偏方向**：实践为体、理论为名——先承认集群工程实践早已在做（架构工程=系统论的工程化、可观测性工程=信息论的工程化、验证工程=科学方法论的工程化、交付运维工程=控制论的工程化），理论只负责给实践点名。数学工具不迁移（bit 计量/传递函数/卡尔曼滤波类），只取定性判据。

**规模错配（同族）**：千人大厂流程原样套进十人小队——每条流程问「谁消费它、拦住过什么」。

## 门 0-bis：机械审计法（排查存量时，只读）

1. **消费方实判**：grep 全仓 bin/scripts/skills/cron/config 找文档设备的运行时引用；0 命中=无消费方。CJK 模式 grep 误报 0 时用 python 逐字节比对复验，不信第一印象。
2. **夹具识别**：DB 表行全部同一秒批量插入 = 测试脚本夹具，不算消费证据。
3. **声称-实况对账**：部署面声称（如「下沉到所有 worker」）逐条 grep 实测计数；对不上 → 修声称对齐实况，不是修世界凑声称。

## 门 0-ter：纠正时盲目剪裁（BLOCKER）

**症状**：排查时把「尚无调用记录」等同于「无效」，一刀切删除先于使用而存在的方法资产。

**判据**：先分类问题性质——
- **假声称**（文档说 A 实况是 B）→ 修声称对齐实况。
- **先于使用**（资产已就位等时机）→ 给恰当应用通道 + 诚实标注证据状态 + 观察窗，不是删。

**分层处置**：契约层只放有运行时消费方的机制（无消费方移档案不删）；方法层允许先于使用存在但诚实标注（Wired/待实判）；档案层零丢失（归档可召回）。

## 门 0-quater：仪式化滥用（BLOCKER，Goodhart 诱饵）

**症状**：把判断力塑造型知识（决策清单/透镜/方法论四问）强制成 comment 念咒仪式。

**判据**：知识按性质选应用通道，不按「有无留痕」一刀切——

| 通道 | 形态 | 验证方式 | 适用 |
|---|---|---|---|
| 结构化 | 铸进格式与门：模板、frozen 验收、回滚预案字段 | 产物天然携带证据 | 不允许跳过的规则 |
| 决策界面 | SOUL/skill 按需加载，启发式 | 抽查产物质量，不查 comment 仪式 | 判断力塑造型内容 |
| 仪式化 | 强制打勾+执行率统计 | 机械统计 | 仅限有实测失败基线且复发频繁的场景；无基线不新建 |

方法论的结构化落点应铸进已有格式门，而非新增检查表。**证据活在产物里，不在检查表里。**

## 工程门（原 fusion 产出五门，全类型通用）

1. **编造 API**：代码示例的每个 API 字段先跑一次最小调用验证。
2. **环境假设**：bash 命令在目标环境实测；git 命令前检测 `git -C <dir> rev-parse --is-inside-work-tree`。
3. **伪函数**：每个函数调用要么有 import 要么标伪代码。
4. **数字不一致**：profile/文件数机械现算，禁沿用旧值；部署面声称先 grep 实测再写。
5. **过度承诺**：prompt 级机制配诚实标注（"prompt 级建议，无运行时强制，真正的强制靠 X"）；理论数学工具不迁移的裁定写明。

## 必跑验证清单

0. [ ] 映射表每行右侧有独立工程判据？理论词删掉后右侧仍剩工程动作？
1. [ ] 代码示例 API 字段跑过验证？
2. [ ] bash 命令在目标环境实测？
3. [ ] 无未定义函数伪装可执行？
4. [ ] 数字/部署面是实机计数？
5. [ ] 「强制」措辞配了诚实标注？
6. [ ] 方法论段落选对了应用通道？判断力型内容没被强制成仪式？
7. [ ] 纠正类改动区分了「假声称→修声称」与「先于使用→给通道」？没有一刀切删除未使用资产？

## 与蓝军审查的关系

本 skill 是自检门；蓝军 delegate_task 是独立审查门。复杂融合任务（≥6 次工具调用）两道门都过；教条排查任务本身也要过门 0-ter。

## Pitfalls

1. **自检走过场** — 清单打勾但没真跑验证命令 → 蓝军会抓到。
2. **蓝军读旧缓存** — 自检后改了文件但蓝军读旧版本 → 浪费审查资源，蓝军前确保产出已定稿。
3. **诚实标注后不补强** — 降级「强制」为「建议」后无替代运行时强制方案 → 标注中说明真正的强制靠什么。
4. **排查报告当裁决** — 只读审计产出的 findings 是证据不是处置令；处置必须再过门 0-ter 分类，由 orchestrator 决策。
