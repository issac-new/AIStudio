# Information Lens（信息论透镜）

> v1.1 融合表达重写（用户纠偏：工程实践为体、认识论为名）：可观测性工程就是信息论的工程化，本透镜把两边的概念一一接上线，不做哲学附体。

**等价对照**：可观测性三支柱（logs/metrics/traces）= 有效观测点设计；结构化日志与采样 = 编码压缩；告警聚合降噪 = 滤波；「这条日志能改变什么排障决策」= 信息增益判据。SRE 黄金信号（延迟/流量/错误/饱和度）= 关键变量识别——四个信号之所以是黄金，是因为它们覆盖了服务健康度的最小充分观测集。

**核心判据**：一条信息有价值 ⇔ ①能改变决策（可判定）且 ②获取成本低于决策改善（增益为正）。两者缺一 → 不采集。工程同构：不加「永不查询的日志」和「永远 0 命中的指标」，省下的注入和存储就是省下的成本（与 S4 只动注入侧同源）。

## 触发场景速查表

| 场景 | 判据/动作 | 可观测性工程同构 |
|---|---|---|
| 观测设计 | 先开变量再谈治理；观测周期快于被观测对象漂移 | 埋点先于功能上线；采集频率覆盖状态变化率 |
| 调研开工 | 信源独立性优先于数量；关键结论 2+ 独立来源交叉确认 | 交叉验证、独立部署的探针 |
| 信源/校验器评估 | 通道各环节尽量不同——同模型自审无效 | 异构监控栈；同源冗余防不了共因失效 |
| 指标上线 | 先过滤再反馈：窗口/样本量/置信度声明 | 告警去抖/聚合/抑制，带噪告警训练出告警疲劳 |
| 成本收敛方案 | 只动注入侧不动能力侧 | 采样率分级、冷热数据分层、保留策略 |
| 派工任务书 | 通道容量匹配：只放该任务需要的 context，附原文锚点不做二级转述 | 日志带 trace-id 直连原文；摘要衰减关键信息 |
| 报告验收 | 模糊措辞=0 信息量，禁入验收区 | 「服务有点慢」不是告警；「P99>2s 持续 5min」才是 |

## 使用规则

1. 观测/调研方案落稿前过相关行，必须写明「预期改变什么决策」；写不出 = 增益存疑，降级或砍掉该采集项。
2. 金书信息论成分（通道容量/滤波六法/信息衰减律）的论证与页锚在 skill `cybernetics-dual-lens` 及 concept-extraction.md，本 skill 不重复造锚。
3. 与方法问衔接：信息到位后立即转假设—验证—证伪循环（科学方法论），不停留在采集阶段。

## 不可迁移边界

不做 bit 计量——香农数学工具不进集群，信息价值用「可判定性+增益」定性判断（金书同款裁定）。
