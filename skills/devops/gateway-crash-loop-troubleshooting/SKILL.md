# Gateway Crash-Loop Troubleshooting

Diagnose and fix Hermes gateway startup failures, crash loops, port
conflicts, and stale Kanban dispatcher locks.

## When to Use

- Gateway won't start or keeps restarting (crash loop)
- `hermes gateway status` shows running but API doesn't respond
- Port 8650 bind errors (`[Errno 48] address already in use`)
- Kanban dispatcher refuses to dispatch ("another gateway holds the lock")
- SwarmStudio and launchd-managed gateways fighting over the same port

## Symptom → Root Cause → Fix

### 1. "Another gateway instance (PID XXXXX) started during our startup"

**Cause**: `KeepAlive=true` + `ThrottleInterval=30s` respawns every 30s
after exit code 1. Old process hasn't released the port → new one detects
double-run → exits → loop.

**Diagnose**:
```bash
grep -c "Another gateway instance" ~/.hermes/profiles/<profile>/logs/gateway.error.log
```

**Fix**: Kill all gateway processes, remove stale state, restart once.

### 2. "kanban dispatcher: another gateway already holds the dispatcher lock"

**Cause**: `~/.hermes/kanban/.dispatcher.lock` is a 0-byte sentinel. If
the gateway crashes without releasing it, the lock persists indefinitely.

**Diagnose**:
```bash
ls -la ~/.hermes/kanban/.dispatcher.lock
```

**Fix**:
```bash
rm -f ~/.hermes/kanban/.dispatcher.lock
# Restart gateway so it reclaims the lock
```

### 3. "[Errno 48] address already in use" on port 8650

**Cause**: SwarmStudio desktop app auto-spawns gateway processes for ALL
profiles on startup. Even though worker profiles have
`api_server.enabled: false`, the processes race to bind.

**Diagnose**:
```bash
lsof -i :8650 -sTCP:LISTEN
ps -eo pid,command | grep "gateway run" | grep -v grep
# Identify HERMES_HOME per process:
for pid in $(ps -eo pid,command | grep "gateway run" | grep -v grep | awk '{print $1}'); do
    ps -p $pid -E | grep -o 'HERMES_HOME=[^ ]*'
done
```

**Fix**: Kill the conflicting process, then restart the orchestrator gateway.

### 4. "Service definition is stale relative to the current Hermes install"

**Cause**: launchd plist was generated by a different Hermes version or
uses custom `ProgramArguments` (e.g. `start-gateway-with-dashboard.sh`).

**Fix**: `hermes gateway install --force --start-now` for default plist,
or ignore if the custom plist is intentional.

### 5. `hermes gateway status` says "not running" but gateway IS running

**Cause**: No launchd plist exists (SwarmStudio manages the gateway).
`hermes gateway status` checks for plist presence first.

**Fix**: Use these instead:
```bash
curl -s http://127.0.0.1:8650/health
# Or check gateway_state.json:
python3 -c "import json; s=json.load(open('$HOME/.hermes/profiles/orchestrator/gateway_state.json')); print(s['gateway_state'], s['pid'])"
```

## Diagnostic Command Sequence

```bash
# 1. Gateway process & launchd state
hermes gateway status

# 2. Port ownership
lsof -i :8650 -sTCP:LISTEN

# 3. API health
curl -s http://127.0.0.1:8650/health

# 4. Platform connectivity from state file
python3 -c "
import json
with open('$HOME/.hermes/profiles/orchestrator/gateway_state.json') as f:
    s = json.load(f)
print(f'PID: {s[\"pid\"]}')
print(f'State: {s[\"gateway_state\"]}')
for name, p in s.get('platforms', {}).items():
    print(f'  {name}: {p[\"state\"]}')
"

# 5. Crash-loop error count
grep -c "Another gateway instance" ~/.hermes/profiles/orchestrator/logs/gateway.error.log

# 6. Dispatcher lock
ls -la ~/.hermes/kanban/.dispatcher.lock

# 7. SwarmStudio-spawned gateway count
ps -eo pid,command | grep "desktop-runtime.*gateway run" | grep -v grep | wc -l
```

## Full Recovery Procedure

When the gateway is in a crash loop with port conflicts:

1. **Stop launchd service** (if using launchd):
   ```bash
   hermes gateway stop
   ```

2. **Kill ALL gateway processes** (launchd + SwarmStudio):
   ```bash
   ps aux | grep "gateway run" | grep -v grep | awk '{print $2}' | xargs kill -9
   ```
   ⚠️ SwarmStudio respawns worker gateways every ~7s. May need 2-3 rounds.

3. **Remove stale locks and deprecated config**:
   ```bash
   rm -f ~/.hermes/kanban/.dispatcher.lock
   # Remove deprecated .env vars that cause warning noise
   sed -i '' '/^MESSAGING_CWD=/d' ~/.hermes/profiles/orchestrator/.env
   ```

4. **Verify port is free**:
   ```bash
   lsof -i :8650 -sTCP:LISTEN  # should return nothing
   ```

5. **Start gateway**:
   ```bash
   # launchd (default plist):
   hermes gateway install --force --start-now
   # Manual background:
   HERMES_HOME=~/.hermes/profiles/orchestrator hermes --profile orchestrator gateway run --replace &
   ```

6. **Wait for full startup** — email takes ~2 min (IMAP + SMTP):
   ```bash
   sleep 120
   curl -s http://127.0.0.1:8650/health
   ```

7. **Verify dispatcher lock claimed**:
   ```bash
   ls -la ~/.hermes/kanban/.dispatcher.lock
   tail -5 ~/.hermes/profiles/orchestrator/logs/gateway.log
   # Should see: "kanban dispatcher: holding singleton dispatcher lock"
   ```

## Gateway Management Modes

### launchd-managed (default plist)

```bash
hermes gateway install --force --start-now   # install + start
hermes gateway stop                           # stop
hermes gateway uninstall                      # remove plist entirely
launchctl kickstart -k gui/$(id -u)/ai.hermes.gateway-<profile>  # restart
```

Pros: auto-restart on crash, auto-start at login.
Cons: `KeepAlive=true` can cause crash loops; stale plist warnings.

### SwarmStudio-managed (no plist)

SwarmStudio desktop app auto-spawns gateway processes for all profiles.
Orchestrator gateway binds :8650; worker gateways have `api_server: false`.

Pros: no crash loops from launchd respawn; SwarmStudio handles lifecycle.
Cons: `hermes gateway status` shows "not running" (no plist to check);
no auto-restart if SwarmStudio itself crashes.

### Choosing

- **Single-gateway (orchestrator only)**: launchd is fine.
- **Multi-profile with SwarmStudio desktop**: let SwarmStudio manage;
  uninstall the launchd plist to avoid port conflicts.
- **Custom dashboard startup**: use a wrapper script but expect "stale"
  warnings (false positive — safe to ignore).

## Pitfalls

### SwarmStudio respawns worker gateways every ~7 seconds

Killing SwarmStudio gateway processes once is not enough — it immediately
respawns them. If you need a clean slate, either:
- Kill in a loop (2-3 rounds with 1s sleep), or
- Quit SwarmStudio entirely, then kill remaining processes.

### Stale dispatcher lock after gateway crash

The `.dispatcher.lock` file is a 0-byte sentinel with no PID inside.
You cannot check "who holds it" — just `rm` it if no live gateway process
exists. The next gateway startup will reclaim it.

### `hermes gateway status` is unreliable without launchd

When SwarmStudio manages the gateway (no launchd plist), `hermes gateway
status` reports "not running" even when the process is alive and serving.
Always cross-check with `curl http://127.0.0.1:8650/health` or
`gateway_state.json`.

### MESSAGING_CWD in .env is deprecated

`MESSAGING_CWD=$HOME/clawd` in `.env` produces warning noise on every
gateway startup. It's been superseded by `terminal.cwd` in `config.yaml`.
Remove it:
```bash
sed -i '' '/^MESSAGING_CWD=/d' ~/.hermes/profiles/<profile>/.env
```

## Log File Locations

```
~/.hermes/profiles/<profile>/logs/gateway.log         # stdout
~/.hermes/profiles/<profile>/logs/gateway.error.log    # stderr
~/.hermes/profiles/<profile>/logs/dashboard.log       # dashboard (if using)
~/.hermes/profiles/<profile>/gateway_state.json        # live state
~/.hermes/profiles/<profile>/gateway.pid              # PID file
~/.hermes/kanban/.dispatcher.lock                     # dispatcher sentinel
```
