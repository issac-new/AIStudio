# 报告篇幅封顶压缩（report-slimming-orch）

> 定位：default profile 的 `document-writing-craft` 是写作质量权威（三毛病/三特征/去AI味/取舍）；本件只补「用户给定页数上限或否定逐对象陈述」时的压缩流程，机制冲突时以原件为准。

## 触发条件

- 用户对报告给出页数上限（「控制在 N 页以内」）
- 用户否定组织方式（「不需要每个 X 单独陈述」「总结概括下」「删掉流水账」）

## 压缩量判定

| 删除量占全文 | 方式 |
|---|---|
| < 1/3 | patch 逐处删句裁段即可 |
| ≥ 1/3，或逐对象结构被整体否定 | 走下方换轴流程 |

## 换轴流程（四步）

1. **换轴不裁枝**：删除全部逐对象小节，正文按机制/主线重组。对象只允许两种形态出现：
   - 一张定位表：每对象一行（定位、关键参数、路线特征），按路线定位分组，不按厂商排列
   - 机制段落内的证据句：「X 用 69 层线性注意力配 24 层稀疏检索」——对象名挂在自己的论点上，不为对象开节
2. **证据先迁后删**：被压掉的参数表、对比矩阵、术语表、完整文献清单先迁入伴随附录文件（优先复用既有提炼版/appendix 文件，禁建一次性文件），主报告结尾一行指针。分工铁律：叙事只在主报告、证据表只在附录——主报告不得复制证据细节，防双事实源。迁移完成才算删除完成（先存档再删）。
3. **全量重写优于密集 patch**：read_file 读完全文（超长用 offset 翻页，同时满足 write_file 的读后写 guard）→ write_file 重写。密集 patch 在大删除量下易吞相邻标题、留孤儿表格行与重复注释，修复返工成本高于重写。
4. **页数机械验收**：

```bash
python3 -c "import re;t=open('<报告路径>').read();print('中文字数',len(re.findall(r'[\u4e00-\u9fff]',t)),'总字符',len(t))"
```

按约 2000 中文字/页折算，表格篇幅另计（粗校准：8KB 含表格的 md ≈ 2–2.5 页）。超限回到第 1 步换轴再砍，不靠目测，交付时报出字数。

## 固定口径

- 用户否定的是组织轴不是信息密度：逐对象陈述=流水账，机制轴+对象作证据=概括
- 页数上限是硬验收项，与内容验收同权重
- 对 default 原件的补位建议留回复待前台直改，不在本件内扩写原件内容
