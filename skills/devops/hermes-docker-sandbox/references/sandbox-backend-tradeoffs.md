# 沙箱后端选型取舍框架（DSec 融合参考，2026-09-25）

> 来源：DeepSeek DSec 技术报告（arXiv 2609.22978；微信解读文 `workspace/research/ai-rd-fusion-20260925.md` [1]，mp.weixin.qq.com/s/Di54RybghrHcRkL6aSi-LQ）。
> 性质：**引用级参考**——DSec 为 RL 训练平台规模（日 300 万沙箱实例/峰值并发 38 万/创建 >5000 每秒），本机为单机 Docker Compose（worker 级容器 <10 个）；吸收的是**选型框架与原则**，不是三层架构（IAM/调度器/edge）与内核级优化。厂商单源，数字未独立复现。

## 一、四后端取舍表（按任务负载选型，不做全语义抽象）

DSec 统一入口 libdsec SDK「刻意不做全语义抽象——因为不同后端在启动开销、隔离强度、系统能力上的差异是本质性的，调用方必须按任务选型」。

| 后端 | 适用负载 | 隔离强度 | 启动开销 | 本机等效物 |
|---|---|---|---|---|
| FnCall（预创建容器复用，GPU 共享/独占） | OJ 判题、算子评测等短平快任务 | 弱（共享宿主内核） | 极低（复用池） | 无——本机无 RL rollout 粒度需求 |
| 容器 | 软件工程类主力任务：启动快、密度高 | 弱（共享宿主内核） | 低 | **当前形态**：per-worker Docker 容器 + `mem_limit`/`cpus` |
| Firecracker microVM | 安全类任务（更强隔离边界） | 强（独立内核） | 中 | 无——macOS Docker Desktop 不支持 Firecracker |
| 完整 VM（QEMU 安卓/图形桌面） | computer-use、移动端等需完整商用 OS 的负载 | 最强（完整 OS） | 高 | 无——macOS 上无此路径 |

**本机选型结论**：单机 macOS 环境下容器是唯一可用档位，但这应是**显式决策记录**而非默认——当负载出现「安全类任务需更强隔离」或「computer-use 需完整 OS」时，当前形态不满足，需迁移平台（Linux + Firecracker/QEMU）再谈。

## 二、三条可移植原则

1. **按任务选型，不做全语义抽象**：为不同负载等级提供不同隔离档位，让调用方按任务性质选——而不是造一个统一抽象把差异藏掉。差异是本质性的，藏掉的代价是选错档。
2. **按需加载 > 预拉取**：DSec 实测各语言镜像运行时真正被访问的数据只占 4.2%~13.3%——「全量拉取一个 12 GB 的 Java 镜像，92% 的流量是白搬的」。预拉取+预热路线被判死刑。本机启示：环境产物（含 skill/插件包）优先按需挂载，不做全量预热的「大镜像」。
3. **可组合环境层 O(m) > 大镜像 O(m×N)**：环境拆三块（基础镜像/workspace/toolkit）独立版本化独立分发，「升级 1 个 toolkit 只需重建 toolkit 自己」；熔成一个大 OCI 镜像则升级组合数级爆炸。本机启示：profile 配置/skill 目录/任务 workspace 三层分离现状与该原则同构，维持分离不合并。

## 三、不吸收项与边界声明

- **EROFS / virtio-pmem / DAMON / core scheduling 内核级优化**：Linux 内核特性，macOS Docker Desktop 不可用；本机规模（worker 级 <10 容器）不触发同类存储/内存/QoS 瓶颈。不吸收。
- **IAM/调度器/apiserver/edge 三层链路**：RL 训练平台多节点规模需求，本机单机不需要。不吸收。
- DSec 生产数字（300 万/天、3200 容器/节点、57% 磁盘写入下降等）为其自家环境实测，**引用时必须带「DeepSeek 生产环境单源」声明**，不作本机容量规划依据。
