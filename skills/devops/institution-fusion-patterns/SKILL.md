# 制度文档集 → 集群机制 翻译（institution-fusion-patterns）

> 触发：用户给一批组织内部治理制度文件（生产变更/监控/问题回顾/运维后评价等 docx/PDF），
> 要求深读后翻译落地为集群机制并回写设计文档。
> 与 GitHub/微信文章源的区别：无 clone/抓取环节，重点是**跨文件共性骨架提取**与**人类机制→机械闸门翻译**；
> 落地载体优先复用既有 skill 升版 + 脚本增强，而非新建规则文件。

## 翻译学说

同一组织的制度文件共享骨架：**准入资料单 → 分工(RACI) → 段式流程 → 特例通道 → 附录资料单**，
与集群「标准 → 闸门 → 有效性判定」范式同构。

翻译核心：把「人盯人」的环译成**机械闸门**——每环配齐三件，缺一不可：
1. **checklist**（逐项可二分判定的准入/验收项；允许标 `N/A+理由`，禁静默跳过）
2. **留痕载体**（kanban_comment / commit / 脚本输出）
3. **独立验证方**（交叉评审 / 复跑）——缺此项的闸门会被「自述已完成」绕过

三者齐备，制度强度才不随执行者自觉性波动。

## 工作流（制度 docx 集 → 落地，7 步）

1. **全文转档通读**：docx → python-docx/pandoc 转纯文本，**汇总前全文读完所有目标文件**，禁读片段即出总结。
2. **共性骨架提取**：跨文件比对段落结构，提炼共享骨架与逐文件差异点（谁多了特例通道、谁多了评分表）。
3. **机制映射表**：逐环提炼为 M1-MN，四列 `源机制 | 制度要点 | 集群落点 | 落地形式`；落点优先复用既有 skill（升版）与脚本（增段），确无载体才新建。
4. **载体落地**：skill 升版（版本号 bump + 新小节：准入清单/评审门/特例通道/观察窗）；脚本增强（如周报脚本追加评价段）。
5. **实跑验证**：脚本跑一遍留输出（rc=0 + 摘要）；skill 新小节按场景走一遍。**映射表每行必须有可运行载体并实跑一次**——没有载体的行是 present-not-wired，实跑输出是 Exercised 证据。
6. **设计文档回写**：新增小节 = 映射总表 + 闭环 mermaid 图 + 有效性段（图与编号规范见 orchestrator-lessons §七）。有效性段双论：充分性 = 环覆盖对照源制度无遗漏；必要性 = 抽掉该机制的失效模式，用集群真实案例做证据。
7. **参数等效翻译**：人类时间尺度参数（如「3-5 工作日观察窗」）译成集群等效机械动作（如「重型变更次日复跑 E2E 无异常才收口」），保留机制意图，禁照抄字面参数——直抄进集群是无意义形式主义。

## 收口判据

- 每个机制行有载体 + 实跑证据；映射行数 = 源制度可译环数（漏环 = 充分性缺口，回读源文件补）；
- 设计文档 § 悬空扫描为 0；图 vision 验收无标题截断、无单字孤行；
- 过程发现（如基线漂移真信号）留待裁决项写进交付汇报，不静默吞掉。
