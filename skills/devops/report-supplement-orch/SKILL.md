# 封顶报告增量补充（report-supplement-orch）

> 权威链：换轴重组/压缩流程以 default 的 `report-slimming-orch` 为准；写作质量门以 default 的 `document-writing-craft` 为准。本件只补「页数已封顶的主报告收到『补充 X 内容』」时的增量机制与 md 末行手术陷阱，不复制上述两件内容。

## 触发条件

- 页数已封顶（或已按机制轴收敛）的报告收到「补充 X / 加上 Y 行业 / 增加Z主题」
- 附带附录文件承接证据的报告做任何末行（来源 footer、单行参考文献）修改

## 增量补充五步

1. **先搜后写，每主题两轮**：第一轮广域拿全景，看缺口再发第二轮补洞。一手来源（厂商工程博客、会议/arXiv 正文、官方产品文档）优先于 SEO 聚合站；聚合站里的数字先认出它转述谁的一手结果——引用归一手、可信度按转述降档。
2. **主报告 § 级最小增页**：每主题一段机制段（3–6 句，数字带证据级标签）插入既有章节；仅当既有表格覆盖该维度时加行（锚定既有行整块替换），不为新主题开节开表。
3. **交叉引用接线**：新主题须在核心判断或趋势判断处接至少一处交叉引用（如「§4.2 行业证据」），否则是孤立补丁。
4. **证据进附录字母节**：全部数字与来源写入伴随附录的新字母节（沿用既有 A/B/C… 序列），节末固定一行 `> 来源：…`。主报告参考文献为单行长列表时，只在**行尾追加** [N] 新条目并标注批次；整行替换会静默吞掉上一批条目。
5. **终检三件**：复测字符数报页数；逐主题确认交叉引用在位；机械数附录 footer 行数对齐节数。

## 末行替换吞行陷阱（md 手术通用）

对一节的末行（来源 footer、单行参考文献）做 patch 时，old_string 若只含插入点周边文本，会把紧邻的保留行一起替换掉——被吞内容是静默的，不读回就发现不了。

规则：
- 末行 patch 的 old_string 从保留内容的最后一段起锚，确保被保留部分完整出现在 new_string 里
- 每次改动 footer/文献行后机械数行数对齐（`grep -c '^> 来源'` 对附录节数），缺了先回补再交付
- 同类排扫义务：一次手术吞了保留行，下次同型手术前先 grep 检查上一处是否也被吞

与 default 原件「删除编号体系必扫悬空引用」同属一类：文档结构手术必须配一次机械扫尾，不信目测。
