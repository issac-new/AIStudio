# 懒生成方法论（Lazy Generation）

> 来源：行者明灵《Harness实践：OpenSpec + Superpowers + CodeGraph + Ponytail + Caveman + RTK》上下篇（2026-09-16/17）+ [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail) v5.3.3（MIT；基准 2026-10-07，39 任务 × 5 次；本机源码级核对 2026-11-07）。
> 证据分级：仓库元数据=A（本机核验）/ 性能数字=B（官方 benchmark 自述）/ 文章对照实测=C（二手信源）。
> 纪律：只引用方法论模式，不 vendor 上游 skill；守决策 26/27——门禁 59 不增（捷径台账挂既有 check_adr 面，不新开 gate），本文档为纯文档载体。

## 一、定位：给"拼装式开发"一个可执行的决策程序

理念层"新功能 = 既有稳定单元拼装 + 最小新增胶水"回答了**为什么**，但没回答**写入第一行新代码前按什么顺序找零件**。七层懒人阶梯把"先查再写"变成自动下探顺序，任何一层命中即停：

| 层 | 先问 | 通过判据 |
|----|------|---------|
| 1 | 真的需要存在吗 | 改写/砍掉需求能消掉就不写 |
| 2 | 代码库里已有吗 | 组件库清单 / recipes 配方 / §A 同类功能命中 |
| 3 | 标准库能解吗 | 语言标准库直接可解 |
| 4 | 平台原生能解吗 | 宿主 / 框架原生能力可解 |
| 5 | 已装依赖能解吗 | 包清单里既有依赖可解（不为一个函数引新包） |
| 6 | 一行调用能解吗 | 单行 shell / 一行库调用 |
| 7 | 都不中 → 最小可用实现 | 只写撑起**当前**需求的最小集，不为想象中的未来预留 |

**整合**：开发工作流 ②探查先查 recipes 与 reference-manual（层 2 的机器面）；⑤编码逐层下探，落到层 7 才允许新增代码。探查产物"可复用稳定单元清单"（exploration-guide §C ★必查）就是层 2 的组件库清单。

## 二、懒 ≠ 偷工（lazy, not negligent）

上游原话"The rule was never 'fewest tokens'"——懒人哲学裁的是**代码量**，永远不裁**正确性**。五类永不裁剪（与开发工作流 门禁下限同向）：

1. 验证与测试（尤其保护真实行为的测试，不为绿而删断言）
2. 错误处理与数据丢失保护
3. 安全检查与信任边界的数据校验
4. 无障碍与可观测性
5. 用户明确要求的东西（"需求里写了"不属可砍范围）

目标技能侧口径：任务路由（task-methodology-router）调的是**仪式复杂度档位**（小任务轻流程），门禁序列与安全铁律不随"任务很小"豁免。

### 懒的是解法，不是改动本身

两条常被混掉：

- **解法最小**：用最少的新代码解决问题（七层阶梯管这个）。
- **改动完整**：任务需要的每一处都得改到——被改函数的调用方、被改签名的消费者、测试、夹具、配置、导出面。**"最短 diff"是在知道它必须碰到哪些地方之后才成立的**；不知道影响面就写的短 diff 不是短，是漏。
- 一行能看懂才算短。需要解码的一行不是短。

配套判据：同尺寸的两个方案，取边界正确性更好的那个；挪动或合并代码时，原有的错误处理与校验跟着走，不因"顺手简化"掉。

### 捷径要留账：`shortcut:` 标记

每个有意为之的简化在代码里留一条注释：

```
shortcut: <上限>, <何时升级>
```

- 上限 = 这个简化在什么范围内成立；何时升级 = 什么条件出现时必须回来重做。**两段缺一不可**——只写上限不写触发条件的，会静默腐烂成永久债。
- **捷径不是污点，未记账的捷径才是**（上游 `/ponytail-debt` 原话）。
- 机检：`check_adr` §5 扫注释前缀（`#` / `//` / `/*`）后的 `shortcut:`，有标记不罚，缺逗号（即缺"何时升级"）计 `no-trigger` 并 warn。扫描面 `ts,js,tsx,jsx,py,go,rs,java,cs,php,rb,kt,swift`，不含 `sh`（门禁源自身是 shell，字面命中会自伤——已知限制）。
- 台账盘点用同一条模式人工复查：`git grep -nE '(^|[[:space:]])(#|//|/\*)[[:space:]]*shortcut:'`。
- 与决策侧台账互补：`decision-governance` 记 `gstack-shortcut(dec-<id>)`（挂在决策记录上），本节记代码级标记（挂在代码上）；两者是同一笔债的两个视角，不复记。

## 三、证据与边界（诚实登记）

- **官方基准（B 级，2026-10-07，39 任务 × 5 次，Opus 5.5）**：相对无技能臂，LOC −53% [−63..−41]、输出 token −45%、成本 −26%、耗时 −41%；18 项隐藏检查通过率 96.7%（无技能臂 95.6%，**持平不劣化**）；风险逻辑带测试 98%（无技能臂 68%）；跨 diff 问题检出 100%（无技能臂 78%）。
- **方法学**（引数字时连同口径一起引）：成对实验臂逐任务交替；每任务 5 次取中位数 → 逐任务算比值 → 取几何均值，报 95% bootstrap 区间与符号检验；每个成品单元隔离宿主 `CLAUDE.md`、仓库上下文与自动记忆，只加载被测插件；全程禁用 Bash——测的是"写出什么"，不是"能不能调试"；21 项非隐藏检查任务的完成度另由盲评判官判定（判官自检通过）。
- **基线伪影教训（上游 issue #126，A 级）**：早先宣称的 −80~94% 总体数字系会话基线伪影，官方已澄清修正——**单例峰值 ≠ 总体均值**。引用上游数字必须写轮次与口径；与"缺失证据不显示为零"同族的估算诚实纪律。
- terse 模型可能因懒生成反烧更多 thinking token（净收益为负的场景真实存在）——按项目模型档实测，不默认开。
- **装完 ≠ 激活**：上游 skill 生效须宿主按内容哈希（trusted_hash）审查信任后激活——"装了≠生效"诚实族，目标技能 hooks 部署文档同口径披露。
