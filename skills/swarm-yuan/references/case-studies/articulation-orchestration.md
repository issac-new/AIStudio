# 案例研究：关节编排（Articulated Orchestration）汇报场景的能力映射

> 真实汇报场景：《AI 赋能研发工作的系统方案》——以「关节编排（Articulated Orchestration）」为核心方法论，面向公司技术总裁，金融清算核心系统交付（资金 0 容错 · 等保四级 · 变更可追溯）。swarm-yuan 的抽象能力在此场景中被映射为一套可对外讲述的工程叙事，每个论点都有机器执法机制兜底「凭什么可信」。

## 为什么需要这个案例

swarm-yuan 的能力（特征卡 / 门禁 / verifier / 合规矩阵）本身是工程化的，但对外汇报时需要一套叙事把抽象机制翻译成业务方可理解的「承诺」。关节编排方法论天然契合：

- **关节** ≈ 特征卡第 11 项「可复用稳定单元」（五维字段：签名/路径/用途/复用方式/稳定性标注）
- **编排约束** ≈ 调用链路分析 §C+.2/C+.3 推导出的导入方向/注册顺序/路由挂载/状态所有权/测试边界
- **安检** ≈ 56 门禁三档 enforce + verifier 司法独立验证
- **左移** ≈ spec 模板 §19/§20/§21 + `--shift-left` 门禁

## 关键纠偏：10⁻¹⁰ 失效概率的归属

PPT 侧的「10⁻¹⁰ 失效概率」是汇报方基于分层防御（strict fail-closed × C1 行为等价 × fixture 双态）独立层残差连乘的**推演模型**，**不是 swarm-yuan 仓库的直接输出**——swarm-yuan 提供分层结构作论据基底，数值化概率论证由使用方自行构造。引用时须区分「工具直接输出」与「使用方推演」。

> 全仓库 grep `1e-10` / `10^-10` / `失效概率` / `FIT` 零命中——这不是遗漏，是职责边界：swarm-yuan 是结构层工具，概率推演是使用方的论证层。

## 关键纠偏：profile 是 4 档不是 3 圈

`FACT_PROFILES=4`（auto/lite/standard/compliance）。汇报场景若用「三圈分级模型」措辞，应映射为 lite/standard/compliance 三档 + auto 自动选择器，建议对外措辞用「四档自适应」更准确。

## 关键纠偏：「103 组件」是项目枚举产物非 skill 硬数字

swarm-yuan 的清单是按目标项目动态枚举（计数核验 ≥ 枚举 × 0.95）。「103 个零件 · 18 类」是某个具体目标项目的枚举产物，不是 swarm-yuan 自身的固定数字——引用时须注明出处（如「某清算核心系统枚举产物」），避免被误读为 skill 的能力上限。
