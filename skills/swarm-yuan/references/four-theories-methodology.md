> **何时读我**：给系统划边界/建模型、评估一段内容值不值得进上下文预算、设计新门禁或强制机制、评估门禁是否拦得住/拦太多、诊断修复环失效、做项目探查建模/裁剪上下文预算预算时。四个来源：系统论与信息论经典框架（整体观与信息度量）+ 钱学森《工程控制论》（*Engineering Cybernetics*, 1954）的系统设计纪律 + 金观涛/华国凡《控制论与科学方法论》（1983）的认知方法论，共同作用于 swarm-yuan。

# 复杂系统方法论四论（系统论 · 信息论 · 科学方法论 · 控制论）

## 总纲 四论闭环

面对复杂系统，四个"论"各回答一类问题，合起来构成完整的认识与行动体系：

| 论 | 目标 | 核心问题 | 主要手段 | 产出 |
|----|------|----------|----------|------|
| 系统论 | 认识系统 | 系统是什么、如何构成、如何运行 | 边界、要素、层次、结构、关系、环境、建模 | 系统结构与整体模型 |
| 信息论 | 降低不确定性 | 什么信息最有价值、如何有效获得 | 测量、信息增益、筛选、编码、压缩、去噪 | 关键数据与有效信息 |
| 科学方法论 | 获得可靠认识 | 假设是否成立、模型是否有效 | 观察、假设、建模、推演、预测、实验、验证、修正 | 理论、模型与可验证知识 |
| 控制论 | 实现目标 | 如何行动、如何纠偏、如何优化 | 目标、测量、比较、决策、执行、反馈、调节 | 控制策略与动态结果 |

四者不是线性排列，是相互耦合的闭环：**系统认识 → 信息获取 → 建模验证 → 决策行动 → 结果反馈 → 再认识**。系统论界定对象与变量；信息论解决"应该观察什么、测量什么、优先获取什么"；科学方法论把信息转化为可检验的模型；控制论把验证过的认识转化为目标、决策与行动；控制过程产生的新状态、新数据、新异常，又成为再认识的输入。

swarm-yuan 自身就是这个闭环的一个实例：探查建模（系统认识）→ 指纹与 inventory 观测（信息获取）→ fixture 正反例与 self-check（建模验证）→ 生成与日常使用（决策行动）→ 决策留痕与 gate-trends 质询（结果反馈）→ 重探查落新基线（再认识）。以下四篇按闭环序展开：系统论篇（看清）→ 信息论篇（看准）→ 认知方法论篇（认识可靠）→ 设计纪律篇（行动有效）。

## 系统论篇 看清整体与结构

swarm-yuan 面对的系统有两个：它自身（生成器 + 目标技能），和它治理的目标项目。新机制、新文档、新计数入网前，先用结构七问定位——答不出位置的改动不入网：

1. **边界在哪？** 它属于生成器侧还是目标技能侧？两体边界（生成器厚/目标技能薄）不容骑跨；不属于任一侧的东西先问该不该存在（术语边界把"什么不属于本系统"显性化）。
2. **要素进哪个计数？** 全要素在 facts.conf 单一事实源计数对账（56 门禁四族清单同理）——新要素不配计数就是黑户。
3. **属于哪一层？** SKILL.md 五层（理念/设计/架构/实现/使用/引用）+ 五层单向依赖——它依赖谁、谁依赖它，方向对不对？
4. **与谁耦合？** 它进生成流程还是开发工作流（日常使用）？这条循环里它的上下游各是谁？
5. **概念的消费方是谁？** 概念↔实物追踪表三列（诞生步/消费方/回流点）填得满吗——填不满的概念是装饰。
6. **环境变化谁感知？** 它引用的外部事实（上游版本/许可证/运行时）由 upstream-baseline 登记 + drift 检测覆盖吗？
7. **演化留痕在哪？** 它的改动在决策史（design-evolution）里留不留痕——不留痕的演化不可回溯。

三条整体论原则：

- **整体不等于要素之和**：单看每个门禁是一个 grep 脚本，整体看是控制系统的检测面。评估任何单点改动，先问它在结构中的位置（配套检查单见设计纪律篇五问）。
- **层次的目的是封装**：每上升一层，下层细节被封装为可推理的单元（56 门禁 → 四族 → 检测面），上下文预算预算才得以成立——分层是压缩的前提（见信息论篇）。
- **边界即裁剪**：被排除在边界外的内容（不支持的宿主、不取的方法，见文末边界节）与边界内的内容同等重要——没有边界声明的系统不可理解。

## 信息论篇 获得关键与有效信息

一条主线：**以最小的信息代价获得最大的认知增益**。一段内容的价值不在于它说了多少，在于它替读者排除了多少不确定性（金观涛定义，展开见认知方法论篇"信息度量"）。七个手段在 swarm-yuan 的对应：

- **信息度量**：上下文预算 ≤11392B（≈11KiB）/≤598016B（584KiB）是"只装缩小不确定性最多的内容"的操作化（展开见认知方法论篇"信息度量"）。
- **信息增益**：观察点的选择决定增益。探查不是"把项目读一遍"，是设计高增益观测——特征卡 17 项，每一项排除一整类不确定性（技术栈、入口、测试命令、约定……）。观察先于行动（见认知方法论篇"黑箱与可控制变量"）。
- **编码**：信息的形态决定使用成本。"何时读我"路由头是寻址编码——读取之前先排除无关文档；rules.d 三值把"该不该拦"的判断编码为可审计的数据；Conventional Commits 把变更意图编码进历史。
- **压缩**：信道有容量约束。SKILL.md ≤11392B（≈11KiB）、reference-manual ≤32KiB 是硬预算；压缩的判据不是"短"，是单位字节排除的不确定性——无消费路径的内容信息量清零（预算）。
- **筛选**：原始信号不等于信息。56 门禁从 AI 的全部行为输出中筛出需要响应的信号；特征卡从全量源码中筛出治理所需的面。
- **噪声抑制**：信号按误报率分级，噪声不得获得阻断权（见设计纪律篇"信噪比分级"）；重复报警是噪声——failure-detector 对同一失败只报一次，是噪声抑制的实例。
- **传输**：信道只载信号且失效语义明确。hooks 在 Claude Code 与 Codex 两类宿主上的挂载是把门禁判定送达 AI 行动前的信道；fail-open / fail-closed 的选择就是信道失效语义的设计（见设计纪律篇"闭环兜底"）。

本文档自身即信息论的产物：带路由头（编码）、按篇组织互指不重复（去重）、预算内成文（压缩）。

**三种熵——AI 编码系统的熵分解透镜（来源：《Harness实践》）**：失控时先命名熵在哪一类，再选治法——三类各有正交的治理面，混治等于不治：

| 熵类 | 失序形态 | swarm-yuan 治法（既有） |
|------|---------|------------------------|
| **流程熵** | 范围蔓延 / 阶段跳跃 / 目标漂移 | 状态机阶段守卫 + 任务路由档位 + trace-log 决策留痕 |
| **代码熵** | 过度工程 / 重复造轮子 / 无谓抽象 | 拼装式开发 + 懒生成七层阶梯（`lazy-generation-methodology.md`）+ check_reuse |
| **上下文熵** | 过期信息滞留窗口 / 陈旧结论反复自证 | 指纹感知变化触发重探查 + 交接包压缩（comet Context Compression）+ 按 fingerprint 失效缓存 |

## 认知方法论篇 形成可靠、可验证的认识（控制论与科学方法论）

目标项目对 AI 是一个黑箱——内部结构未知，只能通过输入输出认识。swarm-yuan 的全部认知设施（探查/特征卡/地图/预算）是同一件事的四个面：**把黑箱变灰箱，并让灰箱可维护**。

### 可能性空间与范围控制

**控制 = 在事物可能性空间中进行有方向的选择**（原著："人们根据自己的目的，改变条件，使事物沿着可能性空间内某种确定的方向发展，就形成控制"）。门禁的本质由此定义：把 AI 行为的可能性空间从"任意可写出的代码"缩小到"该项目合规的代码"。三环节：了解可能性空间（特征卡/地图）→ 选择某些状态为目标（spec）→ 控制条件使事物向目标转化（门禁/hooks）。

- **控制能力的度量 = 缩小倍数的连乘**：一次操作把可能性缩小到 1/n，控制能力即 n；多道检查串联的总能力 = 各道连乘（原著 12 球案例：废品空间 12×2=24 态，天平每次缩到 1/3，3 次能力 3³=27 ≥ 所需 24，故 3 次足够）。fixture 正反例测的就是每道门禁的缩小能力；零拦截（窗口内每次执行全 pass，零 fail 零 warn）= 该道从未发现问题、能力未获证据，入 gate-trends 零拦截清单按季度质疑。
- **控制的目标是范围，不是唯一点**（原著捕鸟网寓言：把鸟控制在整个网内即完成控制，想缩到唯一网眼反而失灵）。门禁不要求 AI 写出"唯一正确代码"，只把行为缩进合规范围——追求唯一解的过度精确控制会使控制失灵，这正是 warn/advisory 档存在的原理依据。
- 分级即预算分配：strict 花在"一次就排除大量错误"的检查上（计数核验/路径存在性）；缩小能力弱或误报高的检查不给阻断权（见设计纪律篇"信噪比分级"——两篇在此闭合）。

### 黑箱与可控制变量

**对象的黑箱程度不取决于对象，取决于认识者与认识方法。** 同一项目对懂该领域的 AI 是灰箱，对不懂的是纯黑箱（领域知识库防达克的另一表述）。

- **黑箱由一对变量刻画**（原著 §5.1）：**可观察变量**（客体输出侧）支撑认识，**可控制变量**（主体输入侧）支撑改造；实践活动 = 主体与客体的反馈耦合。治理只能压在可控制变量上——hooks 拦"写文件/跑命令"（可控制），不拦"AI 怎么想"（既不可观察也不可控制）。
- **认识 = 建立模型**：探查产出特征卡与地图——不追求打开黑箱（全量源码理解），追求可工作的灰箱模型（路径真实存在 + 计数核验 ≥0.95 + 稳定性标注）。
- **实践 = 给黑箱输入并观察输出**：目标技能投入使用后，门禁结果、测试红绿、审查发现（可观察变量流）都是对模型的持续校验——path-check 失配、计数骤降即模型失配信号。
- **认识与实践迭代循环**：fingerprint 感知项目变化 → 局部重探查（再认识）→ 单条更新落新基线。自成长链就是黑箱认识论的迭代环。
- 结构性分叉与局部扰动分治：指纹微变 = 局部扰动（变化目录内重探查）；指纹大变 = 系统分叉（全量重探查），不允许用局部修补应付结构性变化。

### 共轭变换

**不可直接控制的，先变换到可控域，控制后再变换回来（L→A→L⁻¹）。**

- 直接约束"AI 往项目里写什么"不可控；变换：探查建模 + 生成目标技能（L）→ 在受控域执行（A'：spec 约束 + 门禁检查 + hooks 拦截）→ 产出回写到项目（L⁻¹）。生成器整体就是一个共轭控制结构。
- "门禁本身有效"不可直接测；变换：fixture 正反例把有效性变换为可测对象（violating 必须被检出 / compliant 必须放行）。
- "该不该允许这条命令"不可直接枚举；变换：rules.d 把判断变换为 pattern 三值求值（数据可审计、可沉淀）。

### 信息度量

**信息 = 可能性空间的缩小（金观涛定义）。** 一段内容的价值不是它说了多少，是它替读者排除了多少不确定性。

- 上下文预算（SKILL.md ≤11392B、references 拷贝 ≤FACT_ARTIFACT_BYTES_BUDGET，当前值见 facts.conf）的本质：只装"缩小不确定性最多"的内容。两列地图（路径 + 说明与约束）是高信息密度形态——路径排除"在哪"，稳定性标注排除"能不能动"。
- "何时读我"路由头是信息效率设计：让 AI 在读取前就能排除"本文档与当前任务无关"的可能性——路由本身就在缩小可能性空间。
- 反面：重复表述、装饰性概念、无消费路径的内容信息量为零（对应生成物预算与概念落地问责——三制度在此获得信息论表述）。

### 质稳定与受控质变

- **质的稳定性 = 大干扰下状态变化小、偏离后自动回归**——last-good 基线（骤降 >50% 拒写）与 56/56 可达率断言就是该性质的操作化。
- **改变系统结构可以控制稳定性**——profile 四档（lite/standard/compliance）就是用结构参数化调节稳定域宽度。
- **控制的另一目的是引入质变**（新架构取代旧架构）：--upgrade 升级机制与重探查落新基线是受控质变通道——质变走通道，不悬空发生。

## 设计纪律篇 把认识转化为行动（工程控制论）

目标技能的有效性不靠 AI 自觉，靠结构：要求写进 prompt 的同时，必须有机器机制检测它、反馈它、校正它——prompt 约定是开环（AI 可能不执行），hooks 拦截是闭环（违反必然被检测并阻断），合法形态是"开环提要求 + 闭环兜底"。以下五条纪律是这套结构的出厂设定。

### 闭环兜底

**任何强制必须有检测→反馈→校正的闭环；开环（约定、提示、自觉）只允许存在于有闭环兜底的地方。**

- prompt 约定（spec 铁律写进 SKILL.md）是开环——AI 可能不执行；hooks 拦截（fail-gate-hook deny）是闭环——违反必然被检测并阻断。
- 只有开环没有闭环的要求不是要求，是许愿。
- fail-open 只许出现在有下层闭环的地方（hook 失败不阻断，因为命令还要过 precheck 门禁）；权限边界必须 fail-closed。

### 冗余协同

**系统可靠不依赖元件可靠。** AI 会写错代码、漏跑检查、产生幻觉——这是给定条件，不是要解决的问题。可靠性从系统结构中来，三要素：

- **冗余**：多层兜底（hooks 拦截 → precheck 门禁 → 状态机阶段守卫 → 独立验证器；一层失效下一层还在）。
- **反馈**：每个产出被独立检测（verifier 用 fixture 正反例验证门禁本身；gate-runs 账本记录每次触发）。
- **协同**：分层隔离（地图损坏不影响约束层；rules.d 缺失退最小规则集——故障不跨层传播）。

推论：评估一个新机制，先问"它失效后谁兜底"。答不出兜底者的机制在放大单点故障。

### 误差不放大

**误差在产生的环节内被校正；带误差进入下一环节前，误差必须清零或显式登记。**

- fail 之后的修复环：resume 原实现者修复 → 复审 → 熔断裁决（R=5 逐条 adjudicate，禁止静默丢弃）。
- 未修复的误差不是"下次再说"，是入破窗清单并阻断 ship——**系统可以带已知误差运行，不可以假装没有误差运行**。
- 对照：静默跳过（skip 不披露）、静默降级（fail-open 无兜底）、静默吞错（`|| true`）都是误差放大器，一律禁止。

### 信噪比分级

**检测信号按误报率分级进入主回路；噪声不允许获得阻断权。**

- strict（真信号，≥3 fail 可阻断交付）/ warn（疑似噪声，报告不阻断）/ advisory（背景信号，只留痕）三级。
- 判定标准是**误报率**而非重要性：自动 grep 在 taste 类判定上误报高（信号淹没在噪声里），再"重要"也降级为 AI 判断引导。
- 新门禁入网先挂 advisory 观察（gate-trends 记录拦截率），零拦截门禁入季度质疑——**信噪比是维护出来的，不是一次设计出来的**。

### 镇定与稳定域

**扰动把系统推出稳定域后，控制动作使其回归稳定域；校正失败则退回上一稳定态，不带病前进。**

- 扰动：项目演化（依赖升级/结构变更）。感知：project-fingerprint 秒级 diff。校正：变化目录局部重探查 → inventory 单条原子更新 → 落新基线。
- 稳定域由机器锚定义：last-good 基线（质量骤降 >50% 拒写——坏状态不覆盖好基线）、56/56 门禁可达率、上下文预算 ≤598016B（584KiB）。
- 校正动作失败（重探查仍无法解释变化）：退回 draft 态人工介入，而不是让账本继续以失真的地图运转。

### 设计新强制机制的检查单（五问）

新机制入网时先在生成核对清单（generate-skill.sh）补一行"门禁名 + 触发面 + 证据落盘"，再过五问：

1. **闭环在哪？** 谁检测、谁反馈、谁校正——三缺一就不是强制。
2. **失效后谁兜底？** 本机制失效不放大误差（有下层闭环）才算合规。
3. **信噪比多少？** 误报率可观测吗？初挂 advisory 了吗？
4. **误差出口在哪？** 拦下之后修复路径是什么（FORBID 带替代）？
5. **扰动下怎么镇定？** 项目演化后本机制的锚（路径/计数/签名）谁更新？

**空窗期声明**：零拦截清单的"季度质疑"节奏当前靠人工触发（gate-trends 手动跑）；目标技能侧 gate-runs 数据积累不足时，多数门禁执行记录少且全 pass，清单偏长——这是数据冷启动的正常态，不是门禁失效，别在数据不足时下岗判断。
