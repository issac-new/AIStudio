# 洁净代码度量方法论（Clean Code Metrics）

> 来源：`unclebob/ub-mode`（GitHub API 实测 4,858★；`README.md` 2,195B + `SKILL.md` 3,958B，master；2026-10-30 抓取）。
> 证据分级：仓库元数据 A（本机实测）；规则原文 B（官方一手）；第三方解读 C（不采信）。只取模式不 vendor 上游；ub 指 Uncle Bob，与本仓无关。

## 一、命题

长 prompt 里的规则受 Lost in the Middle 影响，越靠中段越易被忽略，规则堆得越多越像建议。ub-mode 把质量约束外化成确定性工具，Agent 只读工具算出的分数，不靠自我声明。本仓同一路线；本档补其中两处度量缺口——**复杂度**与**重复度**。

## 二、三阶段（每处改动都走）

| 阶段 | 纪律 | 本仓承载 |
|------|------|---------|
| 先让它能工作 | 最小改动；一处决策只写一处；先写会失败的测试并确认它因预期原因失败；写不出诚实测试就别凑劣质测试 | 节点⑤模板 + `--shift-left`（同批 test+impl）+ 零断言/断言密度/负向占比/聚焦测试（`_ct_test_quality_check`） |
| 再把它做好 | 修根因（只掩盖崩溃的防护判断不算修）；测试可观测行为、不绑实现；重构固定行为只改结构 | `check_test` 第二层 + §四 指标 + §七 人审清单 |
| 守工程实践 | 留痕（每条改动与理由）；护上下文（主线精简、细节外置）；清理工作区（不动未提交内容）；小批有序提交并写明验证方式 | `trace-log`/`decisions.jsonl` + 审查记录 + 工作流 ⑧⑨ |

判据：**一段测试若在每个函数都返回空值时仍能通过，就没有测到行为**，删掉重写。

## 三、架构边界（写代码时自查）

数据只在入口校验一次，进入内部直接信任；业务逻辑尽量纯函数；用类型让非法状态写不出来；外部数据只解析一次；操作幂等（重复执行或崩溃重试后最终状态一致）；共享可变状态先分离，必须共享时只留一个写者并由结构强制。

## 四、度量口径与阈值

| 指标 | 口径 | 阈值 | 本仓承载 |
|------|------|------|---------|
| 圈复杂度 | 函数内决策点近似计数（if/for/while/case/when/catch/elif/`&&`/`\|\|`/`?`） | `COMPLEXITY_MAX`（建议 15） | `check_method_size` 复杂度维度（启发式，warn） |
| CRAP | CC²×（1−覆盖率）³+CC，须**逐函数**覆盖率 | < 10 | **须外部工具**（crapper 等）；本仓不伪造 |
| 重复度 | ub-mode 口径=块相似度（≥0.8 即须消除）；本仓内置=连续行块精确重复，外部工具=项目重复率百分比 | `DUPLICATION_MIN_BLOCK`（建议 8 行）、`DUPLICATION_MAX_PCT`（按项目基线定） | `check_reuse` 重复维度：内置 Type-1 精确块粗筛 + 外部 `DUPLICATION_CMD` |
| 变异分数 | 杀死变异体÷生成变异体 | `MUTATION_MIN_SCORE`（建议 ≥60） | `check_test`（`MUTATION_CMD`，既有） |

四项均默认关闭（0），配置后执法、未配置诚实跳过。内置重复检测只认 Type-1（忽略空白与注释后的精确重复），改名的 Type-2 近似重复须外部工具。

## 五、阈值标定（ub-mode 踩过的坑）

工具默认值 ≠ 规则值：dryer 原生默认相似度 0.82，ub-mode 要求 0.8，照抄默认参数会漏检。外部工具阈值必须显式写进 conf，并在 spec 记「工具默认值 / 本项规则值 / 理由」三件；只配命令不配阈值时门禁报未标定（`DUPLICATION_CMD` 已内建该配对守卫）。

## 六、边界：指标是兜底，不是万能药

覆盖不到越权、性能退化、业务语义理解偏差；模块拆分与依赖规划是人的战略工作，AI 只做战术编码与反复校验；指标全绿不等于可发布（还须 ⑦ 审查与 ⑨ 主干回归）；小步迭代优于大需求，一轮做完由人复盘架构再继续。

## 七、人审清单（不可机器化项）

1. 测试是否只绑定实现细节（私有方法、内部调用序列、mock 调用次数）？
2. 新增逻辑前是否先消除既有复杂度（先减后加），而不是把新需求硬塞进旧设计？
3. 修的是根因，还是给症状加了防护判断？
4. 同一前提下的两次修复都失败时，是否停下把该前提写成一句话再动手？
