## 三、知识地图（从已落盘全文提炼）

### 3.1 外卡收单 vs 外贸收款（目标号 #1）

- **外卡收单** = 管买家付钱（前端成交）：海外买家 Visa/Mastercard → 卡组织 → 收单机构 → 卖家海外账户 → 结汇回国；全程线上自动
- **外贸收款** = 管自己回款（后端落袋）：TT 电汇/平台回款，多银行中转+贸易真实性核验
- 到账时效: 外卡收单 T+5/T+7 居多（可申请 T+3）；外贸收款 1-3 工作日
- 风控差异: 外卡防拒付/盗刷+争议仲裁；外贸严查贸易背景（合同/提单/发票）

### 3.2 单信息 vs 双信息（目标号 #2，核心机制）

| 维度 | 单信息 Single Message | 双信息 Dual Message |
|------|----------------------|---------------------|
| 报文次数 | 1 次（授权+清分+结算同步） | 2 次（授权实时 + 清算 T+1 批量） |
| "支付成功"含义 | 授权即清算同步触发 | 仅授权通过（冻结额度，未清算） |
| 日切点例 | 银联 23 点、Visa 单信息 19 点 | 按 T+1 批量 |
| 典型场景 | 银联外卡、小额高频零售 | Visa/MC/Amex，跨境电商/酒店/机票/大额 |
| 关键风险 | — | **漏提交清算=挂账不到账**；对账需核对授权/清算/结算三笔数据 |

**三环节框架**：授权（Authorization，实时校验额度/风控）→ 清分（Clearing，数据汇总核对入结算队列）→ 结算（Settlement，卡组织划拨资金至商户）。
**核心认知**："支付成功"≠"到账"；双信息的本质是"二次请款"（first 授权 / second 清算文件）。

### 3.3 三方机构外卡收单体系（《万字》篇，融合主干）

**与国内支付的六大架构差异**：
1. **换汇能力**：交易需汇率获取换算；结算需接换汇通道（外币→人民币入境）
2. **跨境牌照与申报**：资金入境需有申报资格机构做国际收支申报；三方需跨境人民币+外汇牌照，或与有资质机构合作；申报通道可多个（风控标准不同，可换通道重试）
3. **物流信息验证**（跨境货物贸易特有）：防"勾结虚假交易让境外资金入境"洗钱；未上传物流凭证的交易**不显示可用余额**、结算拦截
4. **境内外资金调拨系统**：境内外均开备付金账户，通道/账户时效错配（境外结算慢、对商户快=垫资）→ 需要调拨管理系统
5. **风控系统以拒付（差错）为核心**：事前=商户入网标准（卡组织指标）；事中=拦截+3DS 路由模型；事后=调单/申诉/指标预警对冲；风控指令联动交易核心（实时拦截）与清结算（结算拦截）
6. **3DS 责任转移**：3DS 由发卡行校验；通过 3DS 的交易发卡行承担拒付/欺诈全部损失 → 发卡行手续费分成最高

**信息流/资金流（线下 POS 例）**：
- 信息流：持卡人刷卡 → 商户 → 收单行网关（校验+风控）→ 卡组织 → 发卡行（3DS 校验）→ 逐级回执
- 资金流：日终批结 → 收单行核对 → 向卡组织请款（国外卡组织双信息/国内单信息）→ 卡组织清算（换汇+扣手续费）→ 收单行境外账户 → 申报通道申报 → 国内备付金账户 → 商户平台虚拟余额 → 提现（发票核验）→ 商户国内账户
- 变体：申报未完成时收单机构**垫付**结算；或不入境直接用境内资金结算（外汇留存境外）

**落地案例**（某三方新增线上外卡收单）：
- 无卡组织会员资格 → 接收单行作通道，**大商户模式**入网
- 资金链: 收单行 --USD T+7--> 支付机构境外户 → 自行申报换汇入境 --CNY T+10--> 商户
- 系统清单: 新增独立外卡商户平台（首页/交易/账单/资金/物流/差错/设置）+ 外卡收银台 + 商户 API

### 3.4 资质与合规（辛克派篇 + 《万字》篇交叉）

- 外卡收单 = CNP（Card Not Present）为主的交易模式 → 欺诈/拒付风险显著高于境内
- 从业资质链：第三方支付牌照 + 跨境支付牌照 **不足以**直接受理外卡 → 还需 **VISA QSP / Mastercard PF** 认证（同时通过者少）
- 申请方需通过国际卡组织认证（VISA/MASTER）；收单行须为卡组织会员
- 拒付 Chargeback：Visa 120 天窗口（其他卡组织多为 180 天）；欺诈类 vs 贸易纠纷类（后者可申诉）；流程：拒付→再请款→二次拒付→预仲裁→仲裁（卡组织终判）
- 欺诈类型（卡组织定义）：伪卡/失窃卡/未授权/商户欺诈/网络欺诈

### 3.5 清算 vs 结算与到账慢的三重关卡（融民工老李篇）

- 清算=账务成立（应收应付关系确认）；结算=资金实际划拨——清算完成≠到账
- 到账慢排查次序：① 卡组织↔收单机构结算规则（T+1/T+3、周五交易跨周末顺延）② 结算账户问题（信息错误/二类卡日累计 1 万限额/挂失冻结）③ 通道与垫资（境外通道慢+对商户快=机构垫付）

### 3.6 补充：DCC/EDC 与六大卡组织（《万字》篇）

- EDC（Electronic Data Capture）：常见模式，换汇由卡组织完成，商户收本币
- DCC（Dynamic Currency Conversion）：商户/收单行实时换汇，汇差收益归商户/收单行——客诉与合规敏感点
- 六大国际卡组织：VISA / Mastercard / Amex / JCB / Diners Club / Discover

### 3.7 收单行状态机设计五原则（目标号「状态机设计」篇，工程向核心）

1. **授权 ≠ 清算 ≠ 结算**：必须强拆三条状态线，哪怕表里只存一个主状态
2. **Pending 是常态不是异常**：Visa/MC 授权超时、网络抖动、异步 Advice/Reversal → Pending 是一等公民
3. **Reversal/Void/Refund 三者绝不能混**：未确认授权→Reversal；已确认授权未清算→Void；已清算→Refund
4. **Clearing 以卡组文件为准**：实时返回 ≠ 可清算，一切以 BASE II / GCMS 文件为最终事实
5. **最终账务状态只由 Settlement 决定**：Auth 成功 ≠ 钱到；Clearing 成功 ≠ 已结算
- Chargeback 应诉（Representment）= 收单行通过卡组向发卡行提交证据反驳；证据矩阵：Fraud→3DS/AVS/CVV/设备指纹

### 3.8 Visa 清算技术栈（目标号 Visa 篇 1-6，运维/测试向）

- **VCX（Visa Clearing Exchange）**：处理中心与 VisaNet 间的清算文件网关；传出=CTF→ITF 生成→经 EAS/DEX/OFD/VFG 传输；查重=TC90 头 Processing Date(YYDDD)+File ID(三位)
- **BASE II 系统处理**：收集交换文件→验证→转货币→总计排序→算费→周期末计算客户结算头寸（收付相抵）
- **测试体系**：VCMS（与生产一致的工作站）、VMG（ISO 8583 报文生成：MTI/DE/BitMap）、EAS（增强授权）、VisaNet模拟器
- **核心缩略词族**（篇2 全表）：VTS/VCX/VCMS/VIP/BASE II/DE/CIB——读 Visa 文档的密码键盘
- **ARDEF 表**：account prefix range 维护发卡机构账号范围验证

### 3.9 争议处理全流程（目标号 Dispute 篇，对齐卡组标准）

- 流程：Chargeback → （收单行评估）→ Representment/接受 → （发卡行）Pre-arbitration → Arbitration → WRITE_OFF（核销/认亏）
- WRITE_OFF 账务影响四维：资金=永久损失；会计=坏账/争议损失；风控=提高商户风险等级；合规=计入 CB Ratio
