V 
引  言 
本规范是为TEEI调试接口和协议制定的规范说明书。本规范包括可信应用服务器的异常状况报告、
可信执行环境上的调试日志消息和客户端调试日志消息接口规范。 
本规范介绍了三种不同的规范范围： 
范围一：可信执行环境中可信应用服务器的异常状况报告接口的语法和语义规范，例如，通过可信
执行环境客户端API传输的数据结构，该数据结构会将TAS的异常状况报告给客户端应用。 
范围二：可信执行环境调试日志消息客户端接口的语义和语法规范，例如，通过可信执行环境客户
端API传输的数据结构，该数据结构会将调试“printf”类型的消息移交给显示器或者日志工具。 
范围三：可信执行环境调试日志消息内部接口的语法和语义规范，例如，TEEI上使用了DLM服务的
可用数据结构。

5 概述 
本规范设计了用以支持TAS 的开发和/或TEEI 虚拟机接口API 的一致性测试的接口规范，本规范
定义了两类调试服务TA（PMR 和DLM），TEEI 实现者也可以定义自己的调试服务TA。 
PMR 关注的重点是一致性测试和TVM 的调试。这项服务为TEEI 提供了一种方法，使其能够将已
进入严重异常状态的各TVM 的终止状态告知客户端。如果没有这种能力，TEEI 则不可能证实内部API
的正确功能，因此严重异常状态用于报告各种需要进行测试的错误情况。 
DLM 在TVM 调试方案中十分有用。该服务为TVM 提供了一种方法，使其能够报告简单的授权系
统上的调试信息。此服务也可提供给客户端应用或设备外硬件，也可同时提供给两者。 
DLM 和PMR 都是专门用于符合TEEI 可信执行环境安全性要求的附加调试方法或状态记录方法。
这两种服务都可以利用受监视TVM 的主机名来识别受监视的TVM（并过滤返回的结果）。 
在选择一个TVM 进行调试时，监视应用是如何获取该受监视TVM 的主机名的，此内容已经超出
了本规范的范围。 
一个监视应用如何从会话客户端那里获取该受监视TVM 的上下文标识，此内容
已经超出了本规范的范围。 
不管是否定义在本规范中，专有调试处理是可以扩展的。因此，如果设备制造商选择要添加专有扩
展，则本规范可以是他们实现的一个子集。 
5.1 调试授权原则 
TEEI 调试规范的调试目标是TVM，对于TVM 内部的其他应用开发的调试，不在本规范的定义范
围内，但是可以依靠本规范中定义的机制进行调试，但是调试授权和控制不在本规范的定义范围内。 
本规范授权的调试目标的粒度可以是一个特定的TVM，或者一个TEEI 上的所有TVM。调试规则
分为两层：TEEI 层和TVM 层，其中限制更强的规则将会覆盖限制较弱的规则，例如如果TVM 允许进
行调试，而TEEI 不允许，那么所有的TVM 都不会被允许进行调试。所有部署在TEEI 平台内的TVM
在默认状态都是不可调试的，如果需要将其修改为允许调试状态，必须经由TEEI 管理功能完成。 
调试服务TVM（PMR 和DLM）如何获取系统当前的调试授权原则是由实现者确定，不在本规范
定义范围内。调试规则属性可由TEEI 管理框架控制，也可以采用专有方法来更改调试规则属性，或者
是否使用TEEI 管理框架的扩展，这些都是由设备的设计所决定的。 
5.2 调试架构 
本节提到的所有架构，重点围绕调试服务TVM 的概念介绍了各个系统，该TVM 能够为希望控制
和接收调试输出的各个应用提供连接。然而，这些TVM 也可以由专有的输出和控制机制取代。 
5.2.1 实现调试API 的TVM 
在一般情况下，调试服务TAS 为客户端提供基础协议服务，并且可以被连接到可信执行环境的内
部或外部。 
通常地，调试服务TAS 是否可以是任何意义上的真实的TAS，这是由实现选择的。在其他情况下，
他们可能是通过如TAS 般的可信执行环境客户端API 寻址，但没有与TAS 相同的管理特性（例如，可
能紧密的集成在可信框架中，因此，是不可锁定、不可移动或不可独立升级的。）

6 PMR 协议 
PMR 服务使PMR 监视应用能获得异常状况报告信息。该信息来自于一个特殊的TAS（由主机名或上
下文ID 定义的）。 
6.1 PMR 服务的可用性 
PMR 服务只能为经过授权的监视应用服务。该授权由TAS 和TEEI 可信执行环境具体的调试规则属
性共同决定。PMR 服务的加密保护能力必须与应用于其它TEEI 源保护的加密保护能力一样强壮，如安
全对象存储。如果PMR 服务本身或者TEEI 可信操作系统发生严重异常，那么不能保证通过监视TAS 严
重异常的应用程序能够捕获此相关严重异常。 
6.1.1 释放PMR 信息 
一旦所有能够获取PMR数据的PMR监视应用都接收到数据或者关闭了与PMR服务的会话，那么可信操
作系统必须能够释放与发生了严重异常会话相关的所有状态数据。

该命令会返回发生严重异常TAS的识别信息以及所需的缓冲区的大小。当受监视的TAS已经关闭时，

获得缓冲区大小，以及调用CMD_PMR_FETCHPMR取回详细信息。只有已经处理了一个严重异常，下一个要
发生的严重异常才能由此会话上的CMD_PMR_WAIT来报告。

7 DLM API 和协议 
7.1 概述 
本规范定义一个简单的服务基础协议，该服务协议可将调试日志消息（DLM）从TAS 传送到一个
客户端应用。DLM 由TAS 用类似日志函数的打印函数生成。此函数能力有限，但也足以能够通知开发
人员程序的流程和变量的状态。 
7.2 头文件 
7.2.1 DLM 协议头文件 
客户端调用DLM服务API之前需要声明 “teei_client_DLM_api.h”头文件。 
#include “teei_client_DLM_api.h”                                 
7.2.2 DLM API 头文件 
通过固件调用DLM服务API之前需要声明 “teei_platform_DLM_api.h”头文件。 
#include “teei_platform_DLM_api.h”                                 
7.3 DLM 协议 
设计此命令用于将一个客户端应用连接到一个TAS 提供的调试消息流上。当设备上没有客户端应用
执行时，那么从外部客户端提供类似的功能必须用专有协议。一个受监视TAS 的DLM 服务可以由此受监
视TAS 以异步方式创建。
