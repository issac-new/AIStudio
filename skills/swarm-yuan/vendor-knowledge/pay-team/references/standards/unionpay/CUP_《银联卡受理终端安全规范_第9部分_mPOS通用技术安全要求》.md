银联卡受理终端安全规范 
mPOS 通用技术安全要求 
1 范围 
本要求对受理银联卡（包括磁条卡及IC卡）开展商户收单业务的mPOS终端设备和相关应用及系统
提出安全要求，包括受理终端、终端上位机（支付应用软件）、后台处理系统等受理体系各组成部分自
身的安全要求，以及体系整体的端到端加密机制，旨在提升银联卡账户和交易数据在开放环境下的安全
性。 
mPOS为整体概念，包括终端设备和相关应用。具体指，通过移动通讯设备（所搭载的支付应用软
件）进行商户收银操作，由外接专用受理终端完成银联卡相关信息的采集和加密，通过移动通讯设备与
后台处理系统交互完成交易，这一过程涉及的前端专用软硬件设备。 
开放环境包括公共传输网络、搭载开放式操作系统的终端上位机、以及处于受理终端（或上位机）
与后台处理系统之间的所有非封闭式的信息传递路径及路径上所有设备和系统。凡使用开放协议（如
TCP/IP协议等）进行传输的均认为处于开放环境中。 
本要求为用于银联卡收单业务的终端设备和系统提供基础安全要求，个人支付终端设备和系统也可
参照执行。 
采用封闭或定制操作系统运行环境、符合《银联卡受理终端安全规范》定义的POS终端、自助终端
和智能POS终端仍可遵照相应规范要求进行生产和认证。 
无PIN输入要求且符合《银联卡受理终端应用规范 第3部分 银联卡（IC卡）脱机受理终端规范》
定义的IC卡脱机受理终端仍可遵照相应规范要求进行生产和认证。 
本要求仅对文中描述的直接受理银联卡（包括磁条卡和IC卡）支付的设备、应用和系统提出安全要
求，条码（包括二维码）支付、声波支付、指纹支付等附加功能不在本要求范围内。 
本要求适用于受理银联卡的终端生产企业、支付应用软件开发商及收单机构。

下列术语和定义适用于本标准。 
3.1  
公共网络 public network 
普通大众都可以进入的网络，例如国际互联网和公共电话系统。 
 
3.2  
受理终端 
本要求指外接于终端上位机的银联卡受理终端，可安全获取并保护账户信息、验证信息和交易报文，
功能应包括：证书及密钥的安全存储，与后台系统之间的认证及建立安全通道，安全读取和加密银行卡
信息（包括磁条卡和IC卡），接受用户输入并加密个人标识码（PIN），安全显示交易类型、金额、结
果等交易提示信息，以及加密账户信息、计算报文鉴别码（MAC）等。 
 
3.3  
终端上位机 upper device 
mPOS架构中受理终端的上位机，进行应用处理和后台交互，该终端上位机可以为收银机、POS主
机，也可以为手机、平板电脑等通用移动设备，本要求主要指手机、平板电脑等，主要功能包括建立与
后台的通信连接、启动一笔支付交易（产生订单，生成并向受理终端发送交易金额、交易类型等信息）、
交易处理等。简称为上位机。 
 
3.4  
个人标识码 personal identification number: PIN 
个人标识码是在联机交易中识别持卡人身份合法性的数据信息，在计算机和网络系统中的任何环节
都不应以明文方式出现。 
 
3.5  
报文鉴别码 message authentication code: MAC 
报文鉴别码，是消息来源正确性鉴别的数据。 
 
3.6  
卡片主账号 primary account number: PAN 
即卡号，用于标识银行卡所有者及卡片唯一性的号码，由发卡机构标识代码、个人账户标识和校验
位组成。 
 
3.7  
账户信息 account information 
账户信息是指银行卡上记录的所有账户信息以及与银行卡交易相关的用户身份验证信息。记录在银
行卡上的信息包括：卡号、磁条信息、卡片验证码、有效期等。与银行卡交易相关的用户身份验证信息
包括：网上业务、电话银行、手机银行等业务中的用户注册名、密码、真实姓名、证件号码、联系方式
等。 
 
3.8  
交易数据（信息） transaction data / transaction information 
交易信息是指银行卡在各类业务中的事务处理数据，数据内容视业务不同而有所不同。基本内容包
括：卡号、密码、磁条信息、卡片验证码、有效期等。

敏感数据（信息） sensitive data / transaction information

——受理终端：经过检测认证、符合安全标准的可被信任的支付受理设备，可安全获取并保护账户

安全为前提，个人支付终端遵循《银联卡受理终端安全规范 第7部分 个人支付终端安全规范》，但建

4.2 开放环境 
开放环境包括4.1节所述传输路径和搭载开放式操作系统的上位机（如未经定制的手机或平板电
脑）。 
本要求所述“开放环境”指上位机和传输路径所构成的整体环境是开放的，例如：上位机搭载有通
用操作系统、传输路径中包含公共网络传输等，即只要数据传输链条中存在任意一环节处于开放条件下，
该系统整体便为基于开放环境的系统，所使用的终端便为基于开放环境的受理终端。凡使用开放协议（如
TCP/IP协议等）进行传输的均认为处于开放环境中。 
非开放环境包括对资源访问权限、外设接口、系统和应用校验、数据存储和传输等进行安全设计或
定制、并符合安全要求的专用设备（如：符合《银联卡受理终端安全规范》的POS终端、智能POS等专
用安全设备），以及专线网络。 
本要求中所述“经定制的手机或平板电脑”指在操作系统、硬件等方面进行了安全设置，使之能满
足银行卡支付安全要求、达到银行卡账户和交易信息保护水平的专用设备，非通用电子设备。 
 
5 安全目标 
5.1 账户信息安全保护 
受理终端应对账户信息进行安全保护。账户信息保护要求参见《银联卡收单机构账户信息安全管理
标准》（银联风管委【2013】9号）和《银联卡账户信息与交易数据安全管理规则》（银联风管委【2006】
6号）。 
其中，完整磁道信息、PIN、卡片验证码、卡片有效期等敏感数据应被安全加密和解密，在受理终
端和后台系统的硬件加密模块之外不得以明文形式出现，应保证数据在处理和传输过程中不被泄露、窃
取和篡改。 
任何设备和系统均不得存储敏感数据（即使已经加密），账户信息只用于完成当前合法银联卡交易，
不得用于任何其他用途。 
 
5.2 交易信息安全保护 
除卡号、PIN、磁道信息、有效期、卡片验证码等交易信息（参见银联风管委【2013】9号和【2006】
6号相关风险要求）之外，还应保证交易金额、交易类型、货币类型、商户号、终端号等关键交易信息
在处理和传输过程中不被篡改。 
 
5.3 安全提示 
终端应提供相关机制，确保交易过程中流程关键环节（如：交易金额及交易类型确认，密码输入等）
和交易结果能安全、有效地向持卡人和收银员进行强制提示，确认后才可进行下一步操作。 
 
5.4 交易真实性 
对交易报文的来源进行鉴别，保证交易真实性，防止信息伪造和重放攻击。

本部分列举的通用要求均以满足第5章各项安全目标为前提，不应以未列举强制要求为由而妨碍上
述安全目标的实现。 
受理终端连接上位机实现与后台系统的交互，应满足的通用安全要求包括但不限于： 
——受理终端应满足《银联卡受理终端安全规范 第6部分 PIN输入设备安全规范》（Q/CUP 007.6）
对物理、逻辑、脱机、联机、生产、管理等方面的安全要求，敏感数据仅可在受理终端输入，且不得以
明文形式输出。宜实现DUKPT或等效的一次一密机制，建议实施标准DUKPT机制。终端应具有安全机
制，用于抵御来自外部的攻击，应保护敏感信息在受到攻击后不泄漏。 
——受理终端应具有安全读卡功能（包括磁条卡、接触式IC卡和非接触式IC卡），对账户信息中的
敏感数据进行有效保护。 
——受理终端应安全显示交易类型、交易金额和交易结果，5.2节所述交易信息应被安全保护，防
止在传输过程中被篡改。 
——受理终端固件和应用程序的更新机制应确保实现保密性、完整性和服务的真实性。终端必须通
过加密机制对更新内容的完整性和真实性进行验证，在未确认其完整性和真实性的情况下，受理终端应
拒绝进行更新并删除更新的内容。 
——受理终端、相关应用和系统应能抵御重放攻击，防止加密数据和交易报文被重用。 
——受理终端应保证具有唯一性，满足一机一密要求（例如：在主密钥和工作密钥组成的二级密钥
体系中，应保证每台受理终端分配唯一主密钥；在DUKPT中，应保证每台受理终端分配唯一初始密钥序
列号KSN）。受理终端应进行联机签到认证，应上送受理终端设备序列号等信息。上位机软件上送上位
机唯一特征码（如手机的IMEI号或IMSI号）作为平台安全评估的辅助参考手段。应实现受理终端与后
台处理系统双向认证，未通过联机认证不应进行支付交易。 
——受理终端不应向上位机提供单独、直接的PIN和磁道等敏感数据加密计算功能，防止被用于伪
造交易、密钥穷举破解等，如受理终端向上位机提供MAC计算功能，则应对交易金额等5.2节所述交易
信息进行强制校验或填充，防止交易信息被篡改后骗取合法MAC。 
——受理终端应确保所支持的所有有效的传输协议和接口不存在可利用的弱点；应确保对外传输的
所有与交易相关数据的保密性和完整性；终端应能及时检测信息反馈，并对异常情况进行安全处理。受
理终端与后台处理系统之间宜在交易过程中建立逻辑安全通道，确保上位机和传输网络所含威胁被有效
隔离或防止。 
——上位机与后台系统间数据不应以明文形式传输。上位机应采用强壮的加密算法和安全协议，例
如：安全套接字层（SSL 3.0及以上版本）/传输层安全（TLS 1.0及以上版本）或IP安全协议（IPSEC），
以保护数据在开放/公共网络上的传输。 
——上位机上安装并运行的支付应用软件应满足《银联卡支付应用软件安全规范》（Q/CUP 056）
的安全要求。 
——建议收单机构应采取必要的操作人员管理手段对支付应用软件的使用权限进行有效控制；采取
必要管理手段确保应用软件（包含与支付相关以及与支付无关的所有应用软件）通过合法渠道获取并通
过正版授权，由管理员统一管理安装；设置严格的登录保护机制，如通过复杂密码授权方可进行操作；
应确保运行在最低权限，不应有越狱或Root等行为。 
——受理终端或上位机宜具备地理位置信息获取和上送能力，收单机构应采取有效手段加强对此类
终端和对应商户的管理。 
——PBOC Level 2内核不应部署于上位机。 
——对于后台处理系统，建议应能具备安全的加解密功能，维护安全运行环境，有效抵御病毒、
DoS等网络攻击，防止非法终端对系统安全造成影响，并能及时对异常情况进行处理。其中账户信息层
面具体安全要求参见《银联卡收单机构账户信息安全管理标准》（银联风管委【2013】9号）、《银联

机构接入银联的技术安全要求》。

本文档举例的方案基于以下基本考虑： 
1、智能设备安全难以有效控制，数据经由上位机和互联网传输，应尽可能避免上位机对敏感信息

A.8.1 方案特点 
1、后台处理系统对受理终端合法性的验证通过对称密钥完成，受理终端不进行任何私钥运算，对
