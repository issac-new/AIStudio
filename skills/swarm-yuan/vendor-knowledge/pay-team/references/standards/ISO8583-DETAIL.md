## 一、标准族与版本演进

### 1.1 三个版本

| 版本 | 结构 | 关键特征 | 现状 |
|------|------|---------|------|
| **ISO 8583:1987** | 单一标准 | 经典 0xxx MTI 报文集（0100/0200/0400/0800…），位图 + 128 域 | **银联 CUPS 采用的结构**（见 §4.1 证据） |
| **ISO 8583:1993** | 三部分拆分 | 1xxx MTI 报文集重构（授权/金融/对账类重新划分） | 部分行业采用，中国未采用 |
| **ISO 8583-1:2003** | Part 1/2/3 | Part 1: Messages, data elements and code values；Part 2: IIC 申请注册程序；Part 3: 报文/域/码值维护程序；消息类别重构（授权/验证/金融 presentment/冲正/拒付/对账/管理/差错/费用收取等 13 类） | **iso.org 状态: Withdrawn（已撤回）**，无免费后继版；业界实际仍普遍沿用 1987 结构 |

### 1.2 关键结论（勘误 v1.0）

> ⚠️ **v1.0 曾写"0200 = 2003 版"，系错误。** 正确口径（2026-09-06 勘误，同步记入 known-conflicts KC-013）：
> - MTI 首位数字标识**报文结构版本**：0=1987 版结构，1=1993 版，2=2003 版
> - **0200 是 1987 版结构的金融交易请求**。银联 CUPS 全量报文（0200/0210/0220/0400/0420/0620/0800/0820 等）均为 0 开头，即 **CUPS 基于 8583:1987 报文结构 + 银联自有扩展**，与 2003 版无关
> - 银联规范第 0 部分（术语）明确援引"银行卡-交换报文规范-金融交易内容（ISO 8583-1987）"

## 二、报文结构（1987 版结构，即 CUPS 采用版）

### 2.1 整体结构

```
[MTI 4字节] + [主位图 8字节] + [次位图 8字节（可选）] + [Data Elements 按位图顺序] + [MAC]
```

- 位图表述（ISO 惯例）：DE1 本身即主位图；主位图第 1 位=1 表示存在次位图，次位图覆盖 DE65-128
- 银联规范文本表述（语义相同、编号习惯略异）："位图一定义域2到域64，位图二定义域66到域128"（CUPS 第 2 部分 §位图说明原文）——即域 65 不使用

### 2.2 MTI（Message Type Indicator）4 位数字

| 位 | 含义 | 取值 |
|----|------|------|
| 第 1 位 | 报文结构版本 | 0=1987 版，1=1993 版，2=2003 版 |
| 第 2 位 | 消息类别 | 0=保留，1=授权类，2=金融类，4=冲正/拒付类，8=网络管理类（1987 版实际使用子集） |
| 第 3 位 | 报文功能 | 0=请求，1=请求应答，2=通知（advice），3=通知应答 |
| 第 4 位 | 传输源 | 0=收单方发起，1=收单方重发，2=发卡方发起，3=发卡方重发 |

**常见 MTI 对照（CUPS 全部在用，均有库内银联第 1 部分原文支撑）**:

| MTI | 含义 | CUPS 场景示例（库内原文） |
|-----|------|------------------------|
| 0100 | 授权类请求 | 授权请求（除存款/转账/查询/账户验证/汇款/汇款验证外的预授权类） |
| 0200 | 金融类请求 | **消费、预借现金、余额查询等**："消费交易……入网机构以0200请求报文向CUPS转发" |
| 0210 | 金融类请求应答 | 发卡行/CUPS 对 0200 的同步应答 |
| 0220 | 金融类通知 | 存款/转账/查询/账户验证/汇款/汇款验证类交易的通知转发 |
| 0400 | 冲正类请求 | 冲正请求 |
| 0420 | 冲正类通知 | 冲正通知 |
| 0620 | 管理类通知 | 库内在用（第 1 部分交易处理说明） |
| 0800 | 网络管理类请求 | 签到/签退/密钥交换/回声测试（网络管理信息码在域 70） |
| 0820 | 网络管理类通知 | 网络管理通知（库内出现频次最高之一） |

### 2.3 位图机制

- 主位图 8 字节 64 bit，从左到右对应域 1-64（最高位=域 1）
- 位图第 N 位为 1 → 对应数据域存在
- 十六进制展示：每字节 2 个 hex 字符，域存在按 bit 位判断
- 次位图 8 字节覆盖域 65-128（银联表述：位图二定义域 66-128）

### 2.4 数据域类型表示法（ISO 惯例 + CUPS 用法）

| 记号 | 含义 | CUPS 示例 |
|------|------|----------|
| n | 数字字符（定长） | 域 4 交易金额 n12 |
| an | 字母数字（定长） | 域 37 检索参考号 |
| ans | 字母数字特殊字符 | 域 41 受卡机终端标识码 |
| a | 字母 | —— |
| b | 二进制 | 域 52 个人标识码数据、域 128 报文鉴别码 |
| z | 磁道数据格式 | 域 35/36 第二/三磁道数据 |
| LLVAR / LLLVAR | 2 位/3 位长度前缀变长 | 域 2 主账号 LLVAR、域 48 附加数据－私有 LLLVAR |

## 四、中国落地关键差异（CUPS vs ISO 国际版）

### 4.1 报文结构版本

- **证据**（库内银联第 0 部分）: "产生报文的银行卡-交换报文规范-金融交易内容（ISO 8583-1987）"
- **证据**（库内银联第 1 部分）: 消费/预借现金/余额查询等"以 0200 请求报文向 CUPS 转发"
- **结论**: CUPS = 1987 版报文结构 + 银联 128 域自有定义；**不采用** 1993（1xxx）与 2003（2xxx）报文集

### 4.2 与国际惯例的实质差异点

| 差异点 | ISO 8583 惯例 | 银联 CUPS 实际 |
|--------|--------------|---------------|
| 域 43 | 常为 LLVAR（商户名/地址，最长 99/40 视版本） | 定长 ans40 |
| 域 59 | 无标准定义 | 明细查询数据（银联自定义） |
| 域 60-63 | 无标准定义 | 自定义域/持卡人身份认证/交换中心数据/金融网络数据（含国密 SM PIN 承载） |
| 域 121-123 | 无标准定义 | CUPS/受理方保留/发卡方保留 |
| 域 65 | 次位图存在标志 | 银联表述域 65 不使用，位图二定义域 66-128 |
| IC 卡数据（域 55） | EMV TAG TLV | EMV TAG 集 + 银联增补（含国密相关 TAG，详见 PBOC/银联 IC 卡规范） |
| 传输编码 | ASCII/EBCDIC 均可 | ASCII 定长/变长混排，GB18030 中文（详见第 5 部分通讯接口） |

### 4.3 网联（NetsUnion Clearing, NUCC）对照

- 网联**不使用 ISO 8583**：互联接口为 ISO 20022 风格的 XML 报文（Q/NUC 103.x，全文已入库，见 `standards/WANGLIAN-QNUC.md`）
- 冲突裁决 KC-006: 网联报文以 Q/NUC 规范原文为准，"网联报文与银联类似"的说法不成立
- 8583→20022 字段级迁移对照见 `standards/ISO8583-TO-ISO20022-MAPPING.md`
