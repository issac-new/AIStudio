## 二、核心概念（以银联 Q/CUP 指引全文为准）

### 2.1 定义集（指引 §2.2 原文概念）

| 概念 | 定义要点（原文级） |
|------|------------------|
| **支付标记（Payment Token）** | 主账号（PAN）的替代值，**13-19 位数字、通过 LUHN 算法校验**（符合 PAN 基本验证规则），交易中以标记替换卡号、以标记有效期替换卡有效期 |
| **标记 BIN（Token BIN）** | 与卡 BIN 类似用于交易路由，**不得与 PAN BIN 冲突**，仅用于标记发行，属特定 BIN 段并在 BIN 表中标识 |
| **标记有效期** | 替代卡有效期报文域，一般 ≤ 卡有效期 |
| **标记服务提供方（TSP）** | 产生/维护标记的主体：标记库运行维护、标记生成与发布、安全应用与控制、标记相关数据准备、**标记请求方注册**、**生命周期管理**、**去标记化操作**、建立并管理标记请求方 API、确保标记 BIN 与卡 BIN 不冲突 |
| **标记请求方（TR）** | 向 TSP 提交标记申请的机构：**存留卡号信息的商户、数字钱包服务商、收单机构及其外包服务方**等 |
| **ID&V（身份识别和验证）** | 签发前验证持卡人身份与账户真实性的过程，决定担保级别 |
| **担保级别** | 表示标记与其绑定 PAN 的关联可信度，由 TSP 依据 ID&V 等控制措施在标记产生时确定，**可随补充 ID&V 更新**；可用于交易风险控制 |
| **标记的域控** | 限定标记的使用范围（渠道/商户/场景约束） |
| **标记的存储位置** | 标记在请求方侧的存放形式与安全要求 |
| **去标记化（Detokenization）** | TSP 将标记还原为 PAN 关联关系的操作（交易验证时使用） |

### 2.2 角色 vs EMVCo 对照

| 中国（银联指引/JR/T 0149） | EMVCo | 差异 |
|---------------------------|-------|------|
| 标记服务提供方（TSP） | Token Service Provider (TSP) | 一致；中国 TSP 可为发卡行/清算机构（银联）等 |
| 标记请求方（TR） | Token Requestor (TR) | 一致；中国为商户/钱包/收单及外包方 |
| ID&V | Identity & Validation | 术语一致 |
| 担保级别 | Token Assurance Level | 语义对应 |
| 域控 | Domain Restriction（usage constriction） | 一致 |
| —— | PAR（见 §四.3） | 中国体系原生未引入 PAR，外卡落地（万事网联）接入后逐步对齐 |

### 2.3 标记格式

- 数字长度 13-19 位、LUHN 可校验（与 PAN 同构，兼容存量受理系统——这是标记化能落地的工程前提）
- 标记 BIN 段与卡 BIN 隔离
- 承载: 8583 域 2（主账号位置替换为标记）/ 20022 报文对应字段；域 55 芯片数据在非接场景承载 Token 相关 TAG

## 三、标记生命周期（工程核心）

### 3.1 状态流水

```
申请(Token Request) → 账户验证 ID&V → 签发(Provisioning) → 绑定(App/设备)
  → 使用(In-Payment) → 更新/补充 ID&V → 挂起/恢复 → 注销(Deletion)
```

### 3.2 各环节职责与要点

| 环节 | 执行方 | 工程要点 |
|------|--------|---------|
| 申请 | TR → TSP | TR 注册与 API 鉴权（TSP 职责含"标记请求方的注册功能"） |
| ID&V | TSP 协同发卡行 | 短信/生物/卡要素组合；**决定担保级别**；可分步补强升级级别 |
| 签发 | TSP | 生成标记（BIN 段隔离 + LUHN）；有效期 ≤ 卡有效期；域控参数写入 |
| 绑定 | TR | 与设备/商户/场景绑定；存储位置安全（SE/TEE/HCE） |
| 使用 | 全链路 | 交易中标记+有效期替换 PAN；**去标记化仅在 TSP 侧发生**，收单/商户不可见 PAN |
| 更新/挂起/注销 | TSP | 卡换补/挂失联动标记生命周期；Merchant Deletion（EMVCo 亦定义商户侧删除流程） |

### 3.3 与支付报文的耦合（中国 8583 链路）

- 请求: 域 2 = Token（格式同 PAN）；域 14 = Token 有效期
- 芯片/非接: 域 55 TLV 中 Token 相关数据元
- 风控字段: 担保级别/域控信息随交易上送（银联私有域承载，见 `ISO8583-DETAIL.md` §3.2）

## 四、三体系对照（银联 / JR/T 0149 / EMVCo）

### 4.1 框架层

| 维度 | 银联 Q/CUP 指引（2015，全文） | JR/T 0149—2016（事实级） | EMVCo TF v1.0/1.1（全文） |
|------|------------------------------|--------------------------|--------------------------|
| 法律层级 | 企业标准 | 金融行业标准（强制推广） | 国际论坛规范 |
| 角色 | TSP/TR/ID&V/担保级别/域控 | 同银联框架并行业通用化 | TSP/TR/Token Requestor ID |
| 标记格式 | 13-19 位 LUHN | 同（移动支付场景） | PAN 同构 |
| 生命周期 | 管理（TSP 职责条款） | 签发/使用/注销全流程要求 | Provisioning/Lifecycle 完整定义 |
| 动态数据 | 数字签名/动态验证配合 | 要求交易级动态防护 | Transaction Cryptogram（CDOL 上送） |

### 4.2 应用场景

| 场景 | 中国落地 | 国际对应 |
|------|---------|---------|
| 手机闪付（SE/TEE/HCE） | Apple Pay/华为/小米 Pay + 云闪付 | Apple Pay/Google Pay |
| 二维码绑卡 | 银联二维码 Token 化（见 `UNIONPAY-QR-EVOLUTION.md` §1.3） | EMVCo QR + Token |
| 无卡 CNP | 网关/协议支付 Token 化试点 | e-com CNP Token |
| 外卡境内 | **万事网联 2025 标记化平台**（央行+EMV 双标准融合声明） | Mastercard MDES 直连 |

### 4.3 PAR 在中国的位置

- **PAR 定义**（PAR 白皮书 v2.1.1 原文）: "A non-financial reference assigned to each unique PAN and used to link a Payment Account represented by that PAN to affiliated Payment Tokens"——一个 PAN 一个 PAR，跨 Token 关联同一真实账户的**非金融标识**
- 用途: 多 Token（多设备/多钱包）归一账户视图、拒付/风控关联分析、Token 注销后仍可追溯账户关联
- 中国现状: 银联指引未引入 PAR；**万事网联接入万事达网络后，其标记化服务天然携带 PAR 能力**（对外卡境内受理链路生效）——引用时标注"外卡链路可用，境内卡链路尚无公开对标"
