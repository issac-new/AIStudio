# 拒答库模板（.swarm-yuan/out-of-scope/&lt;概念&gt;.md）

> **用途**：把"我们不做这个"沉淀成资产，而不是一次性对话。同一类需求换个说法再进来时，先呈现旧决定，让决策者选：确认拒绝 / 推翻 / 判定为不同概念。
> **来源**：mattpocock/skills `.out-of-scope/`（见 references/mattpocock-skills-methodology.md §9.3）。
> **粒度**：一概念一文件，不是一需求一文件；同概念的多个需求归并到同一份。

---

```markdown
# {概念名}：{一句话结论}

{2-4 句：这个概念是什么，当前边界在哪。}

## Why this is out of scope

{理由必须耐久——从下面三类里选，不要写"最近太忙"}：
- 项目范围 / 产品哲学：{填入}
- 技术约束：{填入（具体的耦合、维护面、不可逆代价）}
- 战略取舍：{填入（我们选择把有限维护力放在哪）}

{若存在替代路径，写清楚走哪条：例如"用 Other 选项手写配置"、"用外部脚本绕开"}。

## Prior requests

- {需求编号或一句话标题}（{当时的语境：时间、规模、版本}）
- {需求编号或一句话标题}（{当时的语境}）
```

---

## 写与不写

| 情形 | 是否入库 |
|---|---|
| 增强请求被以"不做"结案，且理由耐久 | **写** |
| 因为"已经实现了"而关闭 | **不写**（会把去重检查毒化成假拒绝） |
| 因为"这轮排不上"而推迟 | **不写**（那是排期，不是拒绝） |
| 改主意了 | **删文件**，不重开旧需求；新需求走正常流程 |

## 消费方式

① 需求理解的第一步：读 `.swarm-yuan/out-of-scope/` **全部**文件，按**概念相似度**匹配（不是关键词匹配——"夜间主题"要命中 `dark-mode.md`），命中则呈现旧决定并要求三选一。
