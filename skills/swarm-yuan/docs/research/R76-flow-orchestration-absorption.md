## 二、错误根因（不粉饰）

**吸收对象错置：抄了文章的内容，没学文章的方法。** 文章的价值分两层——领域知识层（支付系统怎么编排，属文章内容）与论证方法层（怎么把一个技术方向论证清楚，属文章方法）。首次吸收整体取了内容层：把五阶段链、选型矩阵、12 步链路、自研六模块当作知识点切进两档，交叉引用、测试锁、格式对齐都做了——但**格式越整齐越是剪贴**：吸收的判据错了。

**无消费面判断缺位。** 正确的吸收判据是"swarm-yuan 的哪个环节缺这个东西、谁会在什么时候消费它"。按此复盘首次吸收物：

| 首次吸收内容 | 消费面复判 | 结论 |
|---|---|---|
| 逻辑割裂三文件/悬空状态无出口/补偿多处重复/回调无幂等键 | 探查与评审真实项目代码时可验证 | 有一点消费面，但不足以构成入库理由（见下） |
| 十维表其余维度（编排形态五级链/重放确定性等） | 探查低频触达；Temporal 纪律仅该引擎项目适用 | 弱 |
| 三大阵营九维度矩阵 + 一句话建议 | spec 阶段偶发架构决策时才可能查 | 弱且属"文章内容" |
| 自研轻量 Flow 六模块 | 造引擎团队的清单；在项目里做需求交付的 AI 几乎不会消费 | 无 |
| 12 步跨境出款链路全文 | 领域体感叙事，非项目验证方法 | 无 |

即便"有一点消费面"的前几项，正确载体也应是探查时按需分析，而非把二手领域知识（B/C 级）成建制灌进通用速查表——速查表的纪律是"值得在项目中验证的客观规律"，不是"某篇文章的知识摘要"。

**流程纪律掩盖了判断缺陷。** 全程走了 worktree、sweep 全绿、三面一致、防复发锁——执行纪律无懈可击，但锁住的是不该入库的内容。绿≠对。

## 四、从文章中学到的正确东西：论证方法六条

这是本次调研真正值得留下的产出（记档于此，供未来轮次与写作参考；**不物化进 references 知识库**——方法的正确用法是成为做事的方式，塞进知识库又是一次拼凑）：

1. **用"被什么击穿"给阶段划界**：演进五阶段表的灵魂是最后一列——硬编码被"加一个风控判断就要改主流程"击穿。它回答的不是"各阶段是什么"，而是"什么时候必须离开这个阶段"。判断方案该不该换，看卡住它的具体痛点是否到达。
2. **体感先行**：讲方案前先用 12 步表格把问题规模做实（时间跨度不是毫秒是数天），再一句"等于要写一个能活三天的方法"——抽象概念立刻变成身体感受。
3. **痛点必须能演出来，解法必须讲机理**：不说"可靠性差"，说"服务器重启了状态丢了，内存里那个线程说没就没了"；解法不说"更可靠"，说"切成执行态和休眠态，挂起时持久化上下文，外部事件按业务键唤醒"。
4. **对比拿同一任务的两份完整实物，然后用"缺席清单"说话**：同一笔跨境出款的无引擎版（三文件全贴）vs 有引擎版（一个方法），然后点睛"注意这段代码里没有出现的东西"——说清"不再需要什么"比罗列"多了什么"更有说服力。
5. **高手反例法**：论证"该用 X"必须回答"不用 X 的最强做法是什么"——Stripe 手工补齐"节点/持久化/恢复点/幂等/outbox"五件事，这份清单恰好就是 X 的本质能力边界。
6. **相反决策同逻辑**：Coinbase 选 Temporal、Netflix 自研，结论相反决策逻辑同一条（"看你的瓶颈在哪"）。选型建议给决策变量不给唯一答案；一对相反结论的案例比十个同向案例更教人。

**用法**：写调研台账时（体感先行+两份实物对比）、评审技术方案时（高手反例+击穿信号）、做选型建议时（给决策变量）——问自己这几个问题，而不是检索这份清单。

## 五、给未来吸收轮的教训（长期规则候选）

1. 吸收前先回答两问：**"swarm-yuan 哪个环节缺这个"与"谁在什么场景消费它"**——答不上来就不入库，记台账即可。
2. **文章源先分两层**：内容层（领域知识）默认不吸收；方法层（论证/分析/决策方式）记入轮台账供参考，不物化。
3. 执行纪律（sweep 全绿/防复发锁/三面一致）只证明"做的过程干净"，不证明"该做"——判断在先，纪律在后。
