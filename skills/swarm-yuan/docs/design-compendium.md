# swarm-yuan 设计总览（汇编版）

> 定位：本文是**汇编视图**，把散在设计文档、决策台账、供应链登记、轮档与用户指令
> 史里的关键内容收拢成一份可通读的设计文档。正本不变——各域仍以文末「正本地图」
> 所列文件为准，本文不复制正文，只做总览与指针。初稿日期 2026-10-20；最近一次口径同步
> 2026-10-24（R140 后）。易变数字以 `facts.conf` 与注册表为准，本文不手抄。

## 一、它是什么

swarm-yuan 是一个**项目开发技能生成器**：对任意代码仓库跑一次 13 步生成流程，产出
一个该项目专属的开发技能；此后该项目的 AI 编码会话受这个技能约束，项目演进时由
指纹感知并局部更新。关键口径：编号决策见 `docs/design-evolution.md`（当前至决策 54）；
外部运行时 15 个整合（另 2 个宿主 CLI、5 个机制源/观察源）；方法论篇数以 `FACT_REFERENCES`
为准；生成器本体体积以 git 跟踪面实测为准。产出的目标技能按字节预算控制体积。

它不做什么（Non-goals）：不替代 lint/test 工具链（那是轻量替代品，不是被替代对
象）；不服务 typo 级小改与纯人工开发；不给个人脚本和一次性原型生成技能。

## 二、设计理念

五条判断贯穿全部决策史，每条都配一个具体决策或数字。

**1. 两体系统：生成器厚，目标技能薄。**
探查知识只在生成时读一次，允许厚（references 篇数以 `FACT_REFERENCES` 为准、外部运行时物化镜像都在生成器
侧）；目标技能每次会话重复加载，必须薄（SKILL.md ≤11392B、上下文预算 ≤600KiB（614400B），
超限即 CI 失败，口径见 README 附录 A）。决策 47 把这套预算做成了棘轮：分发面与生
成器侧档分离，新增内容必须给既有段落瘦身腾位。

**2. 自动化出初稿，AI 判断质量。**
脚本只做信号可信的事（枚举、拷骨架、渲染配置、核验计数）；判断性环节（特征卡填
值、规律实例化、习惯采纳）由 AI 做。反方向的分工都出过事故，这条写进了 README
第二章的论证。

**3. 证据分级是准入门槛。**
登记断言按 A（本机实测）/B（官方一手）/C（二手转述）三级标注，C 级未核验不进基
线。这条由决策 39 立法（Harness 实践吸收轮），此后每次吸收都过「判据两问」（决
策 46：内容与方法分离、消费登记不得编造）。

**4. 诚实化默认。**
「没找到」不等于「没能力找」，空扫描不等于通过，未执行不得报完成。这条主线从决
策 12（check_cognition 诚实化）起反复强化，外部吸收也按同一口味筛选（gstack 的
no-findings 只算结论、ruflo 的假成功清剿三连、ocr 的渲染溢出记为失败评审）。

**5. 运行时调用不重实现，方法论引用不 vendor。**
外部工具接 CLI 子进程（15 个接线运行时），外部思想蒸馏成自己的 references 文档
（superpowers 等 5 件方法论只取模式不装本体）；唯一例外是访谈与出图这类必须原文
可调的原语，走「原文物化 + 机制蒸馏」双轨（mattpocock 27 技能、diagram-design 45
图表类型，物化在 runtime/）。

## 三、架构与流程

**目录六段**：SKILL.md（操作手册）+ workflow（目标技能侧九节点）+ references（方
法论与知识档，篇数以 `FACT_REFERENCES` 为准）+ assets（门禁脚本、facts.conf 单源、本体类型目录、标准映射、
行业档）+ scripts（生成器与安装器）+ runtime（两件物化镜像）。

**生成流程 13 步**（唯一编号口径在 references/generation-flow.md）：探查（组件库清
单、调用链、关系边集、任务配方）→ 特征卡 → 骨架 → 填充 → 门禁与 hooks → 验证审
查 → 激活。激活前有一道状态门：骨架生成后是 draft 态、全量门禁禁用，三关全过（占
位符清零、清单路径零幻觉、计数核验达标）才转 active（决策 13 用状态门替代了早期
的断点续传否决令）。

**目标技能九节点**：需求 → 探查 → spec → plan → 编码 → 测试 → 审查 → 合入 → 发布，
逐节点要素由目标技能的 workflow.md 承载。门禁分层按 enforce_level 执行（决策 31），
轻重由 profile 决定：任务规模、技术栈复杂度、spec 规模三路信号驱动，**只升不降且
信号明确才升**（决策 22/24/30，方向修正是决策 30 的内容）。

**成长与指纹**：项目变化由指纹感知，技能局部更新；成长 = 预算内替换（新知识进来，
旧知识出去或总量不增），这条是决策 26（复杂度负向预算）与决策 47（分发面棘轮）的
共同底座。

## 四、运行时与吸收

外部运行时分四层接线（FACT_RUNTIMES=15）：

| 层 | 数量 | 件目 | 安装或落点 |
|---|---|---|---|
| 深度 | 4 | GitNexus、graphify、claude-mem、ocr | 门禁内真实子进程；npm/pip 可装 |
| CLI | 6 | OpenSpec、comet、gsd、codex-security + mattpocock-skills、diagram-design（后两件为仓内物化） | npm/pip 可装或 runtime/ 自带 |
| 方法论 | 5 | superpowers、gstack、Ruflo、ECC、impeccable | 只蒸馏进 references，不装本体 |
| 登记不接线 | 7 | dsh、pua、semantica、pi（机制源）、codegraph（备选）、claude-code、codex（宿主） | 台账登记，供应链可审计 |

供应链登记 22 项在 `docs/upstream-baseline.md`，逐行带版本基线、许可证与
baseline_status 机器标记。跟进纪律：上游标 breaking/major 或季度例行触发重核；patch
级薄轮只回写表行不开档；graphify 的 v1.0.0 异源旧 tag 已拦截 11 例，跟进必须做世系
核验；GitNexus 为 PolyForm Noncommercial，基线钉 1.6.12 不追新。

npm 安装通道有六连陷阱（2026-10-20 R126 实测）：裸名 ocr、comet、openspec、
gsd-tools、codex-security 全是撞名或占位包，真名分别为
@alibaba-group/open-code-review、@rpamis/comet、@fission-ai/openspec、
@opengsd/gsd-core、@openai/codex-security。装任何新运行时，第一步读其仓库
package.json 的 name 字段，不裸猜包名。

## 五、决策史主线（决策 9–47，共 39 条）

39 条编号决策（全文与语境在 `docs/design-evolution.md`，技能 README 附录 C 是溯源
索引）按主题归为五条主线：

**接线真实化线**：决策 9（11 个运行时从半接线改真接线）、15/16（连贯动作与全链路
追踪从理念落成真生成、真接线）、10（Windows 平台真实化）。这条线的教训是「声明
有」不等于「真实跑」。

**诚实化线**：决策 12（认知检查诚实化）、35（未创建且未执行的机制不得声称）、38
（版本口径机器锚）。判定词从「宣称面」与「强制面」两口径分开记。

**轻重自适应线**：决策 18（用户方针：自适应轻重 + 质量优先偏置）、20–24、30、31。
profile 三路信号驱动门禁分层，方向修正过一次（只升不降改为信号明确才升），说明
自动分档初版有过度信任信号的问题。

**预算与吸收纪律线**：决策 26（复杂度负向预算）、27（吸收优先于新增门禁）、33/34
（去抽象化、概念落地问责、生成物税制）、41–46（知识生命周期、吸收判据两问、平实
语言、分发面棘轮）。这条线最密集，占 39 条中的 12 条，核心问题是「技能长大之后怎
么不变成膨胀的文档堆」。

**外部参照线**：决策 28/29（Palantir 标记传播映射）、39/40（证据分级、机制级吸收
边界）、42–44（吸收层接线台账、可达必随发）。维护历程把外部思想的进入通道逐条收紧。
