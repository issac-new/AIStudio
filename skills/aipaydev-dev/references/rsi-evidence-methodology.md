> **何时读我**：吸收轮收口验收（怎么证明这轮改进真的发生了、没改坏别的）、目标技能自成长链设计（问题沉淀/指纹反馈的证据纪律）、升级已有技能、以及任何"自称自我改进"的系统的证据学问题时。RSI（Recursive Self-Improvement，递归自我改进）证据学三源吸收——三类证据分离 / L1-L5 分级 / 密封评测。

# RSI 证据学方法论（三类证据分离 / L1-L5 分级 / 密封评测）

> 来源：清华 RSI 全景综述（404 篇文献拆解，S/I 双系统与三类证据）+ D2I-ai Self-Improving Agent Survey（L1-L5 分级 + 五元组 + DPEI 四相）+ 字节跳动 Seed 三论文解读（Aspire / S³Gym / HarnessDev，自进化系统性短板实证）。证据分级 **B**（公众号文章与论文页转述，框架与公式完整；未逐篇核对 arXiv 原文）。
> 定位：swarm-yuan 自身就是一个自改进系统——吸收轮 = 改进机制更新，references 各档 = 被改的系统状态，自成长链（问题沉淀+指纹反馈）= 执勤侧记忆保留通道。本档为这类系统提供**验收证据学**：改进分三层证据（见 §一），系统变化分四种保留层（见 §二），自动化程度有分级刻度（见 §三），评测信号本身会过拟合（见 §四）。
> 纪律：只吸收证据学与分级机制；RSI 的参数训练路线（权重更新/RL 循环）不适用本技能形态，记档不展开。守决策 27：不新增 `check_*` 门禁。

## 一、三类证据分离：任务增益 ≠ 能力保留 ≠ 改进器增益

把系统拆成两个功能角色：**任务系统 S**（做事：本技能的 references 各档 + 门禁 + 生成流程）与**改进器 I**（诊断 S 的弱点、提出并选择更新：吸收轮本身）。同一模型/同一技能可兼任两角色，但角色必须分开看——否则"改完了"与"改好了"与"以后会改得更好"三种主张会互相冒充。

| 证据类型 | 定义 | 实验形态 | swarm-yuan 对应物 |
|---|---|---|---|
| **任务增益** | 任务成绩的变化（本次改进让 S 做题变好了吗） | 改进前后在同一任务集上对比 | 本轮修复的执勤缺陷（换栈演练缺陷数） |
| **能力保留** | 学过的能力在后续轮次是否保留、能否迁移（改 A 会不会把 B 改坏） | 多轮更新循环 + 已有能力回归检查 | Mutation Check 防复发断言全绿（改门禁不破既有断言）、回归测试套件 |
| **改进器增益** | 新改进器相对旧改进器，制造的后继系统是否更优（以后会改得更好吗） | 冻结改进器对照：同起点同预算，完整循环 vs 冻结 I 的循环 | 吸收轮方法论沉淀本身（吸收判据两问、开工前五面校验——让后续吸收少走弯路） |

判据要点：**"后继系统更好"与"更擅长制造后继系统"是两个问题**，需要不同的实验才能主张。收口报告只报任务增益（修了 N 个缺陷）而不报能力保留证据（回归全绿），等于只交了三分之一的答卷——本档要求吸收轮收口对账时三类各给一句（能力保留=测试与防复发断言状态；改进器增益=本轮沉淀了什么可复用纪律）。

## 二、系统状态四保留方式：递归发生在哪一层

改进的"持久化对象"决定递归深度，四态可共存、不是智能阶梯：

1. **答案修改**：只改当前任务的输出（重试/reflection/自纠错）——系统本身不变。*推理期优化，不算 Self-Improvement（§三 L1）。*
2. **记忆保留**：改动留给后续任务（Memory/Prompt/工具/技能/工作流/数据的持久更新）。*swarm-yuan 自成长链 = 此层：问题沉淀三载体（清单/配方/rules.d）、指纹基线、memory-writeback。*
3. **参数训练**：写进权重（本技能形态不适用）。
4. **改进器更新**：改变"以后如何生成更新"的机制本身。*swarm-yuan 吸收轮 = 此层：每轮调研把新机制写进 references/门禁/scripts，改变的是生成器自己。*

用法：给任何"自进化/自我改进"主张先问**改的是哪一层**——四层的验收口径完全不同（答案层看本次结果；记忆层看后续任务是否用到；改进器层看 §一第三类证据）。

## 三、L1-L5 分级 + 五元组 + DPEI 四相

**五元组**：Agent System = Model + Harness + Data + Trainer + **Improvement Mechanism**（M/H/D/T/I）。Harness=Prompt/记忆/工具/技能/工作流；Data=环境/任务/轨迹/验证/课程；Trainer=奖励/损失/优化器；I=改进机制。改哪一元、怎么验证，回到 §二分层。

**自动化分级**（定位刻度，非越高越好——每升一级，治理成本指数上升）：

| 级 | 名称 | 边界 |
|---|---|---|
| L1 | 人工改进 | 全部人类完成 |
| L2 | 辅助改进 | Agent 诊断+提议，**验证与部署由人类**（当前主流，含 AutoResearch 大部分——runner 只会搜 train.py，搜索逻辑本身固定） |
| L3 | 程序化自改进 | 自动提议/执行/验证，但**改进机制 I 本身固定** |
| L4 | 受限 RSI | I 本身可被修改，**领域受限** |
| L5 | 通用 RSI | 改进能力跨领域迁移 |

**DPEI 四相**：Diagnose → Propose → Evaluate → Integrate——问题沉淀通道的骨架对照（问题发现→方案→验证→沉淀三载体）。

**swarm-yuan 自身定位：L2→L3 之间**——生成器侧吸收轮由用户指令触发、AI 调研提议、人类批准合入（L2）；执勤侧问题沉淀/指纹反馈已程序化但改进机制固定（L3 特征）。目标技能同理（自成长链 L2-L3）。**升级到 L4 前的四缺口**（对照自查）：长程评测（评"改进能力"而非"任务能力"）、可观测可修改的基础设施（轨迹/实验史/状态统一可读改——decisions.jsonl/trace-log 已具雏形）、跨领域迁移（本技能跨栈但方法固定）、治理与安全四件套（验证门/回滚/审计/canary——Mutation Check 防复发断言+last-good+decisions.jsonl+canary-monitoring 已有对应）。

## 四、密封评测协议：评测信号本身会过拟合

自改进系统的特有陷阱：**任何参与过"指导更新"的评测集都会逐渐失去独立性**——密封测试的分数若回流指导更新/停止/挑检查点，密封测试就变成了搜索信号（字节三论文"验证信号过拟合"短板的理论根）。协议三件：

1. **密封独立**：多轮更新循环用训练信号，最终主张只用从未参与更新的密封集；密封分数不回流。
2. **预算对照**：改进循环的全部成本（提案+执行+验证+被拒候选+失败重试）计入再与基线比——"多花十倍算力换一分提升"不是改进。*swarm-yuan 预算登记制度同构（FACT_ARTIFACT_BYTES_BUDGET 逐例登记）。*
3. **改进器消融**：冻结 I 对照同起点同预算跑——分离"I 的贡献"与"堆资源的效果"。

配套纪律（清华综述）：**修复类验收双查**——修完 A 既要验证 A 消失，也要查原有正确行为没退化（= 能力保留证据，本技能"修复面=修复点+相邻路径"纪律的理论根基）；**机制覆盖 ≠ 能力证据**——登记了哪些机制与这些机制获得怎样的验证是两张表（= "登记不算证据"判据的学理出处）。

## 五、字节五短板 × 既有防线映射（同构对账表）

字节 Seed 论文实证的自进化五短板，本技能均有既有防线（非新增，理论定名）：

| 短板 | 既有防线 |
|---|---|
| 验证信号过拟合 | Mutation Check 防复发断言（断言形态多样）+ 换栈演练轮换 fixture 栈 |
| 非单调迭代（后续改进反而变差，需回滚） | last-good 防坏基线 + `--no-ff` merge 可回退 + git |
| 可移植性差（A 项目经验挪到 B 就失效） | 全量随技能分发自包含 + 生成器跨项目复用设计 |
| 自我评判薄弱（自评好 ≠ 真好） | ⑦独立审查节点 + Prove-It + verifier 司法独立 |
| 目标可操作化前置（目标含糊时迭代全部白费） | spec-first hook 硬门 + 结构化访谈协议（节点①前沿轮次制） |

## 六、已登记未实施（触发条件写明）

- **吸收轮候选自举化**（L3→L4 方向试探）：把"调研源发现→吸收两问→落地四步→收口五件套"做成半自动管道（AI 提议吸收清单+验证计划，人只批）。触发：吸收轮频率高到人工两问成为瓶颈时。
- **改进器增益的量化对照**：连续两轮吸收的"次轮回归发现率"追踪（上轮沉淀的纪律有没有减少下轮的同类缺陷）。触发：轮台账积累到可统计时。
