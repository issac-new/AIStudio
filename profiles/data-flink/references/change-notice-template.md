# 表变更通知单模板 (change-notice)

> 数据治理域 SOP #1 的执行载体。任何 DDL 变更(新增表/改字段/改分区/删表)必须发本通知单。

## 通知单

```markdown
## 表变更通知单 <YYYYMMDD-seq>

### 变更内容
- 表: <db>.<table>
- 类型: 新增 | 字段变更 | 分区变更 | 删除
- 明细: <字段级 diff 或 DDL>

### 上游影响
- 源系统: <业务库/表>
- 同步管道: <pipeline 名/作业 ID>

### 下游影响 (血缘)
- 直接受影响作业: <列表>
- 间接受影响表: <DWD/DWS/ADS 层列表>
- 受影响指标: <指标字典中的指标名,如有>

### 兼容性判定
- [ ] 字段类型兼容 (老下游不炸)
- [ ] 主键/分区策略未变
- [ ] 指标口径未变 (若变,指标字典需同步更新)

### 执行计划
- 执行人: data-arch
- 执行时间: <时间>
- 回滚方式: <DDL 回滚语句或策略>
```

## 流程

1. data-arch 填单 → kanban_comment 到相关任务卡
2. data-flink 在 comment 中确认「下游作业兼容」或提出改造需求
3. 确认后 arch 执行变更 → 把执行结果(实际 DDL + 时间)追加入通知单
4. data-flink 验证作业恢复/无反压 → 关闭通知单

## 质量门禁配置参考 (治理 SOP #2)

DWD+ 作业内置检查(在作业 SQL 中以 filters/独立校验作业实现):
- 行数波动: 较前 1 小时 ±30% 告警
- 主键唯一: `COUNT(*) - COUNT(DISTINCT pk) = 0`
- 非空: 关键维度字段 `IS NOT NULL` 比例 ≥ 99.9%
- 及时性: 数据分区时间与当前时间差 ≤ SLA(如 5min)
