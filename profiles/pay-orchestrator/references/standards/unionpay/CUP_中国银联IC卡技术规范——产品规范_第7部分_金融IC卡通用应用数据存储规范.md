6 通用存储概述 
6.1 基本概念 
6.1.1 通用存储整体结构 
6.1.1.1 通用存储概念 
通用存储是指在IC 卡上预先规划的空间内，在统一的数据文件、统一的APDU 指令、统一的应用
模板及统一的安全规则下，实现应用或记录的添加、读取或删除。 
6.1.1.2 通用存储应用 
通用存储应用是指利用IC 卡支持多应用的特性，在IC 卡上以目录文件的形式，预先划分出一部分
空间，并按本规范定义的文件接口或应用模板的要求进行初始化，该部分空间即可支持后续按统一指令
要求进行的应用操作。  
6.1.1.3 通用存储应用与UICS 应用关系 
通用存储是一个独立的应用，它与标准的UICS 借贷记金融应用共存于一张IC 卡上。通用存储应
用与UICS 金融应用之间相互独立，互不干扰，在应用内部各自遵循自定义的应用流程和安全机制。在
卡片上涉及支付方面的功能由金融IC 卡借贷记应用完成。通用存储应用所占卡片区域与金融应用区域

快速通用应用目录可以为一些数据结构简单、安全性要求较低的行业应用提供存储空间和方法。它
在通用存储空间内预先分配特定的应用目录，在应用目录中，相应行业可参考标准行业应用模板文件设
计行业应用文件或记录，并在无需验证或简单验证（例如持卡人通用存储密码验证或记录密钥控制验证）
通过的情况下写入或读出。 
——通用应用目录： 
通用应用目录是采用更高安全机制进行读写控制的目录，其数据内容的控制和管理一般由特定的行
业负责。在通用应用内的文件信息格式和逻辑结构由行业自行负责管理，并不受其他应用的影响。但采
用的文件类型、通讯指令应符合本规范的要求。 
——应用列表： 
应用列表是一个文件，主要包含卡内已添加的应用信息，并由卡片COS进行维护。

6.1.1.4 通用存储文件与通用存储行业应用模板 
通用存储文件是以ISO7816为基础，定义的底层的文件格式，在通用存储空间中所用到的各种应用
均以通用存储文件为基础。在通用存储文件的基础上，本规范还根据各行业特性定义部分标准行业应用
模板（可以是应用，可以是文件），相关行业可方便使用该类模板，写入到通用存储区域。 
6.1.2 安全机制 
符合本规范的IC卡应满足如下基本安全机制： 
应用安全：包括应用与应用间的安全，应用添加的安全、应用删除的安全等。 
数据安全：对应用数据读、写、修改的安全控制。 
认证安全：卡片与终端的双向认证，终端对卡片的单向认证，卡片对系统后台认证，系统后台对卡
片认证等。 
6.1.3 二次个人化 
满足本规范的卡片应支持在从发卡行发出后，使用规范中统一的指令，通过添加一个应用或一个通
用存储文件的方式对通用存储空间内的内容进行修改。通常其基本流程如下： 
第一步：选择通用存储空间 
第二步：取卡片随机数 
第三步：使用认证命令进行认证 
第四步：写入通用应用或通用存储数据 
6.1.4 对支持通用存储功能IC 卡的物理要求 
为实现卡片的多应用存储，满足本规范的卡片建议至少具有如下性能： 
——中央处理器：8bits 高性能CPU（或更高） 
——协处理器：DES/3DES，随机数发生器 
——数据存储空间：32K EEPROM/FLASH (或更高) 
——程序存储空间：64K ROM/FLASH (或更高) 
——数据保存时间：10 年以上 
——数据区擦写次数：10 万次以上 
——IO 通讯速率：接触界面9600 bps 以上，非接触界面106Kbps 以上，并符合PBOC2.0 规范
的要求。

7.3 快速通用应用目录 
7.3.1 快速通用应用目录的概念 
对一些数据结构明确、安全性级别要求较低的行业应用，在通用存储空间内将预先进行归类，并分
配特定的应用目录，即快速通用应用目录。目录中的文件可参照预定的行业通用存储业应用模板进行写
入。 
7.3.2 快速通用应用目录的创建 
快速通用应用目录的创建必须在外部认证通过的情况下，方可在通用存储空间进行创建，发卡机构
可以在发卡同时创建，也可在发卡后通过终端或网络，采用现场或远程的方式进行创建，快速通用应用
目录的创建应遵循本规范统一的AID分配原则。 
7.3.3 快速通用应用目录的结构 
快速通用存储目录内，根据行业特点可以放置一个文或多个文件（可能带有计数器、密钥文件、信
息文件等），使用文件类型应满足规范定义，并可参考通用存储行业应用模板进行个人化。 
7.3.4 快速通用应用目录的初始化  
在创建快速通用存储目录时，应限定该目录所占空间的大小。在创建快速通用存储目录下的文件时，
应同时指定各文件的读写保护权限。 
7.3.5 快速通用应用目录的选择 
除在通用存储空间主控密钥或该目录的主控密钥权限控制下外，快速通用存储目录不能删除，仅有
被读取的权限，能返回目录信息、文件中记录列表等（例如所有优惠券的信息等）。选中一个快速通用
存储目录后，仅能对其内部的文件进行操作，不得操作其它目录下的文件。 
7.3.6 快速通用应用目录的增加 
在卡片初次发出的时候可能未建立所有的快速通用存储目录，在后续新的快速通用应用开发完成
时，应可以在通用存储空间主控密钥或应用添加密钥的控制下，补充到该空间中去。 
7.4 通用应用目录 
主要指遵循统一指令的特定行业应用，该部分应用与快速通用应用不同，通常指需要更高的安全级
别要求，需在行业控制下方可开展文件或记录的操作，文件结构由该应用的提供者进行自行定义。其AID
可由银联统一进行分配，以便于同一行业仅需开发一套行业应用程序即可满足所有银行卡的应用。 
通用应用目录的创建与快速通用应用目录类似。

8.5 安全报文 
8.5.1 外部认证密文计算 
通用存储应用中，外部认证密文长度为8字节，外部认证密文的计算方式如下：在进行外部认证之
前，需要通过取随机数指令，获取8字节随机数；用DEAK对输入的8字节随机数进行3DES运算（ECB链接
模式;无填充处理），得到外部认证所需要的密文数据，作为外部认证指令的数据发送给卡片进行认证。 
8.5.2 MAC 计算 
每次计算MAC前都需要获取随机数作为初始向量。具体计算步骤如下： 
通用存储使用带填充的DES算法作为加密运算来计算MAC。 
计算MAC需要5个步骤： 
步骤1 
取4字节的随机数 +‘00 00 00 00’作为初始变量。 
步骤2 
按照顺序将以下数据连接在一起形成一个数据块： 
CLA， INS， P1， P2， Lc(Lc为终端发出的命令数据域的实际长度，包括4字节MAC),特定应用的
固定数据(命令数据域中包含的明文或密文数据) 
步骤3 
将步骤2产生的大数据块分成8字节为单位的小数据块，标号分别为D1，D2，D3，D4等，最后的数据
块可能为1-8个字节。 
步骤4 
对最后一个数据块按如下方法填充数据，使其达到8个字节： 
若最后一数据块长度已经为8字节，其后仍然添加8个字节的十六进制数字‘80 00 00 00 00 00 00 
00’ 
若最后一数据块长度不足8字节，则在其后添加十六进制数字‘80’，若仍不足8字节，则在其后添
加十六进制数字‘00’，直至达到8个字节为止。 
步骤5 
对这些8字节长度的数据块采用指定的安全报文密钥(应用维护密钥或者计数器增值和减值密钥
等)，以DES算法进行加密(见图 7.2)。 
采用该算法来计算的8字节长度数据块的个数取决于步骤2计算的数据块的长度。SM-MAC 是最后得
到的8字节数据加密块的前4个字节(从左侧起)。

9.2.1 Create file：创建文件命令 
——命令描述： 
该命令用于创建通用数据存储文件，包括ADF、EF（二进制文件、记录文件、计数器文件、带扩展

注：DDF的创建不在本规范的定义之内。 
——使用条件和安全： 
1)在通用存储空间下建立文件，必须通过DDF的应用主控密钥（DACK）或应用添加主控密钥(DAAK)
的认证；指令如需MAC也使用对应的密钥计算； 
2)在ADF下建立文件，必须通过ADF的应用主控密钥ACK的认证，指令如需带MAC也使用ACK的密钥计
算； 
3)ACK必须通过密文+MAC方式更新，参与安全运算的密钥为ACK本身； 
4)同一DF下仅能创建一个安全文件，文件名固定为EF00,否则卡片返回6A80；安全文件创建时，密
钥条数必须大于或者等于创建(ADF/DDF)时已默认存在的密钥，对于更新密钥，允许在未创建安全文件
时更新已经存在的密钥； 
5)DDF、ADF下均可创建多个记数器文件； 
6)在同一DDF下，包括此DDF在内的所有文件的AID必须唯一； 
7)在同一ADF下，包括此ADF在内的所有文件的FID必须唯一； 
8)所有的数据文件(包括二进制文件、记录文件、带扩展域的记录文件、计数器文件)均只能通过短
文件标识符(SFI)访问,SFI的有效范围为1~30，因此一个DF下最多只能创建30个数据文件； 
9)创建文件时,空间不能为0000； 
10)文件记录长度、个数均不能为00； 
11)创建带扩展域与计数器绑定文件时，绑定的计数器文件规则见附录B。

10.1.1 快速通用应用（通用应用）目录增加 
在通用存储空间中，发卡行在卡片发行时可能已预制部分快速通用应用目录或通用应用目录，在卡

终端通过Create File 指令在通用存储空间内创建快速通用目录或通用目录的ADF 以及ADF 下的各
类应用文件。 
1. 创建应用目录ADF 
a) 终端需要先获取卡片的创建权限，即通过外部认证指令验证卡片的通用存储空间主控密钥
（DACK）或通用存储空间应用添加密钥（DAAK）。 
b) Create File 指令中指明新建通用应用目录ADF 的初始主控密钥是全0 或者是继承通用存储空
间DDF 的主控密钥。

c) 如果需要安全报文，Create File 指令中同时指明安全报文是由通用存储空间DDF 的主控密钥

i.终端机具认证方式：终端上插有PSAM 卡，PSAM 卡内存有行业根密钥，终端通过PSAM 卡内分散

c) 在应用目录的主控密钥（ACK）的保护下，通过Write Key 指令，向安全文件中写入各类密钥。

10.2.1 带扩展域文件基本概念 
带扩展域的定长记录文件是一种记录自身具备单独控制权限的特殊文件。此类文件的记录增加以及

Append E-Record指令的安全报文； 
c)卡片查找带扩展域的定长记录文件中的空闲记录，在验证安全报文后，将新纪录内容写入到空闲

A.1.4 优惠券业务功能 
1.优惠券发行 
优惠券发行是指优惠券提供商或者商户将其需要发行的优惠券信息写入用户卡片中。优惠券提供商
或者商户可自行选择将优惠券信息写入EF01或EF02。EF01保存的为低安全性要求的优惠券类型，读写权
限为任意。EF02保存的优惠券则由发行方自行设置密钥保护，以保护该条优惠券信息不被第三方改写或
删除。 
优惠券的发行场所主要包括： 
• 
发卡行或者优惠券运营商设置的集中发行点：可查询并下载多个商户提交的优惠券 
• 
商户：在商户POS 下载该商户专用优惠券 
• 
个人互联网终端：通过远程连接优惠券平台自助查询并下载优惠券 
2.优惠券消费 
用户持卡在优惠券所属的商户进行消费，由商户终端读取优惠券信息，并根据不同的优惠券类型和
实际业务需求进行后续操作。 
• 
对有有效期的优惠券，应先检查是否在有效期之内。 
• 
对记名类型的优惠券，应先检查黑名单，并根据需要对用户进行身份校验。 
• 
对计次类型的优惠券，在正常消费以后应将次数/张数减一。 
• 
对金额类型的优惠券（代金券），在正常消费以后应将该优惠券删除。 
3.优惠券删除 
优惠券的删除应符合10.3通用应用目录记录删除的要求。可由持卡人发起或由优惠券提供商发起。

带扩展域的记录文件与计数器绑定规则 
B.1 绑定计数器文件要求 
1、 计数器文件短文件标识符为0x10，若ADF 下已经存在短文件标识符为0x10 的文件，则卡片返
回6985； 
2、 该计数器文件中的计数器个数与带扩展域的记录文件的记录条数相同。带扩展域的记录文件的
记录号对应了计数器文件中的计数器序号； 
3、 计数器的增值密钥需要使用计数器文件的增值密钥经过密钥分散因子分散后获得； 
4、 计数器的减值密钥即对应记录的记录维护密钥； 
5、 该计数器文件中，当带扩展域的记录删除之后，对应的计数器也一同重置。计数器状态设置为
失效状态，处于失效状态的计数器将无法使用； 
6、 带扩展域的记录文件中的记录APPEND 成功时，其对应的计数器同步启用。可以单独对于启用
状态的计数器进行增减值操作。 
B.2 计数器增值密钥分散 
计数器的增值密钥需要使用计数器文件的增值密钥经过密钥分散因子分散后获得。 
B.2.1 密钥分散因子计算 
取8字节全0，通过对应记录的记录维护密钥进行3DES加密，获得的加密结果即为计数器增值密钥的
密钥分散因子。 
B.2.2 增值密钥分散算法 
推导计数器增值密钥左半部分的方法是： 
——将以B.2.1中计算获得的分散因子作为输入数据； 
——将计数器文件的增值密钥作为加密密钥； 
——用计数器文件的增值密钥对输入数据进行3DEA运算。 
推导计数器增值密钥右半部分的方法是： 
——将以B.2.1中计算获得的分散因子求反，作为输入数据； 
——将计数器文件的增值密钥作为加密密钥； 
——用计数器文件的增值密钥对输入数据进行3DEA运算。
