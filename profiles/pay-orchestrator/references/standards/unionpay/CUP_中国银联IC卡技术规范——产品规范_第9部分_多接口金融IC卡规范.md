3. 术语和定义 
下列术语和定义适用于本规范。 
3.1. 
音频接口 audio interface 
多接口卡上用于和智能设备进行通信的耳机/麦克风接口，用于传输经过调制后的模拟信号。 
3.2. 
声道  audio track 
声音在录制或播放时在不同空间位置采集或回放的相互独立的音频信号，声道数为声音录制时
的音源数量或回放时对应扬声器的数量。

3.3. 
银联多接口金融IC卡  CUP multi-function shaped card 
本规范中“银联多接口金融IC 卡”、“多接口金融IC 卡”、“多接口卡”一词是指具有非接触式
界面，并携带USB 接口和音频通讯功能的智能IC 设备，支持标准借贷记功能和非接触小额支付功
能，同时支持数字证书认证功能。 
3.4. 
接入设备 point of entrance 
指具备USB 接口或者音频接口的可接入互联网的个人电脑（PC）、智能设备等。 
3.5. 
处理中心  process centre  
用于接收、处理或转发多接口卡交易请求信息，并向多接口卡回送交易结果信息的系统。 
3.6. 
安全通道  secure channel  
建立在多接口卡与处理中心之间的安全通信通道。 
3.7. 
安全通道应用 secure channel application 
多接口卡安全主控模块内负责与处理中心建立安全通道的应用。 
3.8. 
数字证书 digital certificate 
用来标志和证明网络通信双方身份的数字信息文件。数字证书包含签发该证书的权威机构对该
证书的签名，通过这个签名保障证书的合法性和有效性，同时也保障了证书中公钥和其他相关信息
的真实性和完整性。数字证书符合X.509 格式。 
3.9. 
数字签名 digital signature 
以电子形式存在于数据信息之中的数据，可用于辨别数据签署人的身份，并表明签署人对数据
信息中包含的信息的认可。 
3.10. 
网上银行 internet banking 
通过互联网为客户提供金融服务的银行系统。 
3.11. 
移动银行 mobile banking 
通过移动互联网为客户提供金融服务的银行系统。 
3.12. 
交易防劫持 anti-hijacking 
 
无屏显或按键的非接触式卡片交易和数字证书签名过程中，卡片或者数字证书设备可被劫持，
导致交易信息被篡改。多接口卡通过屏显交易信息并要求持卡人触动按键确认的方式，防止交易劫
持。 
3.13. 
防劫持阈值 anti-hijacking threshold 
多接口卡不强制持卡人按键即可完成交易的最低交易金额数值。

握手协议工作步骤 
1) 多接口卡获取算法标识A1,并产生随机数r1，r1 和A1 连接后得到R1，根据多接口卡的算
法支持设置在以下步骤中需要用到的对称算法和非对称算法； 
2) 多接口卡将随机数和算法信息发送到处理中心，启动握手协议； 
3) 处理中心选择算法标识A2，产生随机数r2，r2 和A2 连接后得到R2。根据从多接口卡发来
的算法信息，检查处理中心是否支持，如果处理中心支持此算法，则设置处理中心对应的
加解密算法；不支持则返回错误信息，断开连接； 
4) 处理中心发送随机数和处理中心的渠道证书； 
5) 多接口卡使用预置的CA 根证书验证收到的处理中心的渠道证书，如果验证不通过，则发送
出错消息，结束链接；否则，多接口卡产生48 字节随机数作为共享主密钥M1，并且使用
处理中心的渠道证书中的公钥采用之前设置的非对称算法对M1 加密得到E1； 
6) R1 和R2 连接后得到R3，多接口卡先对R3 进行SHA-1 摘要算法得到H1，然后使用多接口
卡私钥对H1 进行签名运算得到S1； 
7) 多接口卡将S1、E1 和多接口卡证书发送到处理中心； 
8) 处理中心使用CA 根证书验证多接口卡证书合法性，若多接口卡证书验证不通过，则发送错
误消息，结束链接；如果多接口卡证书验证通过，则使用多接口卡证书验证S1。若S1 验
证不通过，则发送错误消息，结束链接。否则，从E1 中解密得到共享主秘密M1； 
9) 处理中心对渠道证书进行SHA-1 运算得到H2，对多接口卡证书进行SHA-1 运算得到H3。将
R1、R2、H2、H3、S1、E1 连接后得到T1（T1=R1||R2||H2||H3||S1||E1）；然后对T1 进行
SHA-1 运算得到H4；将ASCII 码“SERVER”和H4 连接后得到D1；使用M1 前16 个字节对
D1 进行HMAC 运算得到F1（HMAC 计算方法见附录B.3）； 
10) 处理中心发送握手验证完成消息F1 到多接口卡； 
11) 多接口卡验证接收到的处理中心发来的F1，若验证不成功，则发送错误消息，结束链接；
否则，多接口卡生成握手验证消息F2；F2 运算与F1 运算方法一样，只需要将F1 运算时的
ASCII 码“SERVER”改为ASCII 码“CLIENT”；

10.3.2. 记录层协议 
握手成功之后，双方可在建立的安全通道上进行数据传输。 
记录层协议的数据加密方法 
在传输的数据Data前添加数据块长度Length(2字节)，构成数据块D =（Length||Data）。使用
加密密钥SKey按照多接口卡与处理中心约定的加密算法（参见附录B.1）对D进行加密。即： 
EData = ESKey (D)； 
记录层协议的数据完整性保护方法 
在记录层协议的传输过程中，为双端每个发送和接收记录指定记录序列号，其初始值Seq0按以
下方法生成： 
取多接口卡随机数的前8个字节Random1，取处理中心随机数的前8个字节Random2，则Seq0 = 
Random1 || Random2。 
每发送或接收一帧记录信息后，记录序列号加1，及Seqi = Seqi-1 + 1。注意双端要保持发送接
收序列号的同步。 
双方交互的应用数据的完整性使用消息认证码MAC进行保护，MAC按以下方法生成： 
DataMAC = MAC( MKey, Seqi || EData)  
（MKey取其前16个字节） 
其中EData是所传输的加密应用数据，Seqi是当前的记录序列号。MAC的计算方法参见B.2。多接口
卡或处理中心接收到数据后，首先验证MAC的正确性，如果正确则进行处理；否则，发送错误消息。
校验错误则需结束当前链接，重启握手协议。

10.5. 
联机PIN获取机制 
联机PIN的获取是指多接口卡从接入设备获取联机PIN的过程，该过程建议通过多接口卡上的按
键实现，若无按键则通过多接口卡公钥加密的方式实现。公钥加密的方式具体过程如下： 
1. 持卡人在接入设备上输入并确认联机PIN； 
2. 接入设备向多接口卡发送“INIT FOR PIN ENCRYPT（初始化PIN加密）”命令，获取多接口
卡的公钥Kp和随机数R（4字节），多接口卡内部保存R直到本次交易结束； 
3. 接入设备对联机PIN采用ANSI X9.8方式填充，即先在PIN的前面加1字节的PIN长度，再在PIN
的右边补F直到8字节PINBLOCK（示例：明文PIN为123456，则PINBLOCK = 0x06 0x12 0x34 0x56 
0xFF 0xFF 0xFF 0xFF）； 
4. 接入设备在PINBLOCK右边连接随机数R，然后在PINBLOCK左边补0直到整个数据块长度等于
多接口卡公钥Kp的长度，将此填充完的数据块标记为D1； 
5. 接入设备用Kp对数据块D1进行RSA加密运算，得到加密结果X1； 
6. 接入设备向多接口卡发送“SET PIN BALANCE”命令，将PIN密文X1发送给多接口卡； 
7. 多接口卡用其私钥Ks对X1进行解密运算，得到数据块D1的明文；

8. 多接口卡从数据块D1中获取随机数R，与多接口卡内部保存的随机数进行比较，如果相同，
则继续；否则结束本次交易； 
9. 多接口卡从数据块D1中获取联机PIN明文；

10.6. 
音频接入模式的异常处理 
在音频接入模式下，由于某些手机应用（通话、通知、媒体播放等）也会操作耳机接口，可能
会出现通信数据被干扰的情况。因此建议音频通信API 以及应用软件做出必要的预防性处理，减少
被干扰的机率。由于各类智能设备操作系统对耳机接口管理以及声源管理的差异性，这些处理手段
不强制要求实现。 
1. 建议应用软件在交易过程中监测到来电时，给予用户提示。让用户选择继续交易，或者拔
出多接口卡以接听电话。 
2. 建议插入多接口卡并开始交易前，记录系统“通知音”(如短信提示音)的音量并调为静音
状态，在交易结束时，恢复通知音的音量。 
3. 如果因接听电话、通知音或媒体播放等因素，导致音频接入模式下的交易中断，系统应按
照规范中的防插拔处理机制进行处理。

附录A-安全通道建立过程示例 
接入设备向多接口卡发送GET CLIENT HELLO命令，多接口卡返回1字节的算法标识和32字节随机
数； 
接入设备从1字节的算法标识中获得多接口卡支持的对称和非对称算法列表，此标识将被发送到
服务器端，服务器端会根据算法列表，检查算法列表中是否包含服务器端渠道证书所用的签名算法
和对称算法； 
随机数在此后的验证和生成认证信息时用到。 
服务器端发送渠道证书、算法标识和32字节的随机数到多接口卡。 
此时多接口卡应该先检查渠道证书的合法性，即HASH SERVER CERTIFICATE命令和VERIFY SERVER 
CERTIFICATE命令； 
HASH SERVER CERTIFICATE命令用来对渠道证书主体进行哈希运算，并且将哈希运算结果保存在
多接口卡内部； 
VERIFY SERVER CERTIFICATE命令则使用多接口卡内的CA根证书对渠道证书的签名值进行解密，
并且与HASH SERVER CERTIFICATE的哈希结果进行对比，从而检查渠道证书的合法性； 
完成对渠道证书的合法性检测后，多接口卡将产生48字节的随机数作为共享主密钥，并且使用
渠道证书对此共享主密钥进行公钥加密，EXPORT MASTERKEY命令即完成渠道证书对共享主密钥的加
密并且返回128字节的密文； 
通过READ CERTIFICATE命令和GET CERT RESPONSE命令读出多接口卡证书，因为考虑到证书大小
比CCID单条命令最大传输字节数还要大，所以无法通过一条命令来读出多接口卡证书，GET CERT 
RESPONSE命令可以多次调用，直到完全读出多接口卡证书，命令详细解释请参见11.2； 
服务器端认证多接口卡时，需要通过校验多接口卡私钥签名来完成。多接口卡通过CLIENT SIGN
命令对传入的服务器端随机数和多接口卡本身随机数的连接值进行哈希和签名操作，返回128字节的
签名数据； 
多接口卡将128字节共享主密钥的密文、多接口卡证书和128字节的签名值发送到服务器端。 
服务器端使用根证书检验多接口卡证书的合法性，如果多接口卡证书合法，则使用多接口卡公
钥验证签名值，从而确定多接口卡的合法性；完成对多接口卡的认证后，则使用渠道证书的私钥对
共享主密钥的密文进行解密得到48字节的共享主密钥；此处需要发送一个服务器端认证完成的消息，
为了防止此消息被伪造，此消息通过计算HMAC的方式来完成，其密钥为48字节共享主密钥的前16个
字节，数据为ASCII“SERVER”、多接口卡随机数、服务器端随机数、渠道证书哈希值、多接口卡证
书哈希值、多接口卡发到服务器端的签名值、和共享主密钥的密文信息； 
服务器端将握手完成消息，即服务器端计算出来的HMAC值发送到多接口卡。 
多接口卡收到HMAC后，使用HMAC（P2=0x01）命令验证服务器端握手完成产生的HMAC值。然后，
使用HMAC（P2=0x00）命令返回多接口卡握手完成产生的HMAC值，此命令计算HMAC值的过程与服务器
端产生HMAC值的方法一样，只需要将ASCII“SERVER”改为“CLIENT”； 
多接口卡将握手完成消息，即多接口卡计算出来的HMAC值发送到服务器端； 
多接口卡通过HMAC（P2=0x02）命令产生会话密钥，此会话密钥只保存在多接口卡内，不能导出，
并且断电需要重新生成。 
服务器端验证多接口卡握手完成消息后，产生会话密钥。 
最终，多接口卡和服务器端都共同拥有48字节的共享主密钥和20字节的会话密钥，其中20字节
的会话密钥的前16个字节作为加密密钥，后面取16个字节作为计算MAC的密钥。

B.1 数据加密 
在更新密钥时的数据加密过程如下： 
步骤1 
数据块的生成： 
– 明文的数据长度(Ld) 
– 明文数据（Ld置于明文之前） 
步骤2 
对步骤1产生的数据块分成8字节为单位的数据块，标号分别为D1，D2，D3，D4等，最后一个数
据块长度可能为1-8个字节。 
步骤3 
对最后一个数据块按如下方法填充数据，使其达到8个字节： 
– 若最后一数据块长度已经为8字节，其后不必添加数据。 
– 若最后一数据块长度不足8字节，则在其后添加十六进制数字‘80’，若仍不足8字节，则
在其后添加十六进制数字‘00’，直至达到8个字节为止。 
步骤4 
采用3DES算法对上述每一数据块进行加密，详见下图。

附录E个人化  
银联多接口卡的个人化，包括金融应用的个人化、安全通道应用的个人化和数字证书应用的初
始化三部分。 
为保证安全性、效率和稳定性，多接口卡个人化时应通过接触接口（推荐用USB接口）进行数据
初始化操作。生产制造和数据初始化设备应能适应多接口卡的各种外型，应做到自动化生产和无人
工干预。 
多接口卡在生产制造时应内置一个设备证书，该证书区别于金融应用、安全通道应用和数字证
书应用的证书。该设备证书的用途是，保证个人化对象和数据在传输写入过程的保密性、唯一性、
防篡改和不可抵赖，并保护数字证书应用的初始化过程。 
E.1 金融应用的个人化 
金融应用的个人化由发卡行完成，采用发卡行数据准备系统生成的制卡数据，完成金融应用的
个人化工作。其流程与标准金融IC卡的个人化基本一致，具体可参考Q/CUP 046.5-2012规范中的描
述。  
应采用设备证书加密保护的方式，把个人化数据从数据提供方（如银行）加密传输到多接口卡，
在多接口卡内解密写入。如下图所示。

G.1 防劫持阈值设定 
持卡人设定防劫持阈值的方式可有2 种： 
 持卡人通过多接口卡的按键来设定阈值 
示例：在开机状态下，长按“C”键，则多接口卡进入阈值设定模式。持卡人使用按键，输入阈值金
额或者选择阈值金额后，按“OK”键完成阈值的设定。阈值为数字，不包含字母、小数点或其他字
符。 
 持卡人通过外部设备，把阈值输入到多接口卡，并按键确认 
示例：持卡人通过移动设备输入阈值。多接口卡屏显阈值金额，待持卡人确认阈值金额并按“OK”
键后，完成阈值的设定。
