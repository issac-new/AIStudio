## 二、互联规范·支付机构接入（Q/NUC 103.2—2018）核心

### 2.1 接入拓扑与通信协议（原文级）

- **专线接入**: "支付机构通过专线与平台连接"（§参与者接入方式）
- **通信方式**: HTTPS POST，平台为服务端，支持 Keep-Alive；报文格式 **XML**（Content-Type: application/xml;charset=utf-8）
- **五项通信安全要求**（交互图原文）: ① HTTPS ② XML 报文 ③ **SSL 单向认证** ④ 通信报文加签 ⑤ **通信过程全包加密**
- **多前置/多数据中心**: 平台提供多个渠道前置系统，支付机构**顺序或随机使用**接入因子实现负载均匀；**专线或数据中心故障时应切换**并均匀使用平台接入因子（§原文）——高可用双活设计

### 2.2 交易流水号规则（§4.4 原文级）

- **31 位交易流水号**，由平台定义生成规则，支付机构创建与维护
- 组成: 含"1 位预留位"（平台分配枚举，附录 A.2）
- **流水号控制位因子机制**: 支付机构在服务初始化时及**每 30 秒定时**向平台获取流水号生成控制位因子 → 获取流水号 → 缓存流水号 → 创建流水号 → 校验流水号（原文流程图六步）
- 因子用尽/失效前须重新获取（防跨机构冲突）

### 2.3 服务功能清单（§5.1.2 全目录，19 项）

| 类别 | 服务 |
|------|------|
| 签约类 | 5.1.2.1 身份认证及签约申请、5.1.2.2 商业委托签约申请（网关建立委托/线下建立委托）、5.1.2.3 解约申请、5.1.2.4 解约通知、5.1.2.17 商业委托查询 |
| 支付类 | **5.1.2.5 协议支付申请**（协议支付/委托支付统一入口，转发付款行）、5.1.2.6 银行验证支付申请、5.1.2.7 银行验证支付提交、**5.1.2.8 网关支付申请**（返回网关支付跳转，机构跳转银行网关）、**5.1.2.9 退款申请**、**5.1.2.10 付款申请** |
| 差错类 | 5.1.2.11 差错提交申请、5.1.2.12 差错调账申请、5.1.2.16 差错状态查询 |
| 查询/对账类 | 5.1.2.13 交易状态查询、5.1.2.14 非正常终态查询、5.1.2.15 交易详情查询、5.1.2.19 对账文件 |
| 异常类 | **5.1.2.18 未明交易**（超时未明处理机制） |

### 2.4 终态通知与超时补偿（原文级）

- **协议支付终态通知**（5.2.2.4）: 平台在超时时间内未收到付款行应答时，通过终态通知服务向支付机构发送"协议支付终态通知报文"，支付机构受理后回"通用应答"
- **状态补偿机制**: "对参与者响应超时但未达交易关闭时间的交易，平台将根据补偿机制发起交易状态查询"（§4 原文）
- **清分口径**: "平台清算时，将根据**正常终态和非正常终态**对交易进行清分处理，在对账文件中向支付机构提供"——对账文件必须区分两种终态
- 网关支付链路: 平台受理机构申请 → 返回**网关支付跳转**（机构跳转银行网关）→ 平台受理银行状态通知 → 返回终态通知

### 2.5 银行接入（Q/NUC 103.1—2018）差异点

- 银行同样以**专线**接入（"平台通过专线与银行连接"）
- 支持**代理清算接入**: "平台支持被代理行通过专线与平台连接，以及通过**汇聚节点**与平台连接"（§图 33 代理清算接入方式）——中小银行经由代理行/汇聚节点间接接入
- 业务范围与机构侧对应（协议支付/网关支付/付款等的银行侧处理）

## 三、安全规范·数据安全传输控制（Q/NUC 104.1—2018）

### 3.1 四大安全模块（§5 原文目录级）

| 模块 | 机制（原文要点） |
|------|----------------|
| **SSL 加密解密**（5.1） | 链路层 HTTPS/TLS 通道安全 |
| **报文签名验签**（5.2） | 发起方**计算整个报文哈希 → PKCS#1 方式非对称签名 → 存入报文"数字签名域"**；接收方用发起方公钥验签；报文头"**签名证书序列号**"标识所用证书；推荐国密算法（RSA 与 SM2 各用对应密码套件）；**证书更新过渡期双证书并行**，原证书有效期内完成平滑切换 |
| **敏感信息加密解密**（5.3） | **数字信封机制**: 发起方自产对称密钥（如 AES256，256 位随机数）加密敏感信息 → 用接收方公钥加密"算法类型+对称密钥"生成**数字信封**（Base64）入报文头 → 接收方按"加密证书序列号"取私钥解信封得对称密钥 → 解密敏感信息；**证书更新同样双证书平滑过渡** |
| **对账文件加密解密**（5.4） | 对账文件同样按加密传输要求处理 |

### 3.2 单证体制 vs 双证体制（原文注释，高频考点）

> "国际算法（RSA）是**单证体制**，签名和加密使用同一个证书；国密算法（SM2）是**双证体制**，签名证书和加密证书使用不同的证书。"

工程含义: 接 RSA 通道的机构维护一套证书即可；接 SM2 通道必须同时维护签名证书对 + 加密证书对，且证书序列号在报文头成对出现。

## 四、安全规范·证书（Q/NUC 104.2—2018 V1.3.1）

### 4.1 证书体系（原文级）

- **双证书制**: "根据用途分为签名证书和加密证书"——签名证书保证信息**不可否认性**，加密证书用于信息**加密传输**
- **双密钥 + 国密**: "包含双密钥和双证书，支持加密和签名采用不同密钥对，使用**国密 SM2 算法，密钥长度 256 位**"
- **签名算法套件**: **SM2withSM3**（规范内出现于算法配置处）
- **传输密码套件**: **SSL-SM2**（国密 SSL 通道套件标识）

### 4.2 CA 与证书层级（原文级）

- **CA 系统: CFCA**（中国金融认证中心）提供 CA 服务与服务器证书服务
- 证书主题样例（规范附录原文）:
  - 企业证书: `O=CFCA RSA OCA31`（RSA 体系普通/高级证书）
  - 企业高级证书: `O=CFCA SM2 OCA31`（国密体系）
  - 网联机构证书 DN 示例: `CN=051@NetsUnion Clearing Corporation@ZG4000311000018@1, OU=Organizational-1, OU=NUCC, O=CFCA RSA OCA31, C=CN`——**DN 内嵌机构编码**（051@机构名@机构码@序号 格式）
  - 服务器证书: `CN=3.3.1.10, OU=SSL-SM2, O=NetsUnion Clearing Corporation, L=Beijing…`

### 4.3 机构接入证书工程清单

1. 机构本地生成 SM2 双密钥对（签名对 + 加密对）
2. 公钥 + 机构资料提交 CFCA/网联审核签发双证书
3. 报文头按用途分别携带签名证书序列号 / 加密证书序列号
4. 证书到期前完成双套证书并行过渡（§104.1 平滑切换要求）
5. 通道侧配置 SSL-SM2 密码套件（或 HTTPS RSA 套件双栈）

## 五、银联 CUPS vs 网联 NUCC 全面对照（原文级修正）

| 维度 | 银联 CUPS | 网联 NUCC |
|------|-----------|-----------|
| 底层报文 | **ISO 8583**（1987 版结构 + 128 域自有定义，见 `ISO8583-DETAIL.md`） | **XML（ISO 20022 风格）** over HTTPS |
| 接入方式 | 专线（通讯接口第 5 部分） | **专线 + HTTPS POST**，SSL 单向认证 |
| 签名/加密 | 8583 域 96/128 MAC + 域 63 国密 SM PIN 承载 | **数字签名域（整报文签名）+ 数字信封（敏感字段）** |
| 证书体系 | 银联 CA（RSA/国密双栈） | **CFCA 签发，SM2 双证体制**（签名+加密分离） |
| 流水号 | 域 11 STAN（6 位）+ 域 37 RRN | **31 位交易流水号** + 平台控制位因子分发 |
| 超时处理 | 冲正（0400/0420）+ 超时重发 | **未明交易 + 终态通知 + 平台补偿式状态查询** |
| 对账 | 第 3 部分文件接口（CUPS 清算文件） | 对账文件服务（5.1.2.19，区分正常/非正常终态） |
| 差错 | 差错处理规范（银联差错分册） | 差错提交/调账/状态查询三服务 |
| 清算 | T+1 净额（CUPS 清分） | T+1 净额（备付金集中存管语境） |
| 典型业务 | 银行卡收单（POS/ATM/闪付/二维码卡基） | 互联网支付（协议支付/网关支付/付款/条码互联） |

> 冲突裁决一致性: KC-006（网联报文=ISO 20022 兼容 XML，非 8583）✅ 本文以原文证实。
