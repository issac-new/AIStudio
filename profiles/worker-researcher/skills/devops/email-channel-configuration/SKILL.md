# Email Channel Configuration

Configure and troubleshoot Hermes email channels. Two independent
approaches can coexist on different email addresses:

1. **IMAP/SMTP gateway adapter** — native Hermes platform, auto-polls IMAP
2. **agently-cli (OAuth)** — agent.qq.com CLI, cron job polls for new mail

## When to Use

- Enabling or disabling the email gateway platform
- Diagnosing "Platform 'Email' requirements not met" errors
- Setting up QQ Mail IMAP/SMTP channel
- Setting up agently-cli as an alternative or additional email channel
- Email channel stopped working after config regeneration
- Gateway logs show IMAP connection failures

## Architecture

```
                    ┌─────────────────────────┐
                    │   Hermes Gateway         │
                    │   (orchestrator profile)  │
                    ├─────────────┬────────────┤
                    │ IMAP/SMTP   │ agently-cli │
                    │ adapter     │ cron job    │
                    │ (native)    │ (script)    │
                    └──────┬──────┴──────┬─────┘
                           │              │
                   your@email.com  your@email.com
                   (QQ Mail IMAP)     (agent.qq.com OAuth)
```

Both channels can run simultaneously. Messages from either channel
route through the orchestrator's board routing rules (§0.5).

## IMAP/SMTP Gateway Adapter

### Critical pitfall: Profile .env vs global .env

The gateway runs as `hermes --profile orchestrator gateway run`, which
loads the **profile's** `.env` file:

```
~/.hermes/profiles/orchestrator/.env    ← gateway reads THIS
```

NOT the global:

```
~/.hermes/.env                           ← gateway IGNORES this
```

The profile `.env` is auto-generated by `generate-configs.py` from:

```
~/.hermes/shared/.env.common  +  ~/.hermes/shared/profiles.yaml
```

**Adding EMAIL_* vars to `~/.hermes/.env` has NO effect.** The gateway
never reads that file. The email adapter's `check_email_requirements()`
function reads `EMAIL_ADDRESS` from the process environment, which comes
from the profile `.env`.

Symptoms (email vars in wrong .env):
```
WARNING gateway.platform_registry: Platform 'Email' requirements not met
ERROR gateway.run: Platform 'email' is registered but adapter creation failed
WARNING gateway.run: No adapter available for email
```

### Enable sequence (verified 2026-07-23)

1. **Add EMAIL_* to `.env.common`** (shared source for all profile .env files):

```bash
cat >> ~/.hermes/shared/.env.common << 'EOF'
EMAIL_ADDRESS=your@email.com
EMAIL_PASSWORD=<16-char-auth-code>
EMAIL_IMAP_HOST=imap.qq.com
EMAIL_IMAP_PORT=993
EMAIL_SMTP_HOST=smtp.qq.com
EMAIL_SMTP_PORT=465
EMAIL_POLL_INTERVAL=30
EMAIL_ALLOWED_USERS=your@email.com,your@email.com
EMAIL_HOME_ADDRESS=your@email.com
EOF
```

2. **Set `email.enabled: true` in `profiles.yaml`** for the orchestrator:

```yaml
# ~/.hermes/shared/profiles.yaml
orchestrator:
  ...
  email:
    enabled: true
```

3. **Regenerate all profile configs** (use Hermes venv python — has PyYAML):

```bash
~/.hermes/hermes-agent/venv/bin/python3 ~/.hermes/shared/generate-configs.py
```

4. **Verify the profile `.env` now has EMAIL_* vars**:

```bash
grep EMAIL ~/.hermes/profiles/orchestrator/.env
```

5. **Restart the gateway** and check email connection:

```bash
hermes -p orchestrator gateway restart
sleep 10
tail -20 ~/.hermes/profiles/orchestrator/logs/gateway.log | grep -i email
```

Expected success log:
```
[Email] Adapter initialized for your@email.com
[Email] IMAP connection test passed. 45 existing messages skipped.
[Email] SMTP connection test passed.
✓ email connected
Gateway running with 3 platform(s)
```

### Gateway log path pitfall

Gateway logs go to the **profile-specific** path (as specified in the
launchd plist's `StandardOutPath`):

```
~/.hermes/profiles/orchestrator/logs/gateway.log     ← CURRENT
~/.hermes/logs/gateway.log                            ← STALE (pre-profile)
```

The stale path may contain old entries (e.g. from July 2) and will
mislead diagnosis. Always check the profile-specific path.

### Disable sequence

1. Remove all `EMAIL_*` lines from `~/.hermes/shared/.env.common`
2. Set `email.enabled: false` in `profiles.yaml` for the profile
3. Regenerate configs
4. Restart gateway

**Critical**: `email.enabled: false` in config.yaml alone is NOT enough.
`gateway/config.py` (~line 1967) auto-enables email when all 4 env vars
(`EMAIL_ADDRESS` + `EMAIL_PASSWORD` + `EMAIL_IMAP_HOST` +
`EMAIL_SMTP_HOST`) are present, overriding the config setting:

```python
if all([email_addr, email_pwd, email_imap, email_smtp]):
    config.platforms[Platform.EMAIL].enabled = True  # overrides False!
```

Must remove env vars from `.env.common` so the `if all(...)` check fails.

### QQ Mail authorization code

QQ Mail requires an app-specific **authorization code** (not the login
password). Format: 16 lowercase letters.

Generate at: mail.qq.com → 设置 → 账户 → POP3/IMAP/SMTP → 生成授权码

Verify before configuring:

```python
import imaplib, ssl
ctx = ssl.create_default_context()
mail = imaplib.IMAP4_SSL('imap.qq.com', 993, ssl_context=ctx)
print(mail.login('your@email.com', '<auth-code>'))  # Should print OK
mail.logout()
```

Also test SMTP:

```python
import smtplib, ssl
ctx = ssl.create_default_context()
server = smtplib.SMTP_SSL('smtp.qq.com', 465, context=ctx, timeout=15)
print(server.login('your@email.com', '<auth-code>'))  # Should print OK
server.quit()
```

### IMAP infinite retry loop (when auth code expires)

When the authorization code expires or is wrong, the gateway retries
IMAP login every 5 minutes (escalating: 60s → 120s → 300s cap), forever.

Log signature:
```
ERROR [Email] IMAP connection failed: b'Login fail. Account is abnormal...'
INFO Reconnect email failed, next retry in 300s
INFO [Email] Disconnected.
```

Fix: generate a new authorization code (see above), update
`.env.common`, regenerate configs, restart gateway.

## agently-cli (agent.qq.com OAuth)

### When to use

- You want OAuth-based email (no IMAP/SMTP credentials to manage)
- You need a secondary email address for different purposes
- The IMAP channel is unreliable (expired auth codes, QQ rate limits)

### Setup

1. Install CLI: `npm install -g @tencent-qqmail/agently-cli`
2. Install skill: `npx skills add https://agent.qq.com --skill -g -y`
3. OAuth authorize: `agently-cli auth login` (interactive — needs browser)
4. Verify: `agently-cli +me` (shows email address and aliases)

See the `agently-mail` skill for full command reference.

### Cron job for periodic email checking

Create a `no_agent=True` cron job that runs a shell script to check
for unread emails. The script outputs a summary when there are new
emails and stays silent (empty stdout) when there are none — this is
the watchdog pattern: no output = no notification.

Script template at `scripts/check-email.sh`:

```bash
#!/bin/bash
UNREAD=$(agently-cli message +list --dir inbox --is-unread --limit 10 2>/dev/null)
if [ $? -ne 0 ]; then
    echo "ERROR: agently-cli message +list failed (exit $?)"
    exit 1
fi
COUNT=$(echo "$UNREAD" | python3 -c "
import sys, json
try:
    data = json.load(sys.stdin)
    print(len(data.get('data', {}).get('data', [])))
except: print(0)
" 2>/dev/null)
if [ "$COUNT" = "0" ] || [ -z "$COUNT" ]; then
    exit 0  # Silent — no new emails
fi
echo "You have $COUNT new unread email(s):"
echo "$UNREAD" | python3 -c "..."  # Format output
```

Cron job configuration:
- `schedule`: `every 30m`
- `no_agent`: `true` (pure script, no LLM tokens)
- `deliver`: `all` (fan out to all connected gateway platforms)
- `enabled_toolsets`: `["terminal", "file"]`

### Two-phase confirmation for send/reply/forward

agently-cli requires a confirmation token for write operations:

```bash
# Step 1: get token
agently-cli message +send --to addr@example.com --subject "Hi" --body "Hello"
# → returns ctk_xxx

# Step 2: user confirms, then execute with token
agently-cli message +send --to addr@example.com --subject "Hi" --body "Hello" \
  --confirmation-token ctk_xxx
```

## Coexistence

Both channels can run simultaneously:

| Channel | Email address | Method | Poll frequency |
|---------|--------------|--------|----------------|
| IMAP adapter | your@email.com | Gateway native | 30s (EMAIL_POLL_INTERVAL) |
| agently-cli | your@email.com | Cron script | 30min |

Both route through the orchestrator's board routing rules (§0.5 in
orchestrator_rules.md). The email_kanban_rules.md applies to both.

## Quick diagnosis checklist

| Symptom | Check |
|---------|-------|
| "Email requirements not met" | `grep EMAIL ~/.hermes/profiles/orchestrator/.env` — vars must be in profile .env, not global |
| IMAP login fail (QQ) | Auth code expired — generate new one at mail.qq.com |
| Gateway not connecting email | `grep -A2 'email:' ~/.hermes/profiles/orchestrator/config.yaml` — must show `enabled: true` |
| Stale logs | Check `~/.hermes/profiles/orchestrator/logs/gateway.log`, not `~/.hermes/logs/gateway.log` |
| agently-cli auth expired | `agently-cli auth status` — check `expires_at` and `token_status` |
| Cron email check not delivering | Verify `deliver='all'` in cron job config |
