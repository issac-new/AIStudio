## 四论 = 软件工程的四条底层纪律

| 四论 | 工程支柱 | 工程实践即论的操作化 |
|---|---|---|
| **系统论** | **架构工程** | 模块边界=系统边界界定（Parnas 信息隐藏：边界处的接口契约即系统的边）；分层架构=层次划分；依赖图=关系分析；上下游服务与环境约束=环境分析；接口变更的 blast radius=牵连面分析 |
| **信息论** | **可观测性工程** | 日志/指标/追踪=有效观测点设计；结构化日志与采样=编码压缩；告警聚合降噪=滤波；「这条日志能改变什么排障决策」=信息增益判据 |
| **科学方法论** | **验证工程** | 单元测试=假设检验；回归测试=记忆（已证伪的结论不得复活）；验收标准=可证伪判据；code review=同行评议；postmortem=误差分析与模型修正；TDD=判据先于实现 |
| **控制论** | **交付与运维工程** | CI/CD=短周期反馈环；灰度/canary=小步扰动试探；回滚=纠偏执行器；SLO/错误预算=设定值与允许偏差；告警→处置→复盘→改进项=负反馈闭环 |

**软件生命周期 = 四论闭环的工程实例**：

```
需求 ──▶ 设计 ──▶ 编码 ──▶ 测试 ──▶ 发布 ──▶ 运维
 ▲        系统论   方法问    科学方法论  控制问    信息论+控制论
 └── 反馈（线上数据/事故/用户信号）回到需求，下一轮迭代 ◀──
```

- **需求**：系统问划边界（这个功能属于哪个模块、牵连谁）+ 信息问识别关键不确定性（先访谈/先埋点还是信息已够）
- **设计**：系统论建模——模块划分、接口契约、依赖方向
- **编码**：方法问——判据先于实现（TDD），每个函数块是一个待验证假设
- **测试**：科学方法论——证伪实践，验收标准可二分
- **发布**：控制问——灰度扰动+回滚预案先行，无回滚不发布
- **运维**：信息论（遥测回答"现在状态如何"）+ 控制论（偏差纠正：扩容/降级/回滚）
- **反馈**：线上数据与事故回灌需求，完成一圈——这就是迭代开发的本质

## 应用通道（知识按性质选通道，不按「有无留痕」一刀切）

| 通道 | 形态 | 验证方式 | 适用 |
|---|---|---|---|
| **A 结构化** | 铸进格式与门：模板、frozen 验收、回滚预案字段 | 产物天然携带证据（派工卡里有边界决策=系统问已用；验收二分可判=方法问已用；发布卡有回滚预案=控制问已用） | 不允许跳过的规则 |
| **B 决策界面** | SOUL/skill 按需加载，启发式 | 抽查产物质量（审分解卡时看边界分析是否在），**不查 comment 仪式** | 判断力塑造型内容（四问/透镜/偏差清单） |
| **C 仪式化** | 强制 comment 打勾 | 机械统计执行率 | 仅限有实测失败基线且复发频繁的场景（如侦察摘要，基线 13%）；无基线不新建 |

**四问的验证证据活在产物里，不在检查表里**——要求 worker comment 念咒是 Goodhart 诱饵。各问的结构化落点：系统问=派工卡 body 必含边界/接口决策（已存在）；信息问=任务书 context 最小集+原文锚点（已存在）；方法问=验收标准 frozen 二分（已存在）；控制问=变更/发布必附回滚（已存在）。worker 侧仅在失败模式真实处加结构钩子（如调研报告「边界声明」节），不造新仪式。

## 四论四问（日常决策界面）

1. **系统问（看清）**：边界、接口、依赖、牵连面是什么？——边界没划、牵连面没列，不动手。
2. **信息问（看准）**：缺什么关键信息？先观测降不确定性，还是已够行动？——看不准不决策；要观测先开变量。
3. **方法问（可靠）**：判断是假设还是已验证？验收判据是什么、什么结果算证伪？——未验证不宣称；判据先于行动定死。
4. **控制问（有效）**：目标与现状的偏差怎么测？出偏差拿什么纠？——无回滚不发布；只记录不消费的告警视同未闭环。

四问之后过 8 项偏差清单（`cognition-self-check` skill）——四问管认识论，偏差清单管认识常见病，叠加使用。

## 各论在集群内的抓手（要展开时读哪）

| 论 | 透镜 skill | 集群机制实例 |
|---|---|---|
| 系统论 | `systems-lens` | capability-graph 能力图、task_links 依赖链、structure-evolution 五步闭环、ontology 对象模型 |
| 信息论 | `information-lens` | S4 注入侧收敛、夜间雷达采样、audit 只读脚本、金书滤波六法（页锚在 cybernetics-dual-lens） |
| 科学方法论 | （不单设——载体即验证工程本身） | rd-validate 三方对账、code-review Diamond 门、证据五档、验收标准 frozen 可二分 |
| 控制论 | `cybernetics-dual-lens`（主镜） | meta-watchdog 交叉互检、异构 fallback、路由留痕→月度聚合→打回→复测、S6 回滚垫 |

**透镜的恰当用法**：透镜是复杂场景（新结构/新观测/新闭环设计）的**设计期检具**，不是日常作业清单。使用方式=遇到对应决策时 skill_view 加载过一遍相关行，finding 写进设计文档或任务卡——它的价值在影响那一次设计，不在产生使用记录。无调用不等于无效；但 30 天零调用且零产物影响 → 按 harness-entropy 归档（存档不删，恢复一条命令）。

## 边界裁决（防止理论硬套）

1. 信息论不做 bit 计量——用「可判定性+信息增益」定性判断。
2. 控制论不搬数学——传递函数/频域/卡尔曼滤波不迁移。
3. 系统论不建第二套本体——ontology.md 管名词，透镜只管分析方法。
4. 科学方法论不替代验收门——四问是决策前自律，证据五档是决策后他律。
