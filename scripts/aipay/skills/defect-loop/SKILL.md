# Defect Loop（缺陷闭环）

## 角色与触发

- 测试侧（qi/fei）：测试执行发现缺陷时。
- 研发侧（chen/hu/lin/xiao）：收到缺陷反馈消息时。

## 测试侧流程

1. 缺陷定级（P0 阻断/P1 严重/P2 一般/P3 建议），附复现步骤、期望/实际、
   环境（分支/commit）。
2. matrix 消息发给对应应用主责研发-agent（@对方），格式：

```
【缺陷】<taskId> P<级> <一句话标题>
应用: <csw-*>
复现: <步骤>
期望: <...> 实际: <...>
分支/commit: <...>
```

3. 本机 kanban 登记缺陷卡片（status=triage，body 同上）。

## 研发侧流程

1. 收到缺陷消息后，本机测试智能体先复现确认（跑测试用例或按复现步骤执行）；
   无法复现 → 回复测试方并附执行输出，缺陷卡片置 blocked。
2. 确认后派给对应应用研发智能体修复：定位根因 → 修复 → 补回归用例 →
   自测全绿。
3. 完成后 matrix 回执测试方（@对方-agent），附修复 commit 与回归结论；
   缺陷卡片由人工确认后置 review，进入提测流程。

## 纪律

- 不许谎报：修复必须以真实测试输出为准，输出附结论行 `FIX-DONE-<defectId>`。
- 一处缺陷一张卡；重复缺陷按 inbox-dedup 合并。
