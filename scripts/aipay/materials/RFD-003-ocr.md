# RFD-003 对账字段与凭证 OCR 提取需求说明书

> 状态：BA 初稿（2026-09-25 补齐成文；OCR 双路提取可行性由 `aipay-ocr-verify.sh` 预研实证）
> 前置：RFD-001 收银台、RFD-002 退款/分账均已上线。材料：`RFD-003-ocr-sample.png`（支付凭证样本）+ `RFD-003-ocr-sample.expected.txt`（对账字段期望探针）。

## 1. 背景

收单商户侧存在人工对账成本：支付凭证（用户支付截图/渠道回执）中的关键字段无法进系统，T+1 对账依赖人工抄录，易错且无法规模化。

## 2. 目标

在已上线的收银台之上增加 **T+1 自动对账能力**：以支付凭证为输入，自动提取对账字段并与系统订单勾稽；差异进待澄清清单人工复核，全程不产生资损。

## 3. 对账核心字段（口径冻结）

| 字段 | 口径 |
|---|---|
| outTradeNo | 商户侧订单号（幂等键之一） |
| transactionId | 渠道侧交易号（与 outTradeNo 成对勾稽） |
| amount | 金额单位**分（int64）**；样本 `10050` = 100.50 CNY，禁止浮点 |
| timeout | 15 分钟未支付自动关单（关单单进 T+1 差异侧） |

## 4. 功能需求

1. **凭证 OCR 提取（双路强制）**：tesseract 严格路 + 语义提取路（vision_analyze 等视觉能力）并行提取，**两路 diff 后勾稽**——单路 tesseract 有字符级偏差（实测 `transactionId→transactionld`，I/l 混淆），单路结果不得直接入账。
2. **要素勾稽**：期望文本逐行作为探针（见 materials/RFD-003-ocr-sample.expected.txt）；关键要素行（订单号/交易号/金额）必须全命中，未命中行进待澄清清单。
3. **差异清单**：勾稽不通过的凭证生成待澄清任务（requirements-analyst 技能 A.1 流程），人工复核闭环。
4. **T+1 对账任务**：按日汇总渠道账单 vs 系统订单 vs 凭证提取三方数据，输出对账报告（匹配/金额不符/单边/超时关单四类）。
5. **幂等与资损底线**：对账任务按 outTradeNo+对账日幂等；任何自动处理不得发起资金动作，差异只进清单。

## 5. 非功能需求

- OCR 提取字段级准确率以"探针全命中"为验收口径（非字符级 100%——由双路 diff 兜偏差）。
- 金额一律分 int64 端到端一致（与 RFD-001 概设口径一致）。
- 凭证图片不入库明文敏感信息需脱敏存储。

## 6. 验收要点

1. 样本凭证双路提取 + 探针 5/5 命中（`bash scripts/aipay/aipay-ocr-verify.sh materials/RFD-003-ocr-sample.png materials/RFD-003-ocr-sample.expected.txt`）。
2. 构造金额不符/单边/超时三类差异样本，对账任务正确分类并全部进待澄清清单。
3. 对账任务重复执行结果幂等（无重复差异单）。
