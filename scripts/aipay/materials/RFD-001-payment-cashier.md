## 1. 背景

公司已上线收单支付平台，支持商户门户（Web）与 H5 收银台。多家收单商户提出：
其消费者主要在**微信小程序与支付宝小程序**场景内完成交易，要求平台提供
**小程序版本的统一支付收银台**，商户在自己主体的小程序内嵌入收银能力，
消费者一次接入即可任选微信支付或支付宝完成付款。

## 2. 目标

1. 交付一套兼容微信/支付宝双端的小程序收银台前端（csw-cashier-mp）。
2. 支付核心（csw-pay-core）支持小程序场景的统一下单、支付单查询、关单与
   支付结果通知。
3. 渠道层（csw-channel-wechat / csw-channel-alipay）按双方公开手册完成小程序
   支付对接适配。
4. 商户接入方只需集成一次 BFF 接口，即可获得双端收银能力。

## 3. 依据的公开技术手册（合规引用）

- 微信支付（财付通）商户平台开发文档（pay.weixin.qq.com 文档中心）：
  - 小程序下单接口：`POST /v3/pay/transactions/jsapi`（V3，微信支付商户平台）
  - 小程序调起支付：`wx.requestPayment(Object)`，参数 timeStamp / nonceStr /
    package（`prepay_id=***`）/ signType（RSA）/ paySign
  - 支付通知（回调）验签：微信支付平台证书 + `Wechatpay-Signature` 头
- 支付宝开放平台文档（opendocs.alipay.com）：
  - 服务端交易创建：`alipay.trade.create`（返回 trade_no）
  - 小程序端唤起收银台：`my.tradePay`，入参 tradeNO
  - 签名算法 RSA2（SHA256WithRSA），验签使用支付宝公钥

## 4. 角色

| 角色 | 说明 |
|---|---|
| 商户运营 | 在商户门户配置小程序 appid 与支付参数 |
| 消费者 | 在商户小程序内选购后进入收银台完成支付 |
| 商户系统 | 调用 BFF 创建支付单、接收支付结果 |
| 平台运营 | 查看交易与对账结果 |

## 5. 功能需求

### F1 收银台首页（小程序双端）
- 展示订单信息（商户名、商品摘要、金额、订单号）与倒计时（支付超时 15 分钟）。
- 支付方式选择：微信支付 / 支付宝（按当前宿主端自动排序与隐藏不可用项）。
- 点击支付：微信端走 `wx.requestPayment`；支付宝端走 `my.tradePay`。
- 支付结果页：成功/失败/处理中三态，失败可重试（不重复下单，复用原支付单）。

### F2 统一下单（BFF → pay-core）
- 商户系统调用收银台下单接口：`merchantId + outTradeNo + subject + amount +
  channelHint + openid（微信端必需）`。
- pay-core 落支付单（幂等：merchantId+outTradeNo），按 channelHint/宿主端路由
  渠道，返回收银台调起参数（微信：prepay_id 及二次签名参数包；支付宝：trade_no）。
- 支付单状态机：INIT → PAYING → SUCCESS / FAILED / CLOSED（超时自动关单）。

### F3 渠道适配
- csw-channel-wechat：V3 jsapi 下单、回调验签、查单、关单。
- csw-channel-alipay：alipay.trade.create、回调验签（RSA2）、查单、关单。
- 两渠道实现统一 ChannelAdapter 接口（createOrder/queryOrder/closeOrder/
  verifyNotify），本期不做退款（见 §8 范围外）。

### F4 支付结果通知
- 渠道回调 → pay-core 验签更新状态机 → 通知商户（既有通知通道复用）。
- 小程序端轮询/返回商户页面前查单确认终态。

### F5 对账支撑
- 支付单记录渠道流水号（transactionId / trade_no），供 clearing 次日对账
  （本期只做字段落库与查询接口，对账作业本身范围外）。

## 6. 非功能需求

| 类别 | 指标 |
|---|---|
| 性能 | 下单接口 P95 ≤ 800ms（不含渠道耗时）；收银台首屏 ≤ 1.5s |
| 安全 | 渠道密钥/证书仅存服务端；接口全链路 HTTPS；回调必须验签；
        支付金额以服务端为准，前端金额仅展示 |
| 幂等 | 下单幂等（merchantId+outTradeNo）；回调消费幂等 |
| 可用性 | 渠道超时自动切换提示文案；关单定时任务兜底 |
| 兼容 | 微信基础库 ≥ 2.x（requestPayment）；支付宝小程序 my.tradePay |

## 7. 验收标准

1. 双端收银台完成一笔真实链路（mock 渠道）下单→调起→回调→终态展示。
2. 重复下单/重复回调不产生重复支付单（幂等测试通过）。
3. 回调验签失败必须拒绝并记录告警日志。
4. 超时未支付订单被自动关单，再次进入收银台提示重新下单。
5. 单测 + 接口测试 + 回归测试全绿；提供测试报告。

## 8. 范围外（本期不做）

- 退款/部分退款；分账；服务商模式；跨境支付；对账作业本身（仅字段与接口）。

## 9. 待澄清（BA 初稿已识别）

1. 商户小程序主体与平台商户号的绑定关系（直连商户号 vs 平台代申请）？
2. 支付宝小程序 `my.tradePay` 在商家自研小程序内的买家体验差异是否可接受？
3. 支付超时 15 分钟是否按渠道分别配置？

## 9. 验收标准（G1 冻结，AC 逐条机械化可判）

- **AC-1 下单幂等**：同 `outTradeNo` 重复调用统一下单返回同一支付单号——apps/csw-pay-core 存在幂等键断言用例且全绿（存在性+行为断言）。
- **AC-2 状态机完整**：INIT→PAYING→SUCCESS/FAILED/CLOSED 全转移有单测覆盖且全绿（用例文件存在 + 执行输出在证据）。
- **AC-3 金额口径**：金额端到端为分（int64），测试含 `10050 == 100.50 CNY` 断言（存在性检查）。
- **AC-4 渠道适配**：微信/支付宝双渠道 ChannelAdapter（createOrder/queryOrder/closeOrder/verifyNotify）四方法有 mock 单测且全绿（≥6 用例存在）。
- **AC-5 回调幂等**：验签失败拒绝 + 重复回调幂等（不重复推进状态）有断言用例且全绿。
- **AC-6 超时关单**：15 分钟未支付自动关单有触发用例且全绿。
- **AC-7 收银台三态**：结果三态展示 + 失败重试不重复下单，前端逻辑层测试存在且全绿。
- 判定形式：每条 AC = 产物存在性（repo_has）+ 执行证据（测试输出日志）；"性能良好/体验优秀"类模糊表述一律不作为 AC。

## 10. Scope-Out（本可做而不做）

退款与分账（RFD-002 承接）；真实渠道网络请求（本期一律本地 mock）；多币种与汇率；T+1 自动对账（RFD-003 承接）；商户后台管理端。

## 11. 影响面

- 模块：csw-pay-core / csw-channel-wechat / csw-channel-alipay / csw-cashier-mp / BFF 聚合层。
- 接口：统一下单、查单、关单、渠道回调接收；对账字段导出。
- 数据：支付订单表（状态机字段、金额 int64 分、幂等键 outTradeNo）；渠道密钥配置。

## 12. 涉敏判定与安全要求（ISO27001 挂钩）

支付资金域数据 → **涉敏（内部-机密级）**。风险评估摘要：①渠道密钥仅服务端环境变量持有，不入仓不入日志②订单数据访问限研发/测试编制账号③回调验签防伪造④日志金额与卡号脱敏。G1 冻结即视为本摘要评估通过，详单见 iso27001/risk-assessment.md 结构。
