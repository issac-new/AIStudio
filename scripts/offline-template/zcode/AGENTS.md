## 0. 优先级与偏离

1. 用户显式指令最高：CLAUDE.md、AGENTS.md、当前会话直接指令。
2. 本文件（用户级 AGENTS.md）。
3. 系统/平台默认。

冲突时以上面的为准；不要自行放宽本文件的约束。偏离需用户明示："不用 worktree""直接在 main 改""这是只读探索"。只读探索（grep、读文件、解释代码）不产生提交，无需建 worktree。

## 1. Branch + Worktree 并行开发
**所有会产生提交的任务一律在 worktree 中进行，不在 main 工作区直接改代码。** 覆盖 feature / fix / refactor / chore 等提交型工作，以及 docs / test / exp 等文档与实验工作。目标：main 始终可发布、任务彼此隔离、可并行推进、收口干净。

### 1.0 选型锚点
| 维度 | 取值 | 理由 |
|---|---|---|
| Worktree 根目录 | `.claude/worktrees/` | 项目 `.gitignore` 已忽略，零额外提交 |
| 合并方式 | `git merge --no-ff` | 保留任务边界 merge commit，与仓库 Conventional Commits 历史一致 |
| 冲突处理 | worktree 内 `rebase origin/main` 后再合 | 冲突隔离在分支侧，main 始终 ff-only 可达 |
| 并行上限 | **≤3 个**在途 worktree | 平衡收益与心智/磁盘负担 |
| 分支命名 | `<type>/<scope>-<slug>`，如 `feat/wp-a-precheck` | 跟随仓库历史 Conventional Commits |

### 1.1 开工

- **开工前自检**：`git worktree list` 在途数达 3 个上限时不得新建；先收口一个或申请放宽；列表常驻超 3 条（不含 main）先自查过期任务——**过期判定一律按 §1.3 的 IN-FLIGHT 规则，禁目测**（「目录看着过期/名字不认识」不构成清理依据）。
- worktree 创建后**立即在其根写 `IN-FLIGHT` 标记**（内容=session 操作者标识+created 时间戳；命令见 skill `worktree-flow`），收口时随目录一并消失。
- 从 `origin/main` 起分支；**嵌套守卫**（检测已在 linked worktree 内则就地开工）与依赖安装规则见 skill `worktree-flow`。
- 完整创建/守卫/安装命令序列：调 skill `worktree-flow`。

### 1.2 工作中

- main 主工作区保持 clean，仅用于同步与合并；各 worktree 频繁提交，Conventional Commits 风格，中英文 header 跟随仓库历史。
- **不跨 worktree cherry-pick**（污染历史、制造隐形耦合）。B 依赖 A 时：等 A 合入 main 后 B 再 rebase，或二者合并为一个任务。

### 1.3 收口

- 原则：一任务一收口不批量合并；`--no-ff` 保留边界；rebase 冲突在 worktree 内解决；合并成功后才删 worktree；失败回 worktree 修复重试，不在 main 改冲突；实验/废弃分支不合入直接删；多任务按顺序逐个收口避免并发 merge 二次冲突。
- **清理一律走 git 通道**：正常收口=`git worktree remove`；目录已失联=`git worktree prune` 只清注册。**禁止 `rm -rf` worktree 目录**——裸删会留「missing but already registered」残注册，并直接击穿把该目录当 cwd 的其他会话 shell（cwd 失效报 `spawn <shell> ENOENT`，与 shell 损坏同形；双删事故实录，主嫌=并行 AI 操作者执行 worktree 卫生时裸删）。
- **IN-FLIGHT 在途保护**：worktree 根有 `IN-FLIGHT` 且 `created` 距今 <24h=在途，任何会话不得清理；>24h 且确认分支已合入 main 才可收口（仍走 git 通道）。无 git 注册的孤儿目录同样禁 `rm -rf`——移入 `.claude/worktrees/.quarantine/` 隔离或报用户裁决。
- 完整收口/合并/清理/验证命令序列：调 skill `worktree-flow`。

## 2. 提交与改动纪律

- **提交时机**：用户要求时，或任务达稳定节点且不破坏构建时；不为"看起来有进度"提交半成品。
- **commit 前自检**：`git status` 干净预期内。跑项目最小测试，按项目类型择一。如 `npm test` / `cargo test`；`pytest` / `go test ./...` 亦可。
- **大改先沟通**：多文件/架构级改动，进 plan mode 先出方案；用户确认后再写代码。
- **回看目标**：改动可被对应任务/issue 描述；需求有歧义，先问清楚再动手。
- **Bash 持久 cwd 不可依赖**（实测）：宿主会在调用边界重置工作目录——cd 出主工作区后下次调用必回弹工作区根（有提示），另有静默重置先例（dev server 曾因此起错树、走查了旧代码）。关键命令（起服务/跑测试/构建/git 写操作/多仓多 worktree 任务）一律显式 `cd <绝对路径> &&` 前缀，不裸跑相对命令；后台服务起后必须 `lsof -p <PID> | grep cwd` 核验所在树再采信其结果。

## 3. 验证门禁：多栈/生成器类工作

适用：模板/生成器派生代码、多语言/多技术栈产物（代码生成 skill、OpenAPI 客户端、跨语言 SDK、脚手架模板等）。七条源自某支付网关项目 69 轮回归、100+ 缺陷的根因沉淀，每条对应一类被真实炸过的坑。

1. **真实工具链先行（最重要）**：emitter/模板分支首次产出必须先跑通一次目标语言编译/lint/构建再宣布完成。"结构看起来对"不算验证；无工具链先装（brew 或官方 tarball），装不上明确标注"此栈未经真实编译"。
2. **每维度单一事实源 + 守门测试**：契约、格式、超时、null 语义、键序等横切维度只在一处定义，每个至少一个自动化测试断言；改动任一端守门测试必须当场 fail。
3. **语言陷阱 checklist**：改某语言生成逻辑前对照语义清单（如 Jackson bean 命名特例、Go `omitempty`、C# 属性与嵌套类 PascalCase 重名、PHP readonly 不可二次赋值、Swift memberwise init 默认 internal、Python 裸公钥 PEM ≠ X.509、TS 无扩展名 import 在 Node ESM 不可解析）。每踩新坑追加。
4. **修复回归面 = 修复点 + 相邻路径**：修完 A 跑全路径端到端，证明修复没引入新问题，而非只验证"A 消失了"。
5. **模板 ↔ 产物双向同步**：产物中修出的问题必须回移模板与生成脚本；改模板后必须重生成产物并过测试。只修一边 = 下次生成复发。
6. **并行/多会话同仓维护，开工先查漂移**：每轮开始内容比对（非仅 mtime）模板与产物关键文件 diff；发现半迁移先补齐再干活。
7. **收敛判据是"零新缺陷的完整轮"，不是"测试全绿"**：全绿只是准入；收尾复跑全部验证维度（编译、一致性、契约、端到端、负面测试、漂移检查），零新缺陷才宣告完成。

## 产出规范
动笔前
1. 先写主旨句：这份产物让读者做什么决策；开头声明写给谁看
2. 取舍：标注 ≤3 个决定性发现 vs 其余参考；删与主旨无关的段落；统计罗列≠有效信息，每段有判断，篇幅守硬上限
写文中
3. 说人话：禁黑话，一律行业术语（可附一句解释）；结论先行、写完整句子，不用箭头链和碎片缩写；代号首现给全称；费曼检验——无背景者一眼看懂；称谓用账户显示名或角色泛称，汇报收口三件事（待裁决什么/还剩什么/建议怎么做）；用户"没看懂"=打回重写；始终中文回复
4. 标题即问题：小节标题用读者会问的问句；节内首段必须直接回答
5. 结构严密：章节相互衔接，无孤立内容；重大设计给充分+必要性论证；论述查四类关系：时序/因果/充分必要/总分一致
6. 产物骨架：理念→设计→架构→实现→使用，环环相扣、逐层递进、与事实相符
7. 图为主文字为辅；长报告用案例贯穿（章首案例→概念挂案例→章末收束）
8. 见人见事见数据：每份报告至少一个典型事例（组件+场景+实测数字）；写结论不写过程（"调研了 X"→"结论是 Y，验证是 Z"）
9. 设计文档叙事顺序：定位价值→调研→问题决策→设计（先逻辑后形态）→实现；合格线=可据此 1:1 复刻，空壳/人类不可读不合格
10. 认知高度：要点罗列=AI 默认层，不合格；合格线=关联水平（论述四查全过）；要扩展抽象必须给迁移目标；高阶任务 Pass 条件写层级不写二值；低阶任务（搬运/检索/转换）直接委派+机械验收
交稿前
11. 去 AI 味四查：破折号密度（单段 ≤1 处）、句长节奏（长短交替）、"不是 X 而是 Y"密度、同型句式可预判
12. 删渲染词（值得注意的是/综上所述/赋能/抓手/深刻）；动词名词化还原；无源论断删除；关键词敢重复不换腔
13. 终态交付：只写"现在是什么、怎么用"；来历叙事、标题日期缀、卡号引用、版本史节、过程记录不入正文，历史归 git；存量文件迁移先把段落命题列全，机制事实用现在时重述，一条不丢
14. 三方一致：规范、设计、实现可对账；能力变更即同步设计文档；删编号必扫悬空引用
15. 红线：不规避问题、不拼凑、不偷工减料、不曲意逢迎、不写鸡汤；结论无锚点（file:line/URL/实测输出）不成立；严禁编造，未覆盖明说；证据本轮真实采集，缺失标"未采集"禁凑数；调研源码级下限，grep 匹配级=不合格；敏感/合规类任务（逆向、1:1 复刻、隐私敏感材料）须用户明示发起，材料只在本地处理不外发

## 工作模式
- 并行优先：能并行的相关工作一律并行——子智能体按文件归属不重叠分派、长命令后台任务、并行提交 worktree、测试 `--jobs`；单实例锁与共享夹具例外；并行不降低验证强度，子代理报告须主会话复跑核验
- 介入判据：AI 默认响应即完成（不建策略、不自查）；验收查策略/核查/不确定三样留痕，全无=没真介入退回；只给动作不给目标和约束，AI 只走最短路径
- 多点反馈用编号清单；长任务"直至完成所有"封口；完成后自动同步设计文档
- 排查类先产出排查清单（编号）再逐项打勾；迭代式推进：MVP 骨架→逐轮修 bug/调参数→收尾
- 长任务值守：每轮汇报四件套——做到第几步/是否正常/ETA/新问题；空转、日志停更、能耗停摆=事故征兆，异常触发式发现禁死等（分钟级）；只读巡检不改现场；值守自动化收官即删，值守中禁建新自动化
- 遗留项台账化：挂账→盘点→清账→验收成链；阻塞任务不具备条件或反复失败显式归档，禁无限重试；定时任务合一收敛
- 自动化纪律：自动化必须带验收（机制存在≠生效）；宣告≠生效——规则/风格类变更在源层验证并回执，防工具 update 洗掉后静默失效
- 面向终端用户：内部过程信息不出站（通道级过滤，非措辞优化）；口吻客观专业严谨、结论先行不恭维；界面不得是流水账、机读信息或假功能

## 多会话工程红线
- worktree/git 分支清理一律走 git 通道（`git worktree remove`/`prune`），禁止 `rm -rf` 目录——裸删留残注册并击穿把该目录当工作目录的其他会话
- 目录内有 `IN-FLIGHT` 标记且创建 <24h=他会在途，禁动；「看着过期」不构成清理依据；孤儿目录移隔离区或报用户

## 决策倾向
- 分叉点按此表裁决，不必请示
- 串行 vs 并行 → 并行优先：子智能体分派/后台任务/worktree/测试 `--jobs` 尽用；单实例锁与共享资源例外串行，验证强度不因提速下降
- 打补丁 vs 根治 → 根治（根因+防复发机制）；重复问题=上次没根治；修复落点一律产品正身，脚手架能力定期上移；修好新不得弄坏旧，验收含不影响既有使用
- 多份并存 vs 合一 → 合一收敛，冗余归档删除；规则单一事实源
- 手动一次 vs 自动化 → 自动化+机械验收巡检；按次计费的守门频率重估、合一进低成本通道
- 推断 vs 实测 → 实测，断言带锚点（file:line/URL/实测输出）；不信自报，独立验收蓝军审查；UI 改动打开实物走查；能耗异常低=疑似空转；变异探针验证守门测试有效性
- 一次性修 vs 长期规则 → 立长期规则写入配置；变更即自动同步设计文档
- 删除类 → 先存档再删，可回滚优先；建设期质量优先于省 token，不激进优化
- 多方案 → 编号+每项一句代价，等用户点头（"执行 A / 选 B / 全做"）才动；"继续"≠扩权
- 边界 → 各 agent 专注本域，skill 不跨域漂移；范围外顺手做=不做，列清单待批
- 换更强模型 → 提议重审该模型产出的存量结论，标注产出模型
- 模型资产 → 评估对比后上岗、退役即清缓存、别名登记
- 多用户数据/对外功能 → 租户隔离严禁交叉可读；先法务审再上线
- 敏感/合规任务（逆向、1:1 复刻、隐私敏感材料） → 须用户明示发起＋标注性质用途＋材料不出本地
- 人的感受是硬验收：无背景者一眼看懂，工程化不像玩具
